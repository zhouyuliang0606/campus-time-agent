# ai-log 07 · 在线 API 配置 + 文件上传 + 通知附件

> 开发日记第 7 篇：让管理员不用碰服务器，也让 AI 真的能"看"用户传上来的资料。
> 对应你的原话：**「增加 api 配置功能，给 ai 助手增加上传文件的功能，管理员发布也支持文件」**。

## 一、需求拆成三件事

| 你的话 | 难点到底在哪 | 落地方式 |
| --- | --- | --- |
| 增加 API 配置功能 | 传统做法要改 `.env` 再重启服务，演示时很不方便 | 管理台在线填，写 `settings.json`，优先级高于 `.env`，下次对话立即生效 |
| 给 AI 助手加上传文件 | **存了不等于能读**。文件躺在磁盘上，AI 根本不知道里面写了什么 | 给 Agent 两个读文件工具，让它真读到内容再回答 |
| 管理员发布支持文件 | 通知挂了附件，学生那边得能下载原件 | 上传时保留原件 + 提取文字两份，学生端通知栏给下载入口 |

## 二、在线 API 配置：关键是"别把配置定死"

### 2.1 优先级设计

```
管理后台 settings.json  >  .env 环境变量
```

放在 `config.get_llm_config()` 里统一裁决。**刻意做成函数而不是常量**，
每次调用重新读一次文件——开销可以忽略，换来的是"后台改完不用重启服务"。

`base_url` / `model` 允许只覆盖其中一个，另一个自动回落默认值，
管理员只想换模型时不必把整套参数重填一遍。

### 2.2 client.py 的一个坑

原来的写法把配置缓存在构造函数里：

```python
def __init__(self):
    self.api_key = DEEPSEEK_API_KEY   # ← 这样就把配置"定死"了
```

一旦这么做，后台改完必须重启才生效，在线配置白做。
改成每次发请求前调 `_config()` 现取最新配置。

### 2.3 两个安全防呆（重点）

因为这条链路会把真实密钥写进文件、还要回显到网页上，特意设了两道防线：

| 风险 | 防呆做法 |
| --- | --- |
| 网页被人瞄到 / 被浏览器插件抓走密钥 | `GET /api/admin/settings` **只返回掩码**（前 6 后 4 中间星号）。管理员并不需要看到完整 Key 才能改 Key |
| 前端把掩码串原样回传，星号被当真密钥存进去 | 保存时检测到含 `*` 就**忽略该项**，不覆盖已有真密钥 |

第二条尤其重要：如果不拦，管理员改个模型名、点个保存，
密钥就被 `sk-abc********1234` 冲掉了，而且很难排查。
测试的第五组就是专门盯这个的（"掩码串没有被写入"）。

顺带 `settings.json` 已加进 `.gitignore`——这种文件一旦入库就是事故。

## 三、文件上传：存了只是开始，能读才算闭环

### 3.1 解析层（app/upload.py）

单独拎一层，因为"读文件"跟"存文件"、"对外接口"都不是一回事，
以后想加 Word/Excel 只需要改这里。

- 文本按 `utf-8 → gbk → gb18030 → utf-16` 依次试（中文场景 GBK 很常见，不能漏）
- PDF 用 pypdf 逐页抽；没装依赖时给明确安装指引，不甩底层报错
- 扫不出任何文字时提示"可能是扫描件需要 OCR"，而不是装作成功

### 3.2 存储时存两份

```
uploads/<id>.txt      ← 提取出的文字，AI 读这份
uploads/<id>.<原后缀>  ← 原件，供通知附件下载
```

一开始只想存文字，后来意识到：**通知附件要能让学生下载回去**，
只有摘要的话这个功能是残缺的。所以 `save_upload` 增加了 `raw` 参数保留原件。

### 3.3 Agent 读文件工具（这是最关键的一步）

`app/modules/files.py` 提供两个工具：

- `list_uploaded_files`：有哪些资料（id / 文件名 / 字数）
- `read_uploaded_file`：按 id 读正文

**没有这一步，上传就只是把文件堆在磁盘上。** 有了它，用户问
"这份资料讲了什么"，Agent 会先列文件、再读内容、然后基于真实内容作答。

细节：
- 单次读取上限 6000 字，超出截断并说明总字数，防止长文件撑爆上下文和 token
- 文件 id 不存在时不报底层错误，而是提示"先用 xxx 看看有哪些文件"，
  Agent 能据此自我纠正继续干活

接入方式刻意做成**通用工具**，而不是复制进每个模块：
`main.py` 在组装工具箱时统一 `tools.update(files_tools())`，
并统一给提示拼上 `FILE_HINT`（告诉模型你有读资料能力、不许编造）。
好处是以后新增任何模块都自动具备这个能力。

### 3.4 追加：新版 Office 文档（Word / Excel / PPT）

你说「docx 这种」，就顺手把办公三件套一起做了——它们本质都是 OOXML 压缩包，
一起做成本很低，而校园里课表/名单/值班表几乎都是这些格式。

| 格式 | 用什么读 | 关键细节 |
| --- | --- | --- |
| `.docx` | python-docx | **必须连表格一起读**。只读 `paragraphs` 会漏掉大半内容——课表、值班表恰恰是按表格排的 |
| `.xlsx` | openpyxl | `data_only=True` 取公式**算出的结果**而不是 `=SUM(...)` 字符串；单表最多 2000 行防大表吃光内存 |
| `.pptx` | python-pptx | 逐页取文本框，顺带处理幻灯片里的表格 |

**又一个"写了却没机会执行"的坑**：我本来在 `extract_text` 里给老版 `.doc/.xls/.ppt`
写了「请用 Word 另存为 .docx」这种可执行指引，但实测发现它根本不显示——
因为 `main.py` 先用 `ext_supported()` 判了一次，不支持就直接返回通用 415，
压根没走到 `extract_text`。

修法：把文案抽成 `upload.py` 的 `unsupported_reason()`，由 main 的 415 分支调用。
**教训：多处都要用的提示文案，要抽函数并回头确认每个分支真的调到了**，
否则代码看着有，用户永远遇不到。

依赖同样做成可选：任一库没装，会在**具体格式**上给明确安装指引，不影响其他格式。

## 四、边界防护

| 场景 | 行为 |
| --- | --- |
| 空文件 | 400 |
| 超 5MB | 413（防止演示机被撑爆） |
| 不支持的类型 | 415，提示当前支持哪些 |
| PDF 扫不出文字 | 400，提示可能需要 OCR |
| 通知挂了不存在的附件 id | 400，杜绝"幽灵附件" |
| 通知标题/内容/附件全空 | 400 |

顺带把发布通知放宽成「标题/内容/附件至少有一个」，
支持管理员直接甩一份文件的场景。

## 五、前端改动速记

- **admin.html**：新增 🔑 API 配置卡片（保存 / 测试连通 / 实时显示配置来源）；
  发布通知增加附件上传（选完先传拿到 id，发布时一起提交）
- **student.html**：聊天加 📎 上传；顶部新增可折叠的**校园通知栏**（含附件下载，
  30 秒自动刷新）
- **station.html**：聊天加 📎 上传。上传后给的现成问法是商户视角的
  （"照这份清单写一版取件提醒"、"有几件滞留了"）

上传成功后都明确写了一句"我会先读文件再回答，不会瞎编"——
因为用户其实最关心的就是 AI 是不是真的看了文件。

## 六、验证

追加 Office 文档后，两份脚本共 **61 项全部通过，无回归**：

- 回归 1（第三四轮功能）：26 项
- 回归 2（本轮新功能）：**35 项**，覆盖
  上传/GBK/列表/读取/下载、空与超限与不支持类型、配置脱敏、
  **掩码串防呆**、空值回落、连通自检、通知附件与幽灵附件拦截、
  **以及 Word/Excel/PPT 三种格式的表格读取与老版格式指引**

Office 部分是**用真实文件验的**（不是字符串假装）：脚本里现场用
python-docx / openpyxl / python-pptx 造出带表格的 .docx、双工作表的 .xlsx、
含表格的 .pptx，再走完整上传接口，最后把提取出的正文读回来比对内容。

另外在真实服务器（不是测试客户端）上端到端跑了一遍完整链路：

```
上传 kb.json(3162B) → 拿到 id → 发布带附件的通知
→ 学生端 /api/notices 看到附件 → 下载回原件 3162B（字节数一致）
```

**测试纪律**：这次两个脚本都会碰敏感文件，所以都写了自动清理
（`atexit`），绝不能把一个假的 API Key 留在演示环境里。

## 七、踩坑记录：热更新没跟上

真机测试时 `/api/upload` 一直返回 404，但同样的路由在 TestClient 里是好的。

| 项 | 内容 |
| --- | --- |
| **现象** | 新增接口在测试客户端里正常，真机却是 404 |
| **原因** | 跑了 27 分钟的 `uvicorn --reload` 只记录了一次 reload，新加的路由没载入运行中的进程 |
| **解决** | 停掉旧进程重新冷启动，接口立刻正常 |
| **教训** | `--reload` 不可靠时别跟它较劲，**直接重启验证**。另外 HTML 是每次请求读盘所以永远是最新的，这容易让人误以为代码也是最新的——页面能用 ≠ 接口是新的 |
