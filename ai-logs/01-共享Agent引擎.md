# ai-log 01 · 共享 Agent 引擎（ReAct + 路由 + 工具箱）

> 开发日记第 1 篇：讲清楚项目的"大脑"是怎么搭的。这是评委最想看的部分——我们没用现成框架，自己写了推理循环。

## 一、Agent 是什么（大白话）
Agent = 会"先想后做"的 AI。普通聊天机器人只回一句话；Agent 遇到要算、要查的事，会：
1. **想**：下一步该干嘛？
2. **做**：调一个"工具"（比如查课表）
3. **看**：工具返回了啥？
4. **再想**：信息够了吗？够了就回答，不够继续调工具。

这种"想→做→看→再想"的循环，学术上叫 **ReAct（Reason + Act）**。

## 二、三个核心文件
| 文件 | 人话作用 |
| --- | --- |
| `app/agent/tools.py` | 定义"工具"长什么样（名字/说明书/参数/真正函数），并把它翻译成 DeepSeek 能识别的格式 |
| `app/agent/engine.py` | ReAct 循环本身：维护对话历史，让模型决定调不调工具，执行后把结果喂回去，直到能回答 |
| `app/agent/router.py` | 意图路由：用户一句话进来，先判断归哪个模块（课表/问答/驿站…），再交给对应模块跑 |

## 三、engine.py 的循环长这样（重点）
```
messages = [系统设定, 用户问题]
for 最多 6 轮:
    让模型基于 messages 回一句（可能说"我要调工具X"）
    if 模型要调工具:
        执行工具函数，拿到结果
        把"模型想调工具"和"工具结果"都加回 messages
        continue  # 让模型看结果后再想
    else:
        return 最终回答 + 思考轨迹(trace)
```
`trace` 记录了每一步在干嘛（想/调工具/结果），前端能直接展示成"Agent 思考轨迹"，是演示推理过程的关键。

## 四、router.py 怎么分类
先用**关键词兜底**（命中就直接归类，省一次模型调用、更稳），拿不准再让**大模型分类**（只输出一个 JSON 告诉我模块名）。分类结果只能是白名单里的：`schedule / faq / station / lostfound / repair / notice / admin`。

## 五、为什么自己写而不套框架
- **透明**：几十行循环，评委一看就懂 Agent 原理；
- **可控**：工具怎么调、轨迹怎么记，全在我们手里；
- **轻**：只依赖一个 `httpx` 发请求，没有沉重依赖。
