# 26 - 课表导入「确认修改」卡不来 + 假待办卡（上传文件不行）

- **日期**：2026-10-03
- **报障原话**：截图配文「上传文件不行」——学生端「📤 上传课表」传了
  《2026秋季课表-纯文本.txt》，管家回的是
  「📄 刚才那条消息里写了方案，可卡片没跟上——我替你把确认条挂出来了：
  要不要把 **确认修改** 排进日程？2026-10-05 (周一) 08:00-09:40」，
  轨迹里躺着模型整理好的课程表和
  「🛟 模型没调工具 → 系统从它的话里补出确认条 — 确认修改 | 2026-10-05 08:00-09:40」。
- **根因（三层叠一起）**：
  1. 前端 `timetableImportMsg` 模板说「整理成预览清单给我看……**先不要写入周表**，
     等我确认后再导入」→ 模型把「先不要写入」读成「先别出卡」，只发文字表格、
     不调 `propose_timetable_change`（真机复现 `options: []`；
     它还承诺「回一句"确认导入"我就出卡」，而**没有任何分支接得住这句话**）；
  2. `main.py` 的待办补条兜底不认识"导入课表"请求：模型一自称发过提案
     （话术里带「确认修改」）它就捞，把「确认修改」抠成任务名、
     表格第一行的「周一 08:00-09:40」抠成时间 → 假待办卡；
  3. 出卡兜底里没有"导入课表"这一路，模型忘了调工具就断链。
- **修法（三处）**：
  - `student.html` 模板重写：点名调 `propose_timetable_change`（确认卡=预览清单），
    删误导句；
  - `planner.py` 新增 `looks_like_timetable_import()` + `timetable_courses_from_reply()`
    （文字表格抠回课程清单；课名有"像名字"闸门：≤12 字、无句读、含汉字/字母）；
  - `main.py` 兜底分路：导入请求**绝不进待办补条**——抠得出清单就由系统补挂
    `timetable_change` 确认卡；抠不出就如实说明 + 指路。
- **护栏**：`tests/test_23_timetable_import_rescue.py` 34 项 / 5 批（含反向三连）。
  第一版解析器被自己的反向测试抓包（话术整句被抠成课名）→ 加闸门后复绿。
  ⚠️ 测试必须喂假配置（`app.main.get_llm_config` 导入时绑定；不喂假 key 会在
  `mock_planner` 提前返回，到不了出卡兜底）。
- **全量**：1696 通过 / 1 失败（24 批）；通过数 = 1662 + 34 分毫不差，
  那 1 红是 test_06 老项（先前 worktree A/B 证明改动前就红）。
- **真机双路验收**（重启后端、只出卡不点确认、前后 `/api/timetable`+`/api/todos` 逐字节一致）：
  - 新模板 → 模型自己调 `list_uploaded_files → read_uploaded_file → propose_timetable_change`，
    5 门课全部上卡；
  - 旧模板（截图原幕）→ 轨迹「🛟 模型没调课表提案工具 → 系统从它的话里补出「确认修改」卡」，
    5 门课上卡、假待办卡绝迹。
- **边界**：语义层把导入请求「听成 问事」是显示层的另一个小别扭，本轮未动；
  未动 PDF；未推送（等新 PAT）。

## 第二轮（2026-10-04 凌晨）：学生回话「解析出来了，卡没出来……可以弹是否更改课表的卡」

- **报障原话**：「解析出来了，卡没出来，由于是修改课表，我认为可以弹是否更改课表的卡」
  ——修完第一轮后，**模型确实把文件读出来了，但确认卡还是不出来**。
  这是对「必须出卡」的硬要求，不是"再润色一下话术"。
- **真机复现（用学生自己那份上传 `1f02a280e950`）**：模型回的是列表体
  `- **周一**：08:00-09:40 高等数学（教三301）｜10:05-11:45 大学英语（外语楼204）…`，
  而**学生的原文件是"一天一行、用；串好几门课"**
  （`周一：08:00-09:40 高等数学 教三301；10:05-11:45 大学英语 外语楼204；…`）。
  v1 解析器**一行只认第一个钟点**（`_tt_course_row`），后面的课全被吞 → 14 门只抠出几门。
- **修法（解析升级 + 兜底的兜底）**：
  - `planner.py`：删掉 `_tt_course_row`（一行一门），换 `_tt_courses_in_line`——
    **按每个钟点切段**，两个钟点之间那段就是这一门课 → 一行能出好几门；
    新增 `_TT_PERIOD_WORDS`（「晚上」是"什么时候"，不是"在哪儿"）、
    `_TT_SPLIT_RE`（；｜、都当分隔符）、`_TT_BRACKET_RE`（「课名（地点）」拆两栏）；
    `_TT_SENT_PUNCT` 去掉「；」——学生文件靠它分课，它是分隔符不是句读。
  - `main.py` 新增 `_tt_file_courses()`：**直接读上传的文件原文**抠课程（硬证据已在库里，
    不用再问模型一次）；两路都抠、**取更全的那份**，卡与回话里写明清单来自
    「管家回话」还是「文件原文」。⛔ 只按**点名**找文件（消息里的《文件名》，
    重试时回本会话最近几句找《…》），**绝不拿"最近那份文件"猜**。
- **护栏**：test_23 从 34 项 → **43 项 / 6 批全绿**（新增 3-bis 批：只念 3 门→补齐 5 门、
  「晚上」那节也在卡上、没点名文件 → 零卡不瞎猜）。
  全量 **1705 通过 / 1 失败（24 批）** = 1696 + 9 分毫不差。
- **真机最坏情况验收**（学生真实文件 + 旧模板这种最易断链的组合）：
  `options kinds: ['timetable_change']`、`导入课表（文件原文解析 14 门课，系统补出确认卡）`、
  轨迹「🛟 …（清单来自文件原文）」，`/api/timetable` 与 `/api/todos` 逐字节未变（零污染）。
- **未决**：库里还留着那张**假卡** `s76ef8b8432`（`title: 确认修改`）——它躺在学生的会话里，
  一进那轮就还会弹出来，误点【确认】会写一条垃圾待办。已报给学生**等他拍板**再清
  （不擅自删真实数据）。

## 第三轮（2026-10-04）：「如果是上传课表就弹是否修改就行，不用每门课单独拎出来」

- **报障原话**：「如果是上传课表就弹是否修改就行，不用每门课单独拎出来」。
- **先定位"念清单"念在哪儿**：卡（`confirm.html`）早就只给门数（更早列过 11 门，
  把弹窗撑到一屏高、按钮都挤没了），真正一门门念的是**聊天流里那句回话**——
  兜底路径本来就是系统话术（不念），但**模型自己乖乖调了 `propose_timetable_change`
  时，它那段"解析完成，共 14 门课：周一…周二…"被原样展示**，学生看到一整屏重复清单。
- **修法**：
  - `main.py`：导入请求且最终有 `timetable_change` 卡时，**不论卡是谁出的**，
    回话统一换成 `_tt_confirm_answer()` 一句「课表读好了，共 N 门课。
    要不要用这份课表替换现在的周表？」；卡上 summary 也从「…系统补出确认卡」
    这种内部腔改成「导入课表（共 N 门课）」。清单只留在 `courses` 里给写库用，不往屏幕上摆。
  - `student.html` 模板：明说「回话里只说一句……**不要把课一门门再念一遍**」（课只进工具参数）。
  - `confirm.html`：按钮「确认变更」→ **「确认修改」**（跟学生原话、规划页那颗
    「确认修改课表」对齐——以前两处叫法不一），卡上加一句「要不要用这份课表替换现在的周表？」。
- **护栏**：test_23 43 → **53 项 / 7 批全绿**（新增 3-ter：模型自己出卡但念了清单 →
  回话被换成一句、课名零出现、清单仍在卡里；反向：普通加课请求不许被换成导入话术）。
  全量 **1715 通过 / 1 失败（24 批）** = 1705 + 10 分毫不差。
- **真机验收**（学生真实文件，重启后端后、只出卡不点确认）：模型自己调出卡、**14 门课**，
  回话只有 **72 字**、课名一个没漏，周表/待办零污染。
- **教训（新）**：★ **「卡上不列」不等于「学生看不到清单」**——模型那句原话也是界面的一部分。
  要钉就钉最终的 `answer`，而且要**不区分卡是谁出的**（否则"乖模型"那条路上照样漏）。
