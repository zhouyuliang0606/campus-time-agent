# 12 · 学生助手人设规矩与工单上报

> 一句话：把学生定下的四条人设规矩（输出要求 / 工单上报 / 个人数据隔离 / 自我定位）真正写进
> 助手的大脑（系统提示）和手脚（工具与接口），并新增「确认后才立案」的工单链路。

## 学生定的人设四条 → 落地方式

| 人设规矩 | 落地 |
| --- | --- |
| ① 回答简洁、异常输入友好提示、不输出低俗内容 | 全局规矩块 `ASSISTANT_RULES`（main.py）拼进**每个模块**的系统提示；前端报错改友好话术（「网络好像开小差了」），不再裸吐 `e.message` |
| ② 外卖丢失/快递问题 → **先问是否上报**，确认才生成工单 | 快递/外卖模块提示新增【上报工单规则】+ 新工具 `submit_work_order`（学生没确认前调用即违规）；普通对话**不再全量上报**管理端（移除前端 `logToAdmin`） |
| ③ 改课表/增删待办只出**预览方案**，确认后才写库 | planner 提示新增【个人数据隔离 —— 预览确认制】；`import_timetable`/`remove_todo`/`update_todo_status` 工具描述全部改为「学生确认后才能调用」；改课表必须整表传入（含未改动课程） |
| ④ 辅助工具不是决策者；上传文件只读 | 同一条全局规矩块；文件模块本来就只读不写 |

## 工单链路（新增）

```
学生在聊天里说"外卖丢了" → 管家先问「是否上报给管理端？」
   ├─ 学生不确认 → 只解释/安抚，不立案
   └─ 学生确认 → submit_work_order 工具 → app/data/workorders.json
面板表单提交工单 → POST /api/workorders（source=panel）
管理端 /admin → 「🛠️ 学生工单」区块 → 查看 + 改状态（待处理/处理中/已解决）
```

- 存储走 `store.py` 的 `add_workorder / list_workorders / update_workorder_status`（与其它数据同一套分层，换库不改调用方）。
- 工单与「学生消息收件箱」是两回事：收件箱是消息存档（按人设规矩普通对话不再写入），工单是**学生确认后**的正式问题记录。

## 课表导入改为「预览确认制」

面板「📤 上传课表」与聊天「📅 让管家读取这份课表」的指令文案同步改为：
读文件 → 给**预览清单**（星期/时间/课名/地点，第几节换算 HH:MM）→ **先不写入** → 学生确认 → `import_timetable`。
面板状态条会提示「管家已给出课表预览，请在下方聊天里确认后再导入」。

## 怎么看效果

打开 `/student`：
- 聊天说「我的外卖丢了」→ 管家先问是否上报 → 回复「上报」→ 工单立案；管理端 `/admin` 的「学生工单」区块立刻可见（5 秒自动刷新），可标「处理中/已解决」。
- 面板「我的日程」→「📤 上传课表」→ 管家给预览清单、周表不动 → 聊天回复「确认导入」→ 周表才更新。
