# 09 · 把验证脚本沉淀成正式测试（含一次真实的翻车）

## 这轮要解决什么

此前每次加完功能，都是临时写一个 `smoke_tmp.py` / `smoke2_tmp.py` / `smoke3_tmp.py`
放在工作区跑一遍就丢。问题有三个：

1. **不在仓库里**：评委拿到项目看不到任何"自检"的证据，也无法自己复现；
2. **路径写死**：脚本里硬编码了 `D:/Workbuddy/.../CampusTime`，换个机器就跑不了；
3. **会污染演示环境**：这是最要命的一条，下面单独说。

## 翻车：备份-还原方案留下了一个假密钥

最早的隔离思路很直觉：

> 跑之前把 `kb.json` 备份一份，跑完还原回去。

听起来没问题，**但只要测试中途崩溃，还原那几行就永远执行不到**。

实际发生的过程：

```
测试跑到一半，某一行 os.remove(settings.json) 抛了 FileNotFoundError
      ↓
进程直接崩了，后面的"还原"没执行
      ↓
app/data/settings.json 里留下 api_key = "sk-abcdefghijklmnop1234"
```

后来跑别的测试时，这条残留配置还会被**复制来复制去**，
导致"未配置密钥时应该给出友好提示"这类用例莫名其妙失败——
排查时才顺藤摸瓜发现根因。最后手工清掉了 `settings.json` / `uploads.json` /
`uploads/` / `notices.json` 四处残留。

**教训**：依赖"进程正常收尾"做清理，本身就是不可靠的设计。

## 改法：给存储层留一个环境变量开关

```python
# app/store.py
DATA_DIR = os.environ.get("CAMPUSTIME_DATA_DIR") or os.path.join(os.path.dirname(__file__), "data")
```

测试启动时先把真实的 `app/data` 整份复制到临时目录，
再通过环境变量告诉程序"数据放这儿"，退出时整个临时目录删掉。
崩溃了也不怕：`atexit` 兜底 + `with` 退出都会删。

配套的两个细节：

- **每次从零开始**：沙箱里会先删掉 `settings.json` / `uploads*` / `notices.json` /
  `student_messages.json` 这类"运行时痕迹"，否则上一次测试的假配置会带偏这一次；
- **每个文件单独起进程**：数据目录在 import 那一刻就定死了，
  放同一个进程里三批测试会互相串味，`run_all.py` 用子进程隔开。

## 顺带修的两个小坑

| 坑 | 现象 | 处理 |
| --- | --- | --- |
| 月表计数用例依赖演示数据 | `app/data/student/todos.json` 里本来就有种子待办，"明天应该是 2 项"实际是 4 项 | 改成**比对增量**：先记下加之前几条，加完再比对，不依赖环境里原本有多少 |
| starlette 的过时警告刷屏 | 满屏 `StarletteDeprecationWarning` 盖住 ✅/❌ 结果 | 它看着像 DeprecationWarning，**实际继承自 UserWarning**，按类别过滤抓不到，只能按消息内容过滤 |

## 最终产物

```
tests/
  README.md          大白话说明：怎么跑、测什么、为什么搞沙箱
  _harness.py        Checker 打分员 + sandbox 沙箱 + make_client 假浏览器
  run_all.py         一键跑全部，末尾给总账
  test_01_basic.py   骨架（29 项）
  test_02_upload.py  上传与配置（35 项）
  test_03_planner.py 学生日程（36 项）
```

跑法：

```bash
python tests/run_all.py
```

结果：**100 项全过**，`app/data` 一个字节没动。

没有引入 pytest——只要项目虚拟环境里已有的 fastapi（`TestClient` 相当于假浏览器），
评委不用装任何额外包就能跑。
