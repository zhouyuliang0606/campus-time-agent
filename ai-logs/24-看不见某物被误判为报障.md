# 24. 「看不见 X」被拿去编原因：推送出了问题、反馈给管理端

> 报障截图：学生说「**我现在没有看见日程显示周二游泳代办项目啊**」，
> 管家回了一大段——
>
> 「我理解你着急，但得跟你说句实在话：**我这边没法直接往你日程里写数据**……
> 刚才那条提案推过去没弹出确认条，说明**系统那一步没走通**……
> 咱们换个稳妥的办法，**你二选一**：1. **再刷新一次**……
> 2. 如果刷新后还是没有，那基本可以确定是**系统推送出了问题**……
> 得让**管理端**那边看一下……我帮你把这个**问题反馈给管理端**处理。」

这段话是**模型说的**（提示层约束拦不住它自由发挥），但根因在系统：
这句话**哪个确定性分支都不认**，整句掉给了模型。

对照学生的规则总览，三条红线全踩：

| 规则 | 它干的事 |
|---|---|
| 学生日程操作默认自主，**不提管理端** | 「得让管理端那边看一下」「我帮你反馈给管理端」 |
| 禁止反复追问、直接给方案 | 让学生「二选一：再刷新一次 / 反馈管理端」 |
| 话术只承诺能兑现的事 | 「我帮你反馈给管理端处理」——**根本没有分支接得住** |

而系统明明能**真查库**：在就告诉他在哪儿，不在就把确认条补挂出来。
全程轮不到"诊断推送"。

---

## 修法

### 一、识别（`app/modules/planner.py::missing_thing_of`）

「没看见 / 看不到 / 没显示 / 怎么没有 / 日程里没有 X」这类话**不是要加新事，
是在问在不在**。函数返回 `{"title", "date"}`，抠法两步：

1. **先拿真名到句子里找**：库里已有的待办名、调用方传进来的近期事名，
   原样出现在句子里就是它（学生抱怨的十有八九是他刚弄过的那件事）。
2. 落空再抹"场话"（日程/显示/待办项目/为什么/……）后 `_pick_title`。

三个实测坑：

* **正则候选顺序**：「怎么没」排在「没看到」前面的话，
  「我怎么没看到周一的健身」先匹配掉"怎么没"，剩下光秃秃的
  「看到」混进事名 → 抠出「看到健身」。**具体的放前面，泛的放后面**。
* **「有」字两头剥**：「有游泳」的"有"是存现动词（日程里**有**X），剥；
  「有氧运动」的"有"是名字的一半，留。别拿长度判（"有游泳啊"带个语气词
  就四打了），白名单列已知的"有X"复合词。
* 尾巴上的「还/出来」也是碎屑（「游泳还没显示出来」→ 先抠出「游泳还出来」）。

### 二、核实（`app/main.py` 3c-ter，插在 3c 之前）

查到什么说什么，四个出口：

| 查到什么 | 回什么 |
|---|---|
| 待办里有 | 「在的，日程里排着呢：**游泳**｜2026-09-29（周二）16:00-17:30」 |
| 说的那天没排、别处有同名 | 「你说的周二没排，倒是周六有一条……」 |
| 课表里有（他找的是课） | 「那是**课**，在周表里：周一 08:00-09:40 高等数学@教三-201」 |
| 真没有、最近说过要加 | **承认"还没写进去"** + 确认条补挂出来 |
| 真没有、最近也没说过 | 「确实还没有「X」。要加的话说一句」 |

全程：不诊断"推送出了问题"、不提管理端、不让学生二选一、不写库。

### 三、提示词（两份同步）

`planner.build_system_prompt()` 与 `schedule.SYSTEM_PROMPT` 各加一段
【学生说"没看见/日程里没有 X"——核实的事交给系统，你不编原因】，
把这次的反面教材原话钉进去，禁止再说。

## 附：全量里那条「规划完也还没写库」不是本轮回归

第十六批加上后 `run_all.py` 只红一条 —— `规划完也还没写库`
（`test_06_add_things.py`，口语时间那条）。第一反应是本轮新分支抢了路，
于是按老规矩 `git stash` → 在旧代码上复跑同一条断言 → **旧代码同样红**
→ 与本轮无关。

真凶是**时钟**：当时 21:40，今天晚上的空档已经过完，无日期的规划落到了
明天，正好和前一段步骤 ② 已经【确认写入】的「游泳」撞到同一天，
`not any(t["title"]=="游泳" and t["date"]==card.date)` 必然为假。
晚上跑测试本来就会踩到这个（白天那会儿是绿的）。

修法：断言不再对**具体某一天**做排除，改成**快照前后对比**——
发请求之前先把待办全量抄一份，请求之后只看"多出来的那条"，
断言"多出来的里没有这张卡对应的那条"。这样无论规划落到哪天都成立。

> 纪律：全量出现失败，**先 `git stash` 在旧代码上复跑同一条**再下"我引入的回归"
> 的结论；判据是"旧代码同样红 = 与本轮无关"。别凭直觉认领别人的锅。
