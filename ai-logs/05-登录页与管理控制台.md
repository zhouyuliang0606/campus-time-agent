# ai-log 05 · 登录页 + 管理员端（发布通知 / 接收学生消息）

> 开发日记第 5 篇：加了身份入口和一扇"管理员能看到学生在问什么"的窗。

## 一、为什么要登录页
原来 `/` 直接进学生端。现在加一层身份选择：学生 / 管理员，各自进各自的端。
演示用、无需密码——重点展示"同一套系统、两种角色、数据互通"。

## 二、登录页（app/static/login.html）
- 居中卡片，两个大按钮：「我是学生」「我是管理员」
- 点哪个跳哪个：`/student`（学生端四模块）、`/admin`（管理台）
- main.py 把 `/` 改为登录页，并新增 `/student`、`/admin` 两个路由

## 三、管理员端要的两个能力（用户明确要求）
1. **发布通知**：左栏表单（标题+内容）→ `POST /api/admin/notify` → 存 notices.json
2. **接收学生消息**：右栏收件箱，`GET /api/admin/messages` 每 5 秒轮询，展示时间/模块/学生问题/管家回答

## 四、学生消息怎么"跑"到管理员那里（闭环）
- 学生每轮对话后，student.html 异步 `POST /api/student-message`（模块+问题+回答）
- 后端 `app/store.py` 把消息追加进 `student_messages.json`
- 管理员端轮询拉取，倒序展示（最新在前）
- 所以：学生在学生端问 → 管理员在管理台实时看到，形成"学生问→管理员看"闭环

## 五、存储设计（app/store.py）
- 两张"表"：student_messages.json、notices.json，都是 JSON 文件
- 演示够清晰、好改；真上线把 store.py 内部换成数据库即可，接口不变
- 写文件带 `ensure_ascii=False` 和缩进，方便人直接打开看

## 六、接口一览（新增）
| 方法 | 路径 | 作用 |
| --- | --- | --- |
| POST | /api/student-message | 学生对话上报 |
| GET | /api/admin/messages | 拉学生消息收件箱 |
| POST | /api/admin/notify | 管理员发布通知 |
| GET | /api/notices | 列出通知（学生端以后可展示） |

## 七、演示话术
1. 打开 `/` → 点「我是学生」→ 问"我有哪些快递待取？"
2. 新开标签页打开 `/admin` → 收件箱里应能出现这条消息（含模块=express、管家回答）
3. 在管理台发一条通知 → 已发布通知区出现
（注：聊天需要 DeepSeek Key；上报/通知/收件箱不依赖模型，Pure 接口即可演示）
