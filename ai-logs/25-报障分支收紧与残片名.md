# 25. 收紧「看不见 X」分支的边界：在哪别误伤，残片别当名字

> 用户说"自己测也没用"——第十六批修完「看不见 X」报障后，我回头验证边界，
> 发现它把正常的**问时间**也吃进去了，还把用户原话里的残留当做事名。
> 这轮把漏洞补上。

## 一、事故："游泳在哪天来着"被当成报障

第十六批（ai-logs/24）接住了核心报障句：

```
我现在没有看见日程显示周二游泳代办项目啊
```

但同一套正则里躺着 `在哪|在哪里` 两个触发词，于是 **「游泳在哪天来着」**
这种**正常问时间**的句子也被命中了。结果：

| 轮次 | 谁说的 | 内容 |
|---|---|---|
| 1 | 学生 | 游泳在哪天来着 |
| 2 | 管家 | 👀 查了日程，**确实还没有**「游泳天来着」 |

两个 bug：
1. **误伤**：问时间被当成"看不见"；
2. **残片当名字**：「天来着」是用户原话里的语气残留，不是事名，被抠出来挂给学生。

## 二、修法

### 2.1 `在哪` 只认"在不在"，不认"哪天"

`_MISSING_RE` 里 `在哪|在哪里` 改成：

```python
r"在哪(?:里)?(?!天|星期|周|月|年|日|号)|"
```

效果：「游泳在哪天来着」不再命中；「我的游泳在哪」仍然命中（这是真报障，问"在不在"）。

### 2.2 给抠出来的名字加一道"像不像真名"

新增 `_MISSING_JUNK` 和 `_missing_title_ok`：

```python
_MISSING_JUNK = ("来着", "天来", "在哪", "怎么", "为什么", "还是",
                 "出来", "进去", "里面", "里边", "上面", "上边")


def _missing_title_ok(name: str) -> bool:
    if not name:
        return False
    if any(w in name for w in _MISSING_META):
        return False
    if any(w in name for w in _MISSING_JUNK):
        return False

```

如果抠出来的是「游泳天来着」「健身显示」这类东西，直接降级成空串。
`missing_thing_of` 返回 `{"title": "", "date": ...}`，调用方 `main.py` 会改走
"最近要加的那件事"那条默认答案；如果连这也没有，就诚实回答「确实还没有」。

## 三、反向断言：第十七批 15 项

第十六批全是正向断言（报障句被接住）。这一批补另一半：

- 「游泳在哪天来着」「帮我找一下游泳的时间」
  「帮我安排一下这周的学习计划」「那给我加上游泳吧」 → 不许被当成报障；
- `_missing_title_ok("游泳")` 放行、`_missing_title_ok("")` 否掉、
  `_missing_title_ok("健身显示")` 否掉、`_missing_title_ok("游泳天来着")` 否掉；
- 正向防回归：报障句仍然认得出「游泳」；「有氧运动」的「有」仍然保住；
- 走接口：「游泳在哪天来着」不许回「确实还没有」；报障原话走接口不许带残片名。
