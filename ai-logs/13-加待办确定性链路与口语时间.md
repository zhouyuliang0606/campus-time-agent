# 13 · 加待办：口语时间、系统追问、确认落空捞回原话

> 一句话：学生说「帮我安排周二下午两点到三点游泳」，管家回「搞定！游泳这条已经正式写进
> 你的待办啦 ✅」，日程里空空如也——因为这句话**根本没被系统接管**，掉给了大模型，
> 而 schedule 模块连一个写入工具都没有，那声「搞定」纯属嘴甜。
> 这一篇把加待办做成和「删除课表」一样的确定性链路。

## 事故链路（学生截图复现）

```
学生：帮我安排周二下午两点到三点游泳
  → wants_add_todo() 判要不要由系统接管
  → 老 _pick_span() 只认阿拉伯数字，「两点」在它眼里等于"没说时间"
  → parse_add_todo() 返回 None → 掉回大模型
管家（schedule 模块，只有查课表/找空档三类只读工具）：
  「搞定！游泳这条已经正式写进你的待办啦 ✅ 刷新一下就能看到」
学生：确认
  → is_confirmation ✓，但暂存里空空如也（提案从来没生成过）
  → 又掉回模型，模型继续说"已经写进了"
结果：学生刷新，什么都没有。
```

## 三处修复

| 位置 | 问题 | 修法 |
| --- | --- | --- |
| `planner._pick_span` / `_pick_title` | 只认 `\d`，认不得「两点到三点」「两点半」「晚上七点半」；`下午2点` 还会被算成 02:00 | 新增 `_cn_num` / `_normalize_clock`（中文报时→数字钟，含「X点Y分」）+ `_pm_fix`（下午/傍晚/晚上 拨 12 小时；止比起还早说明漏拨，补上） |
| `main.py` 3c 分支 | 解析不出就把话交给模型 → 模型撒谎 | 照删课的规矩：**系统追问**缺什么（时间／日期），标记「加待办缺细节」写进会话；学生下一句补充时把**上一句原话拼回来**再解析（标题才丢不了） |
| `main.py` 3a-c 兜底 | 学生回「确认」时提案已不存在，只能继续交给模型 | 新增"确认落空 → 捞原话"：在最近 8 条会话里找学生那句加待办原话，重新解析并**重新挂出确认条**（只出提案、不写库，仍要学生点头） |

配套的判定调整（别抢别的链路）：

- `wants_add_todo` 的"没意图词"兜底放宽到"日期/星期 + 起止时间"（`今天19:00-20:30 复习线性代数`
  这种不带"安排"字样的也接住），带疑问词的不算；
- 「加一节 / 加一门课」一律让给加课链路（否则「周一加一节体育」会被当成待办塞进日程）；
- 标题清理顺序修正：「下周二」要整块擦掉，先削"下周"再削"周二"会剩一个"二"粘进标题。

## 两道"别抢/别重"的闸门

| 场景 | 不加闸门会怎样 | 闸门 |
| --- | --- | --- |
| 「帮我安排这周的学习计划」 | 被当成待办，系统回"时间和日期说一下"——那是 schedule 模块的看家本领（找空档排计划） | `wants_add_todo` 里"让路"必须排在"有意图词就放行"前面：先交出课表/加课/规划类，再谈接住 |
| 学生加完待办又回一句「好的」（也是确认词） | 暂存已空 → 把原话重新捞出来挂确认条 → 再点一下就是同一天两条 | 捞出原话前先看最近几轮有没有系统自己写的回执（"已加入日程"/"已按你的确认"），有就说明已经写成功，不再重新出提案 |

## 防模型嘴甜（提示层）

`ASSISTANT_RULES` 增补一条：**你手上一个写入工具都没有**，加课/加待办/改课表只能请学生
说清时间、由系统出确认条；**严禁**用"搞定／没问题／已经正式写进你的待办啦／刷新一下就能看到"
这类话暗示已完成。
