# 14 · 日程面板：「提案已发给你」但界面上连个确认按钮都没有

> 一句话：学生停在日程面板，管家回了一段
> 「好，那我按这个出个提案：- 任务：健身 - 时间：周一 16:30~18:00 - 范围：本周
>   提案这就发给你，点一下【确认】就入库了！」
> —— 文案写得像提案已经发了，可界面上**连一个按钮都没有**。
> 根因是「课表时间规划」模块手里**一张纸都没有**：它只有查课表、找空档、排计划三个
> **只读**工具，找完空档只能在文字里把方案念一遍。这是 13 号那个病根的另一张脸：
> 上次是"嘴上说写好了"，这次是"嘴上说提案发了"。

## 事故链路（学生截图复现）

```
学生（停在日程面板）：帮我安排一下健身
管家（schedule 模块）：
  find_free_slots 查到周一 16:30 之后有空
  → 它没有"出确认条"的工具，只能在文字里写：
     - 任务：健身
     - 时间：周一 16:30~18:00
     - 范围：本周
     提案这就发给你，点一下【确认】就入库了！
  → 界面上：没有按钮、没有卡片，什么都没有
学生：可以
  → is_confirmation ✓，但暂存里空空如也（提案从来没生成过）
  → 掉回模型，模型继续聊，日程里始终没有《健身》
```

## 三处修复

| 位置 | 问题 | 修法 |
| --- | --- | --- |
| `planner.propose_todo_tool`（新增） | 模块没有"出提案"的手脚 | 新增第四个工具：**只读**，吃学生那句口语（`when="周一 16:30~18:00"` / `"明天下午两点到三点"` 都认），成功返回 `{"__proposal__": …}`，解析不出来就返回带 `hint` 的 JSON 让模型补参数重试——**绝不瞎凑一个时间**。<br>⚠️ 后来改了：**只给 `date`、不给 `start` 也出条**，时间由系统从那天空档里挑（见 `ai-logs/16`）——原来的 `hint` 会让模型转头去问学生"你想几点"，等于把活儿退回去 |
| `schedule.build_tools()` + `SYSTEM_PROMPT` | 工具在架子上，模型才会调；光有工具不写进提示层，它照样只写字 | 注册 `propose_todo_tool`，并在设定里写死：要排任务**必须**调它；⛔ 严禁只在文字里写「任务：…/时间：…」就宣称"提案已发给你"；**没调用工具就别说"提案已经发出"** |
| `main.py` 3a-c 兜底（新增一支） | 万一模型还是不调工具（模型行为管不死） | 照 13 号"确认落空捞学生原话"的思路，这次捞**管家自己那句方案**：用 `parse_todo_from_reply` 按固定格式（"任务/事项/标题：" 配 "时间/时段："）把它还原成提案，重新挂出确认条 |

`parse_todo_from_reply` 的克制之处：**格式对不上就返回 `None`**。
学生回「可以」时，宁可这条不挂，也不能从一堆闲聊里瞎猜出一个待办来（"所以要不要去跑步啊"
这种句子不该被读成"跑步"）。

## 为什么不用改前端

确认条是 `renderOptions()` 按 `options[].kind === "todo_add"` 渲染的，跟模块无关；
引擎的 `_finish()` 也是不管哪个模块都 `save_pending()` 并回传 `options`。
所以只要工具真被调用、提案真进了 `options`，学生停在哪一屏都能看到那条确认条——
**要修的是"有没有提案生成"，不是"确认条怎么画"**。

## 顺手：给 e2e 环境加"播种会话"

`_shot_gym.py` 要复现的那一幕**只发生在历史里**（管家那句话是上一轮说的，
页面从 `/api/conversation/<sid>` 捞回来渲染），所以 `e2e_server` 补了
`seed_conversation(sid, msgs)`。踩到的两个坑记在这儿：

- 会话文件在**学生库** `student/sessions.json`，不是 `data/sessions.json`。
  第一次写错地方，页面历史一片空白，接口那边 `is_confirmation` 也就找不到上下文，
  整句话掉给了 faq 兜底——症状看着像"兜底没生效"，其实是种错了文件。
- 前端 session id 存在 localStorage 里且随机生成，脚本得先用
  `page.add_init_script("localStorage.setItem('campustime_session', '<sid>')")` 定死，
  不然种的那段历史跟页面用的不是同一个会话。
