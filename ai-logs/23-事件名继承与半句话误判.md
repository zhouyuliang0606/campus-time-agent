# 23. 刚说过的事名没继承 / 半句话被当成一件事

> 报障：两张截图 + 一份「规则总览」。
> 图 2 那一幕：学生说「我想去游泳，帮我安排时间」，管家客气一句
> 「你想安排在哪天？还是我直接帮你按本周的空闲时间找找？」，学生回
> 「这周安排一个时间」——**系统只看这一句**就反问「要安排的是什么事」，
> 刚刚才说过的"游泳"没被继承下来。
>
> 规则总览（学生原话摘录）：
> ① 自主日程场景默认，**禁止反复追问、不要多余客套啰嗦**，直接给推荐方案；
> ② 只生成提案，**禁止直接操作数据库**、不能谎称修改完成；
> ③ 优先唤起前端弹窗，含【确认】【取消】；④ 备选：聊天框打字确认同样执行；
> ⑤ 写入成功后自动刷新；⑥ **不需上报管理端、不要提示权限不足**，
>    工单上报仅学生主动提出时才触发；
> 通用约束：AI 永不直接调数据库、只操作当前用户数据、不改工单/通知系统、语言简洁。

这一轮一共动了四处：**两处是真断点**（继承、半句话），
**两处是规格**（提示词写进"直接敲定 + 场景边界"）。

---

## 一、断点一：事名只抠当前这一句（`app/main.py` 3c）

### 现象

| 轮次 | 谁说的 | 内容 |
|---|---|---|
| 1 | 学生 | 我想去游泳，帮我安排时间 |
| 2 | 管家 | 你想安排在哪天？还是我直接帮你按本周的空闲时间找找？ |
| 3 | 学生 | 这周安排一个时间 |
| 4 | 系统 | 要安排的是什么事？❌ |

第 3 句里没有一个字是"游泳"，`todo_title_of` 只能给出"待办"，
于是掉进最保守的那一档——问学生要安排什么事。**他上一句刚说过。**

### 为什么之前没暴露

上一轮（ai-logs/22）把第一站改成了"直接敲定"，少了一轮追问，
于是"学生只回答时间"这种句型第一次大量出现在这条分支上。

### 修法：判不出事名时，从上下文继承

```python
if todo_title_of(blob) == "待办":
    inherited = _recent_add_request(session_id)
    if inherited:
        inh_title = todo_title_of(inherited)
        if inh_title != "待办":
            merged = f"{inherited}，{message}"
            # ⚠️ 合并完还得核对一次：抠出来的必须**还是这一个事名**。
            if todo_title_of(merged) == inh_title:
                blob = merged
```

继承源用 `_recent_add_request`（不是"最近一句用户话"），因为它要求：

* 那句原话**本身带着"安排/加"的意图**（不会把闲聊里的随便一个词抓来当事名）；
* 那句话**不是确认词**；
* **最近没真的写过库**（写过就说明那件事已经办完了，不该再拿来凑）。

⚠️ **最后那句核对是补出来的**，第一版没有，立刻被自己的测试抓包：

```
「帮我安排一下健身」+「再安排一个」  ->  merged title = "健身再"  ❌
```

两句话被揉成一个谁也没说过的怪名字，还照样挂出去了。
加了"合并完必须还是同一个事名"这条核对之后，对不上就**不合并**，
照旧问清楚——宁可多问一句，也不许糊一个怪名字出来。

## 二、断点二：离线 Mock 把半句话当代办名（`app/modules/planner.py`）

### 现象

没配密钥时，`main.py` 会在**模型之前**直接走 `mock_planner`。
它对任何一句话都照单全收：

```
「你帮我找一个合适的时间」  ->  卡上印着「找合适」
```

学生投诉"要识别啥才是真的事情"，说的就是这个。

### 修法：两道闸

1. **擦掉形容词**：`_strip_title_noise` 里加一步 `t.replace("合适", " ")`。
   「你帮我找一个合适的时间」擦完剩「找」，`_TITLE_NOISE` 里的动词把它否掉 → 判"待办"。
   ⚠️ 只擦"合适"这两个字，「找工作」这类真名不受影响。
2. **摊候选之前加一道门**（`mock_planner` 第 4 步，在"查空档"之前）：

```python
if is_confirmation(msg) or todo_title_of(msg) == "待办":
    return {"answer": mock_phrase(persona_key, "ask_thing"),
            "options": [], "awaiting_choice": False}
```

纯应答（「好的」「嗯」）或者判不出事名 → **只问"要安排什么事"，一张卡都不出**。

配套：`student_persona.py` 三份性格各加一句 `ask_thing` 措辞
（"好——要安排的是什么事？说个名字就行，比如「游泳」「健身」「交电费」…"）。

## 三、规格：两份提示词写进"直接敲定 + 场景边界"

`planner.build_system_prompt()` 与 `schedule.SYSTEM_PROMPT` 两处同步改：

* 删掉"先问他'你自己定还是我帮你挑'"那一整段，改成**直接调用
  `propose_todo_tool` 出一张单条确认条**，卡片上写清为什么排在这儿；
  他想自己挑时再说一句"我自己挑"，系统才换 `propose_todo_slots_tool`。
* 新增【场景边界 —— 学生自主 vs 工单上报】整段：
  学生的日程操作**全部默认学生自主**，不需要上报管理端、
  **绝不说"权限不足"**；只有学生**主动**说要找管理员（快递丢失、
  外卖遗失并要求上报）才走工单。

`main.py` 里新增 3c-pre4 承接这个口子：**单条确认条（带 `auto` 标记）
已经挂在那儿时，学生说"我自己挑" → 换出候选卡**（否则第六轮改版
把聊天里的二选一卡砍掉之后，"我自己挑"就没有入口了）。

## 四、回归护栏（第十五批，17 项）

写在 `tests/test_06_add_things.py::test_context_inherit_and_half_sentence`：

* 半句话一律判"待办"：「你帮我找一个合适的时间」「这周安排一个时间」；
  回归：「帮我安排出去吃饭的时间」→「出去吃饭」照旧认得出。
* 离线 Mock 四种半句话（好的 / 嗯 / 你帮我安排 / 你帮我找一个合适的时间）
  → **0 张卡**，且回答里有"要安排的是什么事"。
* 走接口复现图 2 那一幕 → 出 `todo_add / 游泳 / auto=True`，**模型 0 次**，
  且没写库。
* 反向：干净会话说同样的话 → 不许凭空造一条 `todo_add`。
* 反向：写过库之后的旧事名不许再被继承；卡还挂着时说「再安排一个」
  → 不许出现「健身再」。

## 五、本轮踩的坑（值得记住）

### 坑 1：探针脚本的环境变量名写错 → 污染真实演示数据

`sandbox()` 用的是 **`CAMPUSTIME_DATA_DIR`**，我在临时探针里写成了
`CT_DATA_DIR`。结果 `app/store.py` 认不出来，全部写进了真实的
`app/data/student/`——平白多出两条「健身」待办和两个假会话，
**会直接影响后面所有截图**。

* 判据：探针里打印出来的待办列表出现了上一次探针写的东西（时间戳早两分钟）。
* 处置：手工删掉那两条（按 `created_at` 前缀筛）+ pop 掉 `p1`/`p9` 两个会话，
  再跑一次 `tests/_restore_demo.py` 把周表还原。
* 以后：**临时探针一律照抄 `tests/_harness.py` 的 `sandbox()`**，别自己拼环境变量。

### 坑 2：测试自己的"前情"要真的走接口

第 ④ 段第一版我图省事，用 `append_conversation()` 直接把学生的第一句话
写进历史，然后发「确认」——卡从来没挂出来过（`_pending_todo` 是空的），
于是"确认写库"必然失败。看起来像产品 bug，其实是**测试构造错了**。
前情必须真的 `client.post()` 一遍。

### 坑 3：放松"防重复"闸门前，先想清它问的是哪个问题

（延续 22 号的教训）继承这条新路也是同一个陷阱：
"该不该继承"和"该不该把两句糊在一起"是两个问题，
只做前一半就会产出「健身再」这种东西。
