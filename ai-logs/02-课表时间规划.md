# ai-log 02 · 旗舰模块：课表时间规划

> 开发日记第 2 篇：项目的"门面"功能。它最直观地展示 Agent 是怎么一步步推理的，所以放在第一个做。

## 一、它能干嘛
学生问时间安排类问题，Agent 自己决定调哪个工具、看结果、再组织成建议：
- 「周三都有什么课？」→ 调 `get_day_courses`
- 「我这周哪天有空复习高数？」→ 调 `find_free_slots`（可能逐天查）
- 「帮我排 3 小时复习线代，优先周二」→ 调 `plan_task`

## 二、四个工具（都在 `app/modules/schedule.py`）
| 工具 | 入参 | 作用 |
| --- | --- | --- |
| `get_day_courses` | day（如 "周一"） | 查某天全部课程（时间/老师/地点） |
| `find_free_slots` | day | 算某天 08:00–22:00 的空闲时间段 |
| `plan_task` | task_name, need_hours, prefer_day? | 按课表空闲自动排出学习计划 |
| `propose_todo_tool` | title, when / date+start+end | **只读**：把建议变成一张能点的确认条（见 `ai-logs/14`）。<br>**只给 date、不给 start 也行**——时间由系统从那天的空档里挑好（见 `ai-logs/16`）；⚠️ 这一版最终又被学生驳回一次：改成**摊开几段候选让他自己打勾**（`todo_slots` + `POST /api/todos/batch`），见 `ai-logs/16` 的「后记」 |

> 后记（2026-09-25）：`propose_todo_tool` 的工具名和说明书现在收在 `planner.propose_todo_tool_tool()` 里，
> 由 schedule 和"给所有模块兜底"共用一份；`find_free_slots` / `list_day_todos` / `propose_slots` /
> `propose_todo_tool` 这四件**只读**工具会发给每个模块（`planner.build_scheduling_tools()`），
> 这样路由把话分给哪个模块，管家都出得了确认条。

## 三、示例数据
`app/data/courses.json` 放了一份周一~周五的演示课表（高数/英语/程序设计/线代/体育/毛概/数据结构/心理选修）。后面可换成真实课表或接学校教务接口。

## 四、Agent 推理示例（演示用）
用户：「帮我排 3 小时复习线代，优先周二」
1. 🤔 思考：要先看周二有没有空 → 调 `find_free_slots("周二")`
2. 📦 工具结果：周二 空闲 12:00~14:00(2h)、18:00~22:00(4h)
3. 🤔 思考：够排 3 小时，放周二晚上 → 调 `plan_task("复习线代", 3, "周二")`
4. 💡 最终回答：给出具体时段安排（如 周二 18:00~21:00 复习线代 3 小时）

前端会把 1~4 的 `trace` 展示成"思考轨迹"，评委一眼看到 Agent 在干活。

## 五、文件职责（人话）
- `schedule.py`：模块本体，含三个工具函数 + `build_tools()`（把函数包装成 Agent 能用的 Tool）+ `SYSTEM_PROMPT`（告诉模型"你是课表助手"）
- `courses.json`：工具读取的真实数据，和代码分离，方便改

## 六、接入方式
在 `app/main.py` 的 `REGISTRY` 里加了一行 `"schedule": (SYSTEM_PROMPT, schedule_tools)`。以后每个新模块都照这个格式加一行即可，路由命中后自动启用。
