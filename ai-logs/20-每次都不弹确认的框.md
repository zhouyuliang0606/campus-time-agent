# 20 · 每次都不弹确认的框：又两种写法没被认出来

> 报障原话：「**改完自动刷新日程，和删除课表一个逻辑，都是在日程做改变，每次都不弹确认的框**」
> 附一张截图。这是同一件事的**第三次**报障（前两次见 `ai-logs/18`、`ai-logs/19`），
> 前两次修的都是"兜底挂在哪、认不认散文"，这一次卡在**认不认这两句话**。

## 一、那一幕

```
我：   周四早上吧
管家： 提案好了，就一条：

       **周四 08:00~09:00　健身（1 小时）**

       确认的话，回我一句「确认添加」就行，系统会帮你入库。想换时间也随时说。
我：   确认
管家： 收到，你回「确认」后由系统执行入库，我这边不直接改数据。
       稍等确认条生效就好。周四 08:00~09:00 健身，练完记得吃口早饭再上课。
```

界面上：**一个按钮都没有**。库里：**一条都没有**。

对照前两次报障，症状一模一样，但这次的原因完全不同——所以"上次修过了"不能当作不用查的理由。
每次都得从**它这句原话**重新开始。

## 二、两个断点

### 断点 ①：`claims_proposal_sent` 不认这三种说法

兜底的第一道门是"**它自称发过提案了吗**"。不认，后面全部不启动。

截图里它说的是：

| 原话 | 之前认不认 |
| --- | --- |
| 「**提案好了**，就一条：」 | ❌ 不认（只认"提案已发出/我这就发"） |
| 「系统会**帮你入库**」 | ❌ 不认 |
| 「回我一句「**确认添加**」就行」 | ❌ 不认（只认"回个「确认」"） |
| 「你回「确认」后由**系统执行入库**」 | ✅ 认（第二轮补的"入库"） |

修法是给那份正则补三档：`提案(?:已经|已)?好` / `入库`（单独成词就够）/ `确认添加`。
**"入库"要单独列成一项**——它到处出现，宽松一点没关系：这句话本身就是在讲"要写库了"，
这正是我们想抓的语境；真正的闸门在后面（补不出卡时还有 `has_concrete_span` 兜着）。

### 断点 ②：`_pick_title_from_prose` 抠不出跟在时段后面的任务名

前两路抠法（`ai-logs/19` 补的）是：

1. **引号里的词** —— 「游泳」、《复习线代》
2. **「把 X 加到/排到…」里的 X** —— "把健身加到周四"

截图里这句**两路都落空**：没有引号（只有「确认添加」，是动作不是事名），也没有"把 X 加到"。
任务名「健身」是**跟在时段后面**的：

```
**周四 08:00~09:00 健身（1 小时）**
                 ^^^^ 就是它
```

补第三路：

```python
_TITLE_AFTER_SPAN_RE = re.compile(
    r"\d{1,2}:\d{2}\s*(?:到|至|-|~|～)\s*\d{1,2}:\d{2}\s*"
    r"([^（）()「」『』《》“”\"'，,。；;：:｜|、\s\n]{2,12})")
```

## 三、补第三路时踩的两个坑（都是自己踩出来的）

### 坑 1：右引号被当成标题的一部分

原话是「…就会多出**「游泳 16:00~17:30」**这一条。」——时段后面紧跟的是**右引号**。
排除字符里漏了它，抠出来的标题就是 **`」这一条`**（长度 4、不含噪声词，一路过了 `looks_like_thing`）。
全量测试当场挂了 4 条，报错里写着 `标题没被抠残（是「游泳」，不是那半句话）` —— 13 → 5。

### 坑 2：把"在讲提案本身"的话当成事名

把坑 1 堵上之后，第三路仍然会抠出这种：

| 原话 | 第三路抠出来 | 卡片上会写 |
| --- | --- | --- |
| 已提交，周四 08:00~09:00 **那条稍等生效就好** | `那条稍等生效就好` | 「要不要把 **那条稍等生效就好** 排进日程？」 |
| 提案已经挂出来了：**周四 08:00~09:00**。 | `**` | 「要不要把 **\*\*** 排进日程？」 |

两句都在**讲这次操作**，不是讲要做什么事。两道新闸门：

* `_SPAN_TITLE_NOISE`（**只给第三路用**）——`提案/确认条/确认/提交/入库/挂出/这条/那条/稍等/生效/收到/已经/以上`
  命中就跳过这一段，继续按分隔符找下一段；
  引号里和"把 X 加到"后面那两段更可信，**不该被这份表误伤**，所以它不并进 `_TITLE_NOISE`。
  ⚠️ 这份表**故意收得窄**：本来还想收"写好/写完/排好"，可它们能当动词用——
  「写好论文」「排好队形」都是正经待办名，收了就等于这两个名字**永远排不进日程**。
  宁可漏掉几个噪声，也不误伤真名字（测试里专门钉了这条边界，两边各一条断言）。
* `looks_like_thing` 加一条：**一个名字里总得有个正经字符**（汉字/字母/数字）。
  `**` 长度够、也不含噪声词，可惜全是排版标记。

> 第三条路是这三路里**最松**的一路（前面等于没有任何锚点，只靠"位置"），
> 所以它需要**最严**的判真。这个不对称是有意的：松的那一路必须有闸门，
> 不然助手随口一句「周四 08:00~09:00 有条课」都会被当成提案。

## 四、`_no_card_answer` 的两道闸门

"假话纠正"（认错 + 告诉他下一步怎么说）是有代价的——它会把一段**本来没问题**的回答换掉。
实测误伤过一次：

```
它说：收到，你点确认后由系统执行入库，我这边不直接改数据。
```

这句在**解释流程**，不是在说"我已经提交了"，可 `claims_proposal_sent` 认"入库"、认"回个确认"，
于是被当成假话纠正了。所以加两道闸门，**满足其一**才纠正：

1. 它这段话里**带具体时段**（`08:00~09:00`）——在讲一件已经排好的事；
2. 或者学生最近确实说过要加什么（`_recent_add_request` 非空）——那句"提交了"多半是在说他那件事。

配套在第十二批留了一条专门的回归：`纯解释流程（没有时段、也没说要加什么）→ 不许把它纠正当假话`。

## 五、顺手变好的一件事

`ai-logs/19` 里那句假话已经能捞出方案了：

```
已提交，等系统入库后周一待办里就会多出「游泳 16:00~17:30」这一条。
```

第二轮只能**认出**它是假话然后纠正；这一轮补了第三路之后，它变成**能补出卡**——
学生不用把那件事重说一遍。修正、比纠正更进一步。测试里也把这条从"期望纠正"改成"期望捞出来"。

⚠️ 但"纠正"这条路**不能删**：模型完全可能说「已提交，周四 08:00~09:00 那条稍等生效就好」
——自称提交了、话里也有时段，可**没有能当任务名用的东西**。这时候补不出卡，
那句"已提交"就是在骗人，必须如实纠正。第十二批 ⑤ 段换成这句话来钉它。
