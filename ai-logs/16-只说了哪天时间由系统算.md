# 16 · 只说了「哪天」：时间由系统算，确认条由系统挂

> ⚠️ **这篇的形态后来改过一次，看之前先读文末的「后记」**：
> 本文写的是"系统替他**挑一段**、出一张单条确认条"；
> 学生随后驳回（「我定的太严了……由 ai 帮我去挑选合适时间，**进行列举**……由我打勾」），
> 现在改成 **摊开几段候选让他自己打勾**（`todo_slots` 卡 + `POST /api/todos/batch`）。
> **本文没改**——它是那一轮的真实记录（含两条投诉、两个断点的复现），
> 后记里写清了哪条结论被推翻、哪条仍然成立。

> 学生截屏报障原话：
> 「**没有确认，没有帮我想时间是我问了才说的**」
>
> 截图里那一幕（逐条抄）：
> 1. 学生：周四有课吗 → 管家：周四有两门课：线性代数（08:00–09:40）、体育（10:00–11:40）。
> 2. 学生：周四下午还有什么活动没 → 管家：周四下午确实还空着 **15:40–17:10**……
>    如果你考虑把**健身**放到这个时间段，我可以顺手帮你安排。
> 3. 学生：没有活动吗 → 管家：有的，就是线性代数……在上午。
> 4. 学生：那你帮我加一个健身在周四
>    → 管家（faq）：`好，周四这档提案这就发给你：- 任务：健身 - 时间：周四 15:40~17:10
>      - 范围：本周 点【确认】就入库了。`
> 5. 学生：确认 → **界面上一个按钮都没有，日程里也什么都没写。**

## 先复现，再动手

写了一个只回固定台词的假引擎（一个工具都不调），把上面那几轮原样喂进 `/api/chat`。
复现结果一目了然：

```
[那你帮我加一个健身在周四] -> module=planner options=[]
 助手记进历史的那句是：加待办缺细节
--- 学生回「确认」 ---
暂存（问之前）: None        ← 压根没有提案
options: []                ← 所以界面上没有确认条
日程里有没有健身：没有
```

两个断点，正好对上学生那两句话：

| 学生的原话 | 根因 | 断在哪 |
| --- | --- | --- |
| 「没有帮我想时间，是我问了才说的」 | 学生只说了"哪天"（周四），没说"几点"。旧链路解析不出时间段 → 出的是**追问**「把想安排的时间说一下，比如『下午两点到三点』」——**把活儿原封不动退回去了** | `app/main.py` 3c 分支的"加待办缺细节"那一支 |
| 「没有确认」 | 那条 faq 回复只在**文字里**写方案，没调工具 → 暂存是空的；学生回「确认」时，兜底里"从管家文字捞方案"又要求固定格式（`任务：` + `时间：`），而那句挤成一行、捞不干净 → 什么都不挂 | `app/main.py` 3a-c 兜底 + `app/modules/planner.py` 的 `_REPLY_TASK_RE` |

## 一、核心：缺时间不等于追问，缺时间＝自己算

新增 `planner.pick_free_slot(date, prefer)` + `planner.auto_todo_proposal(text)`：

- `pick_free_slot` 从那天的**真实空档**（已避开课程和已排待办）里挑一段：
  1. 学生说了「上午/下午/晚上」就只在那一段里找；没说就按白天 `08:00~22:00` 找
     （不直接用 `DAY_START=07:00`：学生只说"周六加个健身"时，最长那段从 07:00 起手，
     排出来就是"周六早上七点健身"——帮他排了，但帮得挺糟）；
  2. 优先**最长的那一段**（最经得起塞一件新事），同样长时挑靠后的；
  3. 从那段的起手点取 90 分钟（`AUTO_SLOT_LENGTH`），不把整段空档都占掉。
- `auto_todo_proposal` 拿「标题 + 日期」→ 查空档 → 拼成提案，并标 `auto: True`
  （话术要能说清"这个点是我挑的，不合适你改"）。任何一块凑不出来都返回 `None`，
  交给追问如实说缺什么。

`app/main.py` 的 3c 分支：`parse_add_todo` 失败后**先试** `auto_todo_proposal`，成了就出条：

```
📝 我看了一下，2026-10-01（周四）**15:40-17:10 是空着的**，就先把 **健身** 排在这儿了（共 90 分钟）。
下面点一下【确认加入】我就写进日程，回一句「确认」也一样。
这个点不合适的话，直接说「改成晚上七点到八点」就行。
```

**实测挑出来的正是 15:40-17:10**——和截图里管家自己给的那段一模一样，
但这次它是一张**能点的确认条**，不是一个说法。

## 二、把"算时间 + 出条"做成工具自带的本事

两个改动，让**任何模块**都出得了条：

1. **`propose_todo_tool` 只给日期也能出条。** 原来只给 `date='周四'` 会返回
   `error: 日期或开始时间没解析出来`；模型收到这个错，转头就去问学生「你想几点？」
   ——又是把活儿退回去。现在这一档直接 `pick_free_slot` 挑一段，
   真挑不出来（那天满课）才返回 `hint`，而且 hint 里明写**不要反问他想几点**。
2. **把这组只读工具发给所有模块**（`planner.build_scheduling_tools()`：
   `get_weekly_timetable / find_free_slots / list_day_todos / propose_slots / propose_todo_tool`）。
   原因就是截图这一幕：路由把「那你帮我加一个健身在周四」分给了 faq，
   而 faq 原本文具盒里只有一个 `search_kb`——它**没有出条的手脚**，
   只能在文字里写方案。这一组工具**一个字节都不写库**（真写入永远是后端确认条），
   所以发给谁都安全；`add_todo_tool` 这类真写库的**没有**混进去。

顺带把 `propose_todo_tool` 的工具说明书收成一份（`propose_todo_tool_tool()`），
schedule 和 planner 共用——抄两份迟早走样。

## 三、他真报了个点，就得接住

既然话里说了"不合适你说个点"，学生说了就必须接：新增 3c-pre 分支
（`is_add_todo_followup` 纯时间短句 / `wants_retime_todo` 带"改成/换到"）

| 学生说 | 系统做 |
| --- | --- |
| 「下午两点到三点」 | `retime_todo_proposal` 沿用原卡的标题和日期，换成 14:00-15:00，重出确认条 |
| 「改成周六」 | 换到周六，并**在那天重新挑一段空档**（不是把周四的时段硬搬过去） |

守着一个边界：只认"纯时间短句"或带换时间词的话——
「周四加个复习」这种**新的下单**不能被当成"改时间"吃掉（测试里专门钉了这一条）。

## 四、确认落空的兜底再兜一层

3a-c 兜底里，前面两路（学生原话 `parse_add_todo`、管家文字 `parse_todo_from_reply`）
都解析不出时，**第三路**：`auto_todo_proposal(学生原话)` ——
只说了哪天就去挑空档，把条挂出来。这正是截图那一幕。

同时修了 `_REPLY_TASK_RE` / `_REPLY_TIME_RE` 的**单行捞取**问题：
原来的排除集是 `[^\n，,。；;｜|]`，模型把列表压成一行时
（`…- 任务：健身 - 时间：周四 15:40~17:10 - 范围：本周…`）标题会被捞成
「健身 - 时间：周四 15:40~17:10 - 范围：本周」。现在把 `-—：:` 也当分隔符排掉。
**注意"时间"那条不能排掉 `~`**：`15:40~17:10` 里的波浪号是时段本身的一部分。

## 五、几处顺手补的坑

- **`_pick_title` 的口语前缀**：`t.replace(…)` 会在开头留下空格，
  原来那句 `^(帮我|我要…)` 就匹配不上（"周日帮我安排游泳" → " 帮我 游泳" → 首字符是空格）。
  现在**去空格之后再削一遍**语气词，并且补上「加个/添条」这类"动词+量词连写"的写法，
  还有 `_EMPTY_TITLES` 兜底（"周四加一个" → 当作没标题，去问"要加什么事"，
  不拿"加个"本身当待办名字）。
- **`wants_add_todo` 认口语写法**：「周三加个健身」原来一个意图词都不沾
  （`_ADD_INTENT` 里只有"加一个"，没有"加个"），整句掉给模型。补 `_ADD_TALK_RE`
  正则兜住"动词+量词"，并把"加个课"这类归课表的说法加进让路表。
- **追问话术分得清两种"缺"**（`todo_missing_advice`）：
  ① 根本没说是哪天 → 正常反问日期；② 说了哪天但**那天真排不进** → 如实说
  "这天排不下了，换个日子"，别让他一遍遍补"几点几点"。已经说过的事情名
  也不会再被问一遍（"游泳记下了，就差哪一天"）。
- **判定窗口**：`asking_add` 的回答判定从 `is_add_todo_followup` 放宽成
  `is_add_todo_answer`（也认"只补了日期"的回答，因为追问可能问的就是日期）。

# 后记：这一版被学生驳回了，改成了「列几段让他自己打勾」

## 学生原话（截图 + 一段话）

> 「**我定的太严了，你改一下，由 ai 帮我去挑选合适时间，进行列举，
> 采用和删除课表时同样的弹框，内容变成那几个时间的选择或者其他
> （这个选项可以由我来自行补充—），由我打勾，进行增加，增加确认完立刻刷新日程**」

配的截图还是那一幕：学生问周四有课吗 → 问下午活动 → 说「那你帮我加一个健身在周四」→
管家只在文字里写方案 → 学生回「确认」→ **没有确认条、没有入库**。

## 哪条结论被推翻、哪条仍然成立

| 上一版的结论 | 现在 |
| --- | --- |
| 学生只说了"哪天" → **不许反问"几点到几点"** | ✅ **仍然成立**。学生正是因为不知道哪会儿空才来问，把问题退回去等于没帮上忙 |
| 学生只说了"哪天" → **替他挑一段、出一张"就排这儿了"的确认条** | ❌ **被推翻**。只给一个点等于替他做了主：他要么全盘接受、要么再让你换一次，**来回两轮** |
| 学生自己报了准点 → 就着他给的点出单条确认条 | ✅ 仍然成立（这种情形摊候选反而多此一举） |
| 「哪天都没说」→ 追问日期 | ❌ **被推翻**。改成**跨天各列一段**（今天往后逐天一段）让他挑——比再来一轮"哪天？"快 |

新做法一句话：**AI 列举，学生打勾，系统落库，落完即刷新。**

## 改了什么

### 后端（`app/modules/planner.py`）

- **`candidate_slots(text, max_slots=3, days_ahead=5)`**：列出候选。
  说了哪天 → **只列那天**（那天排不下就如实返回空列表，**绝不偷偷换天**）；
  没说 → 从今天起逐天一段（今天只看"此刻+30 分"之后）；
  学生提了「第 N 节课的位置」→ 按节次表换算那一段并**排第一**（占着就往后找空的那天）。
- **`DAY_PARTS`（上午 9-12 / 下午 14-18 / 晚上 19-22）+ `_day_slots(rotate=)`**：
  一天按三档各给一段。为什么要分档而不是"把最长空档切一半"：学生嘴里的备选就是
  "上午/下午/晚上"这几档；给 15:40-17:10 和 17:40-19:10 两段他反而看不懂差别。
  `rotate` 只管"没说哪天、跨天列"的情形——不然连列三天，三条都是"下午 14:00-15:30"，
  看着像同一个选项复制了三遍。
- **`build_todo_slots(title, slots, hint)`** → `kind="todo_slots"`：
  **一个提案里装着好几个时段**，`label` 形如「周四（10/1）15:40-17:10」（弹框里那行字）。
- **`todo_slots_proposal(text)`**：把上面两步拼成一张卡；凑不出来（没说要加什么事、
  或那几天真排满）返回 `None`，交给调用方如实说缺什么。
- **`parse_slot_text(text, title, fallback_date)`**：认「其他时间」那行自填。
  三种都认——说全了的（"周六 19:00-20:00"）、只说了哪天的（"周六"）、
  **只报了钟点没报哪天的**（"晚上七点到八点" → 用 `fallback_date` 补上；那天这一节已过就顺延到明天）。
  认不出返回 `None`，**绝不瞎猜一个时间**。
- **`slot_is_free(date, start, end)`**：落库前再核一次空档（复用 `_span_free`，
  同时避开课程**和**已排待办）。为什么不能只信学生勾的那一下：候选是上一轮算的，
  中间他可能自己又加了一条。
- **`is_slot_answer(text)`**：区分"在挑时间"和"在开新单"。
  「改成晚上七点到八点」「周六下午三点到四点」→ 挑时间（事情沿用卡上那个）；
  「周六加个游泳」→ 开新单，走正常的加待办链路重新解析标题。
- **`propose_todo_slots_tool`**（只读）：让**真模型**那条路也列得出候选，
  不然路由分给别的模块时，模型还是只会给一个点。
- **节次表 + `period_span()` 搬到文件开头**（`DAY_NAMES` 之后）：原先定义在删课那一节，
  新函数在 250 行就要用，Python 定义顺序会直接 `NameError`。删课处只留一句注释。
- **`_pick_title` 补清洗**：`改成/换到/挪到…`（"改成周六"的标题原来会变成「改成健身」）、
  「第N节课的位置」「在…的位置」、「原本/把」前缀、「待办/代办/事项/日程」后缀。

### 后端（`app/main.py`）

- **3c 分支**：学生报了准点 → 单条 `todo_add`（照旧）；只说了哪天 / 压根没说时间 →
  `todo_slots_proposal` 出**候选卡**；候选也列不出来 → 如实追问（`todo_missing_advice`）。
- **3c-pre2（新）**：学生刚看到一串候选、在聊天里自己报了个点（"改成晚上七点到八点"、
  只说"周六"）→ 就着他给的点出**单条**确认条。这是接住"学生不是在弹框里勾、而是直接说话"的那条路。
- **确认分支多一支**：学生只回「确认」而暂存里是**候选卡**（他还没勾）→
  **一条都不写**，把候选条再挂一遍并说清"得你自己挑一个"。
  他根本不知道你会写哪一个，随便挑一条写进去，写错了还得再来一轮删。
- **`POST /api/todos/batch`（新）**：接收勾中的时段 + 「其他」自填文本，**逐条**写。
  为什么不是前端循环调 `/api/todos`：① 空档复核要在**同一批里逐条**做——
  循环调用时每条各自判断，看不见"同一批里刚写进去的那条"，两条就压在同一个点上了；
  ② 回执合成一句（"已加入日程：健身｜…、…"），也让"确认落空"兜底能靠它判断"最近真的写过"；
  ③ 前端只发一次请求，不会出现"勾了三个、写进去一个半"。
- **`_offer_response()`**：出条这件事现在只写一遍（3c / 3c-pre / 3c-pre2 / 3a-c 兜底四个出口共用）。
  抄四份迟早走样——比如有一处忘了 `save_pending`，学生点按钮时后端找不到提案。
- **3a-c 兜底**：先试"摊候选"，再退回旧的"替他挑一个"（只在候选彻底列不出来时才用）。
- **提示层三处同步改**（`ASSISTANT_RULES` / `planner.build_system_prompt()` / `schedule.SYSTEM_PROMPT`）：
  从"挑一段"改成"**列 2~4 段让学生打勾**"，并写明例外——学生自己报了准点就用单条。

### 前端

- **`app/static/confirm.html`**：新增 `KIND.todo_slots`——候选**可打勾多选** + **「其他时间」输入框**，
  按钮上的字跟着勾选变（"加入日程（2 项）"），一段没勾也没自填就置灰。
  顺带把 `render(p)` 那段错缩进（`return` 之后本该留在函数里的代码看着像落在外面）理顺，
  加了可选钩子 `after(p)`（渲染完挂事件），并让 `showError` 把按钮文字还原
  （原来失败后按钮永远停在"⏳ 执行中…"，学生不知道该不该再点）。
- **`app/static/student.html`**：`todo_slots` 走**跟清空课表/删待办同一套**内嵌确认条
  （`openConfirm` → iframe 载 `/confirm`），落库后 `loadScheduleView()` **当场刷新日程面板**；
  另留一份"确认页载不进来时"的内嵌兜底（勾选框 + 其他时间 + 直接打 `/api/todos/batch`），
  学生不会因为一个 iframe 挂了就加不进日程。iframe 高度上限 430 → **560**

## 一句话记住

学生说的"帮我挑个时间"，要的是**几个可以挑的时间**，不是一个已经被定好的时间。
给他一段，他只能点头或让你重来；给他三段让他勾，一轮就定下来了。
**列举 = 把选择权还给他**，而"打勾 + 其他自填"就是这份选择权的两个出口。

## 又改了一版：这一版也被驳回了

上面这条结论（"一律先摊候选让他勾"）**同样只对了一半**。
学生第三次开口，要的是**先分清两种人**：

> 「要区分两种，一种是我有时间规划了，一种是我没有时间规划让他帮我安排，
> **不要一上来就询问详细时间，先给弹窗，（有时间规划）（还没有，你帮我定）**……
> **核心是 ai 帮我安排时间，ai 去规划时间**，然后这个加入代办，
> **要识别啥才是真的事情**」

于是流程又往前挪了一站：**第一站不再列时间，而是一张只有问题的二选一卡**；
选了"你帮我挑"由系统真去规划并说清理由，选了"我自己定"才摊候选。
另外补上了这一版真正最要命的一关——**认出"这件事到底是什么"**。
