# ai-log 08 · 学生个人库：周表 + 月表 + 待办商量着排

> 开发日记第 8 篇：把"学生脑子里那张课表和一堆待办"变成系统里真正的数据，
> 并且让 AI **排完时间先问一句**，学生点头了才写进去。

## 一、需求还原

| 你的话 | 落到代码上 |
| --- | --- |
| 建立一个学生个人库 | `app/data/student/` 三张表：周表课程、待办、会话历史 |
| 周表由学生上传课表 | 上传文件 → AI 读 → `import_timetable` 写入周表 |
| 学生发待办，AI 根据课表安排时间 | `find_free_slots` 查空档（避开课程和已排待办） |
| **并询问学生** | 系统提示里写死：给 2-3 个候选后**必须停下来问** |
| 学生认为妥当后放进周表时间段 | 确认后才调 `add_todo` 写入 |
| 待办可以插在课程之间 | 用**真实起止时间**而非"第几节"，周表按分钟定位 |
| 月表当天显示待办，非当天显示几项、点开可见 | 月表 = 待办按日期的另一种视图 |

## 二、先解决一个前提：AI 必须记得住上一轮

这条链路最关键的不是排期算法，而是**多轮上下文**。

原来的 `/api/chat` 每轮都是独立对话，后端完全不保存历史。那就会出现：

```
AI：  建议今晚 19:00-20:30，可以吗？
学生：可以
AI：  ??? （它根本不知道"可以"指的是什么）
```

所以先做了会话历史：
- `/api/chat` 新增 `session_id`，没带就服务端生成并在响应里回传
- 前端存进 localStorage，**对话页和日程页共用同一个 id**
- `engine.run()` 新增 `history` 参数，把过往对话接在 system 提示之后

一个取舍：**只回放 user/assistant 的纯文字，不回溯工具调用过程**。
少了些细节，但换来稳定——不会出现 `tool_call_id` 对不上的报错，
而且最终答案里本来就包含商量好的结论。

## 三、周表与待办的数据模型

```
timetable.json  {day:1-7, start:"08:00", end:"09:40", course, location}
todos.json      {title, date:"2026-09-25", start:"14:00", end:"15:30", status}
sessions.json   {sid: [{role, content}, ...]}
```

**为什么用真实起止时间而不是"第几节"？** 这是为了满足"待办插在课程之间"。
按第几节建模的话，待办只能塞进固定格子；用起止时间，19:00-20:30
这种零碎安排能在时间轴上精准落位，自然落在两节课之间。

对应到前端：周表用「**1 分钟 = 1 像素**」定位，所以 11:40 下课这种
非整点也能画准，不会被硬套成整节课。

## 四、planner 模块：把"先问再写"写进规矩里

系统提示里明确写了流程和铁律：

```
1. 收到待办 → find_free_slots 查空档
2. 给 2-3 个候选（说清日期、星期、起止、时长）
3. **停下来问学生** —— 这步绝不能省
4. 学生明确同意后才 add_todo
5. 学生要调就重查再提议
```

为什么非要多问这一句？**时间安排是要学生去执行的事**，
AI 自作主张塞进去、学生不认可，就等于白排。

另外提示里**动态注入今天日期**（做成可调用提示）。
学生说的是"明天""后天"，AI 不知道今天几号根本算不出来。

## 五、几个防呆

| 防呆 | 作用 |
| --- | --- |
| `add_todo` 拦撞课 | 跟课程时间重叠直接拒绝并说明原因，逼 AI 换时间，而不是默默排进学生去不了的时段 |
| `import_timetable` 逐条校验 | day 越界、时间倒挂会说清"第几条有问题"，让 Agent 能自我修正重来 |
| `find_free_slots` 同时避开课程和已排待办 | 返回的必定是真空档（测过：写入待办后空档立刻变） |
| router 关键词顺序 | 「上传课表」必须排在通用的「课表」**前面**，否则会被 schedule 先截走，导入流程根本走不到 |

## 六、上传课表为什么不前端直接解析

课表格式千变万化：有的按表格、有的写"第 1-2 节"、有的按半天分块。
前端写死规则必然漏。所以做成：上传 → 自动给 planner 发一句话 →
Agent 读文件 → 整理成结构化 JSON → 调 `import_timetable` 写入。

这样既全自动，又复用了本项目"AI 动手"的设计，还能顺便让 AI 把
"第几节"换算成具体时刻。

## 七、验证

三份冒烟脚本共 **96 项全部通过，无回归**（26 + 35 + 35）。

本轮 35 项重点覆盖：
- 导入周表（含 day 越界 / 时间倒挂的拒绝）
- 查空档**不与课程重叠**（逐段比对过）
- 撞课被拒、非法时间被拒
- **空档随待办动态变化**（写入 19:00-20:30 后该段消失）
- 待办增删改查接口，缺字段 400、删不存在 404
- 月表聚合：明天 2 项 → 角标数据正确
- 会话历史：记两轮、内容对、上限 20 条、可清空
- planner 路由命中、"上传课表"关键词正确路由（验证了上面那个顺序问题）
- 无 Key 时依然不 500，且回传 session_id

另外用 node 对四个页面的内联 JS 做了 `--check` 语法校验 ——
避免页面白屏却查不出原因（这类问题在浏览器里只会表现为一片空白）。

## 八、还没做的

- 真正的多轮商量要配了 Key 才能演示（无 Key 时只能验证到路由与降级）
- 待办的**跨天/周期性**安排（比如"每周三复习"还没做）
- 多用户隔离：现在 `app/data/student/` 是单份的，真上线要按用户分目录
- 周表只支持"每周固定"，单周的临时调课还没建模
