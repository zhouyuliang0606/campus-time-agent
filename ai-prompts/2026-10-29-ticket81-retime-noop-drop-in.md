## 〇 现场事实

### 0.1 三句话，三张空卡

| 学生原话 | `build_retime_existing_proposal` | 屏幕上 |
|---|---|---|
| `换个时间吧` | `ok`，新 == 旧 == 2026-10-29 15:00-16:00 | 「从 …15:00-16:00 改到 …15:00-16:00」 |
| `游泳改一下` | `ok`，同上 | 同上 |
| `游泳这个撞时间了，改一下` | `ok`，同上 | 同上 |

**三句都是"点了名、但没给新时间"。** 系统出的卡是「原地不动」，而话术说「旧的那段会挪走」。

### 0.2 落点：两处"没给就沿用旧值"，正好凑成一次空改动

`app/modules/planner.py:5213-5255`，两条赋值单独看都对，合起来就成了空改动：

```python
:5232    if not new_date:
:5233        new_date = old_date                    # ① 没说日子 → 沿用旧日子

:5246    if not begin:
:5247        if new_date != old_date:
:5248            slot = pick_free_slot(new_date, prefer=t)
:5252        else:
:5253            begin, finish = old.get("start",""), old.get("end","")   # ② 没报钟点 + 日子没变 → 沿用旧时刻
```

**两条都命中 ⇒ 新三元组与旧三元组逐字段相同。** 而 `:5254` 只挡了「钟点不合法」：

```python
if not (begin and finish) or to_minutes(finish) <= to_minutes(begin):
    return {"status": "unclear", "todos": []}
```

15:00-16:00 是合法区间 ⇒ 一路放行，组出 proposal。

### 0.3 话术还在给它背书

`app/main.py:3754`：

```python
f"下面点【确认加入】我就改好（**旧的那段会挪走**）。"
```

**空改动的卡配上这句，等于让学生亲手把一条待办删掉再加一条一模一样的。**

### 0.4 为什么它不是"无害的重复操作"（这条要写进动机）

改期走的是**删旧加新**（`main.py:6425 _old_id = body.get("old_todo_id")`）。而确认口是：

```python
:6469    note=(body.get("note") or "").strip(),
:6470    category=(body.get("category") or "").strip(),
```

**提案里没有 `note`、没有 `category`**（实测 proposal 键只有
`date / end / kind / minutes / old_todo_id / repeat / retimed / start / summary / title / weekday`）。

⇒ 学生点那张"什么都没改"的卡：**`note` 和 `category` 被抹成空串，`id` 也变了**（`repeat` 带着所以不丢）。
旧条目 `note=带泳镜 / category=运动 / repeat=weekly` → 新条目 `note="" / category="" / repeat=weekly`。

**它不是"白点一下"，是"点一下就掉两个字段"。**

### 0.5 好消息：追问的话术和分支**已经存在**，不用新造

`app/main.py:3790-3800` 的 `unclear` 分支：

```python
# unclear：新时间认不出来
return {
    "module": "planner", "session_id": session_id,
    "answer": "🕘 新时间我没听清——说清楚要改到哪天几点？比如「改到周五 15:00-16:00」。",
    "trace": [{"step": 1, "phase": "🕘 改期新时间缺失", "answer": "请学生补时间"}],
    "options": [], "awaiting_choice": False,
}
```

**这就是本单要的那句追问。** 所以修法不是"新增一个 status 再给调用方加分支"，
而是**让空改动落进这个已有分支**。

（已核实：`"新时间我没听清"` 这句话**没有任何测试钉着**，可以微调；`"unclear"` 只有
`tests/test_11_todo_target.py:155` 一处断言，且那是 `resolve_todo_remove_reply`（删待办），**不受本单影响**。）

## 一 修法

### 1.1 一行判断，堵在组 proposal 之前

`app/modules/planner.py`，插在 `:5254` 那段合法性判断**之前**：

```python
    # ★ #81：既没说日子、也没报钟点 → 两个"没给就沿用旧值"的兜底同时生效，
    #   新三元组与旧的一模一样。这不是"改期"，是"原地不动"。
    #   放它过去会出一张「从 15:00-16:00 改到 15:00-16:00」的卡，学生点【确认加入】
    #   等于删一条再加一条一模一样的 —— 而且 note/category 会被抹成空串
    #   （main.py:6469-6470 从 body 取，提案里没这两个键）。
    #   这种要的是**追问**，不是出卡。落进已有的 `unclear` 分支就够，不新造 status。
    if (new_date == old_date
            and begin == old.get("start", "")
            and finish == old.get("end", "")):
        return {"status": "unclear", "todos": [old]}
```

**判据是三元组全等，不是"没说日子"。** 理由见 §2.2。

带 `todos: [old]`（不是空列表）：让调用方和测试都看得见"我知道你要改哪条，只是没新时间"。
这与 `unclear` 原有的 `todos: []` 不同，但只有 `test_11:155` 那条（删待办）断言了 `len == 4`，
改期这一路没有断言 `todos` 长度，**不冲突**。

### 1.2 话术微调：`unclear` 现在说"没听清"，而实际是"你没说"

「没听清」暗示"你说了我没接住"，而这一族是**学生压根没给**。
改成一句话同时接住两种情况（`app/main.py:3795`）：

```python
"answer": ("🕘 「{title}」现在是 {old_label}。想改到哪天、或者几点？"
           "说一句就行（比如「挪到周五」「改到 20:00」）。"),
```

要用 `_rt` 里现成的 `old_label`（`:5210` 组好的 `日期（周X）时刻`），别再算一遍。
**必须把旧值念出来**——学生说"改一下"往往是因为看见它撞了，不知道现状就无从改起。

### 1.3 连带变红的既有判据：**5 条红，不是 3 条**

执行方报的是 A8 / C2-bis / C3。**实测清点下来是 5 条**，多出的两条在 `tests/test_93_retime_context_hint.py`：

| 行 | 用例 | 现在的断言 | 为什么红 |
|---|---|---|---|
| `:120` | **A8** | `("换个时间", hint="健身房")` → `status == "ok"` | 空改动 → 变 unclear |
| `:124` | **A8-bis** | 同上的卡带 `old_todo_id` | 没 proposal 了 |
| `:143` | **A13** | `("换个时间", None, "约会")` → `proposal.title == "约会"` | **没 proposal 了 ← 执行方漏了这条** |
| `:252` | **C2-bis** | 库里一条 + `"换个时间"` → `status == "ok"` | 空改动 |
| `:259` | **C3** | 库一条 + hint="约会" → `status == "ok"` | 空改动 |

**并且 B 批（端到端）也有一条红的**：

| 行 | 用例 | 现在的断言 | 为什么红 |
|---|---|---|---|
| `:165` | **B1** | 上文只提「健身房」+ `"换个时间"` → **出改期确认卡** | 空改动 → 追问，不出卡 |

**B1 是本单最要小心的一条：它不能简单改成"不出卡"。** 见 §1.4。

仍然**绿**的三条（别看错成要改）：

- `:169` **B1-bis**「没有『同名的』、不倒清单」→ 追问话术里两者都没有，仍绿；
- `:173` **B1-c**「轨迹走改期那一支」→ `unclear` 的 trace 是 `"🕘 改期新时间缺失"`，**含"改期"**，仍绿；
- `:176` **B1-d**「一个字节都不写库」→ 追问同样不写，仍绿。

### 1.4 B1 要**换句子**，不是改期望

B1 测的是 **#77 的「上文捞名字」**——句子自己**不能带名字**，否则 hint 不参与（A12 钉着这条）。

```
原句（空改动）：换个时间                     → 现在会变成追问，测不出"捞名字"
改成（带钟点）：改到 20:00                   → hint='健身房' 参与，new_date 不变、begin=20:00 ≠ 19:00
                                              → 有效改动 → 出卡 ✓ 原意保住
```

并把 `"换个时间"` 这一句**另立一条 B1-e**，钉 #81 自己：

```
B1-e  上文只提「健身房」+「换个时间」→ status 走 unclear、**不出卡**、话术里念出旧值 19:00-20:30
```

**B1 和 B1-e 必须成对存在**：只有 B1 会漏掉空改动，只有 B1-e 会丢掉"捞名字"的验证。

## 二 判断与理由

### 2.1 为什么复用 `unclear`，不新造 `noop`

新造 `noop` 要付三笔账：函数多一个返回值族、`main.py` 多一个分支、测试多一套口径。
而 `unclear` 的语义（**"新时间没有"**）与空改动（**"新时间压根没给"**）**就是同一件事**，
它的追问话术（§0.5）也正好是学生要的。

**两天窗口 + 今晚封版，能用现有的分支说清的事，不要新造一个概念。**

代价：`unclear` 另外两种来源（换了日子但挑不出空档 / 钟点不合法）与空改动共用一句话术。
所以 §1.2 的话术必须写成"两种情况都接得住"的样子——不能写死成"你刚才说的那个时间不行"。

### 2.2 为什么判据是三元组全等，不是"没说日子"

只判"没说日子"会漏掉另一半：**学生报了钟点、但正好是旧钟点**（「游泳改到 15:00」而本来就是 15:00）。
那种情况 `new_date == old_date`、`begin == old.start` ⇒ 同样是空改动，同样该追问。

反过来，**「挪到周五」即使没报钟点也不是空改动**（`new_date != old_date` ⇒ 走 `pick_free_slot` 挑新空档），
三元组判据不会误伤它。

**判"结果是否相同"永远比判"输入缺了哪一项"稳**——输入的组合有十几种，相同只有一种。

### 2.3 note / category 丢失是**另一个洞**，本单不治（但必须写清楚）

`note` / `category` 不只在空改动时丢——**任何一次改期都会丢**，因为提案从来不带这两个键。
本单堵住空改动，只是让"白白丢一次"的机会消失；**正常改期（「挪到周五」）照样丢**。

修它要动确认口的写库路径（`main.py:6469-6470` 改成"没给就沿用旧的"），
那是本单之外的一笔，**封版前不做**。已挂账，演示时不要拿改期去演"备注还在"。

### 2.4 「撞时间的改一下时间吧」→「没找到那条待办」是**另一个改点**，别并进来

`build_retime_existing_proposal("撞时间的改一下时间吧")` 返回 `empty`：事名被抠成残渣「时间」，
而 #77 的 `hint_title` 只在上文捞得到名字时才起作用，这一路卡在 `_pick_todo_name` 的词表上。

**#77 单据 §四.2 明令禁改那张表。** 并进来 = 一单改两个变量，出问题分不清是谁的。
另开一单（演示后再说，分镜里不演这句）。

### 3.3 真机（唯一能把 §0.3 那句假话验掉的地方）

原话走一遍 `游泳这个撞时间了，改一下`（学生真说过这一句）：

- 屏幕上**没有**「从 15:00-16:00 改到 15:00-16:00」这种卡；
- 追问里念出的旧值与他库里的真值一致（**不许念成 14:00**）；
- 点「卡呢」**不允许**把这张空改动卡从暂存里拉出来（追问分支不 `save_pending`）。

### 3.4 变异（每条都要有牙）

| # | 变异 | 必须变红 |

## 五 给执行方的三句

1. **判据是"结果相同"，不是"输入缺了一项"。** 三元组全等这一条，放宽会漏（报了同样的钟点），
   收紧会误伤（换了日子没报钟点）。§3.4 的 V2/V3 是一对，**两条都要跑**。
2. **B1 要换句子，不能改期望。** 它测的是"上文捞名字"，句子必须不带名字；
   把它的期望值改成"不出卡"，#77 就没人验了。换句子 + 新增 B1-e，两条一起上。
3. **`unclear` 的话术要写成"两种缺失都接得住"。** 它现在还要接"换了日子但挑不出空档"那种，
   别写成只针对空改动的措辞——那会让另一种情况说错话。
