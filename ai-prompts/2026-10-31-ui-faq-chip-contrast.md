## 二 根因：玻璃段换了底色，没换字

| 位置 | 内容 | 后果 |
|---|---|---|
| `student.html:335`（基线段） | `.faq-btn { background:#fafbff; color:#1f2733; }` | 近白底 + 深字，浅色主题下正常 |
| `student.html:575`（玻璃段） | `.faq-btn { background: var(--surface); }` —— **只覆盖 background** | 底翻成深色半透明，字还是那句写死的 `#1f2733`，**不会**继承 body 的亮字 |

玻璃段里同样"只改 background"的规则共 **26 条**，它们没出事是因为**基线段没给那些选择器写过 `color`**
（于是继承 `body { color: var(--text) }`）。基线写过 color 的候选共 5 个：`header`、`.user .bubble`、
`.bot .bubble` 被后面更具体的 `html.gx-glass X { … color: var(--text) }` 救回，
**没被救回的两颗就是 `.faq-btn` 与 `.probe-out`**（后者是意图诊断面板，`:413` 写着 `color:#3f4a63`）。
`.probe-out` 这一处不是我找的，是新加的 G1 扫描闸落笔当场抓出来的。

## 三 改法（两行，都用现成 token）

```
.faq-btn   { … background: var(--surface); color: var(--text-2); … }   /* 原 :575 */
.probe-out { … background: var(--brand-soft-2); color: var(--text-2); } /* 原 :616 */
```

- 值取 `--text-2`（`#b9cfc2`）= `:641` 那族 `.tab / .persona / .dlg-btn` 用的同一个 token，不新造颜色；
- 玻璃关掉时这两行连同 `var()` 一起失效 ⇒ 退回基线的深字浅底，**不养第二套样式**（与 `:516` 那条设计约束一致）；
- `:576` 的 hover 本来就带 `color: var(--brand)`，没动。

## 五 护栏：test_44 新增 G 批 6 条 + 变异 M1~M4

G1 是**扫描型配对闸**（玻璃段改了 background、基线写过 color、玻璃段没写 color ⇒ 违规），
G2 钉形状，G3/G5/G6 按**这颗按钮实际用的那一对颜色**算对比度，G4 是反向对照（换回旧字色必须判 < 1.5）。

两条自己踩的坑都留在判据里：

1. **第一版 G3 是空判据**：它算的是 `--text-2` 与 `--surface` 这一对 **token** 的对比度，
   于是变异 M2（把 `.faq-btn` 的字色换回写死的 `#1f2733`）**只红 G2、不红 G3** ⇒ 量化闸形同虚设。
   改成"顺着 `var()` 解引用到该选择器真正声明的那一对"之后，M2 才红 G3。
2. **alpha 解析**：`rgba(16,36,28,.52)` 第一版把 `.52` 读成 `52` ⇒ 合成底算出 `#1db387319` 这种畸形值、
   三条对比度全判错（正则改成 `(1|0?\.\d+)`）。这条与"跑前先核一次未变异基线"是同一课。

变异读数（每笔跑完按字节还原、核 md5 `f1fea5d84b5c` 一致）：
M1 摘掉 chip 的 color ⇒ `G1,G2,G3,G4` 红；M2 换回深字 ⇒ `G2,G3` 红；
M3 把 `--text-2` 改暗 ⇒ `G3,G6` 红（**G4 不该红** —— 它量的是基线那句深字，与 token 无关；我第一版期望写错了）；
M4 摘掉 `.probe-out` 的 color ⇒ `G1,G6` 红。`test_44` 单批 130 → **136 项 / 0 失败**。
