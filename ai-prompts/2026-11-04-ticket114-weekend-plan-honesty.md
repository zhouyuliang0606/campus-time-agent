# 2026-11-04 · #114 「周末安排两次…一次三小时」不再排到周三，装不满也不再说「按你说的 3 小时」

## 一、用户 Prompt 摘录

施工单 drop-in（原件同批入库：`2026-11-04-ticket114-weekend-plan-honesty-drop-in.md`，逐字节一致），两段现场：

- §0：学生说「**周末安排两次打乒乓球一次三小时**」→ 系统排到**周三 08:00-10:05（125 分钟）**，卡上 reason 却写「**按你说的 3 小时 排的**」——日子错、时长缩水、话术撒谎，三件叠加。
- §0.7（本单最硬的一条）：①「周末打篮球，四个小时」→ 说"周末排不下"却给周三候选；②学生纠正「**周三是明天，我说的周末**」→ 回答**一字不变**（照旧周三）。判据：两次 `answer` 字符串相等 → 红。

施工单要求：1.1→1.5 五处是同一次修复的五个面，按序修、不许跳；§五 明令不做四件事（两张独立确认条 / "周末=本周六周日"硬锁 / 动 #112 标题残渣 / 动 `kb.json`）。

## 二、AI 研判与决策（含为什么不那么修）

五处病根照单全修（顺序 1.1→1.5）：

1. **1.1 补词**：新增 `_strip_freq_keep_range`（擦掉频次词、**保留范围词**），只接进 `todo_slots_proposal` 的两处调用（`:1068`/`:1076` 附近）。全仓 `_FREQ_RE` 相关行号实测是 976/1079/1429/2427/2944——与单据点名的行号对不上（单据行号是写作时快照），按"调用方语义"定位而不是照抄行号；其余同族裸 `_FREQ_RE.sub` 三处一个没动（它们没有"周末被吃"这个问题）。不做整句重解析——单据没要求，且会牵动 #71/#74 已钉的行为。
2. **1.2 档尾**：`_day_slots` 兜底段允许跨 phi 取段、`finish = min(begin+length, s["end"])`，"这周末装得下"才是真话（变异 M3 专钉这条）。
3. **1.3 认周末**：`plan_todo_slot` 加 `_weekend_mode` + 两把尺全关时的 14 天宽档。
4. **1.4 说真话**：两趟 `_partial` 循环 + `_auto_card(full=)`——装不满就明说「周末装不满 3 小时，这是能排下的部分」，不许再无条件写「按你说的」。
5. **1.5 日子退让**：`candidate_slots` 的 `picked_day` 与 `plan_todo_slot` 的 `day` 两处，句子里的日子与「周末」冲突时让位给周末（§0.7 的病根；`_pick_date` 会先抓「明天」，所以单据警告只修 M1-M4 不修 M5 现场一点都不会好）。

**前提偏离三条（都有实测，不是偏好）**：

- ① `_FREQ_RE` 处数/行号与单据对不上（见上），只动两处调用。
- ② 单据 §四.1 预期「首段是 11/8（周日）」，实测**首段 11/7（周六）14:00-17:00**——他真实课表周六下午本来就有空档，`days_ahead` 自然顺序就该先落周六；单据判据"不再出现任何周三"照钉，"首段=11/8"按实测改成"首段在周末"。
- ③ ★判据"两次 `answer` 相等→红"的前提过时：单据断言周末最长 160/210 装不下 240，实测他课表**周末真有 4 小时空档**，①本来就出对的周末卡 ⇒ "复述周三"这个病根在结构上已不存在（1.5 让日子先退让），字面判据在真机上没有红的机会。C 批改钉**解析层等价物**：纠正后的合并句必须出**周末**卡、不许再指"明天/周三"，并钉 1.5 两处 `day = ""` 的存在（变异 M5 是唯一能抓这条的）。

**为什么不那么修**：不做成两张 `todo_add` 独立确认条——「两次」靠 `build_todo_slots(preselect=2)` 表达、点【加入日程】走 `/api/todos/batch` 一次写两条，拆成两张正是 #75 花力气消灭的前端叠卡 bug；不做"周末=本周六周日"硬锁——周日当天「周末打球」会一张卡不出（`candidate_slots:551-555` 注释就是踩过这个坑写的）；#112 标题残渣、`kb.json` 均未动。
