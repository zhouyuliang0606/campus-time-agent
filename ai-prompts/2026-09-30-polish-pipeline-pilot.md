## 改动
### 新增 `app/agent/polish.py`（润色基础设施）
- `polish_reply(facts, fallback, *, override=None, timeout=4.0, executed=False)`：
  把**系统算好的结构化事实**交给模型说人话；**任何问题都退回 `fallback`（= 迁移前的模板）**。
- 三条红线逐条实现：
  1. **模型只复述、不决定事实**：facts 由系统产出（列表/卡字段），prompt 明令不许新增/猜测/编造；
  2. **失败即降级**：没 key / 超时（`asyncio.wait_for`，默认 4s）/ `LLMError` / 空回复 → 一律返回 fallback，
     用户侧无感知、绝不 500；
  3. **承诺词守卫**：润色文本含"已经帮你/写好了/已删除/安排好了"等**已完成**字眼、
     而本轮 `executed=False`（没有对应写操作）→ 判违规、退回模板。
- 补丁可见性：客户端与 `get_llm_config` **一律函数内 import**（`from app.llm.client import DeepSeekClient`），
  否则测试的 `_patch_llm` 打不进来（`from X import Y` 是导入时绑定）—— 见 test_19/test_18 的同类教训。
- `llm_available(override)`：先看有没有 key，没配直接降级（离线兜底，免得白等超时）。

### 改 `app/main.py`（两处，逻辑零改动、只把模板话术接上润色）
- **试点 1 · 3d 读待办**：`todos = list_todos()` 照旧；把**结构化事实**（intent/count/每条 title·date·weekday·start·end）
  交给 `polish_reply`，fallback = 原模板列表文案。列表数据**完全来自 `list_todos()`**，与迁移前逐字一致。
- **试点 2 · 3c 加待办**：确认卡字段 / `save_pending` / `_offer_response` / 写库路径**一个字节都不改**；
  只把那张单条确认条的话术交给 `polish_reply`（facts = title/date/weekday/start/end, executed=False），
  fallback = 原模板「📝 要不要把 **X** 排进日程？…」。

> 未迁移分支保持原样，两种风格短期并存（预期内，不顺手"统一"）。

## 验证（见 `tests/test_20_polish.py`，共 36 项 / 7 批）
1. **polish_reply 单元（6 项）**：没 key→模板 / 有 key→模型文本 / 空回复→模板 / 承诺词(未执行)→模板 /
   承诺词(executed)→放行 / 超时→模板。
2. **has_promise（9 项）**：命中 5 个承诺词；不误伤"要不要帮你排进日程？"这类未来式。
3. **试点 1 · 3d（7 项）**：没 key→模板化列表（条数与 `list_todos()` 一致）；有 key→**润色话术出现**、
   模板头消失；用 spy 捕获"交给模型的事实"→**条数/标题集合 == 库里真实列表**（数据与迁移前一致）。
4. **试点 2 · 3c（5 项）**：有 key→**润色话术出现**；照旧出 `todo_add` 卡，且
   **卡字段逐字段 == 迁移前的确定性解析**（`parse_add_todo` 对照）；照旧等学生点确认；没 key→模板。
5. **承诺词守卫端到端 + 问句（3 项）**：模型回"已经帮你加好了"→被拦、退回模板；
   「我要去哪里取快递」→**仍不出任何待办卡**。
6. **离线兜底（3 项）**：没 key → 3d/3c 都 HTTP 200、有内容、无 `⚠️`、照旧出卡（功能不丢）。
7. **反向验证（3 项）**：把 `polish.polish_reply` 拆成"永远返回 fallback" →
   **润色话术立刻消失、模板话术回来**，证明"润色话术出现"这条断言确实盯着真链路，不是假绿。

- **全量回归**：`tests/run_all.py` → **1505 通过 / 0 失败（21 批）**（含 `test_08 / test_15 / test_16 / test_intent_classify`，全绿）；
  `pytest tests/test_intent_classify.py` → 1 passed。
  ⚠️ 首次全量曾红 2 项（test_08「改成念待办列表」/ test_09「LS-S1 列出待办」）：
  这两个用例把模型打桩成**语义分类的 JSON**，而 3d 的润色**复用了同一次打桩** →
  把那段 JSON 当成了"润色话术"。修法：`polish_reply` 加"结果必须是自然语言"守卫
  （回复以 `{`/`[` 开头 → 判无效、退回模板）。修后复跑全绿。
- **离线复跑**：拔掉 key（沙箱即无 key）整批照跑，无 500、无白屏，模板话术与迁移前一致。
