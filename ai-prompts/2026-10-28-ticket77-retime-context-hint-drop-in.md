## 〇 现场事实

### 0.1 用户真机那一幕

上文刚问过「健身房 价格」，学生在同一会话里说：

> **「换个时间」**

系统回：

> 🕘 你想改的是哪一条？**我找到好几条同名的**：
> · **健身房**｜2026-10-26（周一）19:00-20:30
> · **做题**｜2026-10-27（周二）14:00-16:00
> · **约会**｜2026-10-30（周五）15:40-18:40
> · **打篮球**｜2026-10-31（周六）09:00-10:30

**四条一条都不同名。** 学生想要的显然是第一条（上文说的就是健身房），
系统却把**全部待办**倒出来让他重挑——等于把上文整个丢掉了。

### 0.2 链条（`planner.py:5137 build_retime_existing_proposal`）

```
「换个时间」
 ↓ :5156  re.sub 把「换个时间」当换时间词擦掉   →  t_clean = "  "
 ↓ :5158  name = sem.title or ""               →  空（语义层也没给）
 ↓ :5166  name = _pick_todo_name("  ")         →  仍空
 ↓ :5171  if name and name not in ("", "待办", "日程", "事项"):
          ← **名字为空，整段"按名字过滤"被跳过**
 ↓ :5170  pool = list_todos()                  ← 候选池 = 全部待办
 ↓ :5190  if len(pool) > 1: return {"status": "many", "todos": pool}
 ↓ main.py:3681-3696 把 todos[:6] 全列出来
```

**一句话：这里没有"名字缺失"这个分支，它把"没有名字"当成了"这个名字匹配所有"。**

### 0.3 那句文案在骗人

`main.py:3691` 写死：

> 「🕘 你想改的是哪一条？**我找到好几条同名的**：」

它假设 `status == "many"` 只可能来自"同一个名字有多条"。但 `many` 其实有两种来源：

| 来源 | 例子 | 系统现在都说 | 应该说 |
|---|---|---|---|
| **真同名多条** | 日程里两条都叫「健身」 | 「好几条同名的」✅ | 「好几条都叫『健身』，要改哪条？」 |
| **学生压根没说名字** | 「换个时间」 | 「好几条同名的」❌ **在骗人** | 「你要改哪一条？」 |

### 0.4 根因在函数签名上

```python
def build_retime_existing_proposal(text: str, sem: dict | None = None) -> dict:
```

**它只有这一句话和语义字段，看不到上下文。** 上文说了二十遍"健身房"它也拿不到。

对比同文件里做同一件事的 `_recent_add_request`（`main.py:692`）——
"加待办"那条路早就知道要回头捞上文，**改期这条路一直没捞**。

### 0.5 为什么不用暂存卡兜

上一轮是「问健身房价格」，**手上没有挂着的卡**（`peek_pending` 是空的），
所以 `_todo_patch_base` 那一套（三档 base）在这儿帮不上——只能从**对话记录**里捞。

## 一、修法

### 1.1 函数加一个 `hint_title`

`planner.py:5137`：

```python
def build_retime_existing_proposal(text: str, sem: dict | None = None,
                                   hint_title: str = "") -> dict:
```

在 `name` 算完之后（`:5166` 那个 `name = _pick_todo_name(t_clean)` 之后）加：

```python
    # ★ #77：这句话里没点名 → 用上文最近提到的那条（学生说「换个时间」时指的是它）
    #   只在**唯一匹配**时才用；多条或没有 → 保持空，照旧列出候选让他挑（宁可多问一句）。
    if not name or name in ("", "待办", "日程", "事项"):
        name = (hint_title or "").strip()
```

**只加这一处，下面 `:5171` 起的过滤逻辑一个字都不改** ——
名字一旦有值，原有的"按名字过滤 + 没命中就退回从原句抠"那套照常工作。

### 1.2 上文怎么捞：`_recent_todo_title`

跟 `_recent_add_request`（`main.py:692`）同一套思路，放在它旁边：

```python
def _recent_todo_title(session_id: str, span: int = 8) -> str:
    """上文最近提到的那条待办名（人话：学生说「换个时间」时，得知道他指的是哪条）。

    **只在唯一匹配时返回**；匹配到两个以上、或一条都没有 → 返回空串。
    宁可让他多说一句，也别替他把 A 改成 B。

    为什么按 title 去重而不是按 todo 条数：
      上文说「健身房」、库里正好有两条同名卡 → 这里返回「健身房」是对的，
      下游会走 many 分支**列出那两条同名的**，那时「同名的」这句话才是真的。
    """
    msgs = get_conversation(session_id)[-span:]
    if not msgs:
        return ""
    texts = [(m.get("content") or "") for m in msgs]
    if not any(texts):
        return ""
    hit_titles = set()
    for todo in list_todos():
        title = (todo.get("title") or "").strip()
        if not title or title in ("待办", "日程", "事项"):
            continue
        if any(title in tx for tx in texts):
            hit_titles.add(title)
    if len(hit_titles) != 1:
        return ""
    return next(iter(hit_titles))
```

## 二、判断与理由

### 2.1 为什么是"继承上文"而不是"少列几条"

把 `todos[:6]` 改成 `todos[:3]` 之类是治症状——学生该挑的条数变少了，**可他真正想改的那条可能正好被截掉**。
问题的本质不是"列太多"，是**"该知道的那条明明在上文里，却没人去看"**。

### 2.2 为什么必须"唯一匹配"才继承

上文同时提到「健身房」和「打篮球」时，`_recent_todo_title` 返回空 ⇒ 照旧列出候选。
这是刻意的：

- 猜错的代价 = **把 A 改成 B**，而且这是"删旧 + 加新"，改错了要再改回来两次
- 多问一句的代价 = 学生多打五个字

**这笔账在任何情况下都算得过来。** 跟 76 的"宁可漏、不可冤"是同一条纪律。

### 2.3 为什么按 title 去重、不按 todo 条数

见 §1.2 的注释。关键一幕：

```
上文：「健身房 价格」            →  唯一 title = 健身房
库里：两条「健身房」（周一、周三）→  hint_title = "健身房"
下游：按名字过滤命中 2 条 → many → 列出那两条
文案：len(_rt_titles) == 1 → 「有好几条都叫「健身房」」  ← 这时才是真的同名
```

**同一个函数，两种输入走两条路，话术各自诚实。**

### 2.4 代价要认

| 代价 | 说明 |
|---|---|
| `list_todos()` 多调一次 | 它本来就在 `:5170` 调一次；`_recent_todo_title` 里再调一次，纯内存/轻查询，可忽略 |
| 扫 8 条消息 × N 条待办 | O(8N) 的字符串包含判断，N 是个位数，微秒级 |
| 可能"继承错" | 概率被 `len(hit_titles) != 1` 这条挡住了，剩下的都是学生自己上文确实只提了一条 |

## 四、不做的事

1. **不做上下文状态层。** 本单只是把 `hint` 递进一个函数；那一层要等这类"递 hint"的实例攒够再收编。
2. **不改 `_pick_todo_name` 的词表。** 「换个时间」抠不出名字是**对的**——它本来就没说名字。
3. **不把候选条数从 6 调小。** 那是治症状，且可能正好截掉学生要的那条。
4. **不动 `_recent_add_request`。** 它是"加待办"那条路的，跟改期不是一回事，别合并。

## 五、给执行方的三句

1. **`hint_title` 只在 `name` 为空（或占位符）时才生效**，`name` 有值时它**必须完全不参与**——
   P1 钉着这一条，写错了会把"把周三的游泳挪到周五"改成"改健身房"。
2. **`len(hit_titles) != 1` 那个 `!=` 不许改成 `<`**。多匹配时返回空、照旧列候选，
   是这张单子唯一的安全阀；V2 就是射它的。
3. **老调用点不许破**：`build_retime_existing_proposal` 只被 `main.py:3654` 这一处调用，
   但参数必须带默认值（P4 钉着），将来别的地方接进来才不会踩空。
