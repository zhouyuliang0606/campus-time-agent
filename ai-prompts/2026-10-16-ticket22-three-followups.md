## 三、单子 5 —— 坏请求体 400（`be24f7a` + `c91502e`）

**这条 500 是我自己造的**：收口时用 Git Bash 的 curl 发中文 body 到驿站「改状态」那个口，
那壳按控制台码页（GBK）把字节发出去 → `req.json()` 抛 `UnicodeDecodeError` → 500 + 整段 traceback。
**先别当成应用 bug**：换成 UTF-8 正常发，同一批口的负路径本来就对（404 / 400 / 400，真实台账 md5 未变）。
但形状确实是洞：23 个解码点全裸着。

改法按施工单：**一处 `@app.exception_handler`**（`JSONDecodeError` + `UnicodeDecodeError`）而不是 23 个 try。
为什么不是 422：422 = 字段不合形，400 = 这句压根没解开。

护栏 `test_55_bad_body_400.py` 16+5+5=26 项，两处设计上的讲究：
- **"坏 body 该 400"的样本必须挑会走到解码那一步的入口**：实测「不存在的服务 + 坏 body」是 404
  （路由先判存在性），那是对的，拿它当样本就是让测试钉一个错期望；
- B 批 5 条**修复前就是绿的**，它们钉的是"别顺手放宽"：无口令 + 坏 body 打到管理端仍须 401
  （鉴权在解码之前）、不存在的路径仍 404、合法 JSON 正路径照旧通、SSE 那条不许半开挂死。

变异 N1~N5 各咬一条（摘任一类注册 / 改回 500 / 改成 `{"detail": ...}` / 摘掉管理端 notify 的鉴权依赖）。
真机复验：起新进程 + `http.client` 手写 GBK 字节（绕开码页干扰）→ 三个口都回那句人话，
服务端日志里 `UnicodeDecodeError` 计数 0。

## 五、单子 4 —— 低代码接进判定层（主线，`492f6ba` `e91bbbd` `9320d16` `0e8494e` `74c79dd`）

三层各加一段，每层都有一条"合法性只有一份"的收口：

**判定层**（`store` + `intent` + `router`）
- `store`：`custom_module` / `service_of_module` / `is_custom_module` / `match_service_by_trigger`。
  **`custom:<任意串>` 长得太像合法值**，所以合法性 = 回查 `services.json`，不看前缀像不像；
  触发词**最长那条算赢**（否则一句长话被短词随机抢走）。
- 新意图 `custom_record` 进 `KNOWN_INTENTS`，但它**必须绑到一个真实存在的服务**，
  否则整条判定丢弃（不是"降级成 chat 继续用"）。
- `intent.module_ok()` / `main._module_handled()` —— "这个 module 有人接吗"**只写一份**。
  主链路原来两处裸 `in REGISTRY`、router 三档裸 `in MODULE_KEYS` 全换掉：
  **只改一处就会出现"路由给了 custom、主链路不认"的中间态**，那句话被打回 faq，测试绿、真机答非所问。
- 触发词那一档的位置：②样本库 / ③语义层 / ④意图先行 **之后**，⑤通用关键词表 **之前**。
  并且带**问句否决**——复用 `looks_like_question`（实测 `QUESTION_RE` 里本来就有"怎么/如何/哪"，
  所以「我丢了饭卡怎么办」是被现有判据挡住的，**没有另造一张疑问词表**）。

**为什么光有 router 那一档不够（这是本轮最值钱的一次实测）**
配了密钥时语义层几乎总会给一个合法 module（`faq` 也算合法）→
`module_key` 一开始就有值 → **`router.route()` 根本不会被调用**，
触发词档只在"没密钥 / 判定层落空"时才生效。真机上"能不能命中"就全看模型心情，那不等于功能存在。
所以在主链路加了一条**硬信号接管**，条件三条同时成立才动：当前不是 custom、不是问句、
判定层**没把它认成别的事要办**（意图为空或 chat）。反向也钉住：
「我丢了饭卡，先帮我加个明天下午吃饭的待办」照旧走待办，**不抢**。

**能力层**（`app/modules/custom.py`，新）
提示与工具箱都按 `services.json` 那份定义**现算**；工具箱只有一件 `propose_custom_record`，
返回值带 `__proposal__` 交给引擎既有的"结果即提案"机制变成确认条。
**不开第二个工具**（比如"直接登记"）：低代码服务是运行时数据，今天能给失物招领开写入，
明天就能给任何一句随口生成的定义开写入 —— 那已经不是"扩展服务"，是"扩展权限"。

**执行层**（`POST /api/custom/records`）
三道判据：暂存里**必须真有这张卡**（卡是唯一授权凭据，凭空 POST 登记不进去）、
**卡绑这项服务**、字段过 `_custom_field_errors()`（与驿站端**同一份**判据，原来那段内联的抽出来共用）。
点完吃掉这张卡 → 点第二次 409，台账不重复写。

**前端**（`student.html` + `confirm.html`）
登记确认条走**既有**确认页通道（不新造组件）；输入框按 `field_order` **现长**
（前端写死一份字段清单就等于"新服务必须改前端"，低代码白做）；
`custom:<id>` 不印给学生看，标签统一映射成「驿站服务」。
