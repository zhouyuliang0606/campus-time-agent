## 一 修法

### 1.1 `planner.py`：`empty` 时把池子条数带出来

锚点：`build_retime_existing_proposal` 里**三处** `return {"status": "empty", "todos": []}`。

- **`hits` 为空那一处**（池子非空、但一条都没对上名字）→ 加 `"pool_n": len(pool_all)`
- 池子本身为空的那一处 → `"pool_n": 0`（或者不加，调用方用 `.get("pool_n")` 兜）

```python
        if not hits:
            # ★ #84：把"库里到底有没有东西"带出去 —— 调用方要靠它区分
            #   「我没认出来」（池子非空）和「库里真的没有」（池子空）。
            #   这两个处境说同一句"没找到"就是假话（#83 治的就是这个）。
            return {"status": "empty", "todos": [], "pool_n": len(pool_all)}
```

`pool_all` = 进函数时 `list_todos()` 那一份，**在 `pool` 被收窄之前存**（和 #83 的要求同一条）。

### 1.2 `main.py`：`empty` 那支改两分支

## 二 判断与理由

### 2.1 为什么是「事后升级」，不是「事前预判复合句」

事前预判要回答"这句话里有几件事"。我试过设计判据，**在真实句子上就崩**：

| 句子 | 数动作族的结果 | 对不对 |
|---|---|---|
| 有个代办**撞时间**了，帮我换一个时间 | 改期(1) + 撞时间(1) = 2 | 看似对 |
| **删掉撞时间**的代办 | 删(1) + 撞时间(1) = 2 | **错** —— 这条走确定性分支本来是对的 |
| 这周哪天课最少，那天排两小时做题 | 查(1) + 排(1) = 2 | 对 |

「撞时间的」在有的句子里是**筛条件**、在有的句子里是**难点本身**，词表分不开。
按它数动作族，第一条和第二条会一起被判成复合句 —— **一条该升级、一条不该**。

⇒ **别猜"这句话有几件事"，只判"这次办成了没有"。** 办不成才升级，误伤面最小。

### 2.2 为什么本单只改这一处，不推广

因为要**先证明这条路走得通**。推广的判据在 §3.4 —— 不是"代码写完就算"，是看实测：

- 升级后**办成率提升** → 明天推广到其他 `empty` 分支
- 升级了但模型**照样办不成**（常出"这个操作影响比较大，我先跟你确认一下"） → **停**，
  说明病不在"没交给引擎"，而在别处（判定层 / 工具描述 / 事名残渣），推了只会更慢更乱

**两天窗口里，最贵的不是少做一处，是在没验过的方向上铺开。**

### 2.3 这和 #76 是同一件事的第二次应用，不是新架构

#76 的判据：**规则层算不出来** → 交出去
本单的判据：**规则层算出来了，但这个人名/条件它认不出来** → 交出去

两次都用 `_run_agent_loop` 那扇门，都没新建机制。**要说清的是判据，不是说辞。**

### 2.4 和 #83 的关系：**#83 作废，被本单吸收**

v1 里这里是"两条退路并存"。学生说「默认有 Key，不用管没 Key 的情况」之后，砍成一条：

```
池子非空 → 交出去（有 Key 走模型；没 Key 由 `_run_agent_loop:2054` 降级到 mock，它自己管）
池子真空 → 说"没找到"（实话）
```

**「不判 Key」这条不只是"省事"，它比 v1 的写法更对**：

`_run_agent_loop:2050-2054` 本来就有这道判断，而且它不只是判断 —— 没 Key 时它会走
`mock_planner` 然后**自己 return**（`:2072`）。也就是说：

- 在改期支再判一次 Key = **同一个判据写两遍**（红线 4/11）
- 而且判完之后仍然要调 `_run_agent_loop`，那道闸还会再判一次 —— 前面那次纯属多余
- 万一哪天两处对不齐（比如 `model_config` 在中间被改写），会出现"改期支认为有 Key、引擎认为没有"的中间态，
  症状是**能进去但跑的是 mock**，最难查

⇒ **判据只留一份，在 `_run_agent_loop` 里。改期支只判"库里有没有东西"这一件它才该管的事。**

**#83 的"列候选"不做了**，理由：交出去比列 6 条强（模型懂"撞时间的"，能直接办）。
但 **#83 的判据 `pool_n` 要留下** —— 它是本单第 2 条分支的前提，没有它分不开"没认出来"和"真没有"。

## 五 给执行方的三句

1. **这一处用 `return`，不是 `pass`。** 改期支在函数**中段**，`pass` 会掉进报障/删课那些分支
   （学生说「撞时间了」，那些分支很可能接走）。#76 能 `pass` 是因为它插在链尾 —— 形制不同，
   照抄写法会错，照抄**判据**才对。
2. **T2 和 T3 是一对，缺一条这单不能交。** T2 管"别把成功的也交出去"，T3 管"别把真空的说成有"。
   这两条都在边界上，没有它们，本单只是"多调了一次引擎"，说不上是对的还是错的。
   **T3 尤其容易漏** —— 那句 `return {...没找到...}` 就在你改动点的**正下方**，
   写完新分支手一抖就把它连根带掉了，而它**没有任何演示会碰到**（演示时库里永远有数据）。
3. **§3.4 那两列数据要真记。** 明天推不推广，靠的是那 10 句的对比，不是"感觉好多了"。
   我给的推广条件是 ≥3 句办成且没有反复出现"影响比较大"——那条回答是引擎也办不成的信号，
   出现两次就说明这条路的瓶颈不在"交不交出去"。
