# 2026-10-03 课表导入「确认修改」卡不来 + 假待办卡（上传文件不行）

> 报障渠道：学生端主页截图（`上传文件不行`）。截图里学生用「📤 上传课表」传了
> 《2026秋季课表-纯文本.txt》，管家回了一段**自相矛盾的补条话术**：
> 「📄 刚才那条消息里写了方案，可卡片没跟上——我替你把确认条挂出来了：
> 要不要把 **确认修改** 排进日程？2026-10-05 (周一) 08:00-09:40」，
> 轨迹里同时躺着模型整理好的完整课程表和一条
> 「🛟 模型没调工具 → 系统从它的话里补出确认条 — 确认修改 | 2026-10-05 (周一) 08:00-09:40」。

## 用户 Prompt

## AI 研判（先分层，别照截图直接改）

按 `campustime-bugfix` 技能的排查顺序逐层核对：

- **上传本身没坏**：截图轨迹里有整张课程表 = 文件已读成功；`/api/upload` 真机冒烟也 200。
- **模型读了文件但没调 `propose_timetable_change`**（真机复现：`options: []`，
  它把课程整理成 markdown 表格只发文字，还承诺「回一句"确认导入"我就出卡」——
  而这句话**没有任何分支接得住**，属「话术承诺系统兑现不了的事」老毛病）。
- **为什么会这样**：前端 `timetableImportMsg` 模板自己说的——
  「整理成**预览清单**给我看……**先不要写入周表，等我确认后再导入**」。
  模型把「先不要写入」读成「先别出卡」，于是只发文字（模板与工具流程自相矛盾）。
- **假卡的来路**：模型那一轮**自称发过提案**（话术里出现「确认修改」），
  `main.py` 的待办补条兜底 `rescue_proposal_from_reply` 不认识"导入课表"这种请求，
  把「确认修改」抠成任务名、把表格第一行的「周一 08:00-09:40」抠成时间，
  挂出「要不要把 确认修改 排进日程」的假待办卡。

## 第二轮（2026-10-04 凌晨）

**用户 Prompt**：「解析出来了，卡没出来，由于是修改课表，我认为可以弹是否更改课表的卡」

### 研判：不是"再润色话术"，是"必须出卡"

第一轮修完，模型已经**读得出文件**了，但卡还是不来。学生这句话里有两层判断，
两层都得接住：① 解析（模型那一步）已经成功 → 问题不在上传；② 这是「修改课表」，
就该弹「是否更改课表」的卡 → **出卡是硬要求，不是可选优化**。

真机复现用的就是学生自己传的那份文件，一眼看出排版和我的假设不一样：

| | 我以为的 | 实际的 |
|---|---|---|
| 模型回话 | markdown 表格 | 列表体 `- **周一**：08:00-09:40 高等数学（教三301）｜10:05-…` |
| 原文件 | 一行一门课 | **一天一行、用「；」串好几门**（`周一：08:00-09:40 高等数学 教三301；10:05-11:45 大学英语 外语楼204；…`） |

v1 的 `_tt_course_row` **一行只认第一个钟点**，剩下的课全被静默吞掉。

### 改动（第二轮）

| 文件 | 改动 |
|---|---|
| `app/modules/planner.py` | 删掉「一行一门」的 `_tt_course_row`，换 `_tt_courses_in_line`：**按每个钟点切段**，两个钟点之间那段就是这一门课 → 一行能出好几门；新增 `_TT_PERIOD_WORDS`（「晚上」是"什么时候"，不是"在哪儿"——不滤的话前一门课的地栏会写成"晚上"）、`_TT_SPLIT_RE`（「；｜、」都当分隔符）、`_TT_BRACKET_RE`（「课名（地点）」拆两栏）；`_TT_SENT_PUNCT` 去掉「；」——学生文件靠它分课，它是分隔符不是句读 |
| `app/main.py` | 新增 `_tt_file_courses()`：**直接读上传的文件原文**抠课程（硬证据已经在库里，不必再问模型一次）；与"从回话里抠"两路都跑、**取更全的那份**，卡与回话里写明清单来自「管家回话」还是「文件原文」 |

关键取舍：**只按点名找文件**。`_tt_file_courses` 只认消息里的《文件名》（重试时回本会话
最近几句话里找《…》），**绝不拿"最近那份文件"猜**——万一那是别的资料，挂出来的就是一张假卡。
这跟项目一贯的「猜只许猜在结构确定的地方」是同一条规矩。
