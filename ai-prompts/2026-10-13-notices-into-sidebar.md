# 2026-10-13 · 通知不是没做，是被一条 CSS 藏了：搬进侧栏独立一栏

## 一、用户 Prompt 摘录

> 学校发布通知在学生端没有地方显示了，左边单开一项通知吧，还是别的办法
> （我给完三个去处之后）侧边单开，顶部太多东西了，而且本来视野就很小，再长期挂一条在上面更不合理

## 二、先核前提：不是缺功能，是被连坐了

`.notices` 那块（铃铛 + 条数角标 + 可展开列表 + 附件下载）一直挂在 `#chatStage` 顶部，
但 panel 改版这条规则把它跟模块卡片一起关掉了：

```css
/* student.html:386 */
.panel-mode .notices, .panel-mode #modules, .panel-mode #hint { display: none !important; }
```

而默认视图（日程 / 快递 / 外卖）全都是 panel-mode，"校园问答"又不是默认落点
—— 所以学生日常看到的那几屏里通知确实**一处都没有**。`#modules`、`#hint` 是当年有意收的，
通知是被连坐的那一个。这决定了改法不是"加功能"，是**换个地方摆**。

## 三、去处怎么定的

我给三个：侧栏一栏 / 顶栏铃铛 + 抽屉 / 只把隐藏规则去掉。他选侧栏，理由很具体：
顶栏已经挤、视野本来就小，长期挂一条在上面更不合理。
（第三种最省事但把问题留在原样：收起状态下学生还是不知道有没有新东西。）

实现沿用现成机制：`data-nav="notices"` + `#navNotices`，走 switchNav 里
`nav` + cap(view) 那一套纯查看栏（跟"代办事项""设置"同形），不动对话框逻辑。

## 四、红点：把它当偏好，不当数据

比"上次看过"更新的通知 → 侧栏小红点；打开这一栏即算读到最新一条。
"看到哪儿"存 localStorage（`ct_notice_seen`）：换设备/清缓存就回到"有新通知"。
方向是刻意选的反面 —— **宁可多提醒一次，也不把没看过的公告悄悄标成看过**。

## 五、我自己上一轮说错的两条，这轮纠正

1. 我说过"空标题会渲染成一行空白，要加兜底" —— 实际渲染里早就有 `n.title || "(无标题)"`，
   浏览器里量到那条确实显示成「(无标题)」。不用加。
2. 我准备"前端按 ts 倒序排一次" —— 后端 `list_notices()` 本来就是倒序（`reversed`）。
   再排一遍就是给"两边顺序不一致"留第二个说法（同一判断只留一份，红线 11b）。删掉。
