## 二、落地：判据各归一处，登录那一屏两单合写

**#37 归属**——只在 store 取身份：
```python
# app/store.py
"owner": current_student() if owner is None else str(owner),   # add_workorder / add_message 各一处
def list_workorders(include_archived=False, owner=None):
    if owner is not None:                     # ⚠️ 不是 `if owner:`：None(全量) 与 ""(只要老单) 是两种语义
        items = [w for w in items if (w.get("owner") or "") == owner]
```
写在 store 而不是路由，是因为聊天那一路走 `submit_work_order` 工具，**根本不经过 `/api/workorders`**。

**#37 进度**——`GET /api/my/workorders`：靠 cookie 认人、不收学号参数、**无身份回空列表**
（这条接口不挂管理口令，回落一次就是把全校报障摊开）、默认**带已归档**（归档对学生是"这事结了"）。
前端那块改成读它，`localStorage` 那本假账整本删（`test_63` C6 钉"搜不到 `campustime_workorders`"）。

**#37 入口**——委托从 `#sbNav` **替换**成整个 `#sidebar`：
「快递」「外卖」那两项在 `#sbMore > #sbMoreBody` 里，而顶部模块卡又被 CSS 写死
`#modules{display:none!important}` ⇒ 挂 `#sbNav` 等于这两项**一个请求都不发**。

**#38 名录 + 签名**——三道判据分开、顺序不许换：
```python
# /api/login：格式(400，路径安全) → 名录(403，不回名单) → 发 cookie
resp.set_cookie(_STUDENT_COOKIE, _sign_student(raw), path="/", samesite="lax")
# _clean_student：格式 →（配了密钥时）hmac.compare_digest → is_registered，任一不过 ⇒ ""（无身份）
```
`list_accounts()` **每次现读**；文件缺失或坏 JSON = **空表**（谁都进不来），不是"当没这回事全放行"。
中间件里也过一遍（只在 `/api/login` 校验 = 门锁只装了一半）。

**#35 撤播种 + 三态**：`_seed_first_login` 连 `import shutil` 一起删；
判据 `store.timetable_saved()` → `GET /api/timetable` 新增 `uploaded` 字段（只加字段不改形状）→
前端 `schUploaded = t.uploaded === true`，两种空态说两句不同的话。

### 真机抓到的一条，代码检查和接口测试都拦不住

第一版把**两种空态接反了分支**（`uploaded === false` 落进「课表已清空」），
新号 `s1000` 从没传过课表，一进去却被告知"课表已清空、要重新开始就再传一次"——
等于当着一个新人的面说他把上传弄丢了。

而当时 `test_59` D5 是**绿的**：它只查"「课表已清空」和「还没有课表」这两个字符串都在文件里"，
接反了它当然还在。⇒ 修实现的同时把 D5 改成钉**哪一句落在哪一个分支**，并补变异 M14（把两支互换）确认它现在真的会红。

一句话教训（归进指南红线 29）：**"字符串存在性"断言护不住"配对关系"**，
而配对恰恰就是这类"两种状态两句不同的话"的全部内容。
