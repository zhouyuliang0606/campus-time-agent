# 2026-10-08 「一周去三次健身房」：频次待办（展开成 N 条）

## 一、用户 Prompt 摘录

> 「日程的长久代办没法实现，我说一周去三次健身房，增加进代办」

（同轮前置指令仍生效：「每次修改完重启后台，我去进行测试」「细粒度 git 提交 + prompt 快照」）

给方案时用户选了 **展开成 N 条**（另两个选项：给待办加 `repeat` 字段做真·周期；只把文案改诚实）。

## 二、AI 研判与决策

### 2.1 先复现，复现路上先撞到一个 500

第一枪用 `curl -d` 发中文 → **500 Internal Server Error**。查 traceback：

```
File "app\main.py", line 1000, in _chat_impl
    body = await req.json()
UnicodeDecodeError: 'utf-8' codec can't decode byte 0xce in position 12
```

是我发的是 GBK，不是产品 bug——但**它暴露了一个真口子**：`/api/classify` 早就有
`try: body = await req.json() except Exception: body = {}` 的兜底，`/api/chat` 没有，
于是"请求体读不出来"这种客户端错误会以 500 的形式冒出来，前端只显示"网络异常"。
（→ 单独一个 commit `02e965f` 修掉，回 400 并说清是编码问题。）

换成 UTF-8 重发，才看到用户说的那个现象：

```
📝 **我一周要去三次健身房** 这件事我替你看了几个空着的时间段：
　· 周五（10/9）15:40-17:10   · 周六（10/10）19:00-20:30   …
```

### 2.2 根因：不是崩，是"三次"这个信息在链路上根本没有落点

| 环节 | 现状 | 问题 |
|---|---|---|
| 判定层 | 认成"办事（加待办）" | ✅ 对 |
| 标题 `_pick_title` | 整句「我一周要去三次健身房」当事名 | ❌ 频次是排期条件，不是名字的一部分 |
| 候选时段 `candidate_slots` | 一天一段、跨天摊开、可勾多个 | ✅ 机制本来就是多选 + 批量写库 |
| **次数 N** | 代码里没有任何地方读它 | ❌ 这就是"长久待办没法实现"的全部原因 |
| 数据模型 | `{id,title,date,start,end,status}` | ❌ 一条 = 一天一个时段，没有周期概念 |

关键判断：**多选 + `/api/todos/batch` 已经存在**（第七轮规格"列举出来由我打勾"），
所以"一周三次"缺的不是新机制，只是"没人把 3 这个数读出来、并把前 3 段替他勾上"。

### 2.3 为什么不加 `repeat` 字段（用户如果选另一条路会怎么做）

真·周期待办要动的地方：`/plan` 的渲染要按周展开、逐日明细要判断"这条属不属于这天"、
月表角标的计数、批量接口的空档复核、**完成语义**（"这周三次练了一次"是勾一条还是三条？）、
删除语义（删一次还是删整个系列？）。这不是不能做，是它会把"一条待办 = 一行数据"这个
贯穿全项目的不变量拆掉，改到哪儿都容易出岔子——演示当场翻车的成本远大于收益。
展开成 N 条则一行数据都不动，代价是"下周要再说一次"，而这一条**在回话里如实写明**，不假装会自动重复。

### 2.4 边界是刻意划窄的（这几条比"能认三次"更重要）

- **「一天吃三次药」不认**：按天铺开等于替他造 3 条他没说要的东西。只认「周/星期/礼拜 + 次数」这一族。
- **「周四下午第一次上课」不认**：那是节次。`(?<!第)` 挡它。
- **「这周还有两次课」不认**：那是课，不是待办。`(?!课)` 挡它。
- **上限 7**：一周七次已是每天一回，8 次以上判是听错了，宁可不认。
- **「周四一周三次」不预选**：两句本身打架（三段全挤周四 = 一天三练），退回只排那天的老路子。
- **排不满 N 段不谎报**：hint 改口成"这几天只排得出 K 段"，不写"按一周 N 次挑好了"。

### 2.5 踩到的一次自我纠错：正则不能整块擦

第一版把「一周要去三次」整块擦掉，标题变成「我健身房」；而「一星期跑两回」整块擦完
**一个字不剩** → `_pick_title` 返回"待办" → 候选卡直接出不来 → 学生被反问"要安排的是什么事"。
改成两条各擦一半（`_COUNT_UNIT_RE` 只擦数量、`_WEEK_SCOPE_RE` 只擦范围词，**中间的动词留着**），
再补一道兜底：擦完判不过就**退回不擦频次**（名字丑也比没卡强）。

**这一轮抓到 4 个"验证本身的坑"，比功能改动更值得记：**

1. **两条假绿**（都是老毛病：断言搜索范围 > 它声称的范围）
   - E 批原判据 `'checked' in src` —— 页面里 `cb.checked` 也有这个词，**永远绿**；改成钉死模板串 `${i < pre ? " checked" : ""}`。
   - D 批原判据 `"下周" in answer` —— 把"只管这一周"那半句改掉后「下周」还在别处，**永远绿**；改成钉"没有自动重复"。
2. **一次变异自身无效**：N8 第一版只替换了 `⚠️ 这只管**这一周**` 这半行，后半行
   `（现版本没有自动重复这回事）` 还留着 → 实话还在，测了个寂寞。改成删整句。
3. **一次判据口径错**：N10 让测试进程直接崩掉，一条 `❌` 都没打印出来，脚本只数 `❌`
   就把它误判成"没红"。判"红"的正确口径是**这个测试文件整体没过**（退出码非 0 或 ❌>0）。
4. **一次变异脚本用错解释器**：脚本本身用系统 `python` 启动，`sys.executable` 跟着指到系统解释器，
   测试 `import fastapi` 直接失败 → 全程 0 红。变异脚本必须用 `.venv/Scripts/python.exe` 跑。
