## 二、落地：一条判据、两种范围、口径绑在调用方

```python
# app/store.py —— 判据只在这一处
DEMO_OWNER = "demo"
def owner_of_row(row): return str(row.get("owner") or DEMO_OWNER)      # 老记录不迁移文件
def current_owner():   return current_student() or DEMO_OWNER           # 身份来源只有 #32 那一份
def visible_rows(rows, *, staff=False):
    out = list(rows or [])
    if staff:            # 店员口径：放行的是**包裹**，不是"这个人的所有数据"
        return out
    who = current_owner()
    return [r for r in out if owner_of_row(r) == who]
```
九个读入口全走它（快递 `list_my_packages` / `list_pending_pickup` / `get_by_code` / `packages_view`，
外卖 `list_my_orders` / `list_active_orders` / `get_order` / `orders_view`），
`get_by_code(pickup_code, *, staff=False)` 的店员口径由 `station.py` 一处绑：

```python
_lookup_for_staff = partial(get_by_code, staff=True)     # "这是店员"写在工具箱装配那一行
```
⚠️ 刻意**不在 `express.py` 里判 `module_key`**：数据层不该知道谁在调它，认端是 #34 那道闸门的事。

## 三、最值钱的一条：路径在导入时拼死 ⇒ 测试一直在自证过头

`express.py` / `takeout.py` 原先写着 `_DATA_PATH = os.path.join(os.path.dirname(__file__), "..", "data", ...)` ——
**Python 导入即求值**，于是沙箱把 `CAMPUSTIME_DATA_DIR` 换掉之后它们照旧读真实台账（与红线 23 同根，第二次撞）。

证据不是推理出来的：变异 **M7 把那一行退回去，`test_62` 红 9 条**，其中 A1 的回包变成"实际 0 件 []"——
那才第一次看清：**以前凡是"读台账"的断言，量的从来不是沙箱里种的那份，而是用户桌面上那份底稿。**
配套补了 `_harness.write_express / write_takeout`（带 `_require_sandbox` 守卫，整份覆盖写，
漏在沙箱外调用会直接拒绝——那两个是 tracked 文件，写坏了就是一次真实数据事故）。

同族的口径也一并钉住：老记录缺 `owner` 按 `demo` 走、**不批量迁移文件**（与 `status` / `archived` 同一做法）；
身份只有一处来源（cookie 中间件），工具层要过滤就读 `store.current_owner()`。
