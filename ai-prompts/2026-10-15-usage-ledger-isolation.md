## 三、改了什么

`app/store.py`
- `_usage_path()`：`CAMPUSTIME_USAGE_FILE` 有值就直取（绝对路径），否则照旧跟数据目录走；
- `log_llm_usage` 的建目录改成建**账本所在目录**（原来用 import 时缓存的 `DATA_DIR`）。

`tests/_harness.py`
- **import 时**就把该 env 指到进程级临时账本（`campustime-usage-*` 目录，atexit 清掉）——
  这一层才治到"沙箱外的批"；
- `sandbox.__enter__` 再把它指到沙箱自己那份（读账本的测试语义零变化），
  `_clean` 里**恢复前值而不是 pop**：pop 会让沙箱外的下一笔又掉回真实文件。

没动：`intent.py` / `router.py` / `polish.py` / 任何 prompt、判定、路由、润色逻辑（施工单 §3.1）。
**生产不设这个 env**，所以生产记账照旧落进 `app/data/` 下那份 —— 管理端那张表读的就是它。
把生产"顺手一起隔离"是更严重的错误（静默失明），所以 B 批专门钉这条回落。

## 四、护栏与变异（`tests/test_50_usage_ledger_isolation.py`，14 项）

| 批 | 钉什么 |
| --- | --- |
| A 病根 | 有进程级覆盖且不指向 `app/data`；**沙箱外记一笔 → 真实行数不变**；那笔确实落在临时账本（同时要求"读到的不是真实那份"）；沙箱内 clear 后读到 0 笔、记一笔读得到且落在沙箱目录；**沙箱退出后再记一笔，真实账本照样不动**；env 指哪儿打哪儿 |
| B 生产回落 | 起一个**干净子进程**：数据目录指临时、清掉 usage env → 记账必须落在数据目录那份、路径逐字对上（不碰真实文件，也不与在跑的 8000 抢同一个文件） |
| C 形状 | 真正 open 账本的只有 log/read/clear 三处且都走 `_usage_path()`；除 `USAGE_FILE` 定义行外不许写死文件名；建目录用账本所在目录；`_harness` 装了进程级默认 |

变异五处全部能分辨：

```
V1 撤掉进程级默认        → 红 3（前提没有 / 真实账本被写 / 那笔落在真实那份）
V2 _usage_path 无视 env  → 红 3
V3 没 env 也不回落数据目录 → 红 2（B 批整批挂 = 生产管理端会静默失明）
V4 沙箱退出 pop 不恢复    → 红 1（退出后再记一笔，真实账本 +1）
V5 建目录建在缓存 DATA_DIR → 红 1
```

**两条断言是写完当场发现没牙、重写的**（又是"红 0 有多种原因"）：
- A 批"那笔落在临时账本"原来只数"读到了"—— 修之前它在真实账本里同样读得到，属于假绿；
- "沙箱退出后 env 恢复"原来写成比较**我自己刚赋的值**（那是在测测试代码），V4 当场全绿；
  改成"退出后**再记一笔**看真实账本动不动"才有牙。
