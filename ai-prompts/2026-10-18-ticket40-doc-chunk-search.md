## 二、三刀怎么落的

**40-A 分块 + store**（`4ca340b`）
- `chunk_text` 放 `app/upload.py`（跟 `extract_text` 同一层）。三档边界**从后往前扫**取最靠后的那个：
  空行段落 → 句末标点 → 逗号停顿 → 硬切。从后往前是故意的：不然段落一密就碎成几十字一块，
  每块上下文太少，检索命中率反而掉。块是原文的**逐字切片**（不 trim、不压缩空白），带 `start` 偏移。
- store 五个口：`save_chunks` / `list_chunks` / `all_chunks` / `reindex_upload` / `delete_upload`。
  上传时**当场建索引**（不让管理员传完还得去后台点一下）。
- `list_chunks` 对"没建过"和"索引文件坏了"都回空表 —— 坏文件回空表的处境是"这份查不到"，
  管理员看见的状态是"未建"，点一下【重建索引】就好了；抛异常会把整站检索一起拖死。

**40-B search_docs + 修截断**（`196dea9`）
- BM25 + 字符二元组，不引 jieba、不引 numpy（本作品对评委的口径是零额外依赖跑得起来）。
  命中回「《文件名》第 N 块（原文第 X 字起，相关度 …）」—— 出处可核对，模型拿不到全文也编不出来。
- 那个真 bug 的正身：`read_uploaded_file` 超长**不再返回前 6000 字**，只回一句"改用 search_docs" + 文件 id。
  给前半本比明说读不下更糟 —— 模型会拿开头当全文来答。
- `FILE_HINT` 同步（那是所有模块共用的一段提示，改一处全生效；只改工具不改提示就是"只改一半"）。

**40-C 管理端 API + UI**（`4988f48`）
- 三条 `/api/admin/docs*` 全挂 `verify_admin`；删除前先扫通知。
- UI 那一档：侧栏一项 + 表格（文件/字数/块数/索引/时间/【重建索引】【删除】），上传**复用 `/api/upload`**，
  确认走本页那一份 `askConfirm`。

## 三、四处偏离，每条都有证据

1. **块数不写进 `uploads.json`**（单上 §2.2 让在 `item` 里多记一个 `chunks`，**主动没照抄**）。
   证据：写了就是两个地方各说一份块数 —— 【重建索引】之后台账里那份旧数字立刻说谎，
   而"索引状态"这一列的唯一用途就是告诉管理员哪份还得点一下。改成列表页现读 `<fid>.chunks.json`，
   单一来源。护栏 D15 钉的就是谎报本身：把索引文件抽走，列表必须如实回「未建 / 0 块」。
2. **`reindex` 一份不存在的文档回 400，不是 404**（单上没写状态码）。
   证据：管理端 `adminFetch` 把非 2xx 统一翻成异常，而 404 额外带一句
   「接口不存在 —— 多半是服务还在跑旧代码，重启一次再试」。这里接口是存在的，缺的是那份文件，
   拿 404 会把人指去完全错误的方向。同一条理由 #39-D 的撤回通知已经用过（`{"error": "通知不存在…"}` 配 400）。
3. **通知那道闸在 store 和接口各放了一遍**（单上只要求接口层查）。
   证据是两笔变异分开跑出来的：拆掉 store 那道（M4a）⇒ `test_66` B13/B14/B16 红；
   拆掉接口那道（M4b）⇒ 删除**仍然被 store 拦住**，但回给管理员的话变成"文档不存在"（D6/D7 红）。
   也就是说两层各管一件事：store 那道管"数据不许被抽走"，接口那道管"人要知道为什么"。少任一层都是一半。
4. **`all_chunks()` 每次现扫，没做内存缓存**（单上说"嫌慢可缓存"）。
   demo 规模（33 份、几百块）现扫是读几个小 JSON；加了缓存就得管失效，而失效判据（mtime？）又是一份新状态。
   留的是"换函数体不动接口"那个口子。

一条照实说的现状（不是本单改的）：`main.py` 那段 `tools.update(files_tools())` 是**无条件**的，
所以 `search_docs` 驿站端也拿得到。这不扩大暴露面 —— `read_uploaded_file` 本来就能读到全部上传文件，
上传池在演示设定里就是共享的（#32 只把学生个人库按学号分开）。但这句话得写在这儿，
别让以后的人以为 #40 顺手做过端级隔离。

### 这一轮差点出事的那一下（值得单列）

第一次起 8010 是在 bash 里内联
`powershell -Command "$env:CAMPUSTIME_DATA_DIR='…'; $env:CAMPUSTIME_ADMIN_TOKEN='probe-…'; Start-Process …"`，
`$env:` 被 **bash 先当成自己的变量展开成空串**，PowerShell 收到的是一串空赋值 ⇒
服务**悄悄用了真实演示目录**，口令也退回 `.env` 里那把真口令。
表现是 `/api/admin/docs` 一律 401（探针口令没配上），我因此什么都没写进去。
救回来的是两道旧规矩：管理口的 401 + 收尾那次整树 md5 复核（新增 0、改动 0）。
从此加了两条硬动作：① 起服务的环境变量一律写进 `.ps1`，不在 bash 里内联；
② **每轮真机第一件事是传一个金丝雀** —— 验它落在副本、没落在真实数据，不对就停（`check40_live.py` §0）。
顺带一条小坑：`httpx` 走系统代理会把本机请求变成 502，探针客户端一律 `trust_env=False`。
