# AI 对话快照 · 2026-09-26（续）· 改期真实踩坑：样本碰撞 + 旧日误判

> 关联前一篇：`2026-09-26-retime-crud-selfcheck.md`（已接通 INTENT_RETIME 执行分支）。
> 本篇是那一篇的**收尾**：真机验证时「把周四那个瑜伽挪到周五」没走确定性分支，
> 而是掉进大模型 ReAct 兜底，吐出"改时间要分两步，两张确认条都挂出来了"这种自由发挥。

## 用户原话 / 背景

- 上一轮已接通「已排待办改期」（`build_retime_existing_proposal` + 3d-ret 分支 + 确认/接口转发 `old_todo_id`）。
- 本轮回看真机日志时发现**：**`app/data/student/sessions.json` 里躺着一句
  `把周四那个瑜伽挪到周五` → 模型回 `改时间要分两步，两张确认条都挂出来了…`。
  这句话根本没出确认卡，而是被语义/样本层判完之后一路漏到大模型兜底，由模型自由发挥。
- 用户主线诉求不变：「同类的增删查改功能你去自行测试一遍」——要保证真机跑通。

## AI 研判（逐步定位根因）

用 `tests/_dbg_live.py` 离线逐层打点，对 `把周四那个瑜伽挪到周五` 得到：

1. `wants_retime_todo` = **True**（含"挪到"），规则层认得换时间词。
2. `_rule_intent` = **None** → 触发 `understand()`。
3. `understand()` 里 `match_sample()` **先于** `classify_with_llm()` 命中种子
   `"把周四那个健身挪到周五"`（Dice≈0.7 > 0.42），把意图判成 `retime_todo`、
   **title 覆盖成"健身"**。→ `_sem_intent = retime_todo`，title=健身。
4. 3d-ret 分支确实被命中，但 `build_retime_existing_proposal(msg, sem=健身)`：
   - 用"健身"去库里找 → 库里只有"瑜伽" → **零命中 → 返回 `empty`**。
   - 旧代码此处直接回「没找到那条待办」，属于**误判**（其实就在库里，只是名字被样本盖错）。

> 真机那次吐"分两步"是因为当时跑的 server 还没有 3d-ret 分支（端口被旧进程占着），
> 漏到大模型兜底。但**当前代码**的真实缺陷是上一条：样本碰撞把"瑜伽"误记成"健身"，
> 导致改期提案按错名字找库落空。两处都得堵。

第二个隐藏坑（同一句话）：即便名字对上，`_pick_date("把周四那个瑜伽挪到周五")`
会抠到**第一个**日期"周四"（旧日），把目标误判成周四=原地没动。学生说"挪到周五"，
目标日应该是"周五"（换词之后的那个）。

## 代码改动

### 1. `app/modules/planner.py` · `build_retime_existing_proposal`
- **名字回退**：语义/样本给的名字在库里零命中时，退回从**学生原句**抠名字再试一次
  （`_pick_todo_name(t_clean)`）。"瑜伽"就这么对上了，不再被"健身"带偏。
- **目标日修正**：新日期优先取**换时间词（挪到/改到…）之后**的日期片段，
  避开前面的旧日"周四"干扰。→ `把周四那个瑜伽挪到周五` 正确落到周五。

### 2. `app/main.py` · 3d-ret 的 `ok` 分支
- 提案纠正过名字后，把纠正后的真名字（`瑜伽`）写回 `_sem["title"]` 再 `_sem_done`，
  **避免 `remember()` 把错的"健身"学进样本库、越错越深**。

### 3. `tests/test_09_crud_selfcheck.py`
- 加 **RT-S4 回归**：用真机那句 `把周四那个瑜伽挪到周五`（LLM 桩回 chat，逼出
  "样本碰撞 → 退回原句抠名"真实路径），断言：出改期卡、新日是周五（非误判健身）、
  带 `old_todo_id`、确认后旧(周四)移除+新(周五)落库。
- `_run()` 开头 `_swrite("todos.json", {"todos": []})`：自测从干净日程起步，
  防止演示数据被手测/真机跑过的会话污染（本次就发现 live 真机往真实
  `todos.json` 写过一条 瑜伽，导致沙箱里同名出现两条→误判 many）。

### 4. 清理真机污染
- 删掉 `app/data/student/todos.json` 里 live 真机写入的 `瑜伽`（id `059b0959`，
  created `2026-09-26 12:53:54`，时间戳与 live 脚本吻合）。该文件在 `.gitignore`
  内，不入库，仅修本地演示态。
