# 2026-09-26 口语下单识别 + 「平时」按工作日排 + 找卡分支

> 本文件是「AI 创新应用挑战赛」要求的 **AI 对话历史 Prompt 快照**之一。
> 记录一次真实开发会话：用户报障 → AI 研判根因 → 改代码 → 加测试护栏 → 验证。

---

## 一、用户 Prompt（原话摘录）

> 「我说我要平时去吃火锅，76 分钟，第一次给我的卡是只有一个时间周 6 的，
>   我说平时，后面就不弹卡了」

配一张截图。三处症状，一句话里全占了：

1. **口语下单没被认出来** ——「我要去吃火锅」里一个「加 / 安排」的字样都没有，
   整句掉给了大模型；
2. **「平时」被错排成单独某一天** —— 而且只出了**一条**卡（周六），
   跟上一轮定下的「摊多个候选」规格不符；
3. **后面就不弹卡了** —— 追问「卡片呢」时，模型在文字里说「卡片挂出来了」，
   界面上一张卡都没有。

---

## 二、AI 研判（三处症状，三个不同的根因）

### 症状 1：口语下单没识别

`/api/chat` 里「加待办」这条确定性链路的入口是 `wants_add_todo()`，
它认两类说法：

- 词表 `_ADD_INTENT`（安排 / 排一下 / 加入 / 加进 / 添加 / 记一下 / 预约 …）；
- 正则 `_ADD_TALK_RE`（「加个健身」「记一笔」这种动词 + 量词连写）。

「**我要去吃火锅**」两条都不沾 —— 它连「加」字都省了，是**第一人称下单**。
于是整句掉给大模型，模型自由发挥：把「平时」理解成某一天、只给一个点。

### 症状 2：「平时 / 工作日」没有对应的排期模式

`candidate_slots()` 只认「周几 / 几号 / 今天明天」，
`_day_slots()` 也只按**单个日期**取空档。所以：

- 「平时」没被解析 → 退化成 `_pick_date()` 的兜底 → 挑出**一个**周六；
- 又只取 1 段 → 违约了上一轮（2026-09-25）定下的「摊多个候选让学生勾」。

### 症状 3：找卡的话被路由分走

「卡片呢」里的「**卡**」字命中 router 里失物招领的关键词
（`_QUICK_MAP` 有 `"丢"`、`"捡"`、`"失物"` → `lostfound`），
整句被分给失物招领模块，模型顺着「校园卡」联想答了一通，
还嘴上说「卡片挂出来了」——界面上一张卡都没有。

## 三、改动（三个文件，逐条对应上面的根因）

### 1. `app/modules/planner.py` —— 认第一人称口语下单

```python
# 「我要去吃火锅」「我想去游泳」——口语里连"加/安排"都省掉的第一人称下单。
_GO_INTENT_RE = re.compile(r"我(想|要|打算)(去)?")
```

`wants_add_todo()` 里新增一道放行：

```python
if any(w in t for w in _ADD_INTENT) or _ADD_TALK_RE.search(t):
    return True
_name = _pick_title(t)
if (_GO_INTENT_RE.search(t)
        and not any(k in t for k in ("吗", "？", "?"))
        and _name and _name != "待办"):
    return True
```

**为什么不能只认「我要」两个字**：「我想问一下」「我要查课表」也是「我要」开头，
但那是**问答**不是下单。所以加了三重闸门：

- 带疑问词（吗 / ？）不放行；
- **事名必须判真**（`_pick_title` 抠得出像样的事，且不是「待办」占位）——
  这一条是守着学生更早那条红线：「**要识别啥才是真的事情，不是随便拿那一句话
  就去当代办加入日程了**」。

### 2. `app/modules/planner.py` —— 「平时 / 工作日」排期模式

`candidate_slots()` 与 `plan_todo_slot()` 同步加入工作日模式：

```python
workday_mode = any(w in t for w in ("平时", "工作日"))
...
for off in range(0, days_ahead + 1):
    day = (today + datetime.timedelta(days=off)).isoformat()
    if workday_mode and _iso_weekday(day) >= 6:
        continue          # 「平时 / 工作日」不排周末
    for s in _day_slots(day, prefer, limit=1, rotate=off, length=want):
        _push(s)
```

`length=want` 沿用上一轮（2026-09-26 的另一份快照）加的时长参数，
所以「76 分钟」排出来的每一段都是 76 分钟，不是默认的 90。

### 3. `app/main.py` —— 「找卡」分支

在确定性分支里新增一支：话很短（≤12 字）且在找卡/找弹窗 →
**原样重挂**暂存里那张提案（不重新生成、更不写库）；暂存是空的 →
如实说「没有挂着的卡」，绝不让模型凭空编一张。

```python
_FIND_CARD_WORDS = ("卡片", "弹卡", "卡呢", "没卡", "弹窗", "弹框", "确认条")
```

> ⚠️ 顺手排掉一个**自伤**：「**没有收到弹窗**」里也有「弹窗」两个字，
> 可它不是在找上一张卡，而是**投诉那张卡压根没生成** ——
> 那一幕的正解是第十一批的「补条兜底」（从模型那段自相矛盾的话里把
> 16:00-17:30 捞出来重挂一张）。被这里截走的话，学生只收到一句
> 「手上没有挂着的卡」，那一幕就白修了。所以加了排除词表
> `_CARD_NEVER_ARRIVED`（没有收到 / 收不到 / 没弹出来 / 看不见 …）。

### 4. `app/main.py` —— 确定性那一路也带上性格腔调

改完上面三条后发现：性格原本只拼进**模型**的系统提示，
而「加个健身」「我要去吃火锅」这类最常见的说法现在走的是**确定性分支**，
那一路上一个字都不带性格 —— 学生明明选了「暖心朋友」，
每次加待办都听回同一句官方腔。补一个 `_slots_lead(persona_key)`，
出候选卡时去 `student_persona` 取一句同场景话术当开场，没选性格就退回默认引导语。

### 5. `app/modules/planner.py` —— 「平时」不该印在待办名上

实机回归时发现卡片标题是「**平时去**吃火锅」——「平时」是**排期条件**（哪天方便），
不是要做的事，跟「周末」是一类。归进 `_strip_title_noise` 的时间词一起擦掉，
标题回到「吃火锅」。

## 五、验证

**全量测试**：`python tests/run_all.py` → 全绿（详见对应 commit）。

**实机回归**（起后台 `uvicorn app.main:app --port 8000`，curl 打 `/api/chat`）：

| 输入 | 改之前 | 改之后 |
|---|---|---|
| 我要平时去吃火锅，76 分钟 | 掉给模型 → 只出一条周六的卡，标题「平时去吃火锅」 | 出 `todo_slots`，4 段**工作日**空档，每段 76 分钟，标题「吃火锅」 |
| 卡片呢 | 被分去失物招领，模型嘴上说「挂出来了」，界面上没卡 | 原样重挂暂存里那张卡 |
| 没有收到弹窗 | （同上，补条兜底生效） | 仍走补条兜底，重挂 16:00-17:30 |

实测输出（4 段 × 76 分钟，全部避开周末与已有安排）：

```
周一（9/28）19:00-20:16
周二（9/29）14:00-15:16
周三（9/30）09:40-10:56
周四（10/1）19:00-20:16
```
