# 2026-10-06 课表导入·出卡环节诊断留痕

## 用户 Prompt
「你在出卡环节加几句测试的话，这样即使没出卡也能知道那部分出问题」

（背景：前几轮已修好「上传课表→确认修改卡不来 / 假待办卡 / 一门门念课」三连，
现在用户要的是——万一以后又不出卡，能**从界面上直接看出卡在哪一档**，而不是再靠翻代码。）

## AI 研判
- `trace` 字段**本来就在学生端展示**：`student.html` 把它渲染成可折叠的「🧠 我是这么想的」面板，设置里默认**开**（关掉才隐藏）。所以把诊断写进 `trace` 是直接可见的，不必新开任何 UI。
- 之前出卡环节只在两档各留了一条 trace（出卡 / 没出卡），粒度太粗：探测漏了？还是回话抠不出课？还是文件原文也没抠到？学生分不出来。需要在出卡环节**逐档留痕**。
- 关键事实：出卡兜底在 `app/main.py` 的 `_chat_impl` 里、由 `looks_like_timetable_import(message)` 触发，跟语义意图/路由无关——所以诊断写在出卡环节内最准，能覆盖"被判成问事也照样出卡"的情况。
- 一个副作用发现（顺手告知用户，未在本次修）：像「看看我的课表」「帮我弄下我的课表」「我想看下我的课表」这类说法，会被**样本库**误判成「看待办列表」提前返回（界面显示"列出待办"），根本到不了出卡环节——那属于**路由层**问题，不在出卡环节内，所以不会显示课表诊断；但"列出待办"这个结果本身已经提示误路由了。

## 具体改动
**`app/main.py`（`_chat_impl` 出卡段）**：
1. 进出卡环节先算 `tt_detected = looks_like_timetable_import(message)`，把**探测结果**必留痕：
   - 命中 → `🔍 课表导入探测：命中（识别成「读课表文件导入」）`，并带「模型自带 options 数」；
   - 提到「课表」却逃过正则 → `🔍 课表导入探测：未命中（提到课表但说法逃过正则）`，并提示用「上传课表」模板按钮（文案含 `read_uploaded_file`，必命中）。
2. 命中后**逐档**：「从模型回话抠课 → 抠出 N 门」「从文件原文抠课 → 抠出 M 门 / 未找到文件或非文本格式」「最终采用哪份共 K 门 → 出卡 / 没出卡及原因」。
3. 模型**自己调了** `propose_timetable_change` → 标「✅ 引擎已出卡，只统一回话」。
4. 所有诊断先攒进局部 `_tt_diag`，最后统一 `final_trace = final_trace + _tt_diag` 拼回 trace（这样待办兜底分支重置 `final_trace` 也不会丢诊断）。

**`tests/test_23_timetable_import_rescue.py`**：新增**第 6 批「出卡环节诊断」**，三种结果各断言 trace 含对应诊断句（命中出卡 / 命中但抠不出课如实没出卡 / 逃过正则标未命中），并把本批放在 `sandbox()` 假配置假引擎下跑（沿用本文件既有 harness）。

**`tests/README.md`**：test_23 条目由「57 项 / 7 批」更新为「66 项 / 8 批」，并补第 6 批说明。
