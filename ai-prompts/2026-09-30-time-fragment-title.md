# 2026-09-30 · 时间碎片被当成待办名（"明天中午12" → "12" 确认卡）

## 学生报障（原话 + 截图）
> `@image#1:Clipboard_Screenshot.png 说话说一半1发过去了，直接就加了，先理解人话`

截图内容：学生在 planner 栏说了一句 **"明天中午12"**（话没说完 / 只发了一个时间碎片），
系统直接回了一张 **待办确认卡**：标题「12」、日期 2026-10-01（周四）12:00-13:00。
学生诉求：先理解人话，别把数字/时间碎片直接当待办名挂出去。

## 研判（用户 Prompt → AI 研判）
- 这句话**只包含时间信息**（明天、中午、12），没有说「要做什么事」。
- 旧逻辑里 `_pick_title` 擦完"明天/中午"后剩下「12」，而 `looks_like_thing("12")` 返回 True：
  长度 2 在允许区间、有字符、不含 `_TITLE_NOISE` 里的噪声词。于是「12」被当成真事名。
- 更深层：`parse_add_todo` 和 `span_only_proposal` 在生成确认卡时**没有再过 `_title_ok`**，
  所以即便语义层把"12"当 title 传下来，也会直接出卡。
- 一句话：**标题守卫只认了"有字符、不是类别词"，但没认"时间碎片不是一件事"**。

## 改动（`app/modules/planner.py`，3 处）
1. `looks_like_thing` 新增守卫：标题整串只剩数字/中文数字/钟点词
   （"12" / "十二" / "12点" / "十点半" / "一刻" / "整点" / "3分"）→ 不是一件事。
   这保证 `_pick_title` 判不过，返回 "待办"，触发追问分支。
2. `parse_add_todo` 生成提案前加 `if not _title_ok(title): return None`。
3. `span_only_proposal` 确定最终 name 后加 `if not _title_ok(name): return None`，
   防止语义层把"12"这种时间碎片当 title 传下来时 still 出卡。

> 取向：宁可当"没说清"去追问"要安排的是什么事"，也不把钟点碎片写进日程。

## 验证（钉死，见 `tests/test_19_time_fragment_title.py`，共 31 项）
- **单元**：`looks_like_thing` 对 8 种时间/数字碎片返回 False；真实事名（游泳/作业12/三体/双十一）仍通过。
- **单元**：`_pick_title` 对 "明天中午12" / "明天十二点" / "12点帮我安排一下" / "后天12" / "大概一个小时" 返回 "待办"；
  对真实事名返回正确标题。
- **端到端①（复现报障）**：`POST /api/chat {"message":"明天中午12","module":"planner"}`，
  响应 `options=[]`、`awaiting_choice=False`、回答进入追问「好——要安排的是什么事？」。
- **端到端②（不误伤）**：`POST /api/chat {"message":"帮我加个游泳周四19:00","module":"planner"}`，
  仍正常出 `todo_add` 卡（标题「游泳」、19:00-20:00）。

### 反向验证（证明不是假绿）
临时把 `looks_like_thing` 打成"只卡长度"（模拟修复前）复跑端到端①：
复现出 `{"kind":"todo_add","title":"12","date":"2026-10-01","start":"12:00","end":"13:00"}` 的卡——
**与报障截图完全一致**（标题/日期/时段都吻合）。证明守卫确实拦住了破口。
