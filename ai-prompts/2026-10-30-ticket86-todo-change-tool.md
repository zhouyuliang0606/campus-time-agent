## 〇 一句话

引擎手上原本没有"改待办时间"这只工具，所以 #84 之后那四句「查出冲突并指名」只能以反问收场。
本单加了 `propose_todo_change(op=retime)`，并给它一个 **`auto_slot`**：学生只说「撞了/换一个时间」时
**系统替他挑一段排得下的**，不再问「你想改到几点」。
`auto_slot` 默认 `False` ⇒ 确定性分支（`main.py:3729`）**逐字不变**，这是本单的命门（A 批 + V6 钉着）。

## 五 真机（副本 8053 + 副本数据 `data86tool`，真实 `app/data` 只读）

夹具六条，其中**「游泳」就种在真课那一节上**（2026-10-30 周五 08:00-09:40 = 线性代数），
E1 那句「游泳撞时间了」说的撞、库里真撞 —— 否则量的不是"替他挑时间"。

| 句 | 走哪条 | 实测 |
|---|---|---|
| E1「游泳撞时间了，帮我换一个时间」 | **确定性分支** | 追问「想改到哪天、或者几点」（#81/#82 的行为），**没出卡** |
| 同一句 + Agent 模式 | **引擎** | 🔧 `propose_todo_change` ⇒ 出卡 `retimed/old_todo_id=t86t01`，挑的是当天 15:40-17:10（不撞课、不是过去） |
| E2「把游泳改到周三 18:00」 | 确定性分支 | 卡上就是 2026-11-04 18:00-19:00 |
| E3 正控「帮我加个游泳」 | 确定性分支 | `todo_slots` 候选卡，**不带** retimed/old_todo_id ⇒ 没被 change 抢走 |
| E4 正控「把游泳挪到周三」 | 确定性分支 | 原时段平移 + 换日 ⇒ 挑空档，行为与改前一致 |
| 点【确认加入】 | `/api/todos` | 旧 id 被删、新行落库；**备注实测丢**（见 §七） |

**单据 §3.2 的 E1 没分清"哪条路"**：普通模式下这一句仍然追问 —— 而 §2.2 明确说那是**对的**
（确定性分支该追问，引擎该替他挑）。要出卡必须走引擎：勾上 Agent 模式，或那句本身被规则层判成办不成（#84 那扇门）。
这一条不是缺陷，是**验收口径要写清"哪一路"**。
