## 〇、先把"切块"这件事说清（用户的困惑有一半在这儿）

管理端有**两个**长得像、其实完全不同的面板，学生端检索时**同时查这两路**：

| | 「📚 知识库」（`view-kb`） | 「📄 文档知识库」（`view-docs`） |
|---|---|---|
| 存哪 | `data/kb.json`（一问一答条目） | `data/uploads/<fid>.txt` + `<fid>.chunks.json` |
| 切块吗 | **不切**。整条按关键词比对 | **要切**。600 字一块、80 字重叠 |
| 什么时候切 | 不需要 | 上传时自动切；老文件点【重建索引】补 |
| 改完何时生效 | **立刻**（`faq._load()` 每次现读，无缓存） | 重传/重建索引后 |
| 检索入口 | `faq._kb_parts()` 前半段 | `faq._kb_parts()` 后半段 → `files.doc_hits()` |

`faq.py:91-122` 的 `_kb_parts()` 一次把两路都查了（#40 补2 的成果），所以**学生不需要知道有两路**。

⇒ 「我添加进去，还要手动切块」这个动作**在问答条目上根本不存在**。
如果确实觉得"加了却查不到"，往下看 §一，那才是真病根。

## 一、46-A（主因）：`search_kb` 只比对 keywords，**从不看 question**

### 现状

```python
# app/modules/faq.py:105-109
for item in data["entries"]:
    keywords = [k.lower() for k in item.get("keywords", [])]
    if any(kw and kw in q for kw in keywords):
        hits.append(item)
```

问句里出现**关键词**才算命中 —— `question` 字段一个字符都不参与匹配。

而关键词这栏是**可以留空**的：

```html
<!-- app/static/admin.html:351-352 -->
<label>关键词（逗号分隔，用于检索）</label>
<input id="kk" placeholder="如：游泳馆, 预约, 场馆" />
```

```js
// app/static/admin.html:708-712 —— 只校验问题/答案
if (!q || !a) { alert("问题和答案不能为空"); return; }
```

```python
# app/store.py:407 —— 存进去就是空数组
item = {"question": question, "answer": answer, "keywords": keywords or []}
```

⇒ **关键词留空 = 这条永远不可达**，学生问的问题跟 `question` 一字不差也查不到；
而面板还回一句「✅ 已存，下面列表已刷新」。这是"加了却读不到、连原句也识别不到"最直接的解释。

（第二半：关键词写了但没写全。「图书馆开放时间」这条只写 `图书馆,开放,时间`，
学生问「图书馆几点关门」→ 三个词都不出现在问句里 → 不命中。这属于同一病根。）

### 修法：一个函数，两处用

在 `app/store.py` 里加（放 store，不让 `faq` 反向被 import）。
**下面这版是在本机逐条跑过、输出贴在第 3 小节里的**，不是设计稿：

```python
# app/store.py 顶部要补 import re（现在没有）

# 检索时不该当关键词的虚词/疑问词（只列真正会出现在校园问句里的那些，别抄一整本停用词表）
_KB_STOP = ("什么", "怎么", "怎样", "多少", "几点", "哪里", "在哪", "哪个", "哪些",
            "如何", "可以", "能不能", "是否", "请问", "一下", "的话",
            "的", "了", "吗", "呢", "啊", "呀", "吧", "我", "你", "要")

# 两字的通用动宾/泛词：它们几乎能粘上任何问句（「食堂几点开门」也被「开门」粘上），
# 自动派生时丢掉；**管理员手写的关键词不受这张表影响**（那是他的判断，不该被代码覆盖）。
_KB_GENERIC = {"开门", "关门", "时间", "电话", "地点", "位置", "预约", "收费", "费用",
               "价格", "流程", "条件", "要求", "办理", "申请", "发车", "断电", "熄灯",
               "网址", "密码", "东西"}

_STOP_RE = "|".join(map(re.escape, sorted(_KB_STOP, key=len, reverse=True)))
_EDGE_RE = re.compile(r"^[在里与和或及等]+|[在里与和或及等]+$")


def derive_kb_keywords(question: str, limit: int = 12) -> list[str]:
    """从问题原文里抽检索关键词（人话：没填关键词的条目，也能用学生说的原句查到）。

    **不引分词库**（与 `files._tokenize` 同一取舍：零额外依赖也能跑起来）。
    做法三步：按虚词劈成词片 → 每个词片再补 3 字、2 字滑窗片段 → 去重去泛词、长的在前。
    为什么要滑窗：「考试周图书馆开到几点」劈出来是整片，学生却只会说「考试周图书馆几点关」
    —— 补了 3 字片段才含「图书馆」这种真正的实体词。
    """
    q = re.sub(r"[^\w\u4e00-\u9fff]+", " ", str(question or "")).strip()
    out: list[str] = []
    for w in (x for x in re.split(r"\s+", q) if x):
        if w in _KB_STOP:
            continue
        parts = [_EDGE_RE.sub("", p) for p in re.split(_STOP_RE, w)]
        parts = [p for p in parts if len(p) >= 2]
        for p in (parts or ([w] if len(w) >= 2 else [])):
            out.append(p)
            if len(p) >= 3:
                out.extend(p[i:i + 3] for i in range(len(p) - 2))
                out.extend(p[i:i + 2] for i in range(len(p) - 1))
    seen, uniq = set(), []
    for w in sorted(out, key=len, reverse=True):
        if w and w not in seen and w not in _KB_STOP and w not in _KB_GENERIC:
            seen.add(w)
            uniq.append(w)
    return uniq[:limit]
```

**实测输出（本机跑出来的原样，写测试时直接拿这个当断言）**

| 问题原文 | 派生关键词 |
|---|---|

| 宿舍晚上几点断电？ | `宿舍晚上, 宿舍晚, 舍晚上, 宿舍, 舍晚, 晚上` |
| 校车在哪里坐、几点发车？ | `校车` |
| 游泳馆怎么预约 | `游泳馆, 游泳, 泳馆` |

**命中实测（`any(kw in 学生问句)`，与学生端现有判据同一条，不引入第二套）**

> ⚠️ 最后一行是**已知边界，不是待修的 bug**：纯词法做不到"懂意思"，`游泳` 两字确实在两种问法里都出现。
> 压住它只有两条路：上向量检索（冻结后再说），或让管理员把这个条目的关键词写准（`_KB_GENERIC` 只管自动派生）。
> **写进"已知缺口"，别在演示前为了它加规则** —— 加了就会误伤别处。

> ⚠️ `app/store.py` 现在**没有 `import re`**（顶部只有 contextvars/datetime/json/os/uuid）。

> 加这行时顺手确认没有同名变量遮蔽 —— 这是那种"本地跑得过、克隆里 NameError"的典型。

两处接上：

1. **存的时候兜底**（`store.add_kb_entry:403` / `update_kb_entry:413`）：
   `keywords = keywords or derive_kb_keywords(question)`。
   ⇒ 管理员留空也不会变成死条目。
2. **查的时候兜底**（`faq._kb_parts:107`）：
   `kws = item.get("keywords") or derive_kb_keywords(item.get("question") or "")`。
   ⇒ 存量死条目（老数据里关键词为空的）**不用迁移**，当场活过来。

⚠️ 两处都接，不是冗余：只接第 1 处救不了老数据，只接第 2 处列表里显示的关键词栏还是空的（管理员看不出这条靠什么命中）。

3. **管理端加一句提示**（`admin.html:351` 标签）：
   「关键词（逗号分隔，**留空则自动从问题里提取**）」。
4. **列表里要看得出来是自动提的**：`loadKB` 渲染那行（`admin.html:682`）现在是
   `关键词：${(e.keywords||[]).join("、")}` —— 自动派生的一屏能刷出十几个碎片，管理员会以为系统乱写。
   建议：显示前 6 个 + 后缀「（自动提取）」，靠"条目里存的关键词是不是与派生的完全相同"来判
   （**别再加一个 `auto` 标记字段**，那是第二份真相）。

## 二、46-B：面板失败静默 ——「走不通」的一大半来源

```js
// app/static/admin.html:674-677 —— 没有 try/catch
async function loadKB() {
  const data = await (await adminFetch("/api/admin/kb")).json();
  const box = document.getElementById("kbList");
  if (!data.entries.length) { box.innerHTML = '<div class="empty">知识库还是空的</div>'; return; }
```

`adminFetch` 在非 2xx 时**会抛异常**（`:439-455`，401/403 还有专门话术）。
`loadKB` 没接住 ⇒ 未处理的 rejection ⇒ 页面**停在上一次的样子**。
最要命的是首次加载：屏幕上一直挂着 **「知识库还是空的」**——
口令没设 / 口令不对 / 接口 500，看起来全都像"库里没有东西"。

对照同页的 `loadDocs:746-755`，它是有 catch 的、会写「文档列表读不到：…」。
**两个面板对同一类失败给了两种待遇**，这正是用户说"知识库那个模块走不通"的直接体验。

### 修法

照 `loadDocs` 抄，不要发明第三套：

```js
async function loadKB() {
  const box = document.getElementById("kbList");
  const st  = document.getElementById("kbStatus");
  let data;
  try {
    data = await (await adminFetch("/api/admin/kb")).json();
  } catch (e) {
    // 读不到就照实说：把上一分钟的列表留在屏幕上，等于拿旧账充"现在还是这些"
    box.innerHTML = '<div class="empty">知识库列表读不到：' + esc(String(e.message || e))
                  + '（点左边【保存/添加】重试，或检查管理口令）</div>';
    if (st) st.textContent = "❌ 读知识库失败：" + String(e.message || e);
    return;
  }
  const entries = data.entries || [];
  ...
}
```

同时给「知识库」面板加一个 **【刷新列表】** 按钮（`view-docs` 有 `refreshDocs:382`，`view-kb` 没有）——
读失败时用户手上得有个重试的东西。

⚠️ `editKB:689-699` 也是裸 `.then()` 无 catch —— 顺手补上，同一条病。

## 三、46-C：没有"验一下能不能查到"的入口

管理员现在唯一的验法是切到学生端问一句。这既慢，又让"查不到"变成一件要靠猜的事。

### 加一个只读探针接口

```
POST /api/admin/kb/probe      Depends(verify_admin)
body: {"query": "图书馆几点关门"}

200 → {
  "query": "...",
  "entries": [{"index": 3, "question": "图书馆几点开门、几点关门？"}],   # 命中的问答条目
  "docs":    [{"name": "学生手册-测试样本.txt", "i": 0, "score": 2.97}], # 命中的文档块

  "student_view": "问：…\n答：…"        # answer_for_student() 的原样输出（学生真看到什么）

```

实现就三行 —— **不许另写一套检索**（同一判断抄两处是本项目反复吃过的亏）：

```python
@app.post("/api/admin/kb/probe")
async def kb_probe(req: Request, _=Depends(verify_admin)):
    body = await req.json()
    q = str(body.get("query") or "").strip()
    hits, docs = _kb_parts(q)            # 与学生端**同一个函数**
    ...
```

前端：`view-kb` 面板加一格输入 + 【试查】按钮，把 `student_view` 原样显示（`textContent`，别 `innerHTML`）。

⚠️ 探针**只读**：不写 `kb.json`、不进聊天历史、不计 `llm_usage`。
⚠️ 探针也不许带上 `student_view` 之外的技术元数据给前端以外的调用方造成误解——

## 四、46-D：`kb.json` 现在真是空的（要用户拍板，别替他决定）

```

 M app/data/kb.json
$ git diff --stat app/data/kb.json

```

即：仓库里（committed）是 **11 条演示条目**，工作树里被清成了 `{"entries": []}` —— 126 行删除**没有提交**。
所以面板显示「知识库还是空的」**是实话**，不是 bug。

两条路，执行前**先问用户**：

- **要恢复**：`git checkout -- app/data/kb.json`（会丢掉当前这个"空"状态，无其它副作用）。
- **要保持空**：什么都不做，但要在 README / 文档里写明"演示知识库只用上传的文档，条目表为空"。

⚠️ 若恢复，**演示前先看一遍这 11 条里有没有跟上传文档打架的**。已知一处：
- 条目「图书馆几点开门、几点关门？」答 **8:00–22:00（周末 9:00–21:00）**；
- 《学生手册-测试样本.txt》第 1 章写 **七点半至二十二点半**。

两条同时在库里，`search_kb` 会把两份都交给模型，模型按提示词要求"两种都说出来" →
学生听到「8:00–22:00，另一份文档说七点半到二十二点半」——**演示时这是自打嘴巴**。
建议：恢复后手工删掉与文档冲突的那几条，或把文档换成与条目一致的数字。

### 本条拍板**不收窄** 46-A/B/C 的范围

46-A（关键词派生）不是为那 11 条服务的 —— 它服务的是"**以后**加进去的条目能不能被原句查到"，
那正是用户最初的投诉（"我添加进去…即使学生问的原句也识别不到"）。条目表现在空，
不代表"加了条目还是查不到"这件事可以不管：面板还在，管理员哪天想加一条，它就还会复发。

## 六、顺带发现（**可选，不强制**，但答辩被问到要答得上）

实测两份文档共 29 块时，`doc_hits` 的命中门槛是 **`score > 0`**（`files.py:144`），
只要有一对 bigram 沾上就算"命中"：

| 查询 | 命中的块数 |
|---|---|
| 图书馆在哪里 | 16 |
| 宿舍晚上几点断电 | 17 |
| 补办学生证多少钱 | 21 |

带来的后果：`kb_has_answer()`（`faq.py:183`）几乎恒为真 →
日程栏那条"知识库直答"会把**不相关的段落**也贴进学生气泡；
模型那一路也会拿到一堆低分块（好在 `pick_diverse` 只取 4 块，伤害被限住了）。

**本单不改**，原因说清楚：这是打分阈值调参，`test_66`/`test_70` 钉着"深处查得到"，
一刀切提高门槛很容易把"该查到的"也切掉。若要动，正确做法是**先补一份"负样本"测试**
（问校园无关的事，断言命中为空）再调，且一次只调一个旋钮。
**记进"已知缺口"比现在动手更安全。**
