## 二、审计：Key 本身没泄露，泄露的是"服务器愿意连哪儿"

先说清楚**验实是安全的**部分（这部分上一轮 `test_34` 已经钉过，本轮复查仍然成立）：

| 面 | 结论 |
|---|---|
| 落盘 | 不落。`model_config` 只在请求内作为 `override=` 流动；`save_pending()` 只存 `options/at/applied`；`llm_usage.jsonl` 字段白名单 |
| 回显 | `/api/chat` 响应里没有 `model_config`；全项目无 `print/logging` 带 key 或 header |
| 钓走**管理员**的 key | 本来就打不通：`get_llm_config` 只在 `override.api_key` 存在时才用 override，且入口层丢弃"没带 key 的 model_config" |
| 重定向甩 header | httpx 默认不跟随重定向 |

**真正的洞是 `base_url`。** 我在本机真服务器上实测（带假 key，不碰真实服务）：

```
http://127.0.0.1:8000/api/admin/settings → 服务器自己去打自己的管理接口，
    并把 404 + 完整 URL 原样回显给请求方
http://127.0.0.1:9/v1                    → "All connection attempts failed"（端口关，可分辨）
http://169.254.169.254/latest/meta-data  → 请求已发出（云上就够到元数据服务）
file:///c:/windows/win.ini               → httpx 拒（不是任意文件读）
```

带出去的 key 是请求者自己的，所以**这不是密钥泄露，是服务器被当成任意内网 HTTP 客户端**；
错误分类 + 时延差 + URL 回显合起来就是一台内网探测器。用户说"选错方案了"之后选的这条
（直接禁用学生端 base_url）确实比我给的"只加校验"更彻底——**入口关掉了，威胁模型从
"任意请求方"缩到"管理员自己"**，后面很多权衡都因此变轻。

## 三、按 7 点实施的，以及每一点的实际落法

| 用户的点 | 实际做法 | 偏差 |
|---|---|---|
| ① 关掉入口 | `config.sanitize_override()` 只认 `model`/`api_key`；**两个入口**都过它 | 用户只引了 `/api/classify`（3287），`/api/chat`（1024）是同族的另一处，漏一个等于没关，两处都收 |
| ② 唯一出口统一校验 | `config.py` 两个函数：`check_base_url_shape`（协议+主机名）、`check_base_url_ssrf`（内网/回环/链路本地/云元数据/保留域名/单标签名 + 解析后逐 IP 复核） | **没有放在 `get_llm_config` 返回前**，见 §四 |
| ③ 超时收短 | `httpx.Timeout(30.0, connect=3.0)` | 不是一刀切几秒：探测代价在 connect，read 留 30 秒否则带工具的长回答被误杀 |
| ④ 报错不回显 | `RequestError`/`HTTPStatusError` 分支不再拼 `{e}`（httpx 原文含完整 URL）与 `{base_url}`；完整原因只 print 进服务端日志 | 管理员排查靠日志，不靠界面 |
| ⑤ 管理端同一套校验 | `/api/admin/settings` 写 `base_url` 前过第二层，非法 400 且不落盘 | 鉴权**上一轮 P0-2 就挂了** `verify_admin`（实测无口令 401），这次补的是"值本身合不合法"；理由反而更硬：这里填错会把**管理员的 key** 寄出去 |
| ⑥ DNS 解析后复核 | 第二层里做 `getaddrinfo` 并逐个答案判 | **没防住 rebinding**：先解析校验、httpx 再解析一次连接，中间可换答案（TOCTOU），60 秒缓存还把窗口放宽。要钉死得把 IP 固定进连接层。写进 docstring 与本文，不声称防住 |
| ⑦（我加的）诚实义务 | 新增 `/api/upstream` 只回主机名；学生端弹窗顶部显示"请求会发到这个上游：host（由管理端配置，学生端不能改）"，并去掉 Base URL 输入框 | 关掉自带端点后，学生的 key 会被发到**管理端配的那台机器**。不露出来等于替学生把 key 寄到没跟他说过的主机 |

顺带补一个同族洞：`data["choices"][0]["message"]` 在"连上了但不是模型服务"时直接 `KeyError` → 500。

## 四、本轮最重要的自我纠错：**安全做成了可用性事故**

第一版严格按用户说的"在 `get_llm_config()` 返回前对最终 base_url 做校验"实现，跑测试当场炸：

```
app.config.BaseUrlError: 接口地址得是个完整域名，收到的是单标签名：srv
```

`test_34` 全灭。往深想一层，这不只是测试的事：`get_llm_config()` 被二十来处调用，
包括启动自检和管理台读配置。**在这条路上拦内网，等于让
`http://localhost:11434/v1`（本地 ollama，这个离线演示产品最常见的配法）每次对话直接抛错，
也让任何存量脏配置把整个产品钉死。** 那是修坏了，不是修好了。

落法改成两层：

- **第一层**（协议 + 有主机名）留在 `get_llm_config`，拦的是"根本没法用"的输入，不会误伤；
- **第二层**（内网那一档）只放在**管理端写入时**与**真要发请求之前**；
- 需要内网就显式设 `CAMPUSTIME_LLM_ALLOW_PRIVATE=1`，默认拦。

`test_37` G 批专门钉这条：「`get_llm_config` 读到内网地址不许抛错」——把"别再犯第二次"变成断言。

### 5.1 `test_37_base_url_ssrf_gate.py`：56 项 / 7 批，全绿

F 端到端（settings 里真躺着 `http://127.0.0.1:9` 时，回的是"不合规"那句且不含该地址）·
G 两层分层本身。

### 5.2 反向验证 9 次变异

8 次直接红（S1 不丢 base_url / S2 入口退回直采信 / S4 管理端不校验 / S5 连接前不校验 /
S6 恢复回显 / S7 把第二层塞回 get_llm_config → 红 3 条，正是 §四 那一幕 / S8 超时退回 60 秒 /
S9 上游回完整地址）。

**S3 第一版没红，而且不是判据假**：变异是"摘掉 IP 字面量那一支"，但域名解析那一支同样会
把 `127.0.0.1` 判出来（`getaddrinfo("127.0.0.1")` 返回它自己）——**两处互为冗余，摘一处等于没摘**。
换成废掉真正的判据 `_ip_is_blocked` 后红 12 条。
（区别于上一轮的"变异没变异到位"：那次是断言太弱，这次是代码本身冗余。教训是**变异要打在被保护的性质本身，不是被保护性质的某一份实现**。）

### 5.3 真机（改前 vs 改后，同一组打法）

改后同样三条注入：

```
http://127.0.0.1:8000/api/admin/settings → ⚠️ 大模型拒绝了请求（HTTP 401）
http://169.254.169.254/latest/meta-data  → ⚠️ 大模型拒绝了请求（HTTP 401）
http://127.0.0.1:9/v1                    → ⚠️ 大模型拒绝了请求（HTTP 401）
```

三条全部变成 401 —— 说明注入的地址**根本没被采用**，服务器拿学生那把假 key 去打管理端配的
`open.bigmodel.cn`。这比"被拦下报错"更强：攻击是**失效**的。
正常对话不受影响（智谱回了「你好！有什么可以帮助你的吗？」）；`/api/upstream` 回 `{"host":"open.bigmodel.cn"}`。
