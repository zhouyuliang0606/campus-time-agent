## 〇 现场事实（带 `ct_student=admin1` 实测，22:47）

### 0.1 死循环：同一句话问三遍

待办里「健身房」有 2 条（11-03 周二 20:40、11-04 周三 19:00）。

```
你：把健身房挪到周六
它：🕘 日程里有好几条都叫「健身房」，你要改哪一条？
    · 健身房｜2026-11-03（周二）20:40-21:40
    · 健身房｜2026-11-04（周三）19:00-20:30
    回我一个（比如「周四那条」），我帮你改。

你：周三那条          ← 它又问一遍，一字不差
你：11-04 那条        ← 又问一遍
你：第二条            ← 又问一遍
你：把周三的健身房挪到周六  ← 还是问一遍
你：把 11-04 的健身房挪到周六 ← 还是问一遍
```

**六种续答，六次回到同一句。** 换一个名字也照样：「把背30个单词挪到周六」（4 条同名）→ 同样循环。

### 0.2 那三条追问**没有可点的东西**

原始返回（`POST /api/chat`，22:48）：

```
awaiting_choice: False
options: 0
trace: [{"phase":"🕘 改期遇到多条同名（不猜）","answer":"等学生点名"}]
```

`options` 是空数组 ⇒ 前端不会渲染任何按钮 ⇒ 学生**只能打字** ⇒ 打字必循环。
**这就是「看着像在等你选、其实选不了」。**

### 0.3 追问里那个例子是写死的、而且是错的

> 回我一个（**比如「周四那条」**），我帮你改。

库里没有周四那条 —— 候选是周二、周三。**它教学生说一个不存在的说法。**

### 0.4 唯一能出卡的情形

```
你：把图书馆挪到周五下午
它：📝 好，把图书馆从 2026-11-07（周六）08:00-09:30 改到 2026-11-06（周五）12:00-13:30
```

「图书馆」库里只有 1 条 ⇒ 不需要挑 ⇒ 通。
**换句话说：改期功能只在"名字唯一"时可用，一同名就进死胡同。**

## 一、根因：那个参数早就有了，只是这条路上没传

`build_retime_existing_proposal`（`planner.py:5196`）**已经**有一个 `anchor_date` 参数，
docstring 里写着它存在的理由就是治这个循环：

> ★ #87：库里真有两条同名时，"名字"这一维已经用尽 —— 模型下一轮**还是只能传同一个 title**，
> 于是 `many → need_pick → many` 无限循环（真机实测三次调用三次同两条候选）。
> 学生原话「改 2026-11-09 那天那个」里的日子就是第二维，从这里切一刀。

收窄的实现（`planner.py:5304-5308`）也很稳：

```python
        if anchor_date and len(pool) > 1:
            _hit = [x for x in pool if x.get("date") == anchor_date]
            if _hit:
                pool = _hit
```

**问题只有一个：这个参数只有引擎工具那一条路在传。**

| 调用点 | 传了 `anchor_date` 吗 |
|---|---|
| `planner.py:5492`（`propose_todo_change_tool`，引擎/工具路） | ✅ `anchor_date=(todo_date or "").strip()` |
| **`main.py:3752`（确定性分支，学生直接说话走的就是这条）** | ❌ **没传** |

```python
            _rt = build_retime_existing_proposal(
                message, _sem if _sem_intent == INTENT_RETIME else None,
                hint_title=_recent_todo_title(session_id))
```

**#87 把刀磨好了，只装在工具那一路；学生说话那一路还是钝的。**
「周三那条」其实**进了这个分支**（trace 里能看到 `🕘 改期遇到多条同名`），
只是进去时手里没带"周三"这个信息 —— 它被整个丢掉了。

## 二、修法

### 2.1 取「旧日子」，不能直接取整句的日子

**这是本单最容易做错的一处。** 直接把整句喂给 `_pick_date` 会取到**新**日子：

| 说法 | `_pick_date(整句)` | 要的 anchor |
|---|---|---|
| 把**周三**的健身房挪到**周六** | 2026-11-07（周六，**新**日子）❌ | 2026-11-04 |
| 把健身房挪到周六 | 2026-11-07 | 空（本来就没说哪条，该问） |

所以要在「换时间词」处**切一刀，只取左边**（左边说的是"哪一条"，右边说的是"改到哪"）：

```python
_RETIME_SPLIT_RE = re.compile(r"(改成|改到|换成|换到|换个时间|换个点|挪到|调整到|调到|重排)")
```

实测（今天 2026-11-02 周一）：

| 说法 | 切出来的左边 | anchor |
|---|---|---|
| 周三那条 | `'周三那条'` | **2026-11-04** ✅ |
| 把周三的健身房挪到周六 | `'把周三的健身房'` | **2026-11-04** ✅ |
| 把周二的健身房改到周六 | `'把周二的健身房'` | **2026-11-03** ✅ |
| 把健身房挪到周六 | `'把健身房'` | 空 ⇒ 不缩 ⇒ 照旧问（**正确**） |
| 改 2026-11-09 那天那个 | `'改 2026-11-09 那天那个'` | **2026-11-09** ✅ |
| 把背30个单词里周三那条挪到周六 | `'把背30个单词里周三那条'` | **2026-11-04** ✅ |

### 2.2 改 `main.py:3752`

```python
            # ★ #111：同名多条时，学生下一句说的是"哪一条"（「周三那条」「把周三的挪到周六」）。
            #   不带 anchor_date 的话这一维被整个丢掉 → many 再问一遍 → 无限循环（实测六种续答六次）。
            #   注意取的是**换时间词左边**：右边那个日子是"改到哪"，拿它收窄会把池子收成空。
            _anchor = _pick_date(_RETIME_SPLIT_RE.split(message)[0]) or ""
            _rt = build_retime_existing_proposal(
                message, _sem if _sem_intent == INTENT_RETIME else None,
                hint_title=_recent_todo_title(session_id),
                anchor_date=_anchor)
```

`_pick_date` 返回 **ISO 字符串**（实测 `'2026-11-04'`），正好等于 `todos[].date` 的格式，
不用转换。`_RETIME_SPLIT_RE` 放在模块级（和 `_WEEKDAY_RE` 一起，别写在函数体里每句都 re.compile）。

⚠️ **别自己写一套日期解析**。`_pick_date`（`:3005`）已经认 大后天/后天/明天/今晚/今天/明晚/明早
和 周一~周日（对周X算下一个周X），抄一份必然漂 —— #110 也是这个结论。

### 2.3 追问话术：例子从候选里现取

`main.py` 那段 `_rt_lead` / `_rt_lines` 之后，把写死的「比如「周四那条」」换成候选里第一条的星期：

```python
                # #111：例子不许写死 —— 库里没有周四，原话却在教学生说「周四那条」
                _eg = f"周{_wd2(_rt['todos'][0].get('date', ''))}" if _rt.get("todos") else "周三"
```

后面接 `f"回我一个（比如「{_eg}那条」），我帮你改。"`。

### 2.4 修完之后的预期行为（**别指望一步出卡**）

| 学生说 | 修完的结果 |
|---|---|
| 把周三的健身房挪到周六 | ✅ **直接出卡**（一条命中 + 新日子说全） |
| 周三那条（先问过"哪一条"之后） | 收窄到 11-04 那条 → 改问「**11-04 那条，几点改到几点？**」 |
| 把健身房挪到周六 | 照旧问"哪一条"（正确，他确实没说） |

第二行**仍然是追问，但性质变了**：从「再问一遍哪一条」（死循环）变成「问新时间」（能往下走）——
这句里没有新时间，问是应该的。**话术里必须把 `2026-11-04` 念出来**，否则学生看不出自己那句起作用了。

## 三、验证

### 3.1 判据

| # | 判据 | 断言 |
|---|---|---|
| T1 | 「周三的健身房」收窄得住 | `把周三的健身房挪到周六` → status **`ok`**，提案 `old_todo_id` = 11-04 那条的 id |
| T2 | 「周二的健身房」收窄到另一条 | 同上，`old_todo_id` = 11-03 那条的 id（**和 T1 不是同一条** —— 两条都过才算真收窄） |
| T3 | 不带日子的仍然拒猜 | `把健身房挪到周六` → status **`many`**，`len(todos)==2` |
| T4 | 收窄落空要退回，不许假「没找到」 | `把周四的健身房挪到周六`（库里没周四）→ status **`many`** + `pool_n>0`，**不许是 `empty`** |

**T4 是防假话闸**：`if _hit:` 那句是命门，谁把它改成 `pool = _hit`（不带 if），T4 立刻红成 `empty`，

## 四、不做的事

1. **不改 `build_retime_existing_proposal` 的收窄逻辑**。它是对的（`if _hit:` 那三行是 #84/#87 的成果），
   缺的只是调用方没传参。
2. **不给那三条候选加按钮**。本轮先把死循环拆掉；出按钮要动前端（`student.html` 的 options 渲染）
   和 `awaiting_choice` 语义，比这一单大一圈，另议。
3. **不认「11-04 那条」「第二条」这种说法**（`_pick_date` 不认月-日、也不认序数）。
   今晚的绕法：让学生说「周三那条」。要支持序数得另开一单 —— 那时顺序必须和屏上列表**逐条对齐**，
   错位就是删错/改错，不能拍脑袋。
4. **不和 #109 / #110 合并**。#109 是 `asking_remove` 粘住、#110 是 `_pick_day` 不认相对日期，
   本单是改期这条路的 `anchor_date` 没传 —— 三个文件位置、三组判据。

## 五、给执行方的三句

1. **只给 `main.py:3752` 那次调用补 `anchor_date`**，`planner.py` 一个字不用改 —— 参数和收窄逻辑都现成。
2. **anchor 必须取「换时间词左边」那截**（`_RETIME_SPLIT_RE.split(message)[0]`），
   取整句会把「挪到周六」的周六当定位条件，池子直接空掉（M2 钉着）。
