# 103 · 「你好，你能做啥」被答成「我不替你决定，也没往日程里写一条」——问能力被吃进「问该做什么」那族

> 施工单原件。基准 `HEAD = 13cffae`。优先级 **P0**（这是评委/学生打开产品**第一句**最可能问的话）。
> 来源：用户报障「我让他自我介绍为什么也会卡然后，返回说这是」（附截图：连问两次「你好，你能做啥」「你好你能干嘛」，两次都回同一段空档清单）。
> 本单不动模型、不动超时；只加**第五道排除** + 给一句**确定性**答复。

---

## 〇 现场事实（跑真代码复现，不是猜）

### 0.1 屏幕上那句是哪来的

`app/modules/planner.py:826` 与 `:832`，`what_to_do_suggestion()` 的两个出口。调用点：`app/main.py:3644`

```python
if _asking_what_to_do(message):
    answer, _free = what_to_do_suggestion(message)
```

### 0.2 用真代码逐句过一遍（`./.venv/Scripts/python.exe`，`_asking_what_to_do` 直调）

| 句子 | 现在的判定 | 应该是什么 |
|---|---|---|
| 你好，你能做啥 | **True** ❌ | 问能力 |
| 你好你能干嘛 | **True** ❌ | 问能力 |
| 你能做什么 | **True** ❌ | 问能力 |
| 你会什么 | **True** ❌ | 问能力 |
| 你是谁 | False ✅ | 问身份 |
| 你有什么功能 | False ✅ | 问能力（已对） |
| 我该做什么 | True ✅ | ★ 正控，必须保持 True |
| 今天干点啥好呢 | True ✅ | ★ 正控，必须保持 True |
| 安排点事给我 | False ✅ | 原设计：走追问 |
| 我现在都有啥安排 | False ✅ | 原设计：走清单档 |
| 啥时候放假 | False ✅ | #42-A 已排除 |
| 考试时间是什么 | False ✅ | #43 已排除 |

⇒ **4 条误判**，而且全是同一形状：**「你/您 + 能/会 + 做什么/啥」**。

### 0.3 为什么会漏：两道判据都放行，四道排除都不管这一族

`_asking_what_to_do` 现在是「① 句里有疑问代词」**且**「② 剥掉时间/动作词后裸串是疑问串」两道一起才算，
再挂**四道排除**（在删东西 / 在查清单 / 在问什么时候 / 在问是什么）。

「你好，你能做啥」：

- ① 有「啥」→ 过
- ② `_vague_ask_name("你好，你能做啥")` → 剥尾字后 `endswith("啥")` → **True** → 过
- 四道排除：不是删、不是查清单（没有「有…啥」）、不是问时候（没有「什么时候/哪天」）、
  `asks_about_content` 也 False（那支要求 `X是/为什么$`）→ **四道全不管**

所以这句一路走到 `what_to_do_suggestion`，去读周表空档、催他「说个名字」。
**它其实是同一族缺口的第五个形状**（前四个分别是 #42-A 的「什么时候」、#43 的「是什么」）。

### 0.4 为什么这句必须修，而且不能只靠模型

这是**打开产品第一句**最可能被问的话（评委也会这么问）。现在它有两个问题叠在一起：

1. 答案完全错（问能力 → 答成"我不替你决定"），而且**连问两次答案一模一样**，看起来像坏了；
2. 它本来不必花模型——可现在排除掉之后没有专门的家，会掉给模型，而模型这条路今天正好在抽风（见 #102）。

所以本单**同时**给一句确定性答复：不花模型、没有网络也能答。

## 一、修法

### 1.1 加第五道排除：`asks_capability`

在 `_asking_what_to_do` 的四道排除里再加一道，与新函数放在一起
（紧挨 `asks_about_content`，那一族已经有先例，照着它的注释格式写）：

**判据（人话）**：句子的主语是**你 / 您 / 管家 / 机器人**，后面跟**能 / 会 / 可以**，
再后面跟的是**泛动词**（做 / 干 / 整 / 搞）或**直接就是疑问代词**（什么 / 啥 / 嘛）。

- 有「能/会/可以」+ 泛动词 ⇒ 在问"你能做什么" ⇒ **排除**
- 有「能/会/可以」+ **具体动词**（安排 / 排 / 加 / 改 / 挪 / 找 / 查）⇒ **不排除**（那是让你出主意）

regex 怎么写由你定，**但下面这张表必须逐条过**（这是本单的验收本体）：

| 句子 | 期望 `_asking_what_to_do` |
|---|---|
| 你好，你能做啥 | **False** |
| 你好你能干嘛 | **False** |
| 你能做什么 | **False** |
| 你会什么 | **False** |
| 你会干啥 | **False** |
| 你能帮我做什么 | **False** |
| 您能做点什么 | **False** |
| 你都能干啥呀 | **False** |
| **我该做什么** | **True** ← 正控 |
| **今天干点啥好呢** | **True** ← 正控 |
| **晚上不知道干啥** | **True** ← 无主语，别误伤 |
| **你帮我安排点啥** | **True** ← 有"你"但没"能/会"，是让你出主意 |
| **你能帮我安排点啥吗** | **True** ← 有"能"但动词是"安排"（具体）⇒ 不排除 |
| 你能帮我把周三的课挪到周五吗 | **False 或 True 都行**（这句根本不带疑问代词，两道判据的①就过不了，走的是改期那族） |

⚠️ 表里加粗的四条是**反控**：只把新句子改对、把这几条弄红，等于没修好。
特别是 `你帮我安排点啥` 与 `你能帮我做什么` 这一对——**同主语、同疑问代词，只差"能"和动词**，
它们是这段判据有没有牙的唯一证据。

### 1.2 给它一个家：`capability_intro()`（确定性，不花模型）

在 `planner.py` 里挨着 `what_to_do_suggestion` 加，`main.py` 里排在 `_asking_what_to_do` **之前**判
（顺序很重要：这两族共用疑问代词，判反了又会串）。

文案建议（可改，但**别塞进「你该做什么」那种口气**，也别承诺做不到的事）：

```
👋 我是校园时间管家，能帮你做这几件事：

📅 课表与日程 —— 上传课表（.docx / .xlsx / .txt 都行）我读出来给你预览；
   要加、要删、要改期，说一句就行；加之前我会先看会不会撞课，撞了会告诉你。
📚 校园问答 —— 图书馆几点开门、校园卡丢了怎么办这类，我按学校文件答，答完给出处。
📦 驿站在线 —— 查快递、报修、找失物，驿站那边不登录也能问。
🛠️ 管理端 —— 老师那边能看工单、改模型配置，走一个口令。

想直接开始就上传一份课表，或者问我一句「我这周三有什么课」。
```

要求：

1. **不放候选卡**（`options` 回空），它不是待办；
2. **不写进日程**；
3. **文案里提到的每件事都必须真的能做**——尤其「.docx / .xlsx / .txt 都行」这句，
   对着 `app/upload.py` 的 `supported_desc()` 核一遍再定稿（那边写的是
   `txt / md / csv / json 等文本文件、PDF，以及 Word(.docx) / Excel(.xlsx) / PPT(.pptx)`）；
4. 落进 trace 时要能看出走的是这一档（跟 `what_to_do_suggestion` 同一套路，别新造字段）。

## 二、判断与理由

### 2.1 为什么用「主语 + 能/会 + 泛动词」而不是「含『你』就排除」

因为「你帮我安排点啥」也含「你」，而它**确实**是在问"给我出个主意"，属于原来那族。
用主语一刀切会把这类真需求挡到模型那边去，凭空多一次往返（今天这条路还在抽风）。

### 2.2 为什么不用「能不能做」这种更宽的词表

「你能帮我把周三的课挪到周五吗」带「能不能/能」，但它是**明确的改期指令**。
判据一旦宽到"含能字就排除"，这句就会从改期那族被抢走——那是昨天刚修好的路径（#87）。
所以判据只认"**能/会 + 泛动词/疑问代词**"这个窄形状，宁可漏几个怪说法，也不误伤已修好的族。

（这条取舍与 `_vague_ask_name` 注释里那句「宁可漏掉几个噪声，也不误伤真名字」是同一条原则。）

### 2.3 为什么给固定文案，而不是让模型自由发挥

因为这是**第一句**，也是最不需要模型的一句。今天模型链路在抽风（#102），
这一句如果也要等模型，抽风时就变成第二个"卡住 + 答错"。
写死一段的代价是会随功能过时——所以在文案第 3 条要求里写了「对着 `supported_desc()` 核一遍」，
并建议把这段话术放在一个**唯一的地方**，加功能时顺手改（跟 `_WH_ASK_WORDS` 只有一份是同一条红线）。

### 2.4 代价

- 多一个分支、多一段固定文案要维护（过时风险已上面说过）；
- 极少数怪说法（比如「你会不会做课表」）可能仍落进"问该做什么"那族 —— 可接受，它至少不会答错方向。

## 三、验证

### 3.1 既有判据要不要改口：**不用**

`grep -rn "你能做\|你会什么\|你能干嘛\|你能干啥\|你能做什么" tests/*.py` → **零命中**。
也就是说没有任何既有判据钉着这些句子，本单是纯新增，不需要改口。
（`test_45_ask_what_to_do.py` 里钉的是「我今晚该干点啥呢」，属正控，必须继续绿。）

### 3.2 新增判据（并入 `tests/test_45_ask_what_to_do.py`）

1. §1.1 那张表 **14 条逐条断言**（含四条反控）；
2. `asks_capability` 单独的正控与反控各一条（空判据守卫：喂「你能做什么」必须 True，
   喂「我该做什么」必须 False）；
3. `capability_intro()` 的返回必须 **`options` 为空**（不许摊卡）；
4. 端到端一条：`POST /api/chat {"message":"你好，你能做啥"}` → 答复里
   **不许出现**「我不替你决定」「这几段是空着的」「说个名字」这三句中的任何一句，**且**
   必须出现「课表」和「问答」（证明走的是能力介绍而不是空档清单）。

### 3.3 变异（打在判据上游）

| 变异 | 应红 |
|---|---|
| M1 把 `asks_capability` 的调用从 `_asking_what_to_do` 里删掉 | §3.2-1（4 条误判句） |
| M2 把判据放宽成"含『你』就排除" | §3.2-1 的 `你帮我安排点啥` |
| M3 把判据收紧成"必须有『做』字" | §3.2-1 的 `你会什么` |
| M4 `capability_intro` 返回一条 `options` | §3.2-3 |
| M5 把 `capability_intro` 的判定挪到 `_asking_what_to_do` **之后** | §3.2-4（端到端那句会被空档族抢走） |

## 五、给执行方的三句

1. **这是第五个形状，不是新 bug 家族**：#42-A 挡了「什么时候」、#43 挡了「是什么」，这一单挡「你能做什么」；三道排除加在同一处，注释照 `asks_about_content` 的格式写。
