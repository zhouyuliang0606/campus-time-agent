## 〇 现场事实（带身份实测）

### 0.1 单说这一句就失败


不是上一轮污染，**这一句本身就走不到提案**。

### 0.3 根因就一行

`parse_remove_course` 的 `:6017-6019`：

```python
    day = _pick_day(t)
    if day is None:
        return None
```

而 `_pick_day`（`:6075`）只认星期：

```python
def _pick_day(text: str) -> int | None:
    """从一句话里抠出周几（人话：周一 … 周日，1=周一 … 7=周日）。"""
    m = _WEEKDAY_RE.search(text or "")
    if not m:
        return None
```

**它不认「明天」。** 而学生说「明天」才是常态 —— 他未必知道明天是周二，
就算知道，也没有理由先说星期。

### 0.4 讽刺的是：追问话术教的说法，学生未必肯说

追问让他说「删除周二第二节」。他要是能想到「周二」，第一句就说了。
追问把一个**系统自己的限制**转嫁成了**学生的负担**。

## 一、修法（在 `parse_remove_course` 里兜一层，不动 `_pick_day`）

改 `planner.py:6017-6019`：

```python
    day = _pick_day(t)
    if day is None:
        # ★ #110：学生说的是「明天早上第一节」，不是「周二第一节」——
        #   他未必记得明天周几，也没理由先说星期。`_pick_day` 只认周X，
        #   这里用 `_pick_date` 兜一层再换算成周几。
        # ⚠️ 不许把这段塞进 `_pick_day`：它有 6 个调用点
        #   （main.py:4415、planner.py:5900 / 5928 / 5998 / 6017），

        _d = _pick_date(t)
```

`_pick_date`（`:3005`）已经完整支持这些相对说法，**不用新写词表**：

做法：把 `parse_remove_course` 的源码用 `inspect.getsource` 取出来，**只替换那三行**
（源码一个字没动），在 `planner` 的命名空间里 `exec` 出一个修好的版本，配真课表跑。
今天是 **2026-11-02（周一）**，明天是 **11-03（周二）**：

## 二、判断与理由

### 2.1 为什么不改 `_pick_day`

它有 6 个调用点。其中 `wants_remove_course`（`:5998`）拿它判「这句话算不算删课意图」、
`main.py:4415` 拿它判别的分支 —— 给 `_pick_day` 加相对日期，等于**顺手改了那五处的语义**，
而它们是不是需要这一档，得各自单独想。

`parse_remove_course` 是唯一确定需要它的地方，就修在那一处。

### 2.2 为什么不认「上午/下午/晚上」

「删除今天下午的课」这种，`_pick_date` 能给出周几，但「下午」不是节次，
`_PERIOD_RE` 匹配不到 → 走「剩下那截当课名」兜底 → 猜出的课名不存在 → 返回 None → 追问。

**这个追问是对的**：那天下午有两三节，不说是哪节就不该猜。
真要支持，得写一套「下午 → 第 5~8 节」的映射，然后面对「那几节里有 3 门课，删哪门」的多义问题 ——
那是另一个功能，不是这一单。

### 2.3 和 #109 的关系

| 单 | 病 | 表现 |
|---|---|---|
| #109 | 追问状态**粘住** | 追问之后问「今天几号」，还回「想删哪一节」 |
| #110 | 这句话**解析不出来** | 单说「删除明天早上第一节课」，直接追问 |

**两单互不覆盖**：#109 修完，「删除明天早上第一节课」照样追问（本单不管）；
本单修完，「今天几号」照样被吞（#109 不管）。**两张都要发。**

### 2.4 修完之后 `_pick_day` 与 `_pick_date` 会不会打架

不会。`_pick_day` 先跑，句子里有「周X」就用它（返回 1~7）；
只有它返回 None 时才轮到 `_pick_date`。

唯一要注意的：`_pick_date` 对「周一」算的是**下一个周一**（`(want - today) % 7 or 7`），
而 `_pick_day` 返回 1。但因为 `_pick_day` 优先，这个差异走不到。

## 四、不做的事

1. **不改 `_pick_day`**（理由见 §2.1，6 个调用点）。
2. **不认「上午/下午/晚上」**（理由见 §2.2）。
3. **不新增词表**。`_pick_date` 那份相对日期表是全项目唯一一份，抄一份到 planner 里必然漂。
4. **不改追问话术**。追问本身没错（他确实没说清哪节），错的是「明天」走不到解析。
   ⚠️ 但本单落地后，追问话术里那个例子可以**加一句**「也可以说『明天第一节』」——
   这是 §1 修完才成立的说法，别在修之前改。
5. **不与 #109 合并**（理由见 §2.3）。
6. **不回退到模型路径**（这是本单最容易被提的「更省事」方案，明确否掉）。
   既然老路能过「明天」，为什么不干脆把 `636fc2e` 撤了交回模型？
   因为撤了会把 `636fc2e` 治好的病原样带回来 —— commit message 里那三条
   「弹窗不来、确认不删、删除失败」是**模型没调工具**造成的，它不是偶发，
   而是模型自由裁量必然的风险。**修的方向是让代码认得更全，不是把判断权退回去。**
   顺带：`63aa030`（#109 那半边）也挂在确定性分支上，退回去等于两个病一起回来。

## 五、给执行方的三句

1. **只改 `parse_remove_course` 里 `day = _pick_day(t)` 那三行**，别碰 `_pick_day` 本身（6 个调用点）。
   这是**补回归**，不是加功能：09-25 01:23 之前的模型路径认「明天」，改确定性分支后丢了。
2. **兜底必须排在 `_pick_day` 之后**。反过来的话「周一」会被 `_pick_date` 推到下周一（T4 钉着）。
3. **兜底失败要落回 `None`，不许给默认值**。「删除第一节课」这种没说哪天的，追问是对的（T5 钉着）。
   另外 T6 必须写成「明天 vs 明天的周X 逐字相同」，日期现算不写死 ——
   只测「非 None」的话，`.isoweekday()` 写成 `.weekday()` 也能过（M5）。

## 附：这一单为什么必须和 #109 一起发

用户的原话是「我单独让他删除也是同样的话，没有追问」—— 他以为这是同一个 bug 的另一种表现。

**不是。**「同样的话」只是因为两条路都通向同一个 `return`（追问那句文案）：

```
「删除明天早上第一节课」──┬─→ _pick_day 返回 None ──→ 追问   ← 本单
「今天几号」（追问之后）  └─→ asking_remove 接管 ───→ 追问   ← #109
```

两条路不同的坑，落同一个坑底。**只修一个，用户下次还会撞上另一个** —— 那时他会以为没修好。
