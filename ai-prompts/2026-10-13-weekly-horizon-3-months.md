## 三、这把尺子

```
weekly_horizon(anchor) = 日历月加法(max(今天, 锚点) + 3 个月)
只作用于 repeat=weekly 的推断展开；一次性待办的日子再远也照原样出现
```

三个不显然的点：
1. **取 max(今天, 锚点)**：锚点可能在将来（「明年六月起每个周六」）。只按今天算，
   这一条从生下来那天起就一天都看不见 —— 上限收的是"系统替他推出来的将来"，
   不是他明确写下的日子。
2. **日历月不是 90 天**：2026-11-30 加 3 个月 = 2027-02-28（那天不存在就贴到月末），
   而 2027-01-31 加 3 个月 = 2027-04-30，加 90 天 = 2027-05-01，差一天。
3. **一次性待办不受影响**：2099 年的《毕业礼》必须在 —— 这条单独钉了，
   顺手当变异 V6 的探针（把上限错套到一次性分支，它当场红）。

## 四、我写的两条断言是空的，被变异打回来

`mutate_V.py` 六笔，头一遍跑出**两个红 0**，都是测试的问题不是代码的问题：

- **V2（上限改成 0 个月）红 0**：「上限之内最后一个同星期几仍然算出现」里那个日期是
  `weekly_horizon()` 自己算出来的 —— 上限缩它跟着缩，断言**永远为真**。
  这就是自证式断言：绿得毫无信息量。改成钉绝对日子（四周后那个同星期几必须在、
  半年后必须不在）之后 V2 红 11。
- **V4（拿 90 天冒充 3 个日历月）红 0**：我挑的两个"月末锚点"（11-30、12-31）
  两种算法算出来**恰好相等**，等于没测。换成 2027-01-31 / 2027-05-31 之后 V4 红 2。
- 顺带还有一条把自己坑红的：把**过去**的日子（2026-05-31）当锚点写进断言，
  撞上 `max(今天, 锚点)` 得到的是"今天+3月"，当场红 —— 那是在测我的误解，不是测代码。

三条都写进指南了（§4 新增 6b：变异红 0 的第四种原因就是断言自证；9b：上限这把尺子的三条边界）。

## 五、test_03 那行的改法

原先 `c.check("查空月份返回空", ...month=2099-01... == {})` —— 写死 2099 年**没有信息量**：
远到谁都空，而真机恰恰红在**它不空**（一条 weekly 铺到世界尽头）。
改成拿 `weekly_horizon()` 算出"上限月的下个月"来查，另加一条对照：
2099 年那个月的**一次性**待办仍然查得到。这样"上限设成多大"这件事第一次变得可测。
