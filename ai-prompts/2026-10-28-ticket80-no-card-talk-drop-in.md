## 〇 现场事实

### 0.1 学生输入与屏幕上的回答

```
学生：撞时间了有一处

管家：确实撞了：周四 14:00-15:40 有大学物理，游泳 15:00 开始，重叠 40 分钟。
      周四剩下的空档：15:40-19:00、22:00 之后。给你两段：
      - 周四 16:00-17:00
      - 周四 17:30-18:30
      勾一个，点【加入日程】。

（轨迹）🧠 我把这句听成 问事｜依据：语义层
       🧭 判定 —— 没有办事的说法、也没有时间线索 → 按聊天答
```

**屏幕上没有任何卡片。** 最后那句「勾一个，点【加入日程】」是在指一个不存在的东西。

### 0.2 轨迹铁证（`app/data/trace_log.jsonl` 最后一条，`id=35efcea54909`）

```
ts=2026-10-28 23:08:40  module=planner  agent_mode=False
tool_calls = 2
tools      = ['get_day_courses', 'get_day_courses', 'list_day_todos', 'list_day_todos']
steps      = 9
options_n  = 0          ← ★ 一张卡都没生成
```

它**查了**（`get_day_courses(day=周四)` → 3 门课；`list_day_todos(date=2026-10-29)` → 2 条），
**算出了**（空档 15:40-19:00 / 22:00 之后），**但一次 `propose_slots` 都没调**。

⇒ 事实定性：**它把「出卡」这件事用嘴做了一遍。**

### 0.3 根因：提示词把「必须调工具」和「补那句引导语」拆成了两条

`app/modules/planner.py:6069 build_system_prompt()`，原文（`:6080-6086`）：

```python
【你的工作流程 —— 必须照做】
1. 学生提出一件要做的事（比如"我要复习高数"），先用 find_free_slots 查空档；
2. 挑出 **2-3 个候选时间段**，然后**必须调用 propose_slots 工具**，
   把这些候选以结构化形式交给前端——学生会在界面上看到可勾选的卡片，
   **不要只在文字里罗列时间段**，否则学生没法点选。
3. 文字里补一句"你点一下想要的时间就行"，然后**停下来等学生选** —— 这一步绝不能省。
```

**第 2 条和第 3 条是两条独立指令。** 第 3 条**没有写前提**，读起来像是「无论如何都要补这句话」。
模型在第 2 条上偷懒（没调工具），第 3 条照做（补了引导语）——**于是出现了一句指向不存在卡片的台词**。

第 3 条末尾那个「**这一步绝不能省**」还起了反作用：它在强调"必须补话"，
却没强调"补话的前提是先出卡"。

### 0.4 为什么这句会被判成「问事」——本单不管，但要说清

「撞时间了有一处」是**在报告问题**，语义层把它判成 `chat`（问事），规则层没认出它是要办事。
按 `main.py:1755-1758` 那段注释的说法：**判成问事 ≠ 不出卡**（引擎后面照样可能提议）。

所以这条路径是「判问事 + 模型自愿查了数据 + 自愿没出卡 + 按提示词第 3 条补了引导语」。
**改判定层能治本，但两天窗口内风险太高，本单不动。**

### 0.5 为什么挂在出口，不挂在 planner

`app/main.py:1965 _chat_json(...)` 是**所有 JSON 回答的统一收口**，SSE 那条也复用它：

```python
resp = await _chat_impl(req, meta, emit=emit)     # ← 所有分支（含 :3263 agent 闸门 / :4779 兜底）都汇到这里
...
resp["trace"] = head + tr
```

挂在出口 = **一次覆盖全部路径**（普通模式、Agent 模式、四个模块、低代码 `custom:<id>`），
而且**不改判定、不改出卡逻辑、不动 planner**，风险面最小。
挂在 planner 里 = 只治 planner 这一路，faq/客服那些栏仍会犯，而且要在每条分支里各插一次（红线 4/11）。

## 一 修法

### 1.1 【预防】合并提示词第 2、3 条，把「补话」变成「调用成功之后才允许补话」

`app/modules/planner.py:6080-6086` 改成：

```python
2. 挑出 **2-3 个候选时间段**，然后**必须调用 propose_slots 工具**，
   把这些候选以结构化形式交给前端——学生会在界面上看到可勾选的卡片。
   ⛔ **只在文字里罗列时间段等于什么都没给学生**：屏幕上不会出现任何可点的东西。
3. **调用成功之后**，才可以在文字里补一句「点一下想要的时间就行」，然后停下来等学生选。
   ⛔ **没调用 propose_slots 就一个字都不许提「勾选 / 打勾 / 点【…】/ 下面这条卡」** ——
     这一轮屏幕上没有卡，那句话就是在指一个不存在的东西（学生原话：「瞎编一个弹窗」）。
   这种情况下你要么**直接出卡**，要么**改成问一句**（「要我把游泳挪到 16:00 吗？」）。
```

**要改的实质只有两处**：给第 3 条加「调用成功之后」这个前提；删掉「这一步绝不能省」这个反作用最强的尾巴。

### 1.2 【兜底·本单主体】出口校验：没有卡就不许有「去点/去勾」的话

在 `app/main.py` 里加一个纯函数（放在 `_chat_json` 上方，便于单测）：

```python
# 只在**这一轮一张卡都没有**时才有意义的一句话族。
# ⚠️ 词表宁短勿长：每多一个词就多一次误伤真回答的机会（下面 §三 T2 钉着正控）。
_CARD_TALK_RE = re.compile(
    r"(勾一个|勾一下|打勾|勾选|勾好|"
    r"下面(?:这条|那张|的)卡|在卡上|卡片上|"
    r"点\s*【[^】]{1,8}】|点一下就能|点一下想)"
)


def _drop_card_talk_without_card(resp: dict) -> dict:
    """这一轮没出卡，回答里却在让学生「去勾/去点」→ 把那句换成一句他能照做的话。

    为什么要有这个函数：模型会把「出卡」用嘴做一遍——它查了空档、算了候选，
    然后说"勾一个，点【加入日程】"，而屏幕上**一张卡都没有**（学生原话
    「瞎编一个弹窗」，原句实测 `options_n=0` 但 `tool_calls=2`）。
    提示词已经教它"必须调 propose_slots"（`planner.py:6082`），但那是软约束，会漏。

    ⚠️ 判据必须挂在 `options` 上，不能挂在 intent 上：
       "判成问事"**不等于**"不出卡"（`main.py:1755-1758` 那段注释就是在说这件事），
       真出了卡的时候哪怕判的是问事，那句话也是准的、不许动。
    """
    if resp.get("options"):          # 真出卡了 → 它想怎么说都行，一个字不改
        return resp
    ans = str(resp.get("answer") or "")
    if not ans or not _CARD_TALK_RE.search(ans):
        return resp

    # 改法：把"去点/去勾"那句换成"说一句我就出卡"。
    # 为什么不是整段删掉：前文那些空档和冲突是**真算出来的**，删了就把有用信息一起扔了。
    tail = "想用哪一段，直接告诉我（比如「用 16:00 那段」），我再出确认卡给你点。"
    # 按行切，只砍命中词的那几行；一行都没命中就整段接一句（防漏网）
    kept = [ln for ln in ans.splitlines() if not _CARD_TALK_RE.search(ln)]
    body = "\n".join(kept).rstrip()
    resp["answer"] = (body + "\n\n" + tail) if body else tail
    return resp
```

插入点（`main.py:1965 _chat_json`，`resp` 拿到之后、拼 `head` 之前）：

```python
resp = await _chat_impl(req, meta, emit=emit)
resp = _drop_card_talk_without_card(resp)      # ★ 新增：没出卡就不许有"去点/去勾"
read = meta.get("read")
```

**离线 / 无 Key 的那条 mock 路径同样经过 `_chat_json`**，所以一起被治到，不需要第二处。

## 二 判断与理由

### 2.1 为什么这不是「模型胡编」，而是「提示词拆条拆出来的」

第 3 条原文是「文字里补一句"你点一下想要的时间就行"，然后停下来等学生选 —— **这一步绝不能省**」。
一句话里有三个东西：动作（补一句）、前提（无）、强调（绝不能省）。
模型对"绝不能省"最敏感，对"前提"最不敏感——**它照做了被强调的那一半**。

所以第 1.1 条不是"加强语气"，是**补回被拆掉的前提**。

### 2.2 为什么兜底必须做，不能只改提示词

提示词是软约束。`planner.py:6082` 早就写着「**不要只在文字里罗列时间段**」，
它这次照样罗列了——**同一个提示词已经被违反过一次**，再加一句更强的措辞，没有理由相信它下次一定听。
**能机器强制的东西，不要交给模型自觉。** 这是本项目一贯的做法（`kind` 由系统盖章、不交给模型决定，同一个道理）。

### 2.3 为什么判据是 `options` 而不是 `intent`

`intent == "chat"` 的句子**也可能真的出卡**（`main.py:1755-1758` 注释里那条真机记录就是这种形状）。
按 intent 判 = 会误伤真实的出卡对话，把「点一下这张卡」这种**正确**引导也改掉。
按 `options` 判 = 只盯着"屏幕上一张卡都没有"这个客观事实，误伤面最小。

### 2.4 为什么改写是「换成说一句」而不是「整句删掉」

前文的「周四 14:00-15:40 有大学物理，重叠 40 分钟」和两段空档，是**真的查出来算出来的**，
是这段回答里最值钱的部分。整段删掉 = 把有用的信息一起扔了，学生反而更懵。
换一句「想用哪一段，直接告诉我」——**信息留住，动作从"点"降到"说"，学生照着就能做。**

### 2.5 代价

- 提示词改动：零风险，改的是字符串。
- 出口校验：所有回答多走一次正则。`_CARD_TALK_RE` 是短词表、无回溯风险，代价可忽略。
- **唯一真实风险是误伤**：一句正常的出卡对话如果 `options` 因故为空，会被改口。
  所以 §三 的 T2（正控）是本单**必须过**的那一条。

必须成对，缺一条就是哑弹：

## 四 不做的事

1. **不改判定层** —— 「撞时间了有一处」该不该判成办事，是 76 之后的话题，两天窗口内不动。
2. **不改 `propose_slots` 的返回形状** —— 卡没问题，问题在"该出的时候没出"。
3. **不加新工具** —— 78 号单（改期待办）已砍，别在本单里顺手加。
4. **不动 `main.py:875` / `:1127` / `:1160` 那些「勾一个」** ——
   那些是**真出卡**的路径里的话术，本来就该这么说。本单只处理"没卡"的情况。
5. **不承诺"以后一定出卡"** —— 本单只保证：**没卡的时候不说有卡的话**。

## 五 给执行方的三句

1. **判据挂 `options`，不许挂 `intent`。** 挂 intent 就会把真出卡的对话改坏，
   而那种坏法很难在自测里发现（屏幕上卡好好的，只是那句话被改了）。
2. **T2 正控是本单的命门。** 本单所有的"改"都是"在某些条件下不许改"。
   如果没有一条测试钉住"该不改的时候一个字都没改"，这次改动就是不可验证的。
3. **词表宁短勿长。** 我给的 `_CARD_TALK_RE` 里每一个词都是拿真机句子换来的，
   你**不要**为了"更保险"往里加「确认」「点」「选」这种泛词——那会把
   `已为你生成确认条，点【确认】生效`（真出卡后的正确说法）一起改掉。
