## 〇、现场事实（全部实测，2026-10-22 16:20）

`app/data/kb.json` 现在两条，正好是一对样本：

```json
{"question": "健身房价格", "answer": "一个月159，单次30", "keywords": ["健身房"]}     ← 手写短词
{"question": "游泳馆价格", "answer": "单次30",           "keywords": ["游泳馆价格"]}   ← 留空兜底，整句
```

三层各自的状态：

| 层 | 现状 | 证据 |
|---|---|---|
| ① 「粘贴一句话 → 拆词 → 填进关键词框」（§九 原需求） | **完全没做** | `grep -rn "derive_kb_keywords" app/` 只命中**定义处 + 它自己的 docstring**，零调用方；管理端只有 `kq/ka/kk` 三个裸输入框 |
| ② 留空保存 | 做了，但结果可能是**原句** | `_kb_row`：`kws or kb_head_words(question)`；而 `kb_head_words("游泳馆价格") == ["游泳馆价格"]` |
| ③ 查的时候认不认"这是派生词" | **没做**（#46-I 未落地） | `faq._entry_kws` 第一段 `if hand: return hand` 太早返回，docstring 写的"或存的就是 `kb_head_words` 那几个"那一支不存在 |

③ 的实际代价（实测）：

| 学生说 | 现在 | 补上那一支后 |
|---|---|---|
| 游泳馆价格 | ✅ | ✅ |
| 游泳馆多少钱 | ✅ | ✅ |
| **游泳多少钱** | **❌ 查不到** | ✅ |
| **游泳多少钱一次** | **❌ 查不到** | ✅ |

补上后这条用的词：`["游泳馆价格", "游泳馆", "泳馆价", "馆价格", "游泳", "泳馆", "馆价"]`。
而手写那条 `["健身房"]` **修复前后都只用 `["健身房"]`** —— 正是设计约定的"手写词一个字不动"。

`kb_head_words` 为什么有时吐整句（这决定了 B 必须存在）：

```
游泳馆价格        → ['游泳馆价格']      ← 整句（无虚词，整片就是一个词片）
健身房价格        → ['健身房价格']      ← 整句
宿舍报修电话      → ['宿舍报修电话']    ← 整句
图书馆几点开门    → ['图书馆']          ← 能拆（"几点"是虚词）
补办学生证多少钱  → ['补办学生证']      ← 能拆
考试周图书馆开到几点 → ['考试周图书馆开到'] ← 残渣
```

⇒ **规则层永远拆不对"游泳馆价格"这种短语**，因为它没有虚词可劈、也没有滑窗可用。
这一层只能由"按句意判断"来做 —— 这就是 B 要模型的理由，不是偏好。

## 一、A：`_entry_kws` 补上"派生词"那一支（`app/modules/faq.py`）

现状（`faq.py` 的 `_entry_kws`，docstring 已写、代码没写）：

```python
hand = [str(k).strip().lower() for k in (item.get("keywords") or []) if str(k).strip()]
if hand:
    return hand                      # ← 只要非空就原样返回，"派生词"那支没实现
heads = [str(k).lower() for k in kb_head_words(str(item.get("question") or ""))]
return heads if typo else kb_expand(heads)
```

改成：

```python
q = str(item.get("question") or "")
hand = [str(k).strip().lower() for k in (item.get("keywords") or []) if str(k).strip()]
# 「派生词」= 关键词为空，**或存进去的就是 kb_head_words 那几个**（#46-I）。
# 为什么要认后一种：`_kb_row` 存的时候会用 kb_head_words 兜底，而「游泳馆价格」这种无虚词短语
# 兜底结果就是**原句整串**。不认它，这条就被当成"管理员手写关键词"，
# 享受不到 kb_expand 的 3 字/2 字滑窗 —— 实测「游泳多少钱」直接查不到。
auto = (not hand) or hand == [str(w).lower() for w in kb_head_words(q)]
if hand and not auto:
    return hand
heads = [str(k).lower() for k in kb_head_words(q)]
return heads if typo else kb_expand(heads)
```

⚠️ **两个圈都要走这套**（`typo=False` 与 `typo=True` 是同一个函数，改一处就够，但断言要两圈都测）。
⚠️ **`kb_head_words` 的返回值要 `lower()` 再比**：`hand` 已经 lower 过，不 lower 另一边就是永远不相等（这条错误会让 A 静默失效，表现与没改一模一样）。
⚠️ 判据用 `==` 整表相等，**不是子集**：管理员手写了 `["游泳馆","价格"]` 时 `hand != kb_head_words(...)`，仍按手写处理（他的判断优先）。

## 二、C：停用词与泛词各补几项（`app/store.py`）

### 2.1 `_KB_STOP` 加两个词

```python

```

实测（改前 / 改后，2026-10-22 16:22 跑的）：

| 问句 | 现在 | 补「什么时候」「有没有」后 |
|---|---|---|
| 考试周图书馆什么时候开门 | `['考试周图书馆', '时候开门']` ← 残渣 | `['考试周图书馆']` |
| 图书馆什么时候关门 | `['时候关门', '图书馆']` ← 残渣 | `['图书馆']` |
| 游泳馆什么时候开放 | `['时候开放', '游泳馆']` ← 残渣 | `['游泳馆', '开放']` |
| 宿舍有没有热水 | `['宿舍有没有热水']` ← 整句 | `['宿舍', '热水']` |

### 2.2 `_KB_GENERIC` 加三个词：`"开放"`、`"多少钱"`、`"多久"`

这三个是**实测漏网的**（我按 B 的校验函数跑出来才发现的，不是推的）：

| 词 | 为什么漏 | 后果 |
|---|---|---|
| `"开放"` | `_KB_GENERIC` 有 `"开门" "关门"`，偏偏没有 `"开放"` | 「游泳馆什么时候开放」拆出 `['游泳馆', '开放']`，「开放」占一个名额 |
| `"多少钱"` | `_KB_STOP` 里只有 `"多少"`，`_KB_GENERIC` 里只有 `"价格"` | 模型给 `["多少钱", "怎么", "如何"]` 时，「多少钱」**原样通过** → 这条被放宽到所有问价钱的句子 |
| `"多久"` | 同上（见 §2.3 的完整理由） | 模型给 `["学生证", "补办学生证", "补办", "多久"]` 时，「多久」被留下来 |

### 2.3 **不要**把 `"多久"` 加进 `_KB_STOP`（但要加进 `_KB_GENERIC`）

这两件事看着矛盾，实际是两个函数：

| 表 | 谁在用 | 加 `"多久"` 会怎样 |
|---|---|---|
| `_KB_STOP` | `_kb_split` 拿它**劈词** | 「图书馆能待多久」被劈成 `['图书馆能待']` ← **引入新残渣，更坏** |
| `_KB_GENERIC` | `_kb_clean` 拿它**过滤**（不劈词） | 只让整词等于「多久」的被丢掉，**不改变任何劈词结果** |

实测确认（加 `_KB_GENERIC` 后 `kb_head_words` 一个都没变）：

```
图书馆能待多久        → ['图书馆能待多久']    ← 和加之前一模一样，没有新残渣
图书馆什么时候关门    → ['图书馆']            ← 「什么时候」进了 _KB_STOP，残渣消失
考试周图书馆什么时候开门 → ['考试周图书馆']
```

残渣比整句更坏：整句至少带完整语义，`"图书馆能待"` 会被 `kb_expand` 拆成「图书」「书馆能」这种噪声去匹配。
⇒ 这条写进注释，免得下一位"顺手补齐"又踩回来。

⚠️ **`_STOP_RE` 是模块级预编译的**（`"|".join(...)` 那一行）。改 `_KB_STOP` 必须让它重新生成，
否则词表改了、正则没改，表现是"改了等于没改"——静默失效，最难查。落地时确认这两行在同一个地方、顺序正确。

## 三、B：模型按句意拆词（核心）

### 3.1 后端接口

```python
@app.post("/api/admin/kb/split", dependencies=[Depends(verify_admin)])
async def admin_kb_split(req: Request):
    """一句话 → 模型按句意拆出的**检索关键词**（#55-B）。只产建议，**不写库**。

    为什么不用 `store.derive_kb_keywords`：那是**滑窗 n-gram**。实测
    「游泳馆价格」只能吐出整句 `['游泳馆价格']`（无虚词可劈），
    「考试周图书馆开到几点」会吐 12 个碎片（含「试周图」「馆开到」这种非词）。
    管理员要的是"这条该用什么词才搜得到学生那句话"，这件事只有按句意判断才做得对。

    ⚠️ 这是**全项目唯一允许模型碰关键词的地方**，且它仍然只产草稿：
       模型不知道学校有几栋楼、也不知道学生管游泳馆叫「泳池」还是「游泳池」，
       所以结果必须**回给管理员看、让他改**，不许直接落库。
    ⚠️ 失败一律 502 + 一句人话，**不许回退到 `derive_kb_keywords`**：
       那等于"模型挂了就悄悄换成固定格式拆"，管理员看不出区别，却再也得不到句意结果。

    :param question: 一句话，≤100 字（长到超出的不是"一个学生问题"，是段落，该进文档知识库）
    """
    body = await req.json()
    q = str((body or {}).get("question") or "").strip()
    if not q:
        return JSONResponse({"error": "先把问题写进去，我按它拆词"}, status_code=400)
    if len(q) > 100:
        return JSONResponse({"error": "这句话太长了（限 100 字），问题写成一句话更准"}, status_code=400)
    try:
        gateway = ModelGateway(user="内部:知识库拆词")     # 用量在「用量统计」里单列一行
        reply = await gateway.chat(
            [{"role": "system", "content": _KB_SPLIT_PROMPT},
             {"role": "user", "content": f"问题：{q}"}],
            max_tokens=120,       # 拆词就那么点大；给大了模型开始解释"为什么这么拆"
        )
    except LLMError as e:
        print(f"[拆词] 失败（kind={getattr(e, 'kind', '?')}）：{e}")
        return JSONResponse({"error": _say_llm_error(e)}, status_code=502)
    words, why = clean_split_words(q, _extract_json_obj((reply or {}).get("content") or ""))
    if not words:
        return JSONResponse({"error": why}, status_code=502)
    return {"ok": True, "keywords": words}
```

### 3.2 prompt（`_KB_SPLIT_PROMPT`，放 `_SERVICE_PROMPT` 附近）

> ⚠️ 下面两个示例是**按设计给的期望形状**，不是"实测过模型这么回"。落地后必须真机跑一遍，
> 把模型**实际**回的样子记下来；如果它回得不一样，先改 prompt，别改断言去迁就。

```
你是校园助手的知识库整理员。管理员会给你一条「学生可能问的问题」，你只负责拆出**用来检索的关键词**。

一、判断顺序
1. 先判这句问的是**哪个对象**：游泳馆 / 图书馆 / 校车 / 补办学生证 / 宿舍报修…
2. 再判问的是这个对象的**哪个方面**：价格、开放时间、地点、流程、电话…

二、关键词怎么给
- 对象词必须有，而且要给**学生可能用的别的说法**：全称 + 常用简称 + 口语叫法
  （游泳馆 → 游泳、泳池；补办学生证 → 学生证、补办）
- 方面词**只在它能区分同类条目时**才给：同一条目多半只有一条，通常不需要。
- 每个词 **2~8 个字**，一共 **2~6 个**。
- **禁止**把问题原句整串当关键词（这是最常见也最没用的错）。
- **禁止**给任何问题都会有的泛词：多少钱、怎么、如何、几点、时间、电话、流程、价格、收费、能不能、可以。

三、输出
只输出一个 JSON，不要解释、不要 markdown 代码块：
{"keywords": ["…", "…"]}

示例 1
问题：游泳馆价格
{"keywords": ["游泳馆", "游泳", "泳池"]}

示例 2
问题：考试周图书馆开到几点
{"keywords": ["图书馆", "考试周", "开放时间"]}

示例 3
问题：补办学生证要多久
{"keywords": ["学生证", "补办学生证", "补办"]}
```

为什么示例里一个"价格/时间/多久"都不给：`_KB_GENERIC` 已经把 `价格 收费 费用 时间 电话 开门 关门`
列为"能粘上任何问句"的泛词。给了它们，等于把这条放宽到所有含该词的问句
（「食堂价格」也会命中「游泳馆价格」）。**对象词才是区分度**。

### 3.3 返回校验（`store.clean_split_words`）—— 这一段防的是"模型偷懒"

**放在 `app/store.py`（公开名，不加下划线），不放 main.py**：判断要用的 `_KB_STOP` / `_KB_GENERIC`
是 store 的私有词表，跟着词表走才不会出现"main 直接 import 别人的私有名"这种越界。
main.py 那边 `from app.store import clean_split_words` 调用即可。

```python
def clean_split_words(question: str, obj) -> tuple[list, str]:
    """模型给的拆词结果过一遍闸。返回 (可用词表, 不可用时的人话原因)。

    这里的每一道都是**实测过会出错**的，不是防御性编程的仪式：
      · 模型偷懒时会把原句还回来 —— 现在 `kb.json` 里那条 `["游泳馆价格"]` 就是这个 bug 的样子，
        所以"词 == 原句"必须丢；全丢就报错，不许存进去。
      · 泛词（`_KB_GENERIC`）会让这条放宽到所有含该词的问句（「食堂价格」也命中「游泳馆价格」），扔掉；
        但如果扔完一个都不剩，说明模型没拆出实体词，**报错**而不是存一个空的关键词 ——
        空关键词会走 `_kb_row` 兜底，又变回整句（绕一圈回到原点）。
      · 长度、标点、尖括号：前端 `esc()` 之外再拦一道（同 `_bad_service_field` 的做法）。
    """
    raw = obj.get("keywords") if isinstance(obj, dict) else None
    if not isinstance(raw, list) or not raw:
        return [], "模型没给出关键词，请手动填写。"
    # 比较前把标点去掉：模型很爱在词后面带个问号，而原句里也带一个 —— 不去掉就判不出"这是原句"
    norm = lambda s: re.sub(r"[^\w一-鿿]+", "", str(s or "")).lower()
    q = norm(question)
    out, seen = [], set()
    for w in raw:
        w = norm(w)
        if not (2 <= len(w) <= 8):
            continue
        if w and q and w == q:                        # ← 原句本身（含标点差异）
            continue
        if w in _KB_STOP or w in _KB_GENERIC:         # 泛词/虚词
            continue
        if "<" in str(w) or ">" in str(w):
            continue
        if w in seen:
            continue
        seen.add(w); out.append(w)
    if not out:
        return [], "模型这次只拆出了原句或泛词，换个说法再试一次，或者手动填关键词。"
    return out[:6], ""
```

⚠️ **`norm()` 里 `[^\w一-鿿]` 必须把标点全吃掉**，否则「游泳馆价格？」和「游泳馆价格」判不出来，
   模型那句原句就溜进 `keywords` 了 —— 而一旦存进去，A 那一层也不会再救它
   （`hand != kb_head_words` 时按手写处理），等于这个 bug 原地复活。
⚠️ **不要用 `_kb_clean` 来代替这个函数**：`_kb_clean` 会按长度排序并截断，还会把 2 字词拿去和
   `_KB_GENERIC` 比 —— 那是给自动派生用的口径，跟"审核模型给的建议词"不是一件事。

```js
});
```

⚠️ **按钮标题不许写"智能"**：写「自动拆词」并让结果落在可编辑输入框里，管理员才好判断该不该改。
⚠️ 面板文案「留空则自动从问题里提取」要改成「**留空按问题原文提取，建议先点自动拆词**」——
   现在这句话在承诺一件它对短短语做不到的事（实测「游泳馆价格」提取出来就是原句）。

## 四、三件事的分工（**不许互相顶**）

| 场景 | 谁负责 | 结果 |
|---|---|---|
| 管理员点「自动拆词」并保存 | **B（模型）** | 关键词 = 模型给的实体词，`_entry_kws` 按**手写**处理，原样用 |
| 管理员不点、留空保存 | ② `_kb_row` 兜底 + **A** | 关键词 = `kb_head_words` 那几个，`_entry_kws` 认出是派生词 ⇒ 允许 `kb_expand` 补片段 |
| 老数据（`["游泳馆价格"]` 这种） | **A** | 同上，认出来后补片段，**不用迁移数据** |
| 管理员自己敲词 | A 不动 | 原样用，一个字不扩（他的判断优先） |

⇒ **A 不会被 B 替代**：B 管以后，A 管存量 + 留空那条路。B 上线后 A 照样要测（用例就是那两条现有条目）。

### 5.1 变异（改坏必须红）

### 5.2 真机

1. **老条目自愈**：不点任何按钮，学生端问「游泳多少钱」→ 命中「游泳馆价格」，答「单次30」
2. **老条目边界**：问「食堂多少钱」→ **不许**命中游泳馆那条（说明泛词没有把范围放太宽）
3. **拆词按钮**：管理端 → 知识库 → 问题填「游泳馆价格」→ 点「✨ 自动拆词」→ 关键词框变成
   `游泳馆, 游泳, 泳池`（3 个左右实体词，**不含**原句、不含"价格"）
4. **手改有效**：把拆出来的词删到只剩 `游泳馆` → 保存 → 学生问「游泳多少钱」→ **查不到**
   （证明存的确实是框里那几个词，没有被代码悄悄补全）
5. **原句不许回潮**：问题填「宿舍报修电话」→ 点拆词 → 结果**不得**包含「宿舍报修电话」整串
6. **失败可见**：把 `app/data/settings.json` 里的 key 临时改坏 → 点拆词 → 界面出现
   「❌ 拆词没成功：…（可以手动填关键词）」，**且 `kb.json` 一个字节没变**
7. **权限**：`curl -X POST /api/admin/kb/split` 不带头 → 401/403（它带 `verify_admin`）
8. **用量**：拆一次词，「用量统计」里多一条 `内部:知识库拆词` 的流水

### 5.3 回归

- `_kb_parts` 的条目命中与文档命中都还在（别把 `doc_hits` 那一路碰坏）
- 「考试周图书馆开到几点」这类**已经能查**的句子，改完仍然能查（A 只放宽、不收紧）
- 打错字那一圈：「图收馆几点关门」仍能翻到图书馆那条（`typo=True` 也要走同一套 `auto`）

## 六、不做的事（写下来免得下一位以为是漏）

1. **不给条目存"模型拆的原始结果"**：只存管理员最后确认的 `keywords`。存两份，改一个漏一个。
2. **不做批量重拆历史条目**：A 已经让存量自愈；批量重拆要跑 N 次模型，收益是"关键词更好看"，
   代价是把已经能用的数据重写一遍（而且要处理"重拆后反而查不到"的回归）。
3. **不让模型直接写库**：`/api/admin/kb/split` 只回 JSON，落库仍走 `POST /api/admin/kb`。
   这条是项目的硬红线（模型只出提案、写库归系统），拆词也不例外。
4. **不给学生端暴露拆词能力**：学生问一句话就自动拆词扩检索，会把"检索词"变成模型每次现编，
   同一句话两次结果可能不同，没法复现。
