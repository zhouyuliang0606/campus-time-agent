## 三、两处与驿站端**故意不一样**（都是对着这页的代码定的，不是抄漏）

1. **「API 配置」那档进门不现拉。** `loadApiSettings()` 是把值**写回输入框**的
   （`akey.value = ...`），一进就拉等于把管理员刚敲到一半的 key/base_url 抹掉。
   station 那边"进哪块现拉一次"是安全的，因为这页那档不是。真机验过：填一半 → 切走 → 切回，值还在，

2. **口令条常驻顶栏**，不是内容区第一张卡。七档全都吃它：放进某一档就会出现

## 六、收尾全量撞出来的东西：一批断言**依赖"几点跑的"**

给管理端收口跑全量时，`FULL_EXIT=1`：**3556 通过 / 5 失败（57 批）**，
红在 `test_23`（3 条）与 `test_45`（2 条），全是同一族句子：「今晚去健身怎么样」「今晚安排去看电影」——
卡一张都不出（`[]`）。归因链（每步都有实测，没有一步是猜）：

1. **严格克隆里同两个文件同样红 3+2** → 不是他手测把基线弄漂（那条 ★ 老账这次排除掉了）。
2. **拿改动之前的提交 `b00b635` 建工作树单跑，一模一样红** → 不是我这几笔引入的（本轮代码只动了 admin.html/test_57/文档）。
3. 我第一版假设是"晚上没空档"，于是给测试钉了个 19:00 —— **探针直接推翻我自己**：钉 19:00 照样 0 张卡。
4. 扫一遍钟点才看到真分界：**钉 08:00~16:00 出 1 张卡，钉 18:00 起 0 张**。
   机理是那句「今晚」要满足"起手不早于 `now+30`，还要剩 ≥ `AUTO_SLOT_LENGTH`(90) 分钟"，
   而 `DAY_END = 22:00` —— 所以**傍晚之后跑这批必红**，白天绿、夜里红，长得跟回归一模一样。

修法（只动测试，不动产品口径）：

- `_harness` 加 `pin_now(小时, 分钟)`（with 生效、出去原样还原，`_now_minutes` 只在 planner 里被调用，
  一处打全覆盖）—— 两个文件共用这一份实现，不在各自文件里抄两遍；
- 出卡那条钉到 **10:00**（任何时候都有余量）；
- **成对**再钉一条 **20:40**：`21:10` 起手只剩 50 分钟，够不着 90 → 断言它**不硬塞卡**、
  回话也不许说「已经排好/已写入」。只有前面那条的话，"把挑时段整个关掉"也能蒙成绿（指南 4u）。

时刻为什么挑 20:40 而不是更晚：拿变异 X5 试过 —— 钉到 22:30 时，连把门槛降到 10 分钟都不出卡，
**那条成对断言就成了空的**。挑就挑"只差门槛一挡"的那个点。

变异：X1（把出卡圈的钟点挪到 20:40）红 2 条、X2（把 `AUTO_SLOT_MINUTES/LENGTH` 都降到 10）
两边各红 1 条、X4（test_23 那句同样挪）红 3 条，全部逐字节还原。
**X3 我撤了并记在这儿**：本想"把挑时段整个关掉"，锚点其实落在 `find_free_slots` 上，
停掉它会让 `what_to_do_suggestion` 那边 `TypeError` 崩 —— rc=1 但一条 ❌ 都没有，
那是"崩"不是"红"（指南 4h 那一族：红 0 先怀疑变异本身没生效）。

**留下的口子（照实说，没自主做）**：`AUTO_SLOT_LENGTH=90` 与 `DAY_END=22:00` 这两个口径
是不是该在深夜放宽、或者那句回话该不该更明确，属于产品判断，等他点头；本轮只把**测试**变成与墙上时钟无关。
同族还可能藏在别的批里（凡断言"替他挑出时段/候选卡"又带「今晚/今天」的），
下次全量若在傍晚后跑又红，先照这条路归因，别当成回归。
