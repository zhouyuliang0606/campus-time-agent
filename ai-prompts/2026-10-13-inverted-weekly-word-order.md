## 三、自己踩出来的一个误判：「每周两次」

第一版倒装只把「周」当可选单位写在拦截表前面，结果「周天去跑步每周两次」被认成"每周日"。
原因不在字符表少写了字，而在**正则引擎会挑不命中 lookahead 的那条路走**：
`(?:周|星期|礼拜)?` 既然可选，引擎就选"不吃掉周"，于是 lookahead 在「每」的后面直接看到「周」——
而「周」当时不在拦截表里，通过。堵住之后两条路都不通：
「…每周」收尾 ✓ 认，「…每周两次 / 每周五 / 每月」✗ 各归各的主人（频次走 test_35 那一路、
每月归 `unsupported_period` 硬闸门）。这一条有变异 X3 专门盯着。

## 四、我在注释里写了两条没测过的话，被自己的变异打回来

`weekly_repeat_day` 的 docstring 原话是「正装先查（它更具体，也免得倒装把「每周五汇报」抢走）」，
拦截表旁边原话是「上面先查，5 不会被这里的 3 抢走」。写了 X4（调换两条的先后）想验证，结果：

```
X4 调换正装/倒装的先后 → 只有那条形状断言红，行为一条都没红
```

量下来（`chk_order_diverge.py` / `chk_comment_examples.py`）：
「周三开会每周五汇报」倒装那条**根本不命中**（靠的是拦截表，不是靠顺序）；
「每周三上课，周日去健身房每周」两条同时命中、给的都是 3。
也就是说"谁先查"目前不改任何结果 —— 那两句注释就是不实陈述。
两处都改成了实测结论，顺序仍保留（更具体、更严的那条在前是刻意的结构，test_39 用形状钉钉住它，
断言文案也写清了「顺序不改结果」，免得下一个人把它当成"顺序有行为差异"的证据）。

## 六、遗留：截图那句这轮没解决，02 也不解决它

「每周要背七次单词」被拦不是识别失败，是**有意否决**（实测 `chk_prompt02_pre.py`）：

```
每周要背七次单词 → unsupported_period='每周要背七次'（拦）    wants_add_todo=True 但被硬闸门否掉
一周要背七次单词 → unsupported_period=''（走"一周 N 次"铺 N 条那一路）
每周背三次单词   → unsupported_period='每周背三次'（拦）
```

差别只在「每+周+数量」这个写法。用户抱怨的「这种任务完成不了，我也不往日程堆，太多了乱」正是这条 ——
要做的是让「每周七次」和「一周七次」走同一条路（还要加"次数超过一周可用时段就不铺、改成问一句"的上限），
**这是另一个决定**，不在 01 也不在 02 里，等他拍板。

顺带把 02 的一条前提量了出来：`每天/天天/每日` 确实只在 `_UNSUPPORTED_PERIOD`（planner.py:2034）里，
现在三句全部 `wants_add_todo=False`；施工单说「摘掉元组三项就彻底放开」——**摘掉之后会不会真的变 True 还没测**
（`wants_add_todo` 内部就调这条否决，摘掉应当就通，但要实测才敢写进实现）。
