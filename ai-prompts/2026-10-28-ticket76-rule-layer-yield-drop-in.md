### 1.2 判据：三条，全是纯函数、零 API、微秒级

```python
# ── #76 规则层能力清单 ───────────────────────────────────────────────
# 这张表就是「规则层会算什么」的可执行文档。**加一行 = 学会一类说法。**
_RULE_CAN_DO = frozenset({
    "今天", "明天", "后天", "大后天",
    "周一", "周二", "周三", "周四", "周五", "周六", "周日",
    "下周", "本周", "这周", "下星期",
    "上午", "中午", "下午", "晚上", "早上", "夜里",
    "周末", "双休",       # ★ 这一行是 75 挣来的（planner.py:480 `weekend_mode`）
    "每天",               # 一条 daily 习惯，`unsupported_period` 已放行
})

# 规则层算不了、且**现在没有任何机制拦**的说法。
# 收录标准只有一条：`unsupported_period()` 拦不到它。
#   —— 拦得到的（每月/下个月/隔天/每个周末…）一律不收：那边有
#      `_period_reject_response` 的专门话术，如实告诉他"这个我办不了、能办的是哪几种"，
#      比丢给引擎更诚实、更可控。**同一件事不许两处管。**
_RULE_CANNOT = ("隔周", "双周", "月底", "季末", "节假日", "寒暑假", "调休")


def rule_cannot_do(text: str) -> str:
    """原话里有'规则层算不了'的约束吗？返回那个词；没有返回空串。"""
    t = text or ""
    for w in _RULE_CANNOT:
        if w in t and w not in _RULE_CAN_DO:
            return w
    return ""


_UNPARSED_MIN = 3     # 擦完还剩几个字，才算"有内容、但我们没认出来"


def title_unparsed(text: str) -> bool:
    """有实词、却抠不出事名？—— 不是"他没说要加什么"，是"我们没认出来"。

    分界线全靠实测校准（见 §3.1 T3/T4）：
      '时间打篮球'   (5 字) → True   ← 有内容，认不出
      '找个时间打篮球'(7 字) → True
      ''            (0 字) → False  ← 真的什么都没说（"帮我安排一下"），该去追问
    """
    if todo_title_of(text) != "待办":
        return False
    return len(_strip_title_noise(text)) >= _UNPARSED_MIN
```

**判据自洽性验收表**（写测试时照抄，一条都不许错）：

| 句子 | `rule_cannot_do` | `title_unparsed` | 结论 |
|---|---|---|---|
| 周末安排时间打篮球 | `''` | **True** | 让渡 |
| 下周找个时间打篮球 | `''` | **True** | 让渡 |
| 隔周打球 | `'隔周'` | True | 让渡 |
| 月底交报告 | `'月底'` | True | 让渡 |
| 节假日复习 | `'节假日'` | True | 让渡 |
| 帮我加个游泳 | `''` | **False**（title=`游泳`） | **放行** |
| 帮我安排一下 | `''` | **False**（`strip=''`，0 字） | **放行 → 追问** |
| 周末打篮球 | `''` | **False**（title=`打篮球`） | **放行** |
| 每两周打一次篮球 | `''` | False（title=`每两周打篮球`） | **放行 → `_period_block` 拦** |

### 1.5 缺口记账 `_record_gap`

让渡不是白让——**每让一次，就记一笔"规则层不会什么"**。

```python
_GAP_LOG = Path("app/data/intent_gaps.jsonl")


def _record_gap(session_id: str, *, why: str, text: str) -> None:
    """规则层让渡一次记一笔 —— 这是"下一步该补什么"的唯一数据源。

    纪律：记账失败**绝不许**影响对话（整段 try/except 咽掉）。
    """
    try:
        _GAP_LOG.parent.mkdir(parents=True, exist_ok=True)
        with _GAP_LOG.open("a", encoding="utf-8") as f:
            f.write(json.dumps({
                "at": datetime.datetime.now().isoformat(timespec="seconds"),
                "session": session_id,
                "why": why,
                "text": (text or "")[:200],
            }, ensure_ascii=False) + "\n")
    except Exception:
        pass
```

落盘位置 `app/data/intent_gaps.jsonl`（与 `intent_samples.json` 同级，天然 gitignored）。

## 二、判断与理由

### 2.1 为什么是「让渡」而不是「撤卡」

这是本单唯一一个真正的设计决策，写清为什么。

「校验不过就撤卡」的做法（我最初的想法）在**有模型可用**的前提下是错的：

> 撤卡 = 学生说了一句系统听得懂一半的话，系统回「我做不到」。
> 让渡 = 同一句话，交给一个能算的，然后在 5 秒内给出正确答案。

**「做不到」和「换个人做」之间差着整个产品体验。** 而且：
- 撤卡这条路上，「周末」永远无解（规则层不会就是不会）
- 让渡这条路上，`_run_agent_loop` 早就存在、早就在用、零 key 还有兜底

### 2.2 为什么靠「能力清单」变快，不靠「样本库」变快

用户问过：「怎么加护栏又不让它学完变慢？」答案是**这里要学的不是映射，是能力**。

| | 样本库 | 能力清单 |
|---|---|---|
| 学的是 | 这句话 → 什么意图（映射） | 规则层会不会算（**边界**） |
| 变快的范围 | 只有这一句 | **这一类** |
| 会过期吗 | 会（`去完图书馆了` 就被学死成 add_todo） | 不会 |
| 对「周末」有效吗 | **无效**（且这句根本不进 `classify`，见 §2.4） | **有效** |

**加一行 `_RULE_CAN_DO` = 学会一类说法，永久生效、0 秒。** 这就是"学完不变慢"的唯一正解。

### 2.3 为什么让渡点不能放到出口

旧版 76（出口校验闸）要在**所有**提案卡出门前拦一道。本单把它缩到**规则层这一支的入口**，
范围从「全站所有卡」降到「规则层单独判决的句子」，理由三条：

1. 模型出的卡本来就是模型自己算的，不归护栏管
2. 出口是全站唯一通道，写错 → **一张卡都出不来**；入口写错 → 只是这一句走慢路
3. 四个出口 vs 一个入口，改一处比改四处少漏三个

### 2.4 「周末打篮球」这句为什么样本库救不了

`intent.py:700` 的 `hit = match_sample(text)` 是 `classify()` 内部第一行，
而 `classify()` 只在 `main.py:2335` 的条件成立时才跑：

```python
if (_rule_hit is None or _need_review) and not is_confirmation(message) and not _is_material:
```

对这句：`_rule_hit=add_todo` + `_need_review=False` ⇒ **两个都为假 ⇒ `classify` 不跑
⇒ `match_sample` 一次都没执行**。

⇒ 把这句写进样本库是**死数据**：写了也读不到。且样本库只记 `intent`，不记日期，
**就算读到也救不了星期几算错**。

### 2.5 代价要认

| 代价 | 量级 | 说明 |
|---|---|---|
| 让渡那一句变慢 | +4~6s | 只有被让渡的句子付，其余句子 0 成本 |
| 多一次模型调用 | 1 次/句 | 高频让渡会烧额度，所以才要缺口记账及早收敛 |
| 零 key 时收益有限 | — | `mock_planner` 不聪明（实测统一回"先上传课表"），让渡在无 key 环境下**不倒退、但也没什么收益** |
| 模型出卡可能弹两张 | 已知老问题 | 用户截图过；不在本单范围，`_remember_todo_options` 覆盖语义那条另论 |

**误伤是本单第一指标**：判据必须"宁可漏、不可冤"。
「帮我加个游泳」被让渡一次（慢 5 秒），比「周末安排时间打篮球」多错一次更难接受。
