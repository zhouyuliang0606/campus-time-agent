# 2026-10-13 · 习惯做完之后：整族扫查出两个洞（其中一个是我上一笔自己造出来的）

## 一、为什么单独再来一份快照

上一份（`2026-10-13-daily-habit-todo-only.md`）交付完 daily，我按老规矩做**整族扫**：
把「删它 / 勾它 / 改它的点」三族口语 × 「一次性 / weekly / daily」三档，全在沙箱里真打一遍接口。
扫出来两个洞，都不是"再补一处判据"能了事的：

| 说法 | 扫出来的真实行为 |
| --- | --- |
| 「每天背单词完成了」 | 系统给他**新增**一件叫「背单词完成」的每天任务 —— 他明明是在报告今天做完了 |
| 「把背单词改到晚上十点」 | 卡上 `repeat=None`；点确认后旧那条（daily）被删、新的**只剩这一天**，"每天"当场没了 |

## 二、第一个洞：是我上一笔造出来的，weekly 从 2026-10-10 起就有同一个形状

`wants_done_todo` 里有一条让路规矩：`if wants_add_todo(t): return False`（新增优先于标记完成）。
上一笔我给 `wants_add_todo` 加了 daily 档，于是「每天背单词完成了」被新增抢走，完成那一族永远轮不到。
顺手查同族的 weekly 档 —— 「每周日写作业完成了」**同样**被抢（这条洞从 2026-10-10 加 weekly 档那天就在，
只是没人拿"周期 + 已然"的句子去打，所以一直没撞出来）。

修法只加在**周期那两档**上，不加到整个 `wants_add_todo` 头上：

```python
if (weekly_repeat_day(t) and ... and not _done_already_said(t)):   # ← 新增档让路给已然
if (daily_repeat(t)     and ... and not _done_already_said(t)):
```
为什么不能加在函数开头：「每天背单词 晚上9点」「以后每天晨跑」这些**照旧要接单**，
加在开头就等于把上一轮做的功能又关掉一半。`_done_already_said` 本身是 2026-10-12 那一轮写的
（先查计划词、再查句末"了/啦/咯"、再查"已经/刚才/昨天"），这里直接复用，不另判一次。

Y13/Y14 两笔变异各拆一档的让路，各红一条 —— 少一档就少一个洞的保险。

## 三、第二个洞：改期是「删旧 + 加新」，新的那一半没接住 repeat

`retime_todo_proposal`（拿着上一张卡改时间）2026-10-11 就带上 `repeat` 了，
但**按名字改期**那一路（`_retime_todo_by_name`，学生说「把背单词改到晚上十点」时走这条）
是从库里的旧条目重拼一张新卡，旧条目身上的 `repeat` 没人抄过来。
前端 `confirm.html` 的【确认加入】又是自己拼 body（只发 title/date/start/end/old_todo_id），
于是两条叠在一起：卡片不带头、body 也不带头 → 落库成一次性，而旧的那条**已经删了**。

补三处：
1. `_retime_todo_by_name` 的 proposal 带 `old.get("repeat")`；
2. `confirm.html` 的 `todo_add` / `todo_pick` 两个 apply body 都发 `repeat: p.repeat || ""`
   （后端白名单认不得的值一律退回一次性，带空串安全）；
3. 回话多一句「它**仍然是每天**都要做的事（只改了钟点，勾完成还是只算当天）」——
   改期是删旧加新，不说不像没动，学生不敢点。

顺带一句：weekly 也一起受益，因为这两处漏本来就跟档位无关。
