## 〇 现场事实

### 0.1 C3：`need_pick` 是个没有出口的出口（**最重**）

学生的原话是「改 **2026-11-09** 那天那个」。工具的参数只有五个：

```python
"op" / "title" / "new_date" / "new_start" / "new_end"      # planner.py:propose_todo_change_tool_tool
"required": ["title"]
```

- **没有 `todo_id`**，也**没有序号/定位日期**的入口；
- `new_date` 的语义是"**改去哪天**"，不是"挑哪一条"。

⇒ 库里真有两条同名「游泳」时：`title="游泳"` → `many` → `need_pick`；
模型下一轮**还是只能传 `title="游泳"`** → 又是 `many` → **同一个回答，可以无限循环**。
实测：三次调用三次同两条候选。**这条路上没有任何一句话能把它们分开。**

同一份 trace 里模型还说「确认条已经挂出来了」，屏上一张卡都没有 —— **#80 那道兜底
当场把它纠成了实话**。所以学生看到的不是"办不成"，是"办不成还被骗了一次"。

> ⚠️ 这条同时推翻 **86测 卡里 R1 的设计前提**：我写的是"学生说『就游泳』→ 模型再调 `title="游泳"` → 出卡"。
> **真同名时这条路根本不存在** —— title 永远是同一个字符串。那是我按"名字能区分"的假设写的，实测证明假设错了。
> R1 要按本单的 `anchor_date` 重写。

### 0.2 C4：模型自己填钟点，没有任何闸

实测 18:02 调 `find_free_slots(今天)`，返回「周五 07:00-10:00 / 11:40-22:00」——
**这个函数不认识 `now`**（`planner.py:114 def find_free_slots(date, min_minutes=60)`，没有 `not_before`）。

模型的处境：它看见"今天 07:00 空着"，又知道学生想改到今天，于是填 `new_start="16:00"`。
16:00 是过去的 —— 卡照样出、点确认**真落库**。

#82 那道 `not_before` 只堵了**系统自己挑**那一支（`auto_slot` 里那次 `pick_free_slot`，test_98 W9 钉着）；
**模型自己填钟点这一支没有闸**。两条路漏一条，等于没堵。

| 条 | 性质 | 能不能在明天前改 |

## 一 修法

### 1.1 `anchor_date`：给同名待办一个出口

`build_retime_existing_proposal` 加一个**只用来收窄候选**的参数（**不影响任何既有语义**）：

```python
def build_retime_existing_proposal(text: str, sem: dict | None = None,
                                   hint_title: str = "", auto_slot: bool = False,
                                   anchor_date: str = "") -> dict:
```

在**收窄之后、判 `many` 之前**插一段（锚点：`pool = hits` 那句之后、`if len(pool) > 1:` 之前）：

```python
    # ★ #87：同名两条时，"名字"这一维已经用尽（title 永远是同一个字符串）——
    #   必须靠"哪天"再切一刀。学生原话「改 2026-11-09 那天那个」里的日期就是这一维。
    #   ⚠️ 只**收窄**、绝不"改去哪天"：改去哪天仍是 new_date 的事，两者语义不许混。
    if anchor_date and len(pool) > 1:
        _hit = [x for x in pool if x.get("date") == anchor_date]
        if _hit:
            pool = _hit          # 收窄到 1 条就往下走；仍 >1 就照旧 many
```

**为什么放在 `many` 之前而不是一开始就缩池**：没命中时必须**原样退回去**
（学生说的那天其实没这条 → 不许变成"没找到"，那是 #84 那条假话）。`if _hit:` 这一句就是那道闸。

工具参数加一个：

```python
                "todo_date": {"type": "string",
                              "description": "要改的那条**在哪天**：'2026-11-09'。"
                                             "只在命中不止一条、需要区分时才填；可空",
                              "default": ""},
```

调用处把它递进去：

```python
    res = build_retime_existing_proposal(" ".join(parts), {"title": hint},
                                         hint_title=hint, auto_slot=True,
                                         anchor_date=(todo_date or "").strip())
```

**默认值 `""` ⇒ 现有 33 条判据一条都不受影响**（`if anchor_date and len(pool) > 1` 两个条件同时为假就整段跳过）。

### 1.2 过去钟点：在工具层拦，别去改 `find_free_slots`

`propose_todo_change_tool` 里，在 **`nd, ns, ne = (...)` 那一行之后、`if nd:` 之前**加一道
（`nd/ns/ne` 已经算好了，不要再 strip 一遍）：

```python
    # ★ #87：模型自己填的钟点没有任何闸（实测 18:02 它挑了"今天 16:00"，卡出了、点了真落库）。
    #   `find_free_slots` 不认识 now，别去改它 —— 它是只读查询，改了会波及
    #   `_slots_lead` / 候选卡 / `list_slots` 那几处对"空档"的理解。
    #   闸放在**提案生成入口**：这里是唯一"要把一个时刻写成日程"的地方。
    if nd or ns:
        _d = nd or clock.today().isoformat()
        if _d == clock.today().isoformat() and ns:
            # 今天 + 报了钟点：必须晚于 now（留 10 分钟缓冲，比 auto_slot 那 30 分钟松一点：
            # 学生自己报的点，卡上还要他看一眼，别把"马上就到"的点也拦掉）
            if to_minutes(ns) < _now_minutes() + 10:
                return json.dumps({"ok": False, "past_slot": True,
                                   "reason": "past",
                                   "now": to_hhmm(_now_minutes())},
                                  ensure_ascii=False)
```

工具描述补一句（**这句是给模型看的，它决定了拦下来之后它会不会说人话**）：

```
"⚠️ 学生报的钟点如果已经过去（今天且早于现在），工具会回 past_slot —— "
"这时**如实告诉他「那个点已经过了」并给出现在几点**，然后按学生没说时间处理、"
"让系统挑一段，**不要**把同一个过去的点再传一遍。"
```

## 二 判断与理由

### 2.1 为什么用 `anchor_date` 而不是 `todo_id` / 序号

| 方案 | 为什么不选 |
|---|---|
| `todo_id` | **模型看不到 id**。它拿到的是 `need_pick` 里那四条 `{title,date,start,end}`，没有 id；让它凭 id 说话就是让它编 |
| 序号（"第 2 条"） | 要模型记住**上一轮清单的顺序**，且学生说的「那天那个」不是序号词。它会把序号当 `title` 传进来 |
| **`anchor_date`** | ① 学生原话里就有（「11-09 那天那个」）；② 模型从 `list_day_todos` / `need_pick` 的返回里**直接抄得到**；③ 它是**已有维度**（每条待办都有 date），不新造概念 |

**一句话：出口必须是模型手里已有的数据，不能是它看不见的 id。**

### 2.2 为什么 C4 的闸放在工具层，不去改 `find_free_slots`

`find_free_slots` 是**只读查询**，它对"今天 07:00 空着"这个回答**没错**——
错的是"把 07:00 写进日程"这个动作。改查询函数会让候选卡、`list_slots`、
`_slots_lead` 全都跟着变，而那些地方各自有各自的取舍（#82 只给其中一支加了 `not_before`，
就是因为另一支不该加）。

**判据：闸要放在"动作"上，不放在"读数"上。**

### 2.3 代价

- 工具参数 5 → 6 个（`todo_date`）。模型选择面几乎不变，它是可选的。
- `build_retime_existing_proposal` 多一个默认空串的参数 —— **确定性分支（`main.py:3727`）一个字都不用改**。
- C4 那道闸会多一种返回形状 `past_slot`。**模型见不到它会瞎猜**，所以 §1.2 那句描述是配套的、不是可选的。

## 四 不做的事，以及为什么（这三条要写进 #79 的「局限」）

### 4.1 C1「加一节组织课」被加成待办 —— **判据是对的，别去动它**

实测（进程内直接调）：

| 句子 | `wants_add_course` |
|---|---|
| 周三晚上八点加一节组织课 | **True** |
| 周三晚上加一节组织课 | **True** |
| 周三下午加一节实验课 | **True** |
| 周三晚上 19:00 加一节组织课 | **True** |

⇒ **规则层认得出**，`main.py:4116` 那道 `and not wants_add_course(message)` 硬闸也在，
注释写的正是"加课优先于加待办"。所以这句被加成待办，**是中间某一支先把它截走了**
（或者它压根没走到 `:4368 if wants_add_course(message):`）。

**这是"哪一支先抢"的问题，不是"判据不够"的问题。** 修它要挪分支顺序 ——
那是 #76 那一族的核心，明天动它的风险（打崩 5508 项、且坏在看不出来的地方）**远大于**它现在的伤害（一句说错）。

⇒ **只做 §1.3 那行工具描述**（让模型至少别拿 `propose_todo_tool` 去加课），根因登记不修。

### 4.2 C5「背单词是每周三的…挪到九点以后」丢 `repeat` —— 两层，只补一层等于骗人

- 第一层：规则层把它听成"加待办"（同 §4.1，不动）；
- 第二层：`def propose_todo_tool(title, when, date, start, end)` **没有 `repeat` 入参**（已核实）。

只给工具加 `repeat` 参数，第一层不动 ⇒ 那句话还是走不到这个工具。**加了参数不等于修了问题**，
反而会让下一个人以为这格已经补上。

⇒ **只做 §1.3 那半句**（"本工具不支持重复，如实说明"）。真修法是"改期该走改期那条路"，
那是 §4.1 同一个根，一起等下一轮。

### 4.3 C2「`list_todos_range` 说没有、改期却改得动」—— 不是错，是两套视野

- `list_todos_range(2026-10-26, 2026-11-01)` 回「没有」**是对的**：那条健身在 **11-06**，不在这段里；
- 改期工具按名字查**全库**，所以改得动。**两边各自都对，合起来看着矛盾。**

真要统一，得让只读工具的区间**默认**跟"这件事可能在哪"对齐 —— 那要靠猜学生的意图，
比现在更坏。⇒ 只加 §1.3 那句"区间不确定就放宽再查一次"。

## 五 给执行方的三句

1. **`anchor_date` 必须是"只收窄、不覆盖"**：`if _hit:` 那一句删掉，T2 就会把「那天没有」说成
   `not_found` —— 那正是 #84 花了整张单修掉的假话。**两个条件（非空 + 命中）缺一不可。**
2. **C4 的闸只对"今天"生效。** 别图省事写成"任何日期的钟点都跟 now 比"：
   明天的 08:00 是完全合法的，T6 就是钉这个的。**闸写宽了，学生说「改到明天早上八点」会被系统一句话顶回去。**
3. **§1.2 那句工具描述和那道闸是一体的，不许只做一半。** 只加闸不加描述，
   模型收到 `past_slot` 会不知道怎么办 —— 它已经把那个点填进去了，下次多半**原样再填一遍**，
   学生会看到"过点了"这句话重复出现。**闸负责拦住，描述负责教它拦下来之后说什么。**
