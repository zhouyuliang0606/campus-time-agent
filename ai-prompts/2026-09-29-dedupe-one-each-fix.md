# 「每个删一个」被听成"全删"——分配量词 ≠ 整体量词

> 日期：2026-09-29
> 关联代码 commit：ae762d4 / 22a9199
> 关联测试：tests/test_12_batch_todo.py（65 项全过，本次补 G/H 两批共 27 项）
> 前置快照：`2026-09-29-batch-todo-all-reply.md`（上一条把"都"接住了，这一条是它带出来的新毛病）

## 一、用户 Prompt（截图报障 + 原话）

系统按上一条修好的样子，列出了 6 条撞时间的候选（游泳×2 / 交电费×2 / 晨读×2）：

> 1. 游泳｜2026-10-03（周六）14:00-15:00　2. 游泳｜…
> 3. 交电费｜…　4. 交电费｜…　5. 晨读｜…　6. 晨读｜…
> 我：**每个删一个**
> 管家：🗑️ 好，你说的是**上面那 6 条全都要删**。…

学生批注：**脑子有问题**。

期望：**每组（重复的）删掉一个** → 删 3 条，每组留一条。
实际：听成"6 条全删"。

## 二、AI 研判：两种量词被混成了一锅

上一条为了接住「都删了」，加了一张"全选"词表 `_ALL_WORDS`——**把「每个」「每条」也放了进去**。
这是个分类错误：

| 类型 | 例子 | 意思 |
|---|---|---|
| **整体量词** | 都 / 全部 / 全都 / 一起 / 统统 / 剩下的 | "你列的**这一整批**我全都要" |
| **分配量词** | 每个 / 每组 / 各 | "**每一组各自**处理一个" |

「每个删一个」= 每一组各删掉一个 = **去重**（每组留一条），跟"全删"**正好相反**。
一个词表的分类错了，就把"去重"读成了"全删"。

> 教训：**归纳词表时要按语义类别分，不能按"看起来都有量词"混装。**
> 词表里放错一个词，比没放这个词更糟——它会**主动断言一个错误的意思**。

## 三、改动

| 文件 | 改动 |

| `app/modules/planner.py` | ① `_ALL_WORDS` 里**摘掉**「每个」「每条」（只留整体量词）。② 新增 `_ONE_EACH_RE`（每/各 + 删·去掉·去·清·取消·移除·留·保留·剩 + 一个/条/项）+ `_DEDUP_WORDS`（去重 / 去掉重复 / 重复的删 / 只留一条…）→ `_wants_one_each()`。③ 新增 `_one_per_group()`：按「标题+日期+时段」分组，**每组留最早写入的那条**，只交出多出来的。一组的唯一一条不算（他说的是"删**一个**"，不是"删掉它"）。④ `resolve_todo_remove_reply` 新增 `dedup` 分支，**排在 all 分支前面**——两句话都带量词，谁先接就归谁 |

## 五、遗留 / 备注

- 分组键是「标题+日期+时段」——学生眼里的"一模一样的两条"就是同一个 key。
  若同名但**时段不同**，不会被算成一组（那种情况该用「第二条」点名，不是去重）。
- 红线照旧：去重也只是一张**提案**，学生点【确认删除全部】或回一句"确认"之前，一条都不动。
