# 2026-10-09 · 学生自带端点收回来，安全靠闸门而不是靠删字段

## 一、这一轮是从一句报错开始的

用户原话：

> 我的api呢用量统计呢知识库的内容呢，学生工单这些，以前的旧纪录怎么全没了，现在api配置也连不上

**"数据全没了"是假的，两个独立故障叠在一起造成了那个观感：**

1. 管理端每个请求都 401。服务器日志里 `GET /api/admin/kb`、`/api/admin/usage`、
   `/api/workorders`、`POST /api/admin/settings` 全是 401；带正确口令直连同一个接口就是 200
   且数据齐全（知识库 11 条、待办 7 条、工单 4 条、通知 3 条、学生消息 6 条、用量 418 行）。
   根因：**这个项目此前根本没有 `.env` 文件**，管理口令只存在于上一次重启时用命令行临时传进去的
   那个进程变量里 —— 换一次重启就换一个值，新标签页自然对不上。
2. 大模型真的不通。（见下面第三节，这里第一版诊断说错了，纠正记录留在原处别抹。）

排查过程中的两次自我纠正，都记下来：

- **错判一**：我先说"是模型名 `glm-4.7-flash` 智谱不认（`/models` 列表里没有）"。
  这是错的 —— `/models` 那份清单**并不完整**（`glm-4-flash` 同样不在列表里却能 200）。
  真正的现象是 `glm-4.7-flash` 限流很凶：用量流水里 18:33:48 它成功过一次（434 tokens，
  是用户自己点的测试连通），而我在 18:40 连着点就固定 429/1302。
  我当时拿"列表里没有"当判据，是把一个不完整清单当成了白名单。
- **错判二**：上一轮按"最彻底"的方案把学生的 `base_url` 整个收掉，我以为只是收紧了安全边界，
  实际上**当场把"学生自带 Key"做成了假功能** —— Key 是学生的、地址是管理端的，两家不配套
  只会吃一个学生看不懂的 401。用户这轮的报告就是后果。

## 二、用户提的方案与最终决定

> 模型key通了，把学生自配key删了，不换新写一份不行吗

以及：

> 我在学生哪里添加了api，但是现在还是只能使用管理端的默认模型，所有我觉得要不然就删除，要不然就学生用自己api去用模型

给的选择是"删掉" vs "让他真能用"。我选了后者并说明理由：填了却不生效的入口比没有这个入口
更伤演示可信度（评委一点就穿），而且它是服务器 Key 失效时唯一的自救路径（今天下午刚验证过这个
风险是真的）。用户接着追加一句：

> 顺便看看我现在学生自己添加的api有没有暴露

所以这一轮实际交付的是五件事 + 一次泄露审计。

## 三、改了什么

1. **`app/config.py` `sanitize_override()`**：重新收下 `base_url`。
   - 缺协议按 `https://` 补全（人都是这么省略的）；
   - 补完仍过不了**第一层**（`file://`、没主机名）→ **整份 override 作废**，不留半成品：
     连地址都写不对的那份配置，里面的 key 和模型名一样不值得信；
   - 多余字段照旧一概不带过来。
2. **`app/config.py` `get_llm_config()`**：优先级变成 **学生自带 > 管理后台 > .env**，
   每一项单独回落（只填 Key 就只换 Key）。`source` 文案从"学生端自定义 API（地址走服务器配置）"
   改成"学生端自定义 API"—— 旧那句现在是谎话。
   函数顶上那段"2026-10-09 改：彻底关掉 base_url"的说明**改成了三段式记录**
   （以前生效→造成 SSRF；中午关掉→功能变假；现在收但连接前过闸），别再翻第三次烧饼。
3. **`app/llm/client.py`**：闸门位置**一个字节都没动** —— 第 94 行那句
   `base_url = check_base_url_ssrf(base_url)` 拿的本来就是"最终生效地址"，
   学生传来的地址天然会过它。只补了注释（新写发请求路径不许绕过这里）和一句更准确的报错：
   旧文案只提"管理控制台"，现在学生也能改地址，报错就得同时指两条路。
4. **`app/llm/gateway.py`**：用量流水每行加 `key_source` = `server` / `student`。
   这是回答"管理员能不能看见学生自带 Key 的用量"——能看见**这笔账花的是谁的钥匙**，
   看不见钥匙本身。管理端「用量统计」表格加「来源」一列，卡片下方说明老记录没有这个字段。
5. **`app/static/student.html`**：API 弹窗把「接口地址」输入框（`mBase`）加回来，
   文案明说"只接受公网 http/https；127.0.0.1、局域网段、169.254.x 会被直接拒掉"；
   `/api/upstream` 那一行从"学生端不能改"改成"服务器默认上游（接口地址留空就用它）"；
   设置页从"只显示模型名"改成"当前自定义：<模型> · 发到 <host>" —— 不显示就是替学生把
   钥匙寄到没跟他讲过的机器。**改的过程中留了一个重复的 `fetch("/api/upstream")` 处理器**
   （旧的那份在后面把文案覆盖回"学生端不能改"），是 E 批新加的断言 `学生端不能改 not in src`
   当场抓出来的。
6. **本地新建 `.env`**（`.gitignore` 第 2 行挡住，不入库）：`CAMPUSTIME_ADMIN_TOKEN=<换了个新串>`。
   **值不写在任何可提交文件里**。服务改成不带命令行参数启动，口令唯一来源就是这个文件，
   以后重启不再换值。

## 四、泄露审计（用户点名要的那条）

静态扫：`app/data/**` + `D:\campustime-scratch` 全部共 258 个文件，正则捞 Key 形状的串，
与管理端那把做指纹比对。结果只有 4 种串：管理端那把（仅出现在 `settings.json` 与我的备份），
以及 3 把**我自己造的诱饵串**（`sk-CANARY…`、`sk-LIVE…`，在 P0-4 的探针脚本里）。
学生填过的 Key 一个都没落下。

代码面：`grep api_key app/**/*.py` 逐个看落点 —— 只有管理端写 `settings.json`（那是管理员自己的），
学生那把走的是 `sanitize_override → gateway → client` 这条内存路径，没有任何一处写文件。

**真机复验**（比沙箱测试更有说服力，因为扫的是真实文件 + uvicorn 访问日志）：
用诱饵串 `sk-CANARY-LIVE-7c4d9e` 从 `/api/chat` 的 `model_config` 发两次对话：

| 场景 | 结果 |
| --- | --- |
| 自带公网地址 `https://api.deepseek.com` | 拿回 **DeepSeek 的 401**（不是智谱的）→ 证明他的地址真的被用作连接目标；流水记 `key_source=student`、`model=deepseek-chat` |
| 自带内网地址 `http://127.0.0.1:8000/api/admin/settings` | 回"接口地址不合规"，**请求根本没发出**，响应体不含 `127.0.0.1` |
| 诱饵串落盘面 | 扫真实 `app/data/**` + 服务日志：**一个都没有**；响应体里也没有 |
| 本轮被改动的数据文件 | 只有 `llm_usage.jsonl`（新增 4 行，都不含 Key）；改动前的 md5 表存在 `D:\campustime-scratch\bak-live-probe-before.json` |

## 五、护栏

`tests/test_37_base_url_ssrf_gate.py` 56 → **74 项**（B 批按新契约重写、E 批三条反向钉死、
新增 **H 批**）；`tests/test_34_api_key_not_stored.py` 34 → **37 项**
（B5 允许字段加 `key_source`，新增 B5b「取值只能是 server/student 两个标签」、
B5c「自带 Key 那几行必须标 student」）。

H 批是这一轮的关键，因为它不再信"字段有没有被丢掉"这种间接证据：
塞一个假的 `httpx.AsyncClient` 把**实际请求 URL** 取出来 ——
- 公网：断言 URL 就是学生填的那家、`Authorization` 尾缀是他的 key、`last_model` 是他填的模型；
- 内网：断言假 client **一次都没被调用**（`"url" not in sent`），也就是在建连接之前就拦下了，
  而不是"发出去再报错"。

反向验证 6 个变异全部被抓到、文件全部复原（md5 比对）：

| 变异 | 结果 |
| --- | --- |
| 废掉 `client.py` 连接前的闸门 | test_37 红 5 条（含"请求根本没发出"记录到 `http://127.0.0.1:8000…`） |
| override 又丢掉 base_url（回到中午那版） | test_37 红 1 条 |
| 第一层判据废掉（`file://` 也放行） | test_37 红 1 条 |
| 用量不再记 `key_source` | test_34 红 2 条 |
| **`key_source` 直接写 Key 本身**（泄密面） | test_34 红 7 条，其中 B2「沙箱目录逐文件扫过：没有 canary」当场抓住 |
| 学生弹窗删掉接口地址栏 | test_37 红 1 条 |

全量：**2148 通过 / 7 失败（38 批）**。7 条仍是已确认的存量红（`test_06`×6、`test_23`×1），
起因是 `sandbox()` 不清 `student/todos.json`，测试数的是真实演示数据 —— 与本轮无关。

## 六、遗留（都没得到授权，所以没动）

1. **DNS rebinding 的 TOCTOU 现在变严重了**：能填地址的人从"管理员本人"退回"任何连到端口的人"。
   要钉死得把已校验的 IP 固定进连接层。**对外网暴露之前必须补**，`config.py` 与 README 里都写明了。
2. 用量统计里 **174/418 行是测试写进去的**（`model` 字段是 `m`、tokens 全 0、今天新增 66 行）：
   `sandbox()` 没把 `llm_usage.jsonl` 重定向干净，测试噪声进了真实流水，
   管理端那些总数和占比（模型占比第一名叫 `m`）本身就是假的。清它要先得到同意。
3. 管理页在口令填好之前就把所有卡片拉一遍，401 之后只留下空白列表而不是"🔒 还没填口令" ——
   用户这次被吓到"数据没了"正是这个设计造成的。属于 UX 修复，未获批。
4. 历史快照 `ai-prompts/2026-10-08-remove-week-timeline.md` 第 77、100 行写着当时那个临时口令的值，
   而第 100 行还写着"仓库里没有、也不会有" —— 那句现在是不实陈述。
   **按"历史快照不重写"的纪律我没有改它**，改为在本份快照里更正。换上新口令后，
   那个旧串已经不再有任何作用，也不在 `.env` 里。
5. `check_base_url_ssrf` 不看非常规端口（`http://公网IP:6379/` 过闸）。
