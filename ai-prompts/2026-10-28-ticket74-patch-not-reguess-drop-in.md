## 〇 现场事实（全部现查现跑）

### 0.1 三句话的实测对比 —— 时长对了，次数丢了

`.venv/Scripts/python.exe` 直调 `weekly_times` / `wanted_minutes` / `todo_slots_proposal`：

| 学生原话 | `weekly_times` | 卡的样子 | 每段时长 |
|---|---|---|---|
| 帮我在下周安排**三次**健身，**一次三小时** | **3** ✓ | 5 段、预勾 **3** | 180 分钟 |
| 帮我在下周安排**三次**健身，**一次一小时** | **3** ✓ | 5 段、预勾 **3** | 60 分钟 |
| **是改成三次，每次一小时** | **None** ✗ | **3 段、预勾 0** | 60 分钟 |

**时长那一半一直是好的**（180 → 60 跟着改）。丢的是次数。

第三句从「频次分支」掉回了「普通分支」，两处参数一起变：

| | 频次分支（`planner.py:1021-1022`） | 普通分支（`:1039`） |
|---|---|---|
| `max_slots` | `times + 2` = **5** | 默认 **3** |
| `preselect` | `min(times, len)` = **3** | **0** |

所以学生看到的是：三个候选、一个都没勾、也不知道要排三次。**这就是他说的「压根没有去循环确认」。**

### 0.2 为什么「改成三次」认不出 —— `_FREQ_RE` 要求出现「周」

`planner.py:2569-2582`：

```python
def weekly_times(text: str) -> int | None:
    m = _FREQ_RE.search(text or "")
    if not m:
        return None
    ...
```

`_FREQ_RE`（`:2341` 之前定义）的形状要求先出现「(一|每|这|本)周 / 周 / 星期 / 礼拜」，再在 6 个字内出现「N 次」：

- 「下**周**安排三次健身」→ 有「周」，认得出 **3** ✓
- 「**改成三次**」→ 没有「周」字，**认不出** ✗

而学生这一句之所以不说「周」，是因为**上一句已经说过了**。人说话就是这么省。

### 0.3 把上一句拼回来：次数救回，**事名被污染**

实测：

| 输入 | `weekly_times` | 卡 | `title` |
|---|---|---|---|
| `是改成三次，每次一小时` | None | 3 段、预勾 0 | — |
| `帮我在下周安排三次健身，一次一小时，是改成三次，每次一小时` | **3** ✓ | **5 段、预勾 3** ✓ | **「健身是每次」** ✗ |

**⇒ 简单拼接不是免费的。** 它救回次数，却把事名毁掉 —— 因为 `_pick_title` 拿整串从头重抠。

**这一条是本单的核心论据**：问题不在"没把上一句拼进来"，而在**「拼进来之后整句重猜」这个动作本身**。

### 0.4 根子：这些解析函数的签名只收一句话

| 函数 | 签名 | 能不能看到上一轮 |
|---|---|---|
| `weekly_times` | `(text: str)` | 不能 |
| `_pick_title` | `(t)` | 不能 |
| `_pick_span` | `(text)` | 不能 |
| `_pick_date` | `(text)` | 不能 |
| `wanted_minutes` | `(text)` | 不能 |

**它们不是"忘了传上下文"，是结构上没有这个入口。** 所以再怎么把字符串喂长，也只是让它们继续猜。

### 0.5 卡上**存不下**「几次 / 每次多久」

`planner.py:669-679` 的 `todo_slots` 卡字段：

```python
{
    "kind": "todo_slots",
    "title": ...,
    "slots": [...],       # 已经摊好的几段（含 date/start/end/minutes）
    "hint": ...,
    "preselect": ...,
    "repeat": ...,        # "" / "weekly" / "daily"
    "summary": ...,
}
```

**没有 `times`（这批要排几次）、没有 `duration`（单次多少分钟）。**

后果：下一轮学生说「改成三次」时，系统**没有任何地方能读到"上一轮要几次"**。
`slots` 里每段有 `minutes`，但那是"系统替他挑的那段的长度"，不等于"他要求的单次时长"；
`preselect` 只是"勾了几个"，也不是次数意图。

**⇒ 要做"补齐缺口"，必须先让卡片把这几个参数存下来。这是本单的第一笔，也是最容易被跳过的一笔。**

### 0.10 试过的错修法（记在这里，省得重走）

我本来打算把 `_pick_title` 的「切段重试」关掉、只对整句擦一遍 —— **没用**。

`_pick_title` 在整句判不过时会按标点切段重试（`planner.py:3152`），看着像元凶（「下周三次，每次一小时」正好被逗号切成两段，第二段「每次一小时」被抠成「每次」）。
但整句档本身就吐同一个东西：

```
_strip_title_noise('下周三次，每次一小时')  →  '每次'
_title_ok('每次')                          →  True
```

`_DURATION_RE` 把「一小时」整块擦掉（`planner.py:2945`），剩「每次」；
`_FREQ_RE` 没命中（没有「周」字），所以连「三次」那个数量都没擦 —— 留下的是纯计数残渣，
而 `looks_like_thing('每次')` 返回 **True**。

**⇒ 问题不在"切不切段"，在判真门放行了纯计数残渣。** 所以修法要打在 `_title_ok`（§一.5），
不在 `_pick_title` 的结构上。

## 一、修法：五笔，按顺序做

### 一.1 卡片补三个字段（**必须先做**，否则后面几笔无处可依）

`build_todo_slots`（`planner.py:637`）签名加两个参数、返回体加三个键：

```python
def build_todo_slots(title: str, slots: list, hint: str = "", preselect: int = 0,
                     repeat: str = "", times: int = 0, duration: int = 0):
    ...
    return {
        "kind": "todo_slots",
        "title": title or "待办",
        "slots": items,
        "hint": hint,
        "preselect": pre,
        "repeat": repeat or "",
        "times": times,          # 这批要排几次（0 = 没说）
        "duration": duration,    # 单次多少分钟（0 = 没说）
        "origin": title or "",   # 这件事的**事名源头**，见一.3
        "summary": ...,
    }
```

调用点（`planner.py:986 / 1017 / 1052`）按语义传值：

- `:1052`（普通那条）：`times=times`、`duration=_minutes_of(t)` —— **注意这一处现在根本没算 times**
- `:986`（weekly 那条）：`repeat=weekly`、`times=0`（每周一次不是"几次"）
- `:1017`（daily 那条）：同上

⚠️ **`times` 必须在"普通分支"里也传**：`planner.py:1021` 那个 `if times >= 2 and not day:`
之外的情况（比如 `times=1`、或者带了具体某天）走的都是 `:1052`，那条路上 `times` 现在被整个丢掉了。

### 一.2 新增「补丁探测」：这一句只改了哪几项

在 `planner.py` 加一个**只读、无副作用**的函数：

```python
def parse_todo_patch(text: str) -> dict:
    """这一句改了什么？只说到的填值，没说的填 None。

    人话：学生说「改成三次，每次一小时」，就只交出 {"times":3,"duration":60}，
    事名、日期、钟点一律 None —— 那些他没提，不许替他重算。
    """
```

要点四条：

1. **`times`**：先用 `weekly_times(text)`；认不出再走一个**窄口** —— 整句 ≤ 12 字、
   不含事名候选、形如「(改成|换成|是)?N次」时才认。**这个窄口只在本函数里开，
   不动 `weekly_times` 的全局行为**（理由见 §二.3）。
2. **`duration`**：`wanted_minutes(text)`（实测认「一次一小时」「每次一小时」「三小时」→ 60/60/180）。
3. **`date` / `start` / `end`**：`_pick_date` / `_pick_span`，和现有解析同源。
4. **`title` 一律返回 None**，除非这一句**明确带了新事名**（比如「改成游泳」）——
   "明确带了"的判据交给人写死：`_pick_title` 的结果**不等于** base 的 title、且不是常见纠正词
   （改成/换成/是/不对/应该是/我说的是）。这条宁可窄：猜错事名比不记事名糟得多。

### 一.3 合并规则：明说的覆盖，没说的**保持原样**

在 `main.py` 那条加待办分支里，把现在这两行：

```python
blob = (prev_user + "，" + message) if (asking_add and prev_user) else message
proposal = parse_add_todo(prev_user + "，" + message)
```

改成「先取 base，再打补丁」：

```

patch = parse_todo_patch(这一句)
merged = {每项: patch[项] if patch[项] is not None else base[项]}
```

**铁律**：`title` 只在 `patch["title"]` 非 None 时才换 —— **永远不从整串重抠**。

`base` 的取法见 §一.4 的表；三个来源都没有 → **说明这不是补充句**，走原来的全新解析（别硬凑 base）。

⚠️ **光改这一处的合并规则，卡路径照样毁事名** —— 见 §0.8。第三处重抠在 `parse_slot_text` 里，
由 §一.5 收拾，不在这一笔的范围内，也不能靠这一笔顺带修好。

### 一.4 「这是补充句」的判据（**批示五 (a) 定稿：接受"有卡或有哨兵"，但必须配否决**）

```
进补丁分支 ⟺
    ① (暂存里有 todo_slots 卡 / todo_add 卡)  或  asking_add 哨兵
  且 ② parse_todo_patch(message) 至少一项非 None
  且 ③ 否决：这一句**没有纠正语气**，却给出了"新事名"（`_pick_title` 判真通过且 ≠ 卡上 title）
```

**为什么必须有 ③，而且 ③ 不能长成"有新事名就否决"**：那样会把本单自己的 T2 否决掉。实测：

```
_pick_title('是改成三次，每次一小时')  →  '是三次每次'      ← 一个假名
_title_ok('是三次每次')                →  True            ← 判真放行
```

一句纯粹的纠正句，在 `_pick_title` 眼里也"带了个新事名"。所以 ③ 必须先看语气：

```python
# 一.4 用，写死、窄，不追求全
_CORRECT_HINT = ("改成", "改到", "换成", "换到", "不对", "不是", "应该是", "我说的是", "是改",
                 "每次", "一次", "两次", "三次", "挪到", "调到", "重来", "小时", "分钟")
```

判据落成：

```python
def _veto_as_new_order(message: str, base_title: str) -> bool:
    """这一句像不像"换了件事重新下单"（是 → 不许当补丁）。"""
    if any(w in (message or "") for w in _CORRECT_HINT):
        return False                       # 有纠正语气 ⇒ 放行成补丁
    cand = _pick_title(_strip_title_noise(message or ""))
    return bool(cand) and cand != "待办" and _title_ok(cand) and cand != (base_title or "")
```

实测这条规矩的四个边界（现跑）：

| 原话 | `_pick_title` | 含纠正语气 | 否决？ | 对不对 |
|---|---|---|---|---|
| `周六加个游泳` | `游泳` | 否 | **否决** | ✅ 换了件事，该走全新下单 |
| `帮我加个游泳`（卡上是「健身」） | `游泳` | 否 | **否决** | ✅ 同上 |
| `是改成三次，每次一小时` | `是三次每次` | 是（改成/每次） | 放行 | ✅ 这就是 T2 |
| `不对是一次三小时` | — | 是（不对/一次） | 放行 | ✅ 这就是 T3 |

**base 两取（(a) 的第二半，照你说的）：**

| 暂存里有什么 | `base` 取什么 |
|---|---|
| `todo_slots` 卡 | `{title, times, duration, repeat}` |
| `todo_add` 卡 | `{title, duration = card["minutes"], date, start, end, repeat}` |
| 只有哨兵、没有卡 | `parse_add_todo(上一句 user 整句)` —— **今天的行为，不许删**（"缺细节"时根本没卡可读） |
| 三者都没有 | 不是补充句，走全新解析，**不硬凑 base** |

好处：不依赖任何文案、不会被 4 条窗口挤掉、和"手上有没有卡"这件事天然对齐
（`main.py:3211` 的 `held_add` 已经是这个形状，本单只是把它扩到 `todo_slots`）。

⚠️ 这一条与 `asking_add` 并存，**不要删 `asking_add`**：它还被 `:2228`（生理状态让路）用着。

### 一.5 计数残渣不算事名 —— 打在 `_title_ok`（**这一笔同时修好三处重抠**）

`planner.py:3169`：

```python
_COUNT_RESIDUE_RE = re.compile(
    r"(每|共|一共|总共|合计|还有)?[0-9零一二三四五六七八九十百两半]*(次|回|遍|趟)")

            and not _COUNT_RESIDUE_RE.fullmatch(t)      # ← 新增，必须 fullmatch
            and not _looks_like_correction(t)
            and not looks_like_chitchat(t) and looks_like_thing(t))
```

**必须 `fullmatch`，不许 `search`**（实测）：

| 串 | `search` | `fullmatch` | 该不该拦 |
|---|---|---|---|
| `每次` / `三次` / `一次` / `两回` | 命中 | **命中** | 拦 ✓ |
| `二次元` | 命中 | 不命中 | **放行** ✓（这是真事名） |
| `第一次` | 命中 | 不命中 | **放行** ✓ |
| `下次` | 命中 | 不命中 | **放行** ✓ |

1. `_pick_title` 的整句档（`:3148-3150`）和切段档（`:3152-3158`）**都过这一道门**，一处改两档都生效；

3. **三处调用点一起好**：`main.py:3235`、`main.py:6339`（「其他」自填那一行）、

## 二、判断与理由

### 2.1 为什么不能只改 `prev_user` 的取法

§0.3 的实测已经把这条路堵死了：把上一句**正确**拼进来之后，
`weekly_times` 从 None 变 3 ✓，可 `title` 从「健身」变成 **「健身是每次」** ✗。

**拼对上下文 + 整句重猜 = 修好一个、弄坏一个。** 取法对不对，改变不了这个结局。

### 2.2 为什么"整句重猜"这个动作本身就是错的

因为**每一轮纠正都在把已知信息重新赌一次**：

| 轮次 | 学生说 | 系统重猜的字段 | 风险 |
|---|---|---|---|
| 1 | 下周三次健身，一次三小时 | 全部 | — |
| 2 | 一次一小时 | **全部** | 事名、次数都可能被重猜坏 |
| 3 | 改成三次，每次一小时 | **全部** | 同上 |

学生只改一项，系统把五项全赌一遍。**赌的次数越多，错的概率越大** —— 这就是他体感
"每改一次就乱一次"的机制。

改成"补齐缺口"之后，每轮只动他明说的那一两项，其余**数学上不可能变**。

### 2.3 为什么新开窄口，而不是直接放宽 `weekly_times`

`weekly_times` 被多处调用（`planner.py:960` 的 `times`、`unsupported_period` 的邻居判据、
以及 `todo_slots_proposal` 的三条分支）。直接让它认孤立的「三次」，
会波及**所有**含「N 次」的句子 —— 比如「我去了三次图书馆」会被读成"一周三次"。

**窄口开在 `parse_todo_patch` 里**（它只在"手上已经有卡"时被调用），
影响面从"全项目"缩到"补充句这一条路"。**这是本单唯一需要谨慎的地方**。

### 2.4 代价要认

- 卡片多三个字段 → 前端 `confirm.html` / `student.html` 若按白名单渲染，需要确认不会因为多键报错
  （它们现在是**按键取值**、不是白名单过滤，所以多字段应无害 —— 但**必须实测一次**）。
- `parse_todo_patch` 是一条新判据，它判错会把"全新下单"误当"补充句"。
  所以 §一.4 那三条 `⟺` 必须**同时**满足，缺一不可。
- `_title_ok` 收紧之后，**所有**依赖它的路径都受一点影响（它是全局判真门）。
  实测边界已在 §一.5 列出；回归里必须点名 `test_10/11/12/19/20` 这几批盯「加待办」的。
- `wanted_minutes` 进 `auto_todo_proposal` 之后，「周四加个两小时的自习」这类句子排出来的段会**变短**
  （以前 90，现在 120 会要求更长的空档，可能挑不出、返回 None）。**宁可返回 None 让他补一句，也别排一段缺的。**

### 2.5 为什么 (a) 要配否决，而且否决长成那个样子

把判据从"扫哨兵"放宽到"有卡或有哨兵"，**放宽的正是风险本身**：
卡挂着的时候，学生每一句带时间的话都会命中 ①。而"带时间的话"里混着两种完全相反的东西：

- 「改成周六」「是改成三次」→ 是补丁
- 「周六加个游泳」→ **是新单**

光看"有没有可改字段"分不开（两句都有日期）。所以必须有一条专门看**事名**的否决 —— 但你给的第一直觉
"有新事名就否决"会被 `_pick_title` 骗：它把「是改成三次，每次一小时」抠成「是三次每次」并判真通过（§一.4）。
**所以否决得先看语气、再看名字**，顺序不能反。

### 2.6 为什么 (c) 离不开 (b) —— 单取 (c) 就是假绿

这条我要说得直白一点：**函数级 T1~T3 全绿，只证明"函数改对了"，不证明"调用点传对了"。**

`main.py:3235` 就是活标本：`parse_slot_text` 的签名一直是对的、内部逻辑一直是对的，
坏在调用方传了 `held_slots.get("title")` 进去、函数却又自己重抠了一遍。
**这种病，函数级断言一条也抓不到。**

所以：

- 取 (c) 不取 (b) → 73 全绿，真机上学生照样看到「每次」写在卡上；
- 取 (b) 之后 (c) 就成立：链路上唯一不测的是"没找到那条待办"（多段批量写入 `/api/todos/batch` 那一路），
  那族是**另一套 I/O**，和本单没有共用行（§四.6）。

**(c) 的承诺边界写清楚：**

| 本单测 | 本单不测 |
|---|---|
| 三个函数的行为（T1~T5） | `/api/todos/batch` 真写库后条数对不对 |
| 调用点有没有把 `duration` 传下去（S1，静态） | 「没找到那条待办」这类链路报错 |
| 卡片字段有没有被前端渲染压坏（回归 R2） | 多轮对话在真机上走完 4 轮（人工点一次） |
