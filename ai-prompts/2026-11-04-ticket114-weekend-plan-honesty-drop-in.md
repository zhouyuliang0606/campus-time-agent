### 0.2 病根一：`_FREQ_RE` 把「周末」整个吃进频次短语

`planner.py:2290-2297` 那段正则的前缀是：

```python
    r"(?:"
    r"(?:一|每|这|本)\s*(?:周|星期|礼拜)"          # 带前缀：一周 / 每周 / 这星期
    r"|(?<![一二每这本])(?:周|星期|礼拜)(?![一二三四五六日天])"  # 光杆"周"，且不是"周四"那种星期几
    r")"
```

「周末」的「周」后面跟的是「末」——**不在 `(?![一二三四五六日天])` 那张否定表里**，  
所以它照样算"光杆周"。实测：

```
_FREQ_RE.search("周末安排两次打乒乓球一次三小时").group(0)  ==  '周末安排两次'
weekly_times(同句)                                          ==  2
```

于是 `plain`（`:1062`）= `' 打乒乓球一次三小时'`，**「周末」两个字连同频次一起被擦掉**。  
而下游 `candidate_slots` 判周末的判据是 `weekend_mode = any(w in t for w in _WEEKEND_WORDS)`（`:536`）  
—— `t` 里已经没有「周末」⇒ `weekend_mode = False` ⇒ 从今天起逐天铺。

**这一处最阴的地方**：`_FREQ_RE.sub` 在这一行之前还被用来算 `day`（`:1054`），  
两处都擦、都擦掉了「周末」，谁也没觉得少了个词 —— 少的是一个**约束**。

## 一、修法（五处，按 1.1 → 1.5 顺序打；1.1 / 1.3 / 1.5 是"排到周三"的三道关）

### 1.1 擦频次时**把范围词留住**（打病根一）

新增一个小函数，放在 `_FREQ_RE` 定义之后（`:2297` 后面，与 `_COUNT_UNIT_RE` 之间）：

```python
def _strip_freq_keep_range(text: str) -> str:
    """擦掉「一周 N 次」那一段，但把「周末/双休/平时/工作日」原样留住。

    `_FREQ_RE` 的前缀就是「周」（`planner.py:2292-2293`），所以「**周末**安排两次」
    这一整片会被匹配走 —— 擦完句子就**没有周末这个词了**。下游
    `candidate_slots` 判周末靠 `"周末" in t`（`:536`），判不出来就从今天起逐天铺。
    用户报的那句就是这么跑到周三去的（单据 §0.2）。

    为什么补词而不是改正则：`_FREQ_RE` 被四处共用（`:959 :1054 :1062 :1363 :2808`），
    里面那个 `(?![一二三四五六日天])` 是**故意的**（「周三」得读成日子、不能读成"礼拜三次"），
    动它会牵连 `unsupported_period` 和三条候选分支。这里只在"加待办"这条链上补，
    影响面一行都跑不出去。
    """
    t = text or ""
    plain = _FREQ_RE.sub(" ", t)
    for w in _WEEKEND_WORDS + _WORKDAY_WORDS:
        if w in t and w not in plain:
            plain = f"{plain} {w}"
    return plain
```

然后把 `todo_slots_proposal` 里那两处换成它：

```python
# :1054
-    day = _pick_date(_FREQ_RE.sub(" ", t))
+    day = _pick_date(_strip_freq_keep_range(t))
...
# :1062
-    plain = _FREQ_RE.sub(" ", t)
+    plain = _strip_freq_keep_range(t)
```

⚠️ **只换 `todo_slots_proposal` 里的这两处。** `:959`（周期否决）、`:1363`（`mode_to_card` 的频次闸）、  
`:2808`（`parse_todo_patch`）一律不动 —— 那三处不需要保留范围词，动了是白改。

### 1.2 装不下时才越过档尾（打病根三）

`_day_slots:421-424`：

```python
            finish = min(begin + length, to_minutes(s["end"]), phi)
            if finish - begin < min_needed:
                continue
```

改成：

```python
            finish = min(begin + length, to_minutes(s["end"]), phi)
            if finish - begin < min_needed:
                # ★ #114：`phi` 是"这一档到哪儿为止"（上午 12:00 / 下午 18:00 / 晚上 22:00），
                #   它本来只是**排序用的偏好带**，不是禁区（`find_free_slots` 和 `_span_free`
                #   只避课和已排待办，午休/傍晚从来不拦）。可它把**装不下的长请求**整段吃掉了：
                #   11/8 那条 10:30-14:00 的真空档有 210 分钟，够放 3 小时，
                #   却被切成"上午 90 分钟 + 下午 0 分钟" ⇒ 候选归零 ⇒ 学生说的"这周末"被跳过。
                #   所以只在**档内确实装不下**时，才允许越过 phi；装得下就还是原来那一刀，
                #   短线请求（≤180 的上午/晚上、≤240 的下午）行为一字不变。
                finish = min(begin + length, to_minutes(s["end"]))
                if finish - begin < min_needed:
                    continue
```

**已知取舍（写在这里，别当成 bug 报回来）**：这条放开后，会出现「上午 10:30-13:30」这种

### 1.4 装不满就别写"按你说的 3 小时"，并且优先去找装得下的那天（打病根四）

`plan_todo_slot:1270-1301` 那个 `for d in days:` 循环改成**两轮**：

```python

                              length=want, not_before=nb)

        #   所以"要 3 小时、这天只剩 2 小时 05 分"也会被接住。接住本身不是错（总比排不出强），
        #   错的是下面那句 reason 无条件写「按你说的 3 小时 排的」——
        #   卡片上是 08:00-10:05，嘴上说 3 小时，学生点【确认加入】就等于认了一句假话。
        #   所以：装得下的排前面；装不满的留作备胎，且话术说真话。
        if slot["minutes"] < want:
            if _partial is None:
                _partial = (d, slot)
            continue
        return _auto_card(name, d, slot, want, full=True)
    if _partial is not None:
        _d, _s = _partial
        return _auto_card(name, _d, _s, want, full=False)
    return None
```

`_auto_card` 就是把原来 `:1277-1300` 那段搬进一个内部小函数（同一个文件、`plan_todo_slot` 外面、
`_day_slots` 附近），`full` 决定 `reason` 用哪一句：

```python
def _auto_card(name: str, d: str, slot: dict, want: int, full: bool) -> dict:
    """单条兜底卡（#114 从 `plan_todo_slot` 里拆出来，只为让 `reason` 能说实话）。"""
    part = next((n for n, plo, phi in DAY_PARTS
                 if plo <= to_minutes(slot["start"]) < phi), "")
    wd = slot["weekday"]
    head = f"{_mmdd(d)}（{wd}）"
    say = format_minutes(want)
    if full:
        why = f"{head}{part}这一段是空的（你的课和已经排好的事都避开了）。"
        if want:
            why = f"按你说的 {say} 排的，{why}"
    else:
        # 装不满就明说装了多久，别把 2 小时 05 分写成 3 小时。
        why = (f"你说 {say}，但 {head}{part}只排得出 "
               f"{format_minutes(slot['minutes'])}（前后都有课或已经排好的事）——"
               f"要凑满就得跨过别的安排，所以我先摆这一段。"
               f"不合适就说「换个时间」，或者说「缩短到两小时」。")
    return {
        "kind": "todo_add", "title": name, "date": d,
        "start": slot["start"], "end": slot["end"],
        "weekday": wd, "minutes": slot["minutes"],
        "auto": True,
        "reason": why,
        "summary": f"{name}｜{d}（{wd}）{slot['start']}-{slot['end']}",
    }
```

⚠️ `reason` 会**原样进确认条**（纯文本渲染，不认 markdown）—— 里面一个星号都不许加，
沿用原注释那条规矩。

## 二、关于「能不能让模型去识别」—— 本节 21:0x 重写过，别按旧结论做

用户 20:5x 用一张截图反驳了本节原来的第 2 条，他是对的。先摆实测：

| 同一句（§0.7 的合并句） | 普通模式 | Agent 模式 |
|---|---|---|
| 周末打篮球，四个小时 | 周三 08:00-10:05 / 125 分钟 / 「按你说的 4 小时 排的」 | **「周末两天都排不出连续 4 小时的空档，最长是周六 13:00–15:40（160 分钟）、周日 10:30–14:00（210 分钟）。要不要改成 2.5 小时，或者拆成两段？」** |
| 周末安排两次打乒乓球一次三小时 | 周三 08:00-10:05 / 125 分钟 | **周日 11-08 10:30-13:30，正好 180 分钟**，并主动说明「周六只剩 160 分钟排不下」 |
| 耗时 / 轨迹 / 工具 | 0.1s / 3 行 / 0 次 | 5.4s / 16 行 / 6 次 |

**Agent 模式这两句全对，而且话术比本单要修出来的还准。** 所以：

1. **原来的第 2 条（"模型手上没有空档表，只能编"）作废。** 它现在有 `find_free_slots`，
   而且§0.7 那句 `{"info": "…没有 ≥240 分钟的空档了…"}` 本来就是它查出来的。
   **系统一直算得对，是确定性分支在往下传的时候把结果丢了。**
2. **但也不能改成"全交给模型"，两个实测代价摆着**：
   - 慢 **54 倍**（0.1s → 5.4s；`max_steps=6`，每步一次 LLM）；
   - 同一开关下「提醒我周五下午交作业」从 90 分钟缩成 **30 分钟，且卡上 `reason` 是空的**
     （`propose_todo_tool` 走模型那一路不拼理由）；
   - 「帮我把图书馆挪到周五下午」会把「1. 2. 哪一条」的编号列表拍平成一句话。
3. **真正的分界不是"给不给模型"，是"这个能力有没有做成工具"**：
   写死 = 把**答案**焊进代码（`_PERIOD_START` 坚持"第二节就是 08:00"）；
   给工具 = 交出**能力**（`list_day_todos` / `find_free_slots` / `propose_todo_change`）让它自己组合。
   `find_free_slots` 是工具（好）；`_day_slots:422` 那个 `phi`、`_pick_date` 抢在「周末」前面锁日，
   都是**焊死的答案**（坏）—— 本单 1.2 / 1.5 修的就是后者。
4. **所以本单照做，但定位要改**：这五处不是"为了绕开模型"，是"**把确定性分支自己弄丢的东西捡回来**"。
   捡回来之后，普通模式 0.1 秒给出和 Agent 模式一样对的答案，那才是这个项目该有的形状。
5. **`skill` 化（用户 11-02 提的那条）解决不了这一族**：这是同一个函数族里"算对了没传下去"，
   不是耦合太重。拆成 skill 只会把这几行搬到另一个文件里，照样丢。
