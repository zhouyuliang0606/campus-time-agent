# 2026-10-12（深夜）· 软取消要作废**那张还没点头的卡**，不是去日程里翻一条删

配套施工单（用户附件，原件已入库）：`2026-10-12-active-proposal-soft-cancel.md`。
这一份记的是我按它做完之后，**三处必须偏离它的地方**和理由。

## 一、这一幕的荒谬程度值得原样抄下来

```
学生：明天去吃自助            → 系统：⏰ 给你找了几个空着的时间段…《吃自助》
学生：算了不吃了              → 系统：你说的这条对上了好几条待办，我不敢替你挑 🗑️
                                1. 交计算机网络作业 2. 写作业 3. 体检预约…（整张日程）
```

库里**压根还没有**《吃自助》这条 —— 他反悔的是那张刚挂出来的卡，
系统却跑去删"已存在的待办"，还把三条无关的摆到他面前。上一笔（`d171a9c`）
把这句从"掉给模型当闲聊"修成"删待办"，是修了一半：判定层对了，执行层少一层分辨。

## 二、照抄施工单会做成**死分支**（本轮最重要的一条）

它 §3.1 要求拦截条件之一是 `_is_blind_delete(message)` 为真。实测：

```
_is_blind_delete("算了不吃了") = False     ← 截图里那句，恰恰为假
```

因为 `main._DELETE_ACTION_WORDS` 是**第四份**手抄的撤销动作词表
（planner 里已经有 `_REMOVE_TODO_SOFT` / `_REMOVE_TODO_INTENT` 两份），
抄件里没有「不吃」「不做」「不要」：`todo_title_of("算了不吃了")` → 「算了不吃」，
擦完还剩「不吃」→ 判 False。**照抄之后那道拦截对这一辈子都不会生效**，
测试全绿、屏幕上什么都没变 —— 跟上一轮那颗 `[半整]` 死分支是同一类事故（mutation H1 红 0）。

所以先修词表再接线：
1. `_DELETE_ACTION_WORDS` 的后半改成**从 `_REMOVE_TODO_SOFT` 推**（去掉词尾「了」就是标题形）；
2. `_is_blind_delete` 里那段残渣计算抽成 `_delete_residue`，给新旧两处共用（红线 11b）。

派生顺带修好一条更老的洞：那条待办**已经写进库**时，「算了不吃了」现在走回执路
直接定位到它（`_recent_written_todos`），不再列整张日程。K 批 ⑥ 专门钉这个。

## 三、施工单自己没实现的两条边界，按它的边界表补上

- §3.2 那个 helper 里 `if title and title in t: return True` 是**空的** ——
  匹配和不匹配两支都 `return True`，等于没判断；
- §3.1 条件③「点名另一条就不作废」在代码里根本没写。
  但它 §3.4 的边界表明确要求「我要取消健身」（卡上是《吃自助》）不作废。
  所以我按边界表实现，判据用 `_delete_residue`：擦完**为空**=纯反悔；
  剩下的是**别的东西的名字**→ 不作废；剩下的**就是这张卡的事名**（「吃自助餐不吃了」对《吃自助》）→ 作废。

另外两条它没提、我认为必须有：
- 话里**明说「删」**（「把那个删了」「不吃了，删掉吧」）不作废卡 —— 那是他明说要删库里的一条，
  拿作废卡顶掉就把他真正要办的事吞了；
- 「确认」「嗯」「好的」必须不作废（否则学生点个头就把卡撤了）。

## 四、我摘掉了它要求的一道闸，因为它是死条件

施工单 §3.3 那段前面要 `not asking_rm_todo and not answers_held`。
可暂存每个会话**只有一个位置**（`save_pending` 整份覆盖），挂着 `todo_remove_candidates` 时
`_active_add_proposal` 拿到的就是 None —— 那道判断永远为真。摘掉之后**测试一条都没红**，
这就是它本来没在把关的证明（留着只会让人以为它在把关）。
