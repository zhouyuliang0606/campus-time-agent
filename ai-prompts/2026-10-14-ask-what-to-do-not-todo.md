# 2026-10-14 · 「今晚安排点啥」不入库：问「该做什么」判成问事，改报空档建议

## 一、用户原话与你选的那条路

我上一条汇报里说的是"探针顺带撞见的现象，只报不修"，他当场批了并定了走法：

> 「今晚安排点啥」这种是问事情闲聊的，不入库

我给三个走法（AskUserQuestion），他挑了第三个：

1. 掉给问答（问事/闲聊）—— 没密钥时会看到「还没配置大模型密钥」；
2. 不建卡，追问一句「要安排的是什么事」；
3. **不建卡，但给一句实在的建议** ← 他选的。

"实在"落到实现上就是：读周表空档，告诉他**哪几段真的闲着**，请他报个名字；
不挂任何卡、不写库、不替他决定做什么。所以这一档必须是**确定性分支**（有密钥/没密钥同一句）。

## 二、实测到的三处漏（比汇报那一句宽）

一句探针话（`probe43_family.py`，26 句一族）打出来是这样：

| 句子 | 修前实际 |
| --- | --- |
| 今晚安排点啥 | 挂 `todo_slots` 卡，标题 **「点啥」** |
| 晚上安排点什么 / 安排点什么呢 | 标题 **「点什么」** |
| 安排啥比较好 / 今晚安排什么好 | 标题 **「啥比较好」/「什么好」** |
| 你说我安排啥 | 标题 **「说我啥」** |
| 帮我安排点事 / 安排点事给我 | 标题 **「点事」/「点事给我」** |
| 干点啥好呢 / 今天做点什么好 / 我今晚该干点啥呢 / 这周干啥 | `wants_add_todo` 为 False，掉进无密钥兜底那一档，`_guess_title(msg)` **拿整句话当任务名**，各摊三张卡 |
| 今晚去健身怎么样 | 这句**确实是下单**，可标题成了 **「健身怎么样」**（疑问尾词没擦） |

学生早就驳回过这个形状（快照 `2026-09-29-todo-candidate-reply-fix` 引的原话）：
「**不是随便拿那一句话就去当代办加入日程了**」——这次是它另一头的复发。

## 三、判据一份（红线 10），两处共用

```
_WH_ASK_WORDS = ("啥", "什么", "嘛")          # 只有这一份
_VAGUE_THINGS = ("点事", "一些事", "些事")     # 不收"点东西"：「去买点东西」是正经待办
_vague_ask_name(裸串)  → 首或尾是疑问代词 = 不是事名
asking_what_to_do(句子) → 句里带疑问代词 且 剥完的裸串是疑问串 且 不在删/不在查清单
```

两个取舍都写在注释里，因为都是**实测**推出来的：

· 判据是"**剥完裸串的首或尾**"，不是"含疑问代词就否" —— 含就否会把《什么是爱》这类真名字挡掉
  （同「写好/排好」那条教训：宁可漏几个噪声，不误伤真名字）。变异 V5 把判据写宽，A 批立刻红 2 条。
· 第二道用裸串，不用"抠不出事名" —— 抠不出事名有**别的原因**：
  「安排看《什么是时间管理》」是被「时间」这个老噪声词挡掉的，拿"抠不出"当判据就把这句
  有真名字的下单句判成了"问主意"。第一版我就是这么写的，全量跑出来才看见。

「你帮我安排」这种**没疑问代词**的半句话留在原档（追问「要安排的是什么事？」，test_06 十五批钉着）；
「帮我安排点事」也留在原档 —— 它是"说了要加、没说加什么"，只是名字「点事」不再放行。

## 四、第一版太宽，全量跑出三条真冲突（这就是"改判据必跑全量"）

| 红项 | 现场 | 结论 |

| `test_15`「把那个啥删了 → 不许出加待办卡」 | 我的档抢先答了「这句是在问我该做什么……这几段空着」 | 他在**删**东西。把「删/取消」那道判据从 `wants_add_todo` 搬成 `_has_delete_intent()`，两处共用一份 |

| `test_23` 4c-bis「补条那一档照旧走得通」 | 我上一轮刚把例子换成「我今晚该干点啥呢」，这句现在归新档接走 | **测的必须是走到的** → 换成「帮我看看今晚」（两档都不认它，补条那档照旧被钉住） |

三条都不是"测试写错了"，是我的判据越界截了别人的活；两条排除进判据，一条换例子进测试。

### 但"全量绿了"不等于对：真机复验又查出一条**位置**问题

修完跑全量 0 失败，我重启 8000 在他机器上复验，结果「今晚安排点啥」答的是
「📋 你目前的待办（共 11 条）」——**判据没错，位置排错了**：

· `main` 里那段 `# 3c) 确定性加待办分支` 的注释下面压着 3c-pre* / **3d 列表档** / 3c-ter 一堆分支，
  我把新档紧贴 3c 的 `if` 放 = 排在列表档**之后**；
· 他机器上的样本库早就把「今晚安排点啥」学成了 `list_todo`，判定层第一档就命中列表；
· 沙箱测不出来 —— `SCRATCH` 把 `intent_samples.json` 清了，样本库是空的，
  于是"我这档排第一"在测试里是真、在用户机器上是假。

修法：整档搬到列表档之前（`9f0b5b4`）。两条断言钉住它：C 批比字节偏移，
B 批**往沙箱灌一条同款样本**（`remember("今晚安排点啥", "list_todo", {})`）再问一次。
变异 V8 是真的把那 1135 个字符搬回列表档之后 → 红 2 条，现场逐字复现「你目前还没有任何待办」，
搬回原位逐字节一致。

**记下来的规矩**：凡是"某一档可能被样本库/语义层抢走"的判据，
① 往沙箱灌同款样本再测，② 在真机（用户的 key + 用户的数据）复验一次 —— 少一道就是假绿。

## 七、顺带查到的同族四条，**没修、也没批**（证据在手）

`probe45_conflicts.py` 实测，全是"查/看我现有的安排"被拽进下单或兜底档：

```
「看看我的安排」      → 挂 todo_slots 卡，标题「看看我」
「我今天的安排满不满」 → 挂 todo_slots 卡，标题「我的满不满」
「我今天都有什么事」   → 兜底档三张卡，标题就是整句话
「有啥安排」         → 列表档（这条是对的，对照用）
```

它们是**另一族**（问"已经有什么"该走列表档），不是这次那族（问"该做什么"）；
要修得动 `wants_list_todo` 那道判据，风险面比这次大。要不要一并收，等你点头。
