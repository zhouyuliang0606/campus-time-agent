## 一、改了什么（一笔 `0b4f159`，`app/static/admin.html` 7/3）

成功路径补三行（`adminFetch` 里、401/403 那支与非 2xx 抛异常**之后**、`return resp;` **之前**）：

```js
adminLocked = false;
document.getElementById("adminToken").style.borderColor = "";
if (getAdminToken()) setTokenStatus("✅ 口令有效（只对本次标签页生效）", false);
```

- **为什么写在这儿、不写进点按钮那一刻**：七个 loader 是异步的，点按钮时还不知道成没成；写在那儿就是"定时报成功"——错口令也会绿（M1/M5 专打这一条）。
- **`if (getAdminToken())` 那道保险**：没填口令时任何 `adminFetch` 都不该印「口令有效」（M4 把它写反 ⇒ 判据要红）。
- L1：删掉 403 那支话术（「这台服务器没设管理口令…」）连同它猜的原因；401 话术照旧**把 `resp.status` 打进字面量**（那道闸 401/403 都收，硬写 401 会把 403 说成 401）。
- **没动**：初始未填口令时的红 401 态（单据明说 L2 不是本单）、`admin_guard.py`、`_mask()`、#96 的窄屏两条 CSS、29 个调用点。

## 二、护栏（一笔 `0095409`；`test_57` D 批 8→12、文件 27→31，0 失败）

- **P1 两端钉**：pending 那句仍在 `initTokenBar` 的 click handler 里（**正控**：它不在=判据对着空气转）+ 成功词只在 `adminFetch` + click handler 一个字都不许提「有效 / 生效」。
- **P2 顺序**：`401 闸 < 非 2xx 抛异常 < 成功回写 < return`，且整个封装里**第一次** `setTokenStatus` 也得在闸之后（防"进门先报成功"）。实测锚点：`401@262 http@1829 成功回写@2126 return@2197｜首个 setTokenStatus@769`。
- **P3 死话术**：剔注释后的 JS 里「没设管理口令」「被服务端拒绝」都不许有、「口令不对」必须在；负向判据自带 must-hit 样本（`dead in (js + dead)`）。
- 第四条：闸若还收 403，话术必须走 `resp.status`（不许硬写 401）。
- 两处旧标签改口（不增减项数）：`test_58:311` 的标签原写着「服务器没设口令 / 口令不对」，删掉前半句（它指的是已删掉的那支话术）；`test_57` 两条同理。**断言本体都没动**。
- `_fn_body` 的坑：`async function adminFetch(url, opts = {})` 参数表里就有 `{}` ⇒ 不能取第一个 `{`，从 `") {"` 之后起算。
