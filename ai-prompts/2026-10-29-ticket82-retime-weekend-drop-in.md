## 一 修法

### 1.1 在 `new_date` 兜底之前插一支：周末 → 候选日 → 第一个排得下的

锚点：找到 `# 新日期：语义层给的 > 话里抠出来的 > 没说就沿用旧日期（只改时刻）` 这一段，
在它的**最后那条兜底**（`if not new_date:` / `new_date = old_date`）**之前**插入：

```python
    # ★ #82：说了「周末 / 双休」却没落到具体哪天 —— `_pick_date` 不认「末」（那张正则要
    #   「周 + 一二三四五六日天」，:528 的注释自证）。不接这一档就会掉进下面那句
    #   "沿用旧日期"，然后被 #81 的空改动判据拦住 → 追问「想改到哪天」，
    #   而学生**已经说了**。实测「你帮我想一个周末的时间改改过去」连问两遍同一句。
    #   #75 在排新待办时已经认了周末（`_WEEKEND_WORDS`），这里只补"改期也认"——
    #   不重造词表，也**不动 `_pick_date` 的正则**（那张有二十几处调用方）。
    if not new_date and any(w in t for w in _WEEKEND_WORDS):
        base = clock.today()
        cand = []
        if base.weekday() >= 5:            # 今天就是周末 → 先看今天（"改到周末"多半指眼前这个）
            cand.append(base.isoformat())
        sat0 = base + datetime.timedelta(days=(5 - base.weekday()) % 7)
        cand += [(sat0 + datetime.timedelta(days=off)).isoformat() for off in (0, 1, 7, 8)]
        cand = list(dict.fromkeys(cand))   # 今天是周六时 sat0 就是今天，去重
        new_date = next((d for d in cand if pick_free_slot(d, prefer=t)), "")
        if not new_date:
            # 两个周末、四个日子全都排不下 → 如实说，不硬凑（跟 pick_free_slot 的约定一致）
            return {"status": "unclear", "todos": [old], "old_label": old_label}
    if not new_date:
        new_date = old_date
```

**三个技术细节，一个都不能省**：

1. **`datetime.timedelta`**，不是 `timedelta` —— 这个文件是 `import datetime`（模块级，没有 `from datetime import`）。
2. **`(5 - base.weekday()) % 7`** —— `weekday()` 周一=0、周六=5。今天周六得 0（今天），
   今天周日得 6（下周六）。少了 `% 7`，周日那天会算出负数。
3. **`dict.fromkeys` 去重** —— 今天是周六时 `sat0` 就是今天，不去重会出现两个相同候选，
   `next()` 虽然不会错，但候选项数会骗人。

### 1.2 候选日为什么是 `(0, 1, 7, 8)` 这四天

`(0,1)` = 最近的周六、周日；`(7,8)` = 下一个周六、周日。

一个周末只有两天，而这两天可能全被课占满（和 #75 在 `:538-544` 里写的两笔账同一个理由）。
只给两天 ⇒ 本周末排满就归零，学生明明说了"周末"却被告知"排不下"。
给两周够用，且**最多只多算两次 `pick_free_slot`**（纯计算，不写库）。

### 1.3 「你帮我想」这个意图，本单**不单独处理**

学生那句是「你帮我想一个周末的时间改改过去」——**两个东西**：一个意图（你替我定）+ 一个范围（周末）。

**只要「周末」被接住，系统就已经在"替他想"了**（`pick_free_slot` 自己挑一段、并按最长空档优先）。
所以这一半自然解决，不需要额外的"替我挑"分支。

真要处理"完全没有约束的、你随便挑一个"（「你帮我随便改个时间」），那是另一个决定：
**它可能挑到学生根本不想去的日子**，而且和目标日无关。留给演示后，不在本单。

## 二 判断与理由

### 2.1 为什么不改 `_pick_date` 的正则，把「末」加进字符集

看起来最省事：`[一二三四五六日天]` 改成加个 `末`。**但 `_pick_date` 有二十几处调用方**，
其中 `:1406`、`:3599`、`:3647`、`:3670`、`:3721` 这些地方拿它的返回值当"学生说了一个确定的日子"用。
让它对「周末」也返回一个日期，等于**让所有调用方都以为"周末"是一个具体日子** ——
那正是 #75 在 `:527-530` 花了一整段注释去避免的事。

**判据只在需要它的那条路上加，不要改公共函数的语义。**

### 2.2 为什么挑"第一个排得下的日子"，而不是直接给周六

直接给周六最省事，但学生说"周末"**没有指定哪一天**，周六满了周日空着，硬给周六
只会让他再说一遍 —— 又回到"说了等于没说"。

`next((d for d in cand if pick_free_slot(d, prefer=t)), "")` 的语义正好是
**"最近的那个排得下的周末日子"**，这就是学生说"周末"时脑子里想的东西。

### 2.3 `prefer=t` 传整句，是故意的

`pick_free_slot(d, prefer=t)` 里的 `prefer` 用来认"上午/下午/晚上"这类偏好。
整句里可能还有「下午」——「周末下午改过去」，那它就能把时段收窄到下午。传整句比传空串信息更多。

（「周末」本身不在 `pick_free_slot` 的时间词表里，传进去无害。)

### 2.4 代价

- 多调 1~4 次 `pick_free_slot`（纯计算，只读库）。可忽略。
- 真正的风险：**这段插在 `new_date` 的推导链里，链一断，「挪到周五」也跟着坏了**。所以 §三 的正控是本单命门。
