## 一、改了四处

### 1.1 页面那两路：与工具那两路同一个判据

`app/main.py:6021`（`GET /api/todos`）与 `:6031`（`GET /api/todos/month`）原本都是
`return {"todos": list_todos(date)}` —— **原始记录直接出去**，一个键都不筛。

修法不是「在 main 里再写一遍 `t.get("id")`」（那就有第二份判据了），是
**从 `planner` 把 `_todo_has_id` 借过来**（`main.py:81` 那句 import 里补一行）：

```python
    _todo_has_id,                    # #66 收尾：页面那两路也要按同一个判据滤，见 /api/todos
```

两路改完：

```python
@app.get("/api/todos")
async def todos_list(date: str | None = None):
    rows = list_todos(date)
    keep = [t for t in rows if _todo_has_id(t)]
    return {"todos": keep, "dropped": len(rows) - len(keep)}
```

```python
@app.get("/api/todos/month")
async def todos_month(month: str = ""):
    ...
    days: dict = {}
    dropped = 0
    for d, rows in list_todos_in_month(month).items():
        keep = [t for t in rows if _todo_has_id(t)]
        dropped += len(rows) - len(keep)
        if keep:
            days[d] = keep
    return {"month": month, "days": days, "dropped": dropped}
```

三处设计要说清：

- **为什么页面这一路也要滤，而不是兜成空串**：`id` 在这一路是**操作句柄** ——
  前端勾完成走 `PUT /api/todos`、删除走 `DELETE`、改期也带它，缺了就是 `id=undefined`
  打回来。要么删不掉，要么命中的是另一条。**这跟工具那两路是同一条理由**，不是新判据。
- **`dropped` 为什么必须给**：工具那两路能说一句人话（`{"info": …}`），JSON 这一路不能插话；
  但"少了一条"不许没人知道 —— 页面上要能显示「另有 N 条数据不合规」，所以给计数。
- **月视图某天被滤空就把那天从表里删掉**，不留空列表：前端按「没有这个键 = 0 项」渲染，
  留一个空列表会让格子显示「有 0 项」这种自相矛盾的角标。

### 1.2 `public_view` 的「共 N 条」：说明行不是一件事

`app/agent/public_view.py` 新增一个判据（放在 `_item_line` 之前）：

```python
def _is_note(it) -> bool:
    return isinstance(it, dict) and set(it) == {"info"}
```

`list` 那支改成先拆后数：

```python
    items = [it for it in obj if not _is_note(it)]
    notes = [it for it in obj if _is_note(it)]
    if not items:
        return _strip_internal("；".join(n for n in (_item_line(x) for x in notes) if n))
    lines = [ln for ln in (_item_line(it) for it in items[:3]) if ln]
    head = f"共 {len(items)} 条"
    body = head + ("：" + " / ".join(lines) if lines else "")
    tail = "".join(f"（{n}）" for n in (_item_line(x) for x in notes) if n)
    return _strip_internal(body + tail)
```

**两个坑，第二个比第一个更常见**：

| 坑 | 表现 |
|---|---|
| 计数把说明算进去 | 「共 3 条」= 2 件事 + 1 句说明（真机撞到的就是它） |
| 说明句**占掉「挑三项」的位置** | `list_todos_range` 把 `notes` 摆在**最前面**（`planner.py:1423` 那句 `notes + [...]`），所以 `obj[:3]` 先读到的是说明 —— 三条真条目一句都挤不进去，输出变成「共 3 条：另有 1 条待办没有 id…」。这条改装前的版本其实更严重，只是没人念到 |

判据只认「**只有** `info` 一个键」的行：带别的键的记录即使也写了 `info`，它仍然是一件东西。

## 二、两个判断（这两条是本单的主要结论）

### 2.1 「另存原文」还是「把话改小」→ **改话**

三条理由：

1. **`public_view` 存在的理由就是剥掉内部指令**（`public_view.py:4-8`：写侧收一次，三个面都干净）。
   #64 落盘走同一份 ⇒ 管理端看到的和学生看到的一致。**这是设计，不是缺陷。**
2. **另存原文 = 新增一份更敏感的落盘数据**。`d78e953` 的提交信息自己写着「这本比用量账更敏感」，
   而原文里带着「严禁…」「可以用 list_day_todos 看一下…」这类写给模型的指令 —— 再加一层原文，
   敏感度只会更高，**对演示零增量**。
3. **改话之后那句话反而更有说服力**：原来靠「我存的是原始的那份，所以可信」撑场面；
   现在能指着 `engine.py:229` 说「这里和学生屏幕是同一份数据，前端只是显示时再截 120」。
   **同源 > 自称原始。**

### 2.2 同族那 7 处要不要整族收 → **不收**（而且那 7 处只有 5 处站得住）

先把数目改对。指南 §六 现写的是「**7** 处真读盘（`files.py` 的上传 meta ×5、`intent.py` 的样本与自定义服务 ×2）」，实测那 2 处 `intent.py` **都不是真读盘**：

| 位置 | 实际 | 判 |
|---|---|---|
| `intent.py:432` `out["intent"]` | `out` 是**同函数上一行自造的字面量**（`intent.py:420` `out = {"intent": best.get("intent"), …}`），键一定在、值是 `None` ⇒ 不会 KeyError | **扫描误判**，属"代码自造 dict"那一档 |
| `intent.py:470` `s['id']` | 进 `rows` 时已经过 `and s.get("id")` 前置过滤（`intent.py:464`）⇒ 缺 id 的根本进不来 | **扫描误判** |
| `files.py:35` `f["id"/"name"/"chars"/"ts"]` | `visible_uploads()` 的产物，真读盘 | 真（4 处） |
| `files.py:156` `f["id"]` | `list_uploads()` 的产物，真读盘 | 真（1 处） |

⇒ **真读盘 5 处，全在 `files.py` 一个文件里。**

**还是不收**，三条理由（跟数目无关，跟性质有关）：

1. **缺键只会「崩」，不会「错」。** `files.py` 那 5 处缺键 → KeyError → 500，看得见、查得到。
   待办那两处之所以值得修，是因为 `by_id[""]` 会把好几件事**并成一条**（`row["dates"].append` 一路加）
   —— 那才是"静默错乱"。**崩比错便宜**，这条判断不改。
2. **收口期每改一处，要重跑 88 批 5098 项 + 重验一条演示链。** 现在离提交只剩几天，
   拿**确定性**换**一致性**，不划算。
3. **它们赌的「写侧必写」比待办那两处更硬**：`add_upload` 只有一个写入口、`id` 是 uuid4 造的，
   没有"后加字段"的历史包袱（`status` 那种情况）。风险本来就低一档。

### 2.3 启动自检 `/api/health/data` → **不做，但它才是这 5 处的正解**

- **为什么不做**：它是可观测性，不是正确性。演示时不会有人打这个接口；而它要扫四个 loader 的产物
  + 定一份「哪些键必须存在」的表，成本比看起来大（那份表就是第二份 schema，也要人维护）。
- **为什么它才是正解**：A 口径（读侧兜底）明码标价的代价是「数据被手改过不再当场可见」。
  这笔账的正确还法是**一个可以随时问的地方**，而不是在 5 处各补一个 `.get`（那只是把 5 处
  的风险挪到"永远没人知道"）。
  ⇒ 将来做这件事，**不要在 `files.py` 里补 `.get`，去做那个口**。
