> 这是**上一层楼的问题**——不是列被撑爆，而是**同一时段的两条被叠在一起**。

## 用户原话

## AI 研判（先用真数据实名核对，别照着截图猜）

先把 `/api/timetable` 与 `/api/todos` 拉出来对照，并算出本周（9/21–9/27）每一天的构成：

| 列 | 内容 |
|---|---|
| 周四 9/24 | 大学英语 10:00 / **数据结构 14:00-15:40**（课） |
| **周五 9/25** | 线性代数 08:00 / **心理学选修 14:00-15:40**（课）/ **小组会议：项目分工 14:00-15:30**（待办） |

**关键发现：真凶在周五那列**——`心理学选修`（课，14:00-15:40）与
`小组会议：项目分工`（待办，14:00-15:30）**本身就是真时间冲突**。
学生看到 `小组会议` 压在 `数据结构` 上，是因为周五列自己内部两条叠了，
再加上上一轮修掉的**列宽溢出**让整列横向挪位，视觉上就像压到了隔壁周四的 `数据结构`。
**两个 bug 叠在一起，症状长得很像，根因完全不同。**

## 根因（两种周表，各有各的毛病）

1. **`plan.html` 的周表是"时间轴式"**：`.blk { position:absolute; left:3px; right:3px }`，
   纵坐标 `top = 开始分钟 − DAY_START`（1 分钟 = 1 像素）。
   **两条时间有交叠时，两条块宽度位置完全相同 → 后画的（待办）把先画的（课）整个盖没。**
2. **`student.html` 的周表面板是"列表式"**：没有时间轴，条目按开始时间顺序往下排。
   同一时段的两条只能上下挨着、长得一模一样 → 学生以为界面"重合/画错了"。

## 代码改动

### 1. `app/static/plan.html` — 冲突并排（核心修法）

把当天条目（课程 + 待办）先合到一起，按开始时间排序，然后**按"最大结束时间"做冲突分组**：

```js
const groups = [];
items.forEach(it => {
  const g = groups[groups.length - 1];
  if (g && it.s < g.end) { g.items.push(it); g.end = Math.max(g.end, it.e); }  // 与当前组交叠 → 并入
  else groups.push({ end: it.e, items: [it] });
});
```

同一组的块**并排成 N 栏**，用 CSS 变量把左右边界交给样式：

```css
.blk { position: absolute; left: var(--bl, 3px); right: var(--br, 3px); /* ... */ }
```

```js
const l = (i === 0)    ? "3px" : `calc(${(i * 100 / lanes).toFixed(2)}% + 3px)`;
const r = (i === lanes-1) ? "3px" : `calc(${((lanes-1-i) * 100 / lanes).toFixed(2)}% + 3px)`;
```

- 冲突 2 条：各占半宽（`3px / 50%+3px` 与 `50%+3px / 3px`）——两边都能看见。
- **单条（lanes=1）：回到 `3px / 3px`，与原样式零差异**，不影响任何无冲突的场景。
- 待办加了 `📌` 前缀与课程区分（原来两者只在颜色上不同）。

### 2. `app/static/student.html` — 冲突记号

列表式面板没法并排（没有时间轴，硬做会很难看），改为**明确指出这是时间冲突**：

```js
evts.forEach((x, i) => {
  x.clash = evts.slice(0, i).some(p => x.s < p.e && x.e > p.s);
});
```

冲突条目加 `.clash`（红边 + 内阴影）与右上角「撞」角标（`title="和其他安排时间重叠"`）。

### 3. `tests/test_05_student_views.py`（新增第十四批）

- `plan.html`：有冲突分组算法、块用 `--bl/--br` 变量、按 lane 算百分比、
  **不再把块写死 `left:3px; right:3px`**。
- `student.html`：算了 `clash`、挂 `clash` class、有「撞」角标与 `.evt.clash` 样式。
- 算法自证：两条 14:00 起（15:30 / 15:40 收）必须被归进**同一组**且拆成**两栏**；
  单条时回到 `3px/3px`。

## 教训（写进技能）

1. **"看着一样"的两个报障，根因可能完全不同。**
   这一轮和上一轮（列宽溢出）症状都是"叠在一起"，但一个是 CSS 尺寸计算、一个是绝对定位无避让。
   **永远拿真数据实名核对**（拉接口 + 按天重建），别照着截图猜是哪一列/哪一天。
2. **绝对定位的日历块必须做冲突避让**，否则同一时段的后画者必然盖住先画者。
   "按最大结束时间分组 + 同组并排分栏"是通用解法（Google Calendar 也是这么做的）。
3. **列表式视图没有空间做避让时，就给冲突加显式记号**（红边/角标），
   让学生知道"这是时间冲突"而不是"界面坏了"——错误可见 ≠ 功能错误。
4. **分栏算法务必保证 `lanes=1` 时退化成原样**，否则会波及所有无冲突场景。
