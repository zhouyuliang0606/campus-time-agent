# 2026-09-30 · 闲聊出口与人设红线（"聊日常被转到待办"）

## 学生报障 / 本轮诉求
> 症状原话：**闲聊兜不住，聊日常会被转到待办；人性化不够。**
> 本轮指令：**闲聊部分进行收尾。**
> 交办 Prompt：`CampusTime-闲聊出口与人设红线-prompt.md`（另一窗口写的规格）。

两条实证（都先跑代码复核，不信印象）：
- **「记一下今天很开心」** → `_ADD_INTENT` 里的"记一下"命中，`_pick_title` 抠出「很开心」，
  `looks_like_thing('很开心')` 判真**通过** → 出卡「要不要把 **很开心** 排进日程？」。
  学生要的是吐槽，系统给他排了件"事"。
- **「我饿了」** → 规则层是**干净**的（`wants_add_todo` 返回 False），可**在线语义层判成了 add_todo**，
  照样拉出待办卡 —— 模型把"状态"读成了"指令"。
- 第三个根子：共享排程工具（`propose_todo_tool` 等）**注入所有模块**。
  尾部模型手上正好有"出待办卡"的工具，学生一闲聊，它顺手就来一句
  "要不要我帮你安排个…？"——闲聊变成**推销**。

## 改动（三处代码，写路径/校验件**零改动**）

### 1. 人设层 —— `app/main.py` 新增 `CHITCHAT_RULES`「闲聊守则」+ 拼装
与 `FILE_HINT` / `ASSISTANT_RULES` 同一处（`prompt = base_prompt + FILE_HINT + ASSISTANT_RULES + CHITCHAT_RULES`），
**改一处、所有学生端模块生效**。四条：
1. 学生说累/天气/吃饭/吐槽心情 → 像靠谱学长一样自然回一两句，可带一句关心；
2. ⛔ 闲聊时绝不主动提议加待办、排时间；**绝不调用** `propose_todo_tool` /
   `propose_todo_slots_tool` / `propose_todo_mode_tool`；
3. ⛔ 不用"要不要我帮你安排个…？"这类话收尾**推销**；
4. 保持一两句，写完就停。

> 这是**加守则，不是改判定逻辑**；一条写路径都没碰。

### 2. 语义层提示词 —— `app/agent/intent.py` 的 `_INTENT_SYSTEM`
`chat` 定义下补日常例子：`好累啊`、`今天好热`、`中午吃什么`、`我饿了`、`我困了`、`我累了`
→ 一律 `chat`（module 给 `faq`）；并加两条红线：
- **感叹、心情、日常问候、生理状态都不是 add_todo**；
- 学生说自己饿了/困了，是**在表达状态**，不是下达指令——"他想吃饭"是你的猜测，
  **没有他的话就不许替他排**。

### 2.5 保险丝 —— `intent.physio_state_only()`：生理状态句**确定性否决**
> 提示词补例子只能降低概率、**消不掉**（模型是非确定性的），所以再加一条与问句守卫同款的硬否决。

判据三条**同时**成立（宁可漏判，也不替他瞎排）：
① 摘掉程度词/人称/同字词干扰后还剩生理状态词（饿/困/累/渴/饱/撑/疲惫/疲倦）；
② 整句**一个行动词/事名都没有**；③ 没有报钟点、且句子很短（≤15 字）。

接线三处（`app/main.py`）：
- 判定层：命中 → 把语义层结论一起改成 `chat` + `faq`（**不无中生有**造一份语义结果）；
- 工具门禁：`_schedule_tools_allowed()` 对状态句 `return False`——**一个排程工具都不给**；
- 加待办分支（3c）再补一道 `and not _physio` 安全绳。
- ⚠️ **例外**：学生正在补上一轮"要安排什么事"的追问时**不算**（那是在**回答**，不是自言自语），
  否则追问会原地打转。

### 3. 标题判真 —— `app/modules/planner.py` 新增 `looks_like_chitchat()`
`_title_ok` 加一道：标题主体**摘掉心情/生理/天气感叹词 + 程度词 + 语气词 + 人称后一个字不剩**
（很开心 / 好累 / 好热 / 我饿 / 肚子好饿 / 无聊死了 / emo了）→ 不是一件事，走**既有追问**。
- 判据刻意写成"**主体只剩这些词**"（而不是"含这些字就否掉"）：
  「买冷饮」摘掉"冷"还剩"买饮"，照旧判真——**不误伤真待办**。
- 词表宁小勿大（未收"有点/难受"之类拿不准的）。
