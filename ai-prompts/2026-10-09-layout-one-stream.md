# 2026-10-09 布局咨询：诊断出"病根不是版面"，然后做了四件打通语境的事

## 一、用户 Prompt 摘录

> 「我现在感觉布局很奇怪，主用的是日程这个板块，校园问答是一个小模块，而且两者对话记录不在一起，
> 在校园问答去说一些代办的事情会出现不弹卡的情况，还要这个登录页面，管理端页面布局也不合理，
> 你帮我想想怎么布局，可以去网上找点已有现成的网站，去模仿」

追问「有没有更好的改法，没有的话就按这个改」→ 选 **先打通语境**；登录页 → 选 **删掉，直接进学生端**。

## 二、AI 研判与决策

### 2.1 先查代码，再谈版面——三个症状里两个半不是布局问题

| 用户的感受 | 实际根因 | 是不是版面能治 |
|---|---|---|
| 「两者对话记录不在一起」 | `student.html` 的 `sessionId(view)` 给每个左侧模块各发一个 key（`campustime_session` / `_schedule` / `_express`…），两段历史、两份待确认卡 | ❌ 是数据隔离 |
| 「在问答栏说待办的事不弹卡」 | `main.py:1110` 一道主动拦截 `_in_qa_column`：问答栏说删/改/标记完成，只回一颗「前往我的日程」按钮 | ❌ 是一条规则 |
| 「主用的是日程，问答是小模块」 | 落地页写死 `switchNav("chat")` | ✅ 这个才是版面 |
| 「还要这个登录页面」 | `login.html` 只有三颗跳转按钮，零认证 | ✅ 删掉即可 |

**动手前用真机把症状复现了一遍**（打 `/api/chat`，同一句话在 faq / planner / station 三个栏目各一次）：
加待办哪儿都出卡；**删/改在问答栏被挡**；「我那些待办都列一下」在问答栏答成「没找到您上传的待办事项文件」。
最后那条后来查明是**模型编的**（全项目搜不到这句话，只存在于 sessions.json 的历史里）。

### 2.2 为什么顺序必须是"先语境后版面"

上一轮（项目历史上）「把日程当主页」这一改做过**并被回退过**（接手指南写着"用户觉得丑"）。
如果不先拆掉数据隔离和拦截，改完版面还是会出现"日程栏说的话切到问答栏就没了""问答栏点不弹卡"，
用户只会觉得白改一遍版面还更难用。**先让同一句话在哪个栏目都同样办事，再谈谁占第一屏。**

### 2.3 四条备选布局为什么都不如"打通语境 + 日程落地"

- 把 pending 塞进 `/api/conversation` 一次取回 → 动后端，且把"历史"和"待确认提案"耦进一个接口；
- 卡片按原位置插回消息流 → 要改 `append_conversation` 的记录格式；
- 不自动恢复、历史里放一颗「继续处理」按钮 → 学生多点一次，而"卡还挂着"是系统本来就知道的。

参考形状（用户提的"模仿现成网站"）：**Google Calendar + Gemini 侧栏**、**飞书日历 + AI 助手侧滑**、
**Notion Calendar** —— 共同点是"日程是主体，AI 是一条常驻输入"，而不是两个并列的聊天栏目。
本轮先做到"日程当落地页 + 一条聊天流常驻下方"，没动视觉规格（栏宽/密度/色板留给下一轮）。

### 2.4 中途试过又**撤掉**的一处扩表（重要，别照抄）

为了让「我那些待办都列一下」不再被模型胡说，我给 `wants_list_todo` 补了结构判据
（"提到待办 + 无写动作字样 → 就是读列表"）。跑全量：**13 条红**，全是误伤——
「健身怎么没出现在待办里」这类报障句被拉去念了一遍清单。已 `git checkout` 回退。
教训：**读意图也不能纯靠"没得写意图就算读"这种反向判据**，一句抱怨里既没有写动词也不是在读列表。
「列待办被模型答成文件」这条**根因仍未修**，留作待决（见 §六）。

### 2.5 改完之后自己撞出来的第五个问题

落地页改完，真机回归发现裸发「我一周要去三次健身房」**不出卡了**，trace 写着「听成 问事」。
不是布局改坏的：那句话里没有"加/安排"这类意图词，规则层本来不接，
之前能出卡全靠我上一轮探针跑成功时**学进样本库的那条映射**——而我把它当脏数据删了。
这说明"用户原话的可用性挂在一颗学来的样本上"本身就是隐患。
补法：`wants_add_todo` 认「一周 N 次 (N≥2) + 事名判真 + 不带疑问样」→ 规则层直接接住（commit `0208dc1`）。

## 四、验证

### 4.1 全量

**通过 2056 项 / 失败 7 项（37 批）**。7 条红 A/B 证明**全部是存量**：
临时还原 `main.py`（拆拦截前）单跑 `test_06`+`test_23` → 六条 + 一条，与拆完后完全一致。
另记一笔：`test_06` 的红从历史上的 2 条涨到 6 条，**原因不是代码**——
`sandbox()` 只清 `settings.json`/`uploads*`/`notices`/`student_messages`/`workorders`，
**不清 `student/todos.json`**，测试数的是真实演示数据；用户今天加的 3 条「健身」把计数预期打乱了。
这条属于护栏自身的缺陷（见 §六）。

### 4.2 反向验证

- `test_36` G 批 + `test_35` H 批：H1 把频次规则摘掉 → 红 8 条，且端到端那条当场回出
  模型编的话（「我看了下你这周的空档，给你挑了几个合适的时间段」）——正是它该防的一幕。
- 拆拦截那次没做单独变异，因为 `test_10` D 批③「同一句话两个栏目回同一种卡」本身就是
  一条反向断言：把拦截加回去它就红。

### 4.3 真机（browser-use）

1. `/` → 302 → `/student`，落地即「我的日程」面板（周视图 + 逐日明细，今天高亮），聊天输入常驻下方；
   `stage.scrollTop=0`、`panel可见=true`、`session键数=1`；
2. 发「我一周要去三次健身房」→ 出卡、5 行、**勾 3**、按钮「加入日程（3 项）」，trace 走规则层；
3. 切「校园问答」→ 消息数不变、卡还在、日程面板隐藏（一条流跨栏目成立）；
4. 上一轮的 F5 恢复仍然正常（G 批断言未破）。
   探针留下一张**未确认**的卡在该浏览器 session 的 pending 里（3 小时 TTL 自动失效），没写进任何数据。

## 五、还没做、建议下一轮做的（按性价比排）

1. **管理端按使用频率重排**（用户明确说不合理）：现在 7 张卡是开发顺序，
   高频的「学生工单 / 消息收件箱 / 用量」沉在最底下，配一次就不看的「客服人格」在第二屏。
   建议两栏 + tab：左「今天要用」（工单、收件箱、用量），右「配置」（API、知识库、人格、通知）。
2. **视觉规格**：本轮只改了结构，没碰栏宽/密度/色板。上一轮"觉得丑"如果重演，差在这一步。
3. **`sandbox()` 应该给测试一份干净的 todos**（否则任何往日程加待办的用户操作都会红一片）。
4. 「列待办被模型答成上传文件」的根因（§2.4）——方向是**收紧 faq 的兜底话术**，
   不许它声称"您上传的文件"这种它没查过的东西，而不是再给 `wants_list_todo` 补词表。
