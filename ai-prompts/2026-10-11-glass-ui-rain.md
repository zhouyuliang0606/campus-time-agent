## 2. AI 研判

### 2.1 动手前先核对 skill 的假设成不成立（结论：只对 1/7 页面成立）

skill §6 写着「把 token 注入 `:root` 就能全局生效」。实测本仓库：7 个页面里**只有
`student.html` 有 CSS 变量层**（`:root` 在 435–448 行，全站 101 处 `var()`，是
2026-10-02「清爽留白」那层收进去的），其余 6 页 `var()` 数量为 **0**，硬编码色 5–59 处。

→ 决定：**改值不改名**。13 个 token 键名一个不动，只换值，101 处引用自动跟上。
改名等于把一次视觉改版做成一次全文件重构，而且 `test_44` B 批专门钉住这件事——
CSS 变量改名是**静默失效**（不报错，只是掉回继承值），没人会看见。

### 2.2 skill 的 veil 原值在这张图上不成立（实测推翻）

按 90×18 的文字窗口逐格取均值算合成亮度，对 `--theme-muted-fg`（比 `--theme-fg2` 更弱）
求 WCAG，取全页最差值，**反解**每档背景需要的 veil 强度：

| 背景 | 半透 .16 需要 veil | 微透 .30 需要 |
|---|---|---|
| 雾松林（CC0） | **.31** | .23 |
| 银河（CC BY 4.0） | .40 | .33 |
| 450 星空（开亮核压暗后） | ≈.10 | — |
| 用户提供的草坪 | .62 | .56 |

草坪图要 .62 才够 4.5:1，那就等于放弃"看得见背景"——**深色玻璃配亮图，veil 每一分都在
吃背景；配暗图，veil 几乎免费**。这条决定了背景取向，也解释了为什么用户拧任何档位都觉得不对。

### 2.3 「土」的根因不是配色，是界面性质不匹配

对照 skill 原版 `assets/showcase.png`：那是一张**稀疏 landing page**（一个大标题 +
一张手机模型 + 四颗胶囊），而学生端是**密排工具界面**。玻璃拟态在前者显贵、在后者显贱。
四条按性价比排：① **界面在拿 emoji 当图标**（最大单一来源，emoji 自带颜色与风格，
任何配色都压不住）② 强调色铺太满（原版只 4 处，我们十几处）③ 字阶太平（全站 12–16px）
④ 容器一圈亮边。本轮做了 ①，并顺手把「--brand 一名两用」的坑堵了（见 2.5）。

### 2.4 背景素材去 Commons 而不是 GitHub

用户说"去 GitHub 找找"。GitHub 不是素材主场（搜出来是 awesome 列表和 0 星模板）；
改走 **Wikimedia Commons**，它有许可元数据与直链，能按"许可证干净 + 比例接近 16:9"筛。
捞回四张候选，选中两张入库：`forest.jpg`（CC0）、`milky.jpg`（ESO/S. Guisard，CC BY 4.0）。
用户自己提供的两张图**没有进仓库**——来源未确认，公开仓库提交前得先落实授权。

### 2.5 三处实现层的坑（都记进代码注释了）

- **`--brand` 一名两用**：它既被当文字/边框色、又被当底色用。浅色主题下「蓝底白字」成立，
  换成亮柠檬绿后「亮绿底 + 白字」直接糊掉。实测抓到 `.tab.active` 中招，连同 `.btn` 族、
  `.sb-avatar` 一起把文字翻成 `--brand-fg` / 亮绿字 + 深色投影。**透明度一降，字色必须跟着翻。**
- **`<use>` 引 symbol 会让动画失效**：use 复制出的内容在 shadow 树里，文档样式（含 `.wg`
  的扇翅动画）选不中，只会得到一只不会动的鸟。所以图标可以 `<use>`（无动画），鸟必须内联。
- **iframe 里的确认卡拿不到父页背景**：`student.html` 的 `.cf-inline` 是动态建的 `<iframe>`
  加载 `/confirm`，`backdrop-filter` 只能模糊 iframe 自己的内容。本轮**未解**，见 §5。
