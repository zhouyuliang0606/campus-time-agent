### 1.2 待办本来就在周六：**排序那一行不够**（本单最大的一笔偏离）

单据给的是那一行，放在 `next(...)` 之前 —— 我照抄了，然后实测发现它**只解决了一半**：

```python
# 单据 §1.2 那一行（原样落进 `build_retime_existing_proposal`）
_old_d = old.get("date", "")
if _old_d in cand:
    cand = [d for d in cand if d != _old_d] + [_old_d]
```

候选日的顺序对了，但**定时刻那一步**（`if new_date != old_date:` 那一支）仍按"日子换了没换"来判断：
学生选中的仍是周六（旧日期只是排到最后、没被删），`new_date == old_date` ⇒ 走 else 沿用旧时刻
⇒ 撞上 #81 的空改动判据 ⇒ 又是一句「想改到哪天」。

所以补了第二处（这是**偏离单据**的地方，配了独立判据）：

```python
_from_weekend = False            # 周末档里挑中了哪天就置 True
...
if new_date != old_date or _from_weekend:     # 定时刻那一步也认周末档
```

**证据就是变异 W2**：只留排序、把 `or _from_weekend` 拿掉 ⇒ F2 当场红
（F2 那一幕 = 周日 + 下周末全满、周六另有空档 ⇒ 应回**周六换个时段**，实测退化成 unclear）。
这笔正是"照抄单据那一行会漏掉的东西"。

另外把单据这句话抄进代码注释与测试口径：**改期时"目标日期集合"里，那一天本身不是不能选，是不该优先选。**

### 1.3 `unclear` 按 `reason` 分来源，一套机制四个出口

`weekend_full` 并进 `no_slot`（它就是 no_slot 的特例，没有独立语义）。实测的形状（改后，AST 取返回键）：

| 出口 | `reason` | 还带什么 | `main` 说的那句 |
|---|---|---|---|

两条技术要求都落了并各有一条判据（单据 §1.3）：
1. **两个来源都要标** ⇒ E3 按 AST 数：`no_slot` 两处 + `no_time` 两处，且
   `n_slot + n_time == n_exit == 4`（只数 reason 挡不住"新加一个不标 reason 的出口"）；
   W3 那一笔（空改动不标）当场红 C6 + P4 + E3 —— 这一族** runtime 与静态都有牙**。
2. **按 reason 分支前先取默认值** ⇒ `(_rt.get("reason") or "no_time").strip()`，判据 E3-bis。
   ⚠️ 这笔的牙**只有静态那一根**（W5 只红 E3-bis）：今天四个出口都带 reason，
   没有任何运行时输入能走到"缺 reason"那一步 —— 这条判据防的是**以后的调用方/老测试**，
   不是现在的链。别把它当成"运行时兜底已经验过了"。
