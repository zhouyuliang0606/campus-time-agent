## 一、改了什么

### 1. `cabc508` store 层（校验只有一份规则，编辑复用同一份）

- `validate_service_def(obj, exclude_id="")`：`taken`（重名闸）与 `existing`（撞车闸）**必须用同一份
  `rows`**，`exclude_id` 只在这一处过滤一次。写在这里的理由也写在注释里：只排除一处就只修好一半
  —— 重名过了、撞车还拒，报错仍然说「撞了」，看报错的人查半天不知道撞的是谁（M2 钉这一条）。
- 新增 `update_service(sid, patch)`：就地并 `SERVICE_FIELDS` 里的键，**id / created_at / dept 一律不跟着
  patch 走**。不复用 `add_service`（那是 append，会多出一条同名服务而旧的那条还在）；
  id 是台账 `custom/<id>.json` 对上的钥匙，换 id = 把已登记的记录甩掉（M3 钉这一条）。

### 2. `c109e6f` 接口层：两端共用一份编辑逻辑

- `_apply_service_edit(sid, body, dept_scope)`：404（不存在）→ 403（不归这端管）→ 400（内置那项不能改）
  → 校验 → 落库。**顺序是"先判归属再判内置"**：管理端碰内置那项（`pkgloss` 归驿站）回的是 403
  「归驿站处理，后勤这边不能改」，不是 400 —— 这是 T6-b 钉住的实测形状，与单据写的"内置 400"
  在管理端那一支不同，照实登记。
- 三只新口：`PUT /api/admin/services/{sid}`（带口令，后勤）、`DELETE /api/admin/services/{sid}`
  （带口令，后勤）、`PUT /api/station/services/{sid}`（**不挂口令**，与同族那几个驿站口同一个口子，#18 的口径）。
- 删除的口径与驿站端**逐字一致**：不存在回 400 + 一句「内置服务不许删，或者这项服务不存在」，
  不是 404（`test_65` A3 钉着）。

### 3. `753be12` 两端界面

- 管理端「后勤报修」每张自建卡两个按钮（【编辑触发词】/【删除服务】）；驿站端服务清单每条自建项
  一个【编辑触发词】。**内置那项两端都不给按钮** —— 后端那道拒改/拒删才是真的，前端只是让人不必点。
- 弹窗（`askPrompt` / `stPrompt`）一行一条、预填现有触发词；提示语两端**逐字一致**，
  并且明写「疑问句（『报修要多久』这种）不要写进来 —— 那是问事，写进来会把提问接成报修登记」。
  本单**不修**"问句被当触发词"这个根（要改的是 `match_service_by_trigger` 那一层，单据 §四.4 说另立一单），
  但既然把编辑口打开了，至少在人家正在写那一句的地方把真话说出来。
- 删除确认里那句真话照写：`只删服务定义。它名下已登记的记录留在台账里，不受影响。` +
  `定义删了只能用那句话重新生成一份；已登记的记录不会跟着走，但新服务也接不上旧记录。`
- 改完/删完各自 `loadRepair()` / `loadServices(true)` 立即重画，不等 5 秒轮询。
