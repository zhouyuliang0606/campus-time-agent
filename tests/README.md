# tests/ —— 项目的自检清单

## 怎么跑

在项目根目录敲一条命令就行：

```bash
python tests/run_all.py
```

（Windows 上如果用项目里的虚拟环境，就是 `.venv\Scripts\python.exe tests/run_all.py`）

想单独跑一批，也可以：

```bash
python tests/test_01_basic.py
```

跑完最后会有一行「总账：通过 X 项，失败 Y 项」。有 ❌ 的行就是具体挂掉的步骤。

## 这些测试在测什么

| 文件 | 人话 |
| --- | --- |
| `test_01_basic.py` | **骨架**：服务健不健康、5 个页面打不打得开、管理员改知识库/客服人格是不是真存下来了、没配密钥时会不会崩 |
| `test_02_upload.py` | **喂给 AI 的东西**：上传课表、乱传文件会不会被拦、管理员填的密钥会不会被泄露回去、Word/Excel/PPT（含表格）能不能真读出内容 |
| `test_03_planner.py` | **学生那张表**：课表导入、AI 找空档会不会撞课、待办能不能插进课间、月表每天几项、多轮商量靠什么记住上下文 |
| `test_06_add_things.py` | **「说了加上却看不到」的护栏**：加待办/加课的确定性链路（系统出提案 → 学生点头 → 系统落库）、加课缺星期由系统追问、刷新后聊天记录还在 |

## 端到端（真开浏览器点）

单元/接口测试用的是"假浏览器"（fastapi 的 TestClient），快但不点真按钮。
要验「点确认卡之后页面到底有没有变」，就得真开浏览器 —— 那三份脚本干这个：

| 文件 | 人话 | 结果 |
| --- | --- | --- |
| `_e2e_add.py` | 加待办 / 加课：出卡 → 点确认 → 日程当场看得到 → 刷新不丢 | 10 / 10 |
| `_e2e_clear.py` | 清空课表：提案 → 弹窗 → 确认 / 取消 → 课表真的空了 | 16 / 16 |
| `_e2e_confirm.py` | 删课：一句「确认」就由系统落库，不再回「我没有权限」 | 9 / 9 |

跑法（要 `playwright`，在项目根目录 `pip install playwright && python -m playwright install chromium`）：

```bash
python tests/_e2e_add.py     # 另外两个同理
```

它们**自己起服务器、自己备数据**，不用先手动开服务：
`_e2e_env.py` 会把 `app/data` 复制一份到临时目录，起一台只认这份副本的 uvicorn
（随机端口），测完连服务器带目录一起删掉。
所以演示数据不会被它们改 —— 清空课表那种不可逆操作也一样安全。

> 注意这里**不删** `settings.json`：那份演示密钥是删课链路需要的，
> 早先照搬上面 sandbox 的"运行时痕迹"清单把它删了，
> e2e 一启动就"还没配置大模型密钥"，依赖模型的链路当场全红。

## 两个关键设计（为什么这么写）

**一、测试跑在"沙箱"里，绝不碰真实数据。**

测试会保存假密钥、传临时文件，这些要是留在演示环境里就很尴尬。
所以 `sandbox()` 会先把 `app/data` 整个复制到一个临时目录，
再通过环境变量 `CAMPUSTIME_DATA_DIR` 告诉程序"数据放这儿"，
跑完整个临时目录删掉。真实数据一个字节都不动。

> 之所以要给 `store.py` 留这个环境变量开关，是因为早期版本用的是
> "先备份、跑完还原"——一旦测试中途崩溃就还原不回去，
> 实测真出过一次：一个假 API Key 被留在 `app/data/settings.json` 里。

**二、数据目录每次读写都重新问一遍环境变量。**

`store.py` 早先是在"导入那一刻"把数据目录定死，结果一个进程里跑完第一批沙箱之后，
后面所有写入都还指着 **真实演示数据** —— 测试一直在偷偷改演示数据
（周表被改成 13 门、`todos.json` 里堆着十几条测试待办），
表面症状却是"某批测试偶发失败"，非常难查。
现在 `store.py` 每次读写都重新读 `CAMPUSTIME_DATA_DIR`，一个进程连开几个沙箱也各管各的。

**三、每个文件单独开一个进程跑。**

数据目录虽然改成每次重读了，放同一个进程里跑大量测试仍会慢在反复复制文件上；
而且进程隔离能让某一批崩了不连累别人。`run_all.py` 就是给每个测试文件单独起一个子进程。

## 常见问题

**Q：为什么不用 pytest？**
A：希望评委在没装任何额外包的情况下也能跑。现在只依赖项目虚拟环境里已有的
fastapi（它的 TestClient 相当于一个"假浏览器"，不用真起服务器也能调接口）。

**Q：提示"缺依赖"跳过了几条？**
A：Office 那几条需要 `python-docx / openpyxl / python-pptx`，
在项目根目录执行 `pip install -r requirements.txt` 即可。

**Q：测试报"通过 0 项"？**
A：一般是 import 失败，看子进程那段报错的最后一行，通常是依赖没装全。

**Q：我明明没改数据，怎么演示数据自己变了（周表门数不对、待办里多了几条）？**
A：多半是 8000 端口上还挂着一台旧的 uvicorn，它读的是真实数据目录，
会覆盖你刚刚还原的数据。用 `netstat -ano | findstr :8000` 找出来，
`taskkill /PID <上面的数字> /F` 结束掉，再重跑测试。
