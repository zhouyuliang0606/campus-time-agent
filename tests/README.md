# tests/ —— 项目的自检清单

## 怎么跑

在项目根目录敲一条命令就行：

```bash
python tests/run_all.py
```

（Windows 上如果用项目里的虚拟环境，就是 `.venv\Scripts\python.exe tests/run_all.py`）

想单独跑一批，也可以：

```bash
python tests/test_01_basic.py
```

跑完最后会有一行「总账：通过 X 项，失败 Y 项」。有 ❌ 的行就是具体挂掉的步骤。
（这个数字是**每个文件里每一批**加起来的总数。早先这里是覆盖式统计、只算最后一批，
数字一直偏小，2026-09-25 修好了。）

的「后记」）；第九批专测**候选时段**（学生原话「我定的太严了……由 ai 帮我去挑选合适时间，**进行列举**……**由我打勾**，进行增加，增加确认完立刻刷新日程」——说了哪天只列那天、没说就跨天各列一段、每段都真在空档里、「第N节课」换成 08:00-09:40、那天满了如实给空列表；`todo_slots` 卡走跟清空课表同一个弹框，**勾选多选 + 「其他时间」自填**；打勾后走 `POST /api/todos/batch` 一次写完（同一批里逐条复核空档，重复提交被拦、自填认得出就写、认不出如实说、什么都没给就 400）；只回「确认」不勾选时**一条都不写**，把候选条再挂一遍请他挑）；第十批专测**「先问时间怎么定」**（学生原话：「要区分两种，一种是我有时间规划了，一种是我没有时间规划让他帮我安排，**不要一上来就询问详细时间，先给弹窗，（有时间规划）（还没有，你帮我定）**……核心是 ai 帮我安排时间，ai 去规划时间，然后这个加入代办，**要识别啥才是真的事情，不是随便拿那一句话就去当代办加入日程了**」——只说了哪天时**第一站不再是候选卡**，而是一张二选一卡（**只有问题、没有时间**，两颗按钮就是动作本身，所以这卡没有页脚【确认】）；选「我自己定」才摊候选让他打勾，选「你帮我挑」由系统**真去空档里拣一段**并在卡上加一条"为什么排这儿"、回答里也说一遍；他要是答了句认不出的话（「随便」「都行」）就**再问一次**、不瞎猜；没说什么事时**只追问"要安排什么事"**（他说的时长要认下来，内部标记不许漏到学生眼前）；标题判真（`大概一个小时帮我安排时间` → `待办` 而不是 `大概小时帮我时间`，`周三12点到2点我要去吃自助餐，帮我添加` → `吃自助餐`）；`1.5 小时` 要读成 90 分钟（不许读成 5 小时）；暂存里那张**没有时间**的卡不许被完整性检查丢掉（丢了学生回「确认」就会掉进"确认落空"兜底）；只回「确认」而没选方式时**一条都不写**；`POST /api/todos/mode` 四条路径（挑/自己定/方式非法 400/卡过期 404））；第十一批专测**「模型没调工具时系统替它补条」**（报障就一句「**没有收到弹窗**」——截图里管家在 `schedule` 模块回了一段自相矛盾的话：前半句"提案我这边还没生成出来…你现在点【确认】是空确认"，后半句"**待办提案** - 事项：游泳 - 时间：周二 16:00~17:30 …提案已发出，请点确认条上的【确认】"，界面上**一个按钮都没有**。根因不是"捞不出来"（那段原文 `parse_todo_from_reply` 捞得**分毫不差**），而是**那一步压根没被调用**：补条兜底以前只挂在"学生回确认"那一支（3a-c）里，而学生说的是"没有收到弹窗"、`is_confirmation` 为假 → 整条兜底被跳过 → 请求掉给模型 → 模型又没调工具 → 什么都没有。这一批把兜底接到**模型那一路**：只要它自称发过提案，系统就照它的意思把卡补出来（新增 `claims_proposal_sent` / `rescue_proposal_from_reply`，正文捞不出方案时退到"第一站"二选一卡）。顺带修掉两个更早的坑：① **`propose_todo_tool` 把 `end` 丢了**——`_, finish = _pick_span(end)` 让单个钟点的 finish 拿到 `None`（`_pick_span("17:30")` 返回的是 `("17:30", None)`，单个钟点算**起点**），于是模型传 `start=16:00/end=17:30` 时卡片变成 `16:00-17:00`，学生要的 90 分钟被悄悄砍成 60，模型还照着卡片解释了一句"系统默认按 1 小时出的条"——**把 bug 说成了设计**；② **模型那一路挂的条回「确认」写不进去**（它存进暂存是 `todo_pick` 形状，而 `_pending_todo` 只认 `todo_add`、`_match_todo_pick` 又要求消息里带日期+时间，两头都不认 → 掉进 3a-c 换来一句"刚才那次可能没接上"，**条挂出来了、按钮也是好的，可他再回一句「确认」还是这句，原地打转**）——新增 `_lone_todo_pick` 接住"暂存里只有一张已定好时间的卡 + 学生裸回一句确认"这一档，两道闸门（消息里不能带日期时间、暂存里只能有一张）差一道就会写错）；第十二批专测**「散文式方案」与「已提交」这种假话**（报障原话：「**没有代办页，我要的是和更改课表一样的在个人数据库的日程周表和月表显示，没有出现弹窗**」——那一幕三轮：「加」→ 管家在文字里写"好的，帮你把「游泳」加到周一待办里，时间就按咱们说的 16:00~17:30 来…你回个「确认」，系统就入库了"→「确认」→ 管家回"**已提交**，等系统入库后周一待办里就会多出「游泳 16:00~17:30」这一条"——**卡片没挂、库没写、还说已提交**。根因不是"信息不够"：把那段话拆开喂进去，`_pick_title` 抠得出「游泳」、`_pick_date` 算得出周一、`_pick_span` 认得 16:00~17:30，**三样全在**，是 `parse_todo_from_reply` 死认「事项：/时间：」固定格式，散文式方案一个字段都对不上 → 整个方案被判成"捞不出来"。这一批给捞方案补了**散文兜底**（`_pick_title_from_prose`：先看「」/《》里的词、再看"把 X 加到/排到"）并要求它**自称发过提案**才走这一档——散文抠法比固定格式宽松得多，松的那一档必须有闸门，不然助手答一句「「高等数学」在周一 08:00-09:40 上课」都会被当成提案；同时把 `claims_proposal_sent` 扩到认**过去式假话**（已提交/已入库/已加入/已排好/回个「确认」），并在模型那一路补一条：**自称提交了、可卡片又补不出来时，不许把假话端给学生**，，换成如实纠正 + 告诉他下一步怎么说）；第十三批专测**两种没被认出来的写法**（报障原话：「**改完自动刷新日程，和删除课表一个逻辑，都是在日程做改变，每次都不弹确认的框**」——那一幕三轮：「周四早上吧」→ 管家「**提案好了，就一条：周四 08:00~09:00 健身（1 小时）** 确认的话，回我一句「确认添加」就行，系统会帮你入库」→「确认」→ 管家「收到，你回「确认」后由系统执行入库…稍等确认条生效就好」——又是卡片没挂、库没写。两个断点：① `claims_proposal_sent` 不认**「提案好了」「系统会帮你入库」「回我一句「确认添加」」**这三个说法 → 兜底第一步就不启动；② 就算认了，`_pick_title_from_prose` 也抠不出任务名——那句里既没有「」引号、也没有「把 X 加到」，任务名**健身**是**跟在时段后面**的（`**周四 08:00~09:00 健身（1 小时）**`），前两路全落在盲区。这一批补第三路抠法（时段后面紧跟的那几个字）+ 认全那三种说法 + 一档「任务名用学生的、时间用它给的」合并策略；顺带给「假话纠正」加了**两道闸门**——光认「有没有时段」还是不够，「你点确认后系统才会入库」这种纯流程解释会被误伤，所以要求它这段话里**带具体时段**、或者学生最近确实说过要加什么） |

## 端到端（真开浏览器点）

单元/接口测试用的是"假浏览器"（fastapi 的 TestClient），快但不点真按钮。
要验「点确认卡之后页面到底有没有变」，就得真开浏览器 —— 那四份脚本干这个：

| 文件 | 人话 | 结果 |
| --- | --- | --- |
| `_e2e_add.py` | 加待办 / 加课：出卡 → 点确认 → 日程当场看得到 → 刷新不丢 | 10 / 10 |
| `_e2e_clear.py` | 清空课表：提案 → 确认条 → 确认 / 取消 → 课表真的空了 | 17 / 17 |
| `_e2e_confirm.py` | 删课：一句「确认」就由系统落库，不再回「我没有权限」；确认条必须**贴在聊天流里**（不弹全屏遮罩） | 13 / 13 |
| `_e2e_clearchat.py` | 清理聊天记录：点 🧹 → 弹窗 → 取消无事 / 确认清空 → 刷新不再回来，课表待办不动 | 23 / 23 |

跑法（要 `playwright`，在项目根目录 `pip install playwright && python -m playwright install chromium`）：

```bash
python tests/_e2e_add.py     # 另外三个同理
```

可以把演示周表还原成 12 门课——`app/data/student/timetable.json` 是运行时数据，
手点演示或跑端到端都可能让它少一门课。

它们**自己起服务器、自己备数据**，不用先手动开服务：
`_e2e_env.py` 会把 `app/data` 复制一份到临时目录，起一台只认这份副本的 uvicorn
（随机端口），测完连服务器带目录一起删掉。
所以演示数据不会被它们改 —— 清空课表那种不可逆操作也一样安全。

> 注意这里**不删** `settings.json`：那份演示密钥是删课链路需要的，
> 早先照搬上面 sandbox 的"运行时痕迹"清单把它删了，
> e2e 一启动就"还没配置大模型密钥"，依赖模型的链路当场全红。

`e2e_server` 另外备了三个"播种"方法，都是往那份副本里写，碰不到演示数据：
`seed_timetable(课程)`、`seed_todos(待办)`、`seed_conversation(sid, 消息列表)`。
最后那个是给"报障场景只发生在历史里"用的——比如那段「任务：健身／时间：周一 16:30~18:00」
是管家上一轮说的话，页面是从 `/api/conversation/<sid>` 把它捞回来渲染的，
不先种进去就复现不出来。配套要注意两点：

* 会话文件是**学生库**里的 `student/sessions.json`（不是 `data/sessions.json`，
  写错地方页面历史一片空白）；
* 前端 session id 存在 localStorage 且随机生成，截图脚本得先用
  `page.add_init_script("localStorage.setItem('campustime_session', '<sid>')")`
  把它定成同一个，两边才对得上。`_shot_gym.py` 是现成例子。

## 两个关键设计（为什么这么写）

**一、测试跑在"沙箱"里，绝不碰真实数据。**

测试会保存假密钥、传临时文件，这些要是留在演示环境里就很尴尬。
所以 `sandbox()` 会先把 `app/data` 整个复制到一个临时目录，
再通过环境变量 `CAMPUSTIME_DATA_DIR` 告诉程序"数据放这儿"，
跑完整个临时目录删掉。真实数据一个字节都不动。

> 之所以要给 `store.py` 留这个环境变量开关，是因为早期版本用的是
> "先备份、跑完还原"——一旦测试中途崩溃就还原不回去，
> 实测真出过一次：一个假 API Key 被留在 `app/data/settings.json` 里。

**二、数据目录每次读写都重新问一遍环境变量。**

`store.py` 早先是在"导入那一刻"把数据目录定死，结果一个进程里跑完第一批沙箱之后，
后面所有写入都还指着 **真实演示数据** —— 测试一直在偷偷改演示数据
（周表被改成 13 门、`todos.json` 里堆着十几条测试待办），
表面症状却是"某批测试偶发失败"，非常难查。
现在 `store.py` 每次读写都重新读 `CAMPUSTIME_DATA_DIR`，一个进程连开几个沙箱也各管各的。

**三、每个文件单独开一个进程跑。**

数据目录虽然改成每次重读了，放同一个进程里跑大量测试仍会慢在反复复制文件上；
而且进程隔离能让某一批崩了不连累别人。`run_all.py` 就是给每个测试文件单独起一个子进程。

## 常见问题

**Q：为什么不用 pytest？**
A：希望评委在没装任何额外包的情况下也能跑。现在只依赖项目虚拟环境里已有的
fastapi（它的 TestClient 相当于一个"假浏览器"，不用真起服务器也能调接口）。

**Q：提示"缺依赖"跳过了几条？**
A：Office 那几条需要 `python-docx / openpyxl / python-pptx`，
在项目根目录执行 `pip install -r requirements.txt` 即可。

**Q：测试报"通过 0 项"？**
A：一般是 import 失败，看子进程那段报错的最后一行，通常是依赖没装全。

**Q：我明明没改数据，怎么演示数据自己变了（周表门数不对、待办里多了几条）？**
A：多半是 8000 端口上还挂着一台旧的 uvicorn，它读的是真实数据目录，
会覆盖你刚刚还原的数据。用 `netstat -ano | findstr :8000` 找出来，
`taskkill /PID <上面的数字> /F` 结束掉，再重跑测试。
