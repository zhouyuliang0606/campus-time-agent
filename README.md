# 校园时间管家 Agent / CampusTime

一个校园 AI 服务助手：把**课表、待办、快递、外卖、校园问答**收口到同一个助手，
并且守一条硬规矩 —— **AI 只出提案，学生点了确认，系统才写库**。

## 一、三个角色，一个引擎

| 端 | 定位 | 入口 |
|---|---|---|
| **学生活端（旗舰）** | 课表时间规划 + 校园问答 + 快递查询 + 外卖查询 | `/student`、`/plan` |
| **驿站 / 商户侧** | AI 客服：答复咨询、推送取件提醒与滞留预警，人设可配 | `/station` |
| **管理控制台** | 零代码维护知识库、客服人格、**在线配置大模型本身** | `/admin` |

三层**共享同一个 Agent 引擎 + 一份知识库 + 一份大模型配置**，不重复实现。
在管理台改一条知识库、换一次模型 Key，另外两端立刻生效，**全程不用重启、不用碰服务器**。

## 二、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | **Python + FastAPI** | 把函数变成网页可调用的接口，uvicorn 启动 |
| 前端 | **原生 HTML / JS** | 不需要打包工具，不引入前端框架 |
| 大模型 | **DeepSeek API** | Key 走 `.env` 或管理后台，**不写进代码、不入库** |
| Agent | **自写的轻量 ReAct 循环** | 不套 LangChain 等重框架，确定性分支优先于模型 |
| 存储 | **JSON 文件**（`app/data/`） | 演示够用；`store.py` 已按"换数据库不改调用方"分层，替换成本低 |
| 测试 | **FastAPI TestClient + 自写 Checker** | 不需要 pytest，评委零额外安装即可跑 |

页面共 **7 个**，API 端点 **48 个**
（口径：`app/main.py` 里唯一的 `@app.<方法>("路径")`，用
`grep -oE '@app\.(get|post|put|delete|patch)\("[^"]+"' app/main.py | sort -u | wc -l` 核一遍；
数字随开发增长，核一遍即知当次真实值）。

## 三、架构主线：判定层 / 执行层分离（本项目最重要的设计）

这条线是整个项目的地基，也是它和"随便套个 LLM 问答"的根本区别。

```
┌─ 判定层：听懂这句话要干什么、归哪个模块（可换、可兜底、可以交给模型）
│   ① 样本库   历史成功原话做 Dice 模糊匹配（零成本、离线可跑，兼作 ② 的缓存）
│   ② 语义层   问一次大模型，只要一个 JSON：{module, intent}
│   ③ 规则兜底 30 多张关键词表 + router._QUICK_MAP
└──────────────────────────────────────────────────────────
┌─ 执行层：查空档 · 排期 · 出候选卡 · 写库（系统独占，模型永远碰不到）
└──────────────────────────────────────────────────────────
```

**为什么要把这两层切开？** 因为学生报过一句一针见血的话：

> 「很多的字都是接不住的，你现在能接住的都是我测试给的。」

过去每报一次障就往词表里加一条，`planner.py` 里堆到 **30 多张**关键词/正则表，
`router.py` 里还有 **50 多个**硬编码词，全是 `if keyword in text` 这种朴素子串匹配 ——
**拿字符串匹配干语义理解的活**，词表加多长都收敛不了：中文口语的写法是无限的。

所以 2026-09-26 起引入判定层，2026-09-27 又把**顺序倒成「语义优先、关键词兜底」**：

| 档 | 做什么 | 成本 | 没配 Key 时 |
|---|---|---|---|
| ① 样本库 | 历史成功原话模糊匹配（Dice 相似度 ≥0.42） | 零 | 照样能用 |
| ② 语义层 | 问一次 LLM，**只要** `{module, intent}`，置信度 <0.6 直接丢弃 | 一次调用 | 自动跳过 |
| ③ 规则兜底 | 词表命中就走 | 零 | 兜底 |

关键设计：语义层那个 LLM **拿不到任何写库接口**，也碰不到排期算法。它只负责"听懂"，
拿到 JSON 之后，查空档、摊候选、出卡、写库**走的还是原来那套确定性代码**。
所以「AI 只提案、系统才执行」这条架构主张一条都没破 —— 变的只是"听懂人话"这一步不再由正则独占。

判定层一律**偏保守**：白名单 intent / 置信度低于 0.6 不要 / 词长不足不匹配 / 没配 Key 就安静返回 `None`。
取向是「**宁可漏判掉回老路，不可替学生办错事**」。

### Propose / Execute 分离（同一根地基的另一半）

早期版本用纯模型直接回「已经帮你排好啦」，学生刷新日程却空空如也 ——
模型没有写库能力，只是在文字里"表演"写库。现在：

- Agent 只调用 **read-only 工具**（查空档、列待办、读文件）；
- 任何会改变状态的操作，先变成一张「提案」返回，提案上的 `kind` 由**系统盖章**，不由模型自报；
- 前端按 `kind` 渲染确认卡，学生点【确认】后，**才由系统真正执行写库**。

写库的唯一入口是系统侧的确认动作，**模型无论走哪条路都碰不到写入接口**。
这句话不由人设保证，由 `tests/test_31_no_write_tool_for_model.py` 钉住：它用 AST 扫全部
模块的全部工具，函数体里真调用落库函数的就是越权（2026-10-08 之前这里确实漏过一个
`add_todo_tool`，当时的"防线"只是工具描述里一句"必须等学生确认后才能调用"）。

**提案不怕刷新。** 暂存是"内存 + 磁盘双写"（`app/agent/pending.py`，带 3 小时 TTL），
页面加载或切模块时 `restorePendingCard()` 会去 `/api/pending/{sid}` 把**上一轮没点的那张卡**
接回聊天流末尾（排在恢复出来的历史之后，并附一句「这张卡是上一轮没处理完的」）。
点过的卡会被 `mark_applied` 标掉、`/api/pending` 从此不再返回它 ——
所以刷新不会让同一张卡被点第二次、也就不会重复写库（`tests/test_36_pending_card_restore.py` 钉的就是这条命门）。

## 三点五、管日程的三条入口（学生端「我的日程」是只读概览）

学生的日程（待办 + 课表）有**三条写入/查看入口**，三条**同源**于 `/api/todos` 与
`/api/timetable` —— 在任一条里改，另外两条刷新即见：

| 入口 | 在哪 | 角色 | 适合场景 |
|---|---|---|---|
| **① 对话出卡** | 学生端聊天框 | AI 出提案 → 学生点【确认加入】→ 系统写库 | 懒得打字，直接说「周六早上去图书馆」 |
| **② 上传课表** | 我的日程 → 📤 上传课表 | 批量导入：读文件 → 出「确认修改」卡 → 确认后写 | 开学一次性导整张课表 |
| **③ 完整版管理页** | `/plan` | 周表（时间轴网格）+ 月表，直接增/改/删 | 自己动手调时间、批量处理 |

**学生端「我的日程」面板是只读的**，两档 tab：
**周视图 = 逐日明细**（默认只列**今天起四天**，工具条上「展开整周 ▾」可看周一…周日整周，
选择记在本机；每天一条列表，课程与待办按开始时间排序，
同一时段撞车的那条标「撞」；只读，不给改）+ **月表**（点任意一天下钻看当天待办）。
要调时间就去 `/plan`，或者说话让管家改。

**学生端只有一个主页，「校园问答」不再是一栏**（2026-10-10 改版）：侧栏原来是「校园问答 / 日程」
两个并列入口，但日程面板本来就常驻对话上方，两栏并列等于逼学生先回答"我该点哪个"。
现在问答是主页工具条上那颗「❓ 校园问答」按钮打开的**抽屉**（11 条知识库的高频问题按钮墙，
点一条直接问管家；它自己的「收起问答 ✕」不走通用收起，免得把日程面板一起关掉）。
**侧栏的「日程」这一项保留**——它是从「设置 / 代办」回主页的唯一入口，摘掉就没路回家了。

**两种"频次"是两条路，别混（2026-10-10 起）**：

**① 「一周 N 次」= 数量频次，没有固定日子 → 铺 N 条**（2026-10-08 定的规格，一字未改）。
学生说「我一周要去三次健身房」，系统读出次数 3 → 标题只留「健身房」→ 按这一周排
**3 段、一天一段**（另给 2 段备选）、确认条里**前 3 段默认已勾上**，点一次【加入日程】写 3 条普通待办。
它**仍然不是自动重复**：回话里如实说"这只管这一周，下周说一声再排一轮"。「一天三次」（吃药）、
「周四下午第一次上课」（节次）、「这周还有两次课」（是课）**都不认**——按天铺开等于替学生
造他没说要的东西，宁可少认。排不满 N 段时 hint 直说"只排得出 K 段"；
指定了哪天的矛盾句（「周四一周三次」）不预选，退回只排那天的老路子。

**② 「每个周天」= 固定星期几 + 无限重复 → 一条记录，每周都出现**（2026-10-10 加）。
学生说「每个周天都加一个写作业的代办」，系统认出"每周日"→ 标题「写作业」→ 只给**周日**的空档
（往后四周里的那个星期几）→ 勾一段【加入日程】**只建一条**，以后每个周日它自己出现在日程里。
实现是给待办加了三个字段：`repeat`（`""`/`weekly`）、`weekday`（1–7）、`done_dates`（已完成的那些日子）。
⚠️ 这里要认一句账：①那条的原文写过"待办模型没有 repeat 字段"，②把这句话推翻了——
**字段确实加了**，因为用户 2026-10-10 明确选了"真·长期"这条路；但①的行为**没有**被顺手改成重复，
`tests/test_39` 的 F 批专门把"一周三次仍然是铺 N 条"钉住。
"勾完成"对重复待办**只算当周**（记进 `done_dates`），下周它还在；不想要了就删掉那一条。
刻意不认的：「每个周末」（周六+周日两天，一条表达不了）、「每周都交周报」（没点哪天，
替他挑一天等于替他做主）、以及光秃秃的「周日去健身」（单日说法，判成永久就是凭空造几十件事）。

**③ 表达不了的周期，现在明说办不了（2026-10-11 收口）**：「每天 / 天天 / 每月 / 每个周末 /
隔一天 / 下个月…」这一类，一条日程**表达不了**（只能落某一天，或每周固定的某一天）。
以前它会从**另一条路**溜进来：规则层从来不接，可样本库/语义层能单独判成"加待办"并出卡 ——
用户原话「在下个月的每个周末三点开始大约三个小时」就是这么被建成一条 15:00-18:00 的孤零零待办的，
而且那句还被**学进了样本库**，同一个错以后会自己繁殖。
现在判据收在一处、不分层（`planner.unsupported_period`）：规则、样本库、语义层，
以及模型手里那三件提案工具，**任何一档**说"这是加待办"都不出卡，回话只说事实并给出
两种能办的说法（「每周一背单词」建一条每周重复 / 「这一周要背三次」铺三段）；
被否掉的那句**不再学进样本库**。
边界同样划清：「平时 / 工作日」**不在**这份名单里——跨工作日摊开列是现有功能，
把它一起拦掉等于打掉能用的东西。

**学生点了钟点，就一定用那个钟点**（2026-10-10 收口）。一句话里的日期、星期几、起止时刻、
时长、周期，现在**一次**解析成一个结构（`planner.parse_time_spec`），候选时段直接吃它——
以前是各读各的：`_pick_span('晚上七点到九点')` 明明读对了 19:00-21:00，
`candidate_slots` 却只拿走时长、把钟点丢了，于是「周五晚上七点到九点值日」排出 15:40-17:10。
现在实测 `下周三晚上七点到九点值日` → 19:00-21:00 精确命中、`每天早上七点晨跑` → 07:00-08:30。
**排不进去时明说为什么，不默默换**：`周五晚上七点到九点值日` 会得到
「⚠️ 你说的 19:00-21:00（2026-10-16）排不进去——那个时间有课或已有安排，下面给的是别的时间段」
（那晚 19:00-20:40 确实有《班会》）。换时间是对的决定，但不说原因，
学生看到的就还是"你没听懂我的话"——这条是被投诉出来的。

**但"只说了一个数字几点"不算点了钟点**（2026-10-11 补）。`_pick_span('三点开始')` 给的是
**03:00**，而学生嘴里的"三点"几乎都是下午三点 —— 以前「周日三点开始写作业」真出过一张
03:00-04:00 的凌晨确认条。现在解析结构里多了一个 `clock_ok`：1～6 点且没报上午/下午就算
"没听清"，**四条出卡的路共用这一条判据**（候选段的第一段、单条确认卡、自填那一行、
"改成三点"的换时间），一律不认这个点；候选卡的 hint 明说
「⚠️ 你说的「3 点」没说是上午还是下午，我不敢替你定 —— 照着字面排就成了凌晨 03:00」。
报了档（下午三点 / 早上七点）照旧精确命中，一个都不误伤。
同一处还钉死了另一种谎：那个点**没被认下**时，不许说成"那个时间有课排不进去" ——
凌晨三点通常空得很，编个理由等于骗学生第二回。

**说另一件事时，名字不许缝上上一轮的**（2026-10-11 补）。挂着「写作业」的候选卡时学生改口
「周五晚上七点到九点值日」，以前卡片标题成了 **「值日写作业」** —— 因为解析那一句时
无条件把上一轮的事名拼进来一起抠。现在先问这句**自己**报了什么事名，报了就用它自己的；
只说了时间没报名（「周六」「下午两点到三点」）才沿用上一轮那件事 —— 那本来就是他的意思。

> **历史：这里曾有第四种入口「周时间轴」**（2026-10-07 加，学生不对话、不上传，直接点格子增/改/删待办，
> `tl_` 前缀、不走提案卡、删必 `confirm`）。第二轮修过"跨小时课逐行重复、同格第二条被静默吞、
> 点课程块误开新增表单"，第三轮按「周时间轴和日程表放一起」做成上下同卡。
> **2026-10-08 按用户「把这个周时间轴去掉，保留逐日明细」整块移除**（容器 HTML + `tl*` 函数 + `.tl-*`
> 浅色与深色主题样式，共 348 行；`student.html` 里 `.tl-` 命中数为 0）。
> 移的是**入口**，不是能力：写库仍走系统侧确定性接口 `POST/PUT/DELETE /api/todos`，契约一字未变，
> 三条红线（删必确认 / 不让模型直连写库 / 不碰 `todo_id` 提案卡字段）由 `/plan` 与待办面板继续守。
> 护栏随功能一起改口：`tests/test_29_schedule_timeline_edit.py` → `tests/test_29_schedule_panel_and_todo_api.py`
> （49 项：无时间轴残留 + 逐日明细完好 + 面板只读 + 接口往返 + 问答抽屉/四天窗口那组改版断言）。

验收（本仓库的真机探针，非只跑单测）：真实浏览器打开「我的日程」，确认**周视图默认只列今天起四天、
「展开整周」能出七天且列数跟着变、月表下钻正常**；点「❓ 校园问答」抽屉能露出那 11 条问题墙、
收起它不影响上面的日程面板；侧栏里没有「校园问答」这一项。
再走一遍 `/plan` 的**增 → 核对落库 → 改 → 核对 → 删（确认弹窗）→ 核对清空**，
全程数据零残留。
判断口径那三条也用真机走一遍（起服务发原话，不看单测）：「每天背30个单词」和
「在下个月的每个周末三点开始大约三个小时」都**不出卡**、回话给两种能办的说法；
「周日三点开始写作业」给的不是 03:00 而是一句"没说是上午还是下午"；
挂着「写作业」的候选卡时说「周五晚上七点到九点值日」，卡片标题是「值日」。

## 四、目录结构

```
CampusTime/
├── app/
│   ├── main.py                 总入口：全部页面路由与 API；/api/chat 的判定层与确定性分支都在这
│   ├── config.py               读配置：.env 是底座，「管理后台 > .env」；做成函数换来"后台改完不用重启"
│   ├── store.py                文件存储层：知识库/人格/设置/上传/消息/通知/学生个人库，接口按"换数据库不改调用方"分层
│   ├── upload.py               文件解析：txt / pdf / docx / xlsx / pptx → 统一变成 AI 能读的纯文字（含表格）
│   ├── agent/
│   │   ├── engine.py           Agent 大脑：ReAct 循环（想 → 做 → 看结果 → 再想）
```

## 五、给零基础的你：怎么跑起来

### 1. 准备 Python
需要 **Python 3.10 或更高版本**（本项目在 3.13 上开发与测试）。
装好后在命令行敲 `python --version` 能看到版本号就 OK。

### 2. 装依赖

```bash
cd CampusTime
python -m venv .venv            # 建一个独立的虚拟环境（推荐，不污染系统）
.venv\Scripts\activate          # Windows 激活；macOS/Linux 用 source .venv/bin/activate
pip install -r requirements.txt
```

> `requirements.txt` 里每一行上面都写了中文注释，说明这个库是干嘛的。
> 其中 `pypdf` / `python-docx` / `openpyxl` / `python-pptx` 只影响**文件上传解析**，
> 不装也能跑，只是那几种格式传不了。

> ⚠️ **`requirements.txt` 请存成「带 BOM 的 UTF-8」，别把开头那三个看不见的字节当垃圾清掉。**
> pip 读依赖清单时：认出 BOM 才按 UTF-8 解，**没 BOM 就按你的系统码页解**。
> 中文 Windows 的码页是 GBK，于是上面那些中文注释会让 `pip install -r requirements.txt`
> 直接崩在这里 —— 这不是本项目的问题，是编码问题：
> ```
> UnicodeDecodeError: 'gbk' codec can't decode byte 0xab in position 6
> ```
> 同理，测试结果里的 ✅ / ❌ 打在 GBK 控制台上也会抛 `UnicodeEncodeError` 把自测打断，
> 所以 `tests/_utf8.py` 会把输出流固定成 UTF-8（`run_all.py` 还会把
> `PYTHONIOENCODING=utf-8` 传给每一个子进程）。这两处都由 `tests/test_30_requirements_bom.py` 钉住。

### 3. 配大模型 Key（**两种方式，任选一种**）

| 方式 | 怎么做 | 生效时机 |
|---|---|---|
| **① 管理后台在线填**（推荐） | 启动后打开 `/admin`，在「🔑 API 配置」卡片里填 Key、地址、模型，点「测试连通」 | **立刻生效，不用重启**；优先级高于 `.env` |
| **② 写进 `.env`** | 复制 `.env.example` 为 `.env`，把 `DEEPSEEK_API_KEY` 换成你的真实 Key | 需重启服务 |

去 https://platform.deepseek.com 注册即可拿到 Key（形如 `sk-xxxxxxxx`）。

> **没配 Key 也能跑**：系统会自动切到确定性的 Mock 模式，
> 排程交互、卡片渲染、知识库问答等**离线链路照常演示**，只是不调用大模型。
> `.env` 已在 `.gitignore` 里，Key 永远不会被提交。

### 4. 启动

```bash
uvicorn app.main:app --reload
```

浏览器打开 **http://127.0.0.1:8000**

> **打开 `/admin` 前请先配管理口令**（学生侧完全不用配，照常聊、照常排日程）：
> 在 `.env` 里加一行 `CAMPUSTIME_ADMIN_TOKEN=你自己起的一串`，重启服务，
> 然后在 `/admin` 页面顶部的「🔒 管理口令」框里填同一串，点「用这个口令」。
>
> 为什么要这道门：后台那些接口能改模型密钥、能读走全部学生消息，
> 不能对任何连到端口的人敞开。**没配口令时管理侧一律 403**（不是放行），
> 学生侧照常——这是有意的默认值，见 `app/admin_guard.py`。
> 口令只存在你这次标签页的 `sessionStorage` 里，关标签即清；不要提交进仓库。

> **学生自配 API 的边界（2026-10-09，一天里改过两次，这是最终版）**：设置里可以填
> **接口地址（base_url）+ 模型名 + API Key**。允许学生填地址，是因为这个功能的全部价值就是
> "服务器没配 Key、或者配的不是同一家时，学生还能自己跑通"——
> 中午那版把地址收掉了，结果 Key 是他的、地址是管理端的，不配套只吃一个看不懂的 401，
> 功能当场变成假的。**但这不代表内网又通了**：
> 地址在**真要发请求之前**过 `app/config.py` 的 `check_base_url_ssrf`
> （协议 + 内网/回环/链路本地/云元数据/保留域名/单标签名 + 解析后逐 IP 复核），
> 学生填的和管理端填的走的是同一个闸门。实测从学生入口塞
> `http://127.0.0.1:8000/api/admin/settings`：请求根本没发出，回的那句话里也不含这个地址。
> `file://` 这类连第一层都过不了的地址，整份自配会被**直接作废**（退回服务器默认配置）。
> 要用本地 ollama（`http://localhost:11434/v1`）这类内网地址，显式设
> `CAMPUSTIME_LLM_ALLOW_PRIVATE=1` 再重启；默认是拦的。
> 地址留空 = 用管理端配的那个，弹窗顶部会把那个上游主机显示出来。
> Key 仍然每轮对话上传、用完即弃、不落盘（`tests/test_34_api_key_not_stored.py` 钉住；
> 管理端「用量统计」新增的「来源」列能看出每一笔花的是谁的 Key，但那里也**只有标签，没有钥匙**）。
> ⚠️ 已知残余风险：DNS rebinding（两次解析之间换答案）没防住，要防得把已校验的 IP 钉进连接层。
> 现在能填地址的人从"管理员"扩大回"任何连到端口的人"，所以**一旦对外网暴露必须先补这一条**。

> **对话里不出现技术内脏（2026-10-10）**：学生看到的每一句话（回答、"思考过程"、判定依据）
> 都不提"模型 / 大模型 / 厂商 / API Key / 密钥 / 管理控制台"——产品不必把自己的内脏摊给人看，
> 被问"你是什么模型"时也只答"我是校园时间管家，底层的实现我不清楚"。
> 实现方式是异常带一个 `kind` 标签，发给学生的**那一刻**按标签挑话术
> （`app/main.py` 的 `_STUDENT_LLM_WORDS`），**技术原文一个字都没删**：
> 服务端日志和管理端「用量统计」照旧记 `HTTP 401 / API Key 无效` 这种能定位问题的句子，
> 否则这道美化等于把管理员一起蒙了。护栏 `tests/test_38_student_no_tech_leak.py`。
> 边界说清楚：学生自己的「模型与 API」配置格**照旧如实写着**——那里他在配东西，藏起来才是骗人。

### 5. 验证功能有没有坏（推荐先跑一次）

```bash
python tests/run_all.py
```

预期总账：


（`<N>` / `<M>` 随每次开发增长，所以**不写死** —— 跑一次就是当次的真实数字。

## 六、跑起来后先试这几句

这些是真实测试用例覆盖过的说法，能直接看出系统的脾性：

| 你说 | 应该看到 |
|---|---|
| 「帮我把复习线性代数安排到周四 19:00–20:30」 | 出**确认卡**；点了确认日程里才出现 —— **没确认就不会写** |
| 「我的代办呢」 | 直接念出真实待办列表（真查库，不是编的） |
| 「把周四那个瑜伽挪到周五」 | 出**改期卡**，确认后旧条目移除、新条目落位 |
| 「健身显示不出来」 | 系统真去查库核实，如实回答"在的/不在" |
| 「我要去哪里取快递」 | 走**校园问答**检索知识库回答 —— **不会**被误当成"加个待办" |
| 「周六早上去图书馆」 | 出候选时段卡，**只列周六那一天**的空档（不会摊到周三等多天）—— 说哪天就只给哪天 |
| 「我一周要去三次健身房」 | 认出**频次=3**：标题只留「健身房」，按这一周排 3 段（一天一段）**默认已勾上**，点一次【加入日程】写 3 条；并如实说明"只管这一周，下周说一声再排" |
| 「每个周天都加一个写作业的代办」 | 认出**每周日**：标题「写作业」，只给周日的空档，勾一段**只建一条**；日程上带 🔁，以后每个周日自动出现，勾完成只算当周 |
| 出一张确认卡后**按 F5** | 卡带着「⏳ 这张卡是上一轮没处理完的」回到聊天流末尾、勾还是勾好的；点它照样写库；**点过之后再刷新就不回来了**（不会重复写） |
| 打开「我的日程」→ 周视图 | 显示**逐日明细**（课程+待办按时间排、撞车标「撞」），**面板只读**；改待办去 `/plan` 或对话 |
| 打开「❓ 校园问答」抽屉点一条，或直接打字问 | 走服务端知识库检索；**问句不会被误判成下单**，也不会冒出候选时段卡（模块锁那套客户端逻辑已删，保护在服务端，test_29 第 4 批钉着） |
| 「中文12点的车」（**故意打错字**，中午→中文） | 认成「中午12点的车」→ 出确认卡 **坐车**，钟点 **12:00**（没说哪天 → 今天这个点已过就顺延到明天）。错别字被纠正，不会把「中文的车」当成事名 |
| 上面任一句说完，看回复**下面** | 有一块「**🧠 我是这么想的**」：写着它把这句话听成了 **办事** 还是 **问事**、**依据是哪一档**（样本库 / 语义层 / 规则层）、**事名读成了什么**。不想看可在「设置 → 思考过程」里关掉 |

最后两条看着不起眼，其实是本项目判定层存在的全部理由：**先分"问"还是"办"，再决定干什么**。

「我是这么想的」那一块是**给学生核对用的**：结果不对时，他能一眼看出是哪一步错了
（没听懂？事名抠错了？时间读错了？），也能拿它决定该不该点【确认加入】。
它是**只读的复述**，不参与任何判定 —— 判定层算完什么，它就说什么。

## 八、几条值得一看的设计取舍

- **弹窗显不显示，不由模型决定。** 提案上的 `kind` 由系统盖章。否则"要不要弹窗"的决定权回到模型手里，
  就会退化成「经常不弹弹窗」。
- **语义层可以反过来复核规则。** 规则判了"要办事"、但这句其实是问句（或人就在问答型栏目里）时，
  让语义层复核一次，只有**正面肯定**才否决规则 —— 因为样本库是模糊匹配，
  误否决一张本来就该出的卡比漏判更让学生恼火。
- **不让关键词表背锅。** 新说法接不住，走语义层/样本库兜底，**不是往词表里再补一条正则**。
- **"用户本人直接操作"和"AI 出提案"是两条入口，不交叉。** `/plan` 是学生自己动手，
  所以它不走 options 提案卡、直接调既有写库接口；但**破坏性操作（删）仍必须有确认**——
  两条入口共享的是同一份数据和同一套写库接口，不是同一种交互。把两者混起来，
  要么让直改变得啰嗦，要么让 AI 那条路绕过确认，都不对。
  （学生端面板 2026-10-07 曾按这条开过"周时间轴"直改入口，2026-10-08 按用户要求撤掉，
  面板回到只读；这条原则本身没变，守它的地方变成了 `/plan` 与待办面板。）
- **"哪天 + 去干啥 + 没说几点"也该被接住。** 学生说「周六早上去图书馆」，
  规则层若只认"显性添加词 + 准点"，这句会掉进语义层的规范话（`to_canonical`），
  而规范话会**把日期丢掉** → 候选摊到一整周。修法是让规则层认出这个模式
  （**动作动词"去/到/来" + 可读日期 + 事名判真**才算，"查课问句/管理指令"不算），
  保住了"说哪天就只给哪天"。
- **测试用数据沙箱而非"备份再还原"。** 早期方案只要中途崩溃就还原不回去，
  实测真出过一次假 Key 被留在 `settings.json` 里；改成临时副本后，崩溃也无所谓。
- **模糊匹配只许借"路线"，不许借"内容"。** 样本库命中分两档：几乎一字不差才复用字段，
  只是"像"就**只借 module/intent、字段全部清空**、回去问模型现读。
  不这么分，学生说「健身」会被回成「游泳」（撞上相似度 0.73 的另一句）——
  说 A 回 B 比"没听懂"坏得多，而且**看不出错在哪**。
- **"全绿"不等于"做对了"。** 这次修错别字，测试 1398 项全绿之后我才拿学生那句
  原话在真机上跑了一遍，发现只修对了标题、**时间还是丢的**。
  所以本项目的验收习惯是：**单测之外，一定要在真机上用报障原话再走一遍**
  （`app/data/` 里那个学生的原句就是这么留下的）。
- **纠错宁可漏纠，不可误伤。** 形近字纠正（中午/中文）有三道闸门，
  每一道都是被"纠错纠出更大的错"打回来才加的：不拦会**连环改**
  （今天→今晚→今夜，一路改烂整句）、会把「上班」纠成「上午」再擦掉
  （**悄悄少一个词**，比报错难发现）、会在没有时间语境时瞎猜。

## 九、当前局限（诚实写出来）

- **图片/扫描件读不出字**：需要接 OCR，目前只支持 txt / pdf / docx / xlsx / pptx 的文字层。
- **没有真正的账号体系**：现在是演示级的身份切换，没有密码。
- **多人隔离未做**：`app/data/student/` 是"一个人的"个人库，没有按学号分。
- **长资料会被截断**：单次最多给模型 6000 字。
- **演示视频需本地录制**：沙箱环境无法录屏，逐镜脚本见 `docs/演示视频分镜.md`。
- **周期性待办未做**：现在一条待办只属于某一个日期。
