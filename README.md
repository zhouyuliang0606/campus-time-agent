# 校园时间管家 Agent / CampusTime

一个校园 AI 服务助手：把**课表、待办、快递、外卖、校园问答**收口到同一个助手，
并且守一条硬规矩 —— **AI 只出提案，学生点了确认，系统才写库**。

## 一、三个角色，一个引擎

| 端 | 定位 | 入口 |
|---|---|---|
| **学生活端（旗舰）** | 课表时间规划 + 校园问答 + 快递查询 + 外卖查询 | `/student`、`/plan` |
| **驿站 / 商户侧** | AI 客服：答复咨询、推送取件提醒与滞留预警，人设可配 | `/station` |
| **管理控制台** | 零代码维护知识库、客服人格、**在线配置大模型本身** | `/admin` |

三层**共享同一个 Agent 引擎 + 一份知识库 + 一份大模型配置**，不重复实现。
在管理台改一条知识库、换一次模型 Key，另外两端立刻生效，**全程不用重启、不用碰服务器**。

## 二、技术栈

| 层 | 选型 | 说明 |
|---|---|---|
| 后端 | **Python + FastAPI** | 把函数变成网页可调用的接口，uvicorn 启动 |
| 前端 | **原生 HTML / JS** | 不需要打包工具，不引入前端框架 |
| 大模型 | **DeepSeek API** | Key 走 `.env` 或管理后台，**不写进代码、不入库** |
| Agent | **自写的轻量 ReAct 循环** | 不套 LangChain 等重框架，确定性分支优先于模型 |
| 存储 | **JSON 文件**（`app/data/`） | 演示够用；`store.py` 已按"换数据库不改调用方"分层，替换成本低 |
| 测试 | **FastAPI TestClient + 自写 Checker** | 不需要 pytest，评委零额外安装即可跑 |

页面共 **7 个**，API 端点 **38 个**。

## 三、架构主线：判定层 / 执行层分离（本项目最重要的设计）

这条线是整个项目的地基，也是它和"随便套个 LLM 问答"的根本区别。

```
┌─ 判定层：听懂这句话要干什么、归哪个模块（可换、可兜底、可以交给模型）
│   ① 样本库   历史成功原话做 Dice 模糊匹配（零成本、离线可跑，兼作 ② 的缓存）
│   ② 语义层   问一次大模型，只要一个 JSON：{module, intent}
│   ③ 规则兜底 30 多张关键词表 + router._QUICK_MAP
└──────────────────────────────────────────────────────────
┌─ 执行层：查空档 · 排期 · 出候选卡 · 写库（系统独占，模型永远碰不到）
└──────────────────────────────────────────────────────────
```

**为什么要把这两层切开？** 因为学生报过一句一针见血的话：

> 「很多的字都是接不住的，你现在能接住的都是我测试给的。」

过去每报一次障就往词表里加一条，`planner.py` 里堆到 **30 多张**关键词/正则表，
`router.py` 里还有 **50 多个**硬编码词，全是 `if keyword in text` 这种朴素子串匹配 ——
**拿字符串匹配干语义理解的活**，词表加多长都收敛不了：中文口语的写法是无限的。

所以 2026-09-26 起引入判定层，2026-09-27 又把**顺序倒成「语义优先、关键词兜底」**：

| 档 | 做什么 | 成本 | 没配 Key 时 |
|---|---|---|---|
| ① 样本库 | 历史成功原话模糊匹配（Dice 相似度 ≥0.42） | 零 | 照样能用 |
| ② 语义层 | 问一次 LLM，**只要** `{module, intent}`，置信度 <0.6 直接丢弃 | 一次调用 | 自动跳过 |
| ③ 规则兜底 | 词表命中就走 | 零 | 兜底 |

关键设计：语义层那个 LLM **拿不到任何写库接口**，也碰不到排期算法。它只负责"听懂"，
拿到 JSON 之后，查空档、摊候选、出卡、写库**走的还是原来那套确定性代码**。
所以「AI 只提案、系统才执行」这条架构主张一条都没破 —— 变的只是"听懂人话"这一步不再由正则独占。

判定层一律**偏保守**：白名单 intent / 置信度低于 0.6 不要 / 词长不足不匹配 / 没配 Key 就安静返回 `None`。
取向是「**宁可漏判掉回老路，不可替学生办错事**」。

### Propose / Execute 分离（同一根地基的另一半）

早期版本用纯模型直接回「已经帮你排好啦」，学生刷新日程却空空如也 ——
模型没有写库能力，只是在文字里"表演"写库。现在：

- Agent 只调用 **read-only 工具**（查空档、列待办、读文件）；
- 任何会改变状态的操作，先变成一张「提案」返回，提案上的 `kind` 由**系统盖章**，不由模型自报；
- 前端按 `kind` 渲染确认卡，学生点【确认】后，**才由系统真正执行写库**。

写库的唯一入口是系统侧的确认动作，**模型无论走哪条路都碰不到写入接口**。

## 五、给零基础的你：怎么跑起来

### 1. 准备 Python
需要 **Python 3.10 或更高版本**（本项目在 3.13 上开发与测试）。
装好后在命令行敲 `python --version` 能看到版本号就 OK。

### 2. 装依赖

```bash
cd CampusTime
python -m venv .venv            # 建一个独立的虚拟环境（推荐，不污染系统）
.venv\Scripts\activate          # Windows 激活；macOS/Linux 用 source .venv/bin/activate
pip install -r requirements.txt
```

> `requirements.txt` 里每一行上面都写了中文注释，说明这个库是干嘛的。
> 其中 `pypdf` / `python-docx` / `openpyxl` / `python-pptx` 只影响**文件上传解析**，
> 不装也能跑，只是那几种格式传不了。

### 3. 配大模型 Key（**两种方式，任选一种**）

| 方式 | 怎么做 | 生效时机 |
|---|---|---|
| **① 管理后台在线填**（推荐） | 启动后打开 `/admin`，在「🔑 API 配置」卡片里填 Key、地址、模型，点「测试连通」 | **立刻生效，不用重启**；优先级高于 `.env` |
| **② 写进 `.env`** | 复制 `.env.example` 为 `.env`，把 `DEEPSEEK_API_KEY` 换成你的真实 Key | 需重启服务 |

去 https://platform.deepseek.com 注册即可拿到 Key（形如 `sk-xxxxxxxx`）。

> **没配 Key 也能跑**：系统会自动切到确定性的 Mock 模式，
> 排程交互、卡片渲染、知识库问答等**离线链路照常演示**，只是不调用大模型。
> `.env` 已在 `.gitignore` 里，Key 永远不会被提交。

### 4. 启动

```bash
uvicorn app.main:app --reload
```

浏览器打开 **http://127.0.0.1:8000**

### 5. 验证功能有没有坏（推荐先跑一次）

```bash
python tests/run_all.py
```

预期总账：

```
总账：通过 1052 项，失败 0 项（共 9 批）
全部通过 ✅
```

测试跑在**临时数据副本**上，不会碰你的演示数据（见 `tests/README.md`）。

## 六、跑起来后先试这几句

这些是真实测试用例覆盖过的说法，能直接看出系统的脾性：

| 你说 | 应该看到 |
|---|---|
| 「帮我把复习线性代数安排到周四 19:00–20:30」 | 出**确认卡**；点了确认日程里才出现 —— **没确认就不会写** |
| 「我的代办呢」 | 直接念出真实待办列表（真查库，不是编的） |
| 「把周四那个瑜伽挪到周五」 | 出**改期卡**，确认后旧条目移除、新条目落位 |
| 「健身显示不出来」 | 系统真去查库核实，如实回答"在的/不在" |
| 「我要去哪里取快递」 | 走**校园问答**检索知识库回答 —— **不会**被误当成"加个待办" |
| 在「校园问答」栏问任何问题 | 走知识库检索；**问句不会被误判成下单** |

最后两条看着不起眼，其实是本项目判定层存在的全部理由：**先分"问"还是"办"，再决定干什么**。

## 七、AI 协同开发是怎么记录的

比赛要求「保留完整、细粒度的 Git 提交历史」和「提交 AI 对话历史 Prompt 快照」，本项目的做法：

- **每个逻辑改动单独 commit**，绝不在最后一次性打包（截至 2026-09-27 为 **197 个**，此后持续增加）；
- 每次开发会话写一份 Prompt 快照到 `ai-prompts/YYYY-MM-DD-<主题>.md`，
  记录「**用户 Prompt → AI 研判 → 改动 → 验证**」四段，**单独提交**、不与代码混在一个 commit；
- 快照文件与其 commit 一一对照，即可还原那一步的协同过程。
- **全部提交的作者与提交者均为参赛者本人**（`zhouyuliang0606 <3215477176@qq.com>`），

## 八、几条值得一看的设计取舍

- **弹窗显不显示，不由模型决定。** 提案上的 `kind` 由系统盖章。否则"要不要弹窗"的决定权回到模型手里，
  就会退化成「经常不弹弹窗」。
- **语义层可以反过来复核规则。** 规则判了"要办事"、但这句其实是问句（或人就在问答型栏目里）时，
  让语义层复核一次，只有**正面肯定**才否决规则 —— 因为样本库是模糊匹配，
  误否决一张本来就该出的卡比漏判更让学生恼火。
- **不让关键词表背锅。** 新说法接不住，走语义层/样本库兜底，**不是往词表里再补一条正则**。
- **测试用数据沙箱而非"备份再还原"。** 早期方案只要中途崩溃就还原不回去，
  实测真出过一次假 Key 被留在 `settings.json` 里；改成临时副本后，崩溃也无所谓。

## 九、当前局限（诚实写出来）

- **图片/扫描件读不出字**：需要接 OCR，目前只支持 txt / pdf / docx / xlsx / pptx 的文字层。
- **没有真正的账号体系**：现在是演示级的身份切换，没有密码。
- **多人隔离未做**：`app/data/student/` 是"一个人的"个人库，没有按学号分。
- **长资料会被截断**：单次最多给模型 6000 字。
- **演示视频需本地录制**：沙箱环境无法录屏，逐镜脚本见 `docs/演示视频分镜.md`。
- **周期性待办未做**：现在一条待办只属于某一个日期。
